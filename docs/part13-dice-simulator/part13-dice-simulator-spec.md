### 3-2. 内部値と表示名の分離 [必須B] B1

| # | 仕様 |

**D5に注意する [必須B]：** `select.value` は常に文字列である。`"6"` のまま `Math.floor(r * sides)` に渡すと `Math.floor(r * "6")` となり、JavaScriptの暗黙変換で偶然動いてしまう。**明示的に数値へ変換すること。**

| D7 | **初期値は `6`（d6）** |

## 4. 個数入力仕様

### 4-1. 入力UI [必須A] A3 / [必須B] B3

**`<input type="number" min="1" max="10" step="1">` を用いる。**

| # | 仕様 |
|---|---|
| C1 | `type="number"` とする |
| C2 | `inputmode="numeric"` を指定する（スマートフォンで数値キーボードを表示する） |
| C3 | `min="1"` `max="10"` `step="1"` を指定する |
| C4 | **初期値は `1`** |
| C5 | `<label>` を関連付ける |

#### `<select>` との比較 [必須B]

| 観点 | **A. `<input type="number">`（採用）** | B. `<select>` |
|---|---|---|
| 入力の速さ | 直接入力とスピナーの両方が使える | 毎回リストから選ぶ |
| スマートフォン | 数値キーボード | ネイティブピッカー |
| 不正入力 | **あり得る**（4-2で検証が必要） | 原理的に発生しない |
| 実装量 | 検証処理が必要 | 少ない |

**Aを採用する理由 [必須B] B3：** Bは不正入力が原理的に発生せず安全だが、**1〜10の選択肢を毎回リストから選ぶのは、繰り返し振る用途でテンポが悪い。** 課題文が「ゲームや確率確認などにも利用できる」としており、**繰り返し操作が前提**であることを重視する。

（19章 U3）

### 4-1-1. 個数の増減ボタン [必須B]

`<input type="number">` のネイティブな増減スピナーはブラウザにより表示されないため、入力欄の左右に標準の `<button type="button">` による「−」「＋」を常時表示する。

| # | 仕様 |
|---|---|
| C5a | 配置は `− [ 個数入力 ] ＋` とする。直接入力は維持する |
| C5b | 「−」は現在の有効な整数を1減らし、「＋」は1増やす |
| C5c | 1未満・10超には変更しない。値が1なら「−」、10なら「＋」を `disabled` にする |
| C5d | 空欄・整数でない・範囲外など、現在値が4-2の検証を通らない間は両ボタンを `disabled` にし、値を推測・補正しない |
| C5e | 直接入力に応じてボタンの有効・無効を更新する |
| C5f | ボタン操作後の値も、次回「振る」時に4-2の既存手順で通常どおり検証する |
| C5g | 各ボタンのタップ領域は44×44px以上とし、PC／モバイル共通で使用できること |

増減ボタンは個数入力を補助するUIであり、入力の検証手順・ロール処理・状態管理は変更しない。

### 4-2. 妥当性の判定 [必須B] B3

**`value` を文字列として取得し、以下の順に判定する。**

```
① 前後の空白を除去する
② 空文字なら「未入力」
③ 整数の形式でなければ「整数でない」
   /^[+-]?\d+$/ に完全一致するか
④ Number() に変換し、1 以上 10 以下でなければ「範囲外」
⑤ 上記をすべて通過したものを、有効な個数とする
```

#### 判定結果の実測 [必須B]

**上記の手順をそのまま実行した結果である。受入テストの期待値として用いる。**

| 入力 | 判定 | 備考 |
|---|---|---|
| `1` | **有効（1）** | 下限 |
| `10` | **有効（10）** | 上限 |
| `3` | 有効（3） | |
| `+5` | **有効（5）** | 正符号は許容される |
| `007` | **有効（7）** | 先頭ゼロは許容される |
| `" 3 "`（前後空白） | **有効（3）** | ①で除去される |
| （空欄） | **未入力** | |
| `0` | **範囲外** | |
| `11` | **範囲外** | |
| `-1` | **範囲外** | 形式としては整数 |
| `1.5` | **整数でない** | |
| `1e2` | **整数でない** | 正規表現に一致しないため |
| `abc` | **未入力** | `type="number"` により `value` が空文字になるため |
| `３`（全角） | **未入力** | 同上 |

**`1e2` を弾くために正規表現が必要である [必須B]。** ブラウザによっては `type="number"` が `1e2` を受け付けるため、`Number()` だけの判定では `100` として通ってしまう。

**全角数字を半角へ正規化しない [必須B]。** `type="number"` は全角数字を受け付けず `value` が空文字になるため、正規化しても効果がない。

### 4-2-1. 検証ロジックとブラウザ挙動を区別する [必須B] ← 受入テストの前提

**上表は「その文字列が `value` として得られた場合に、検証ロジックがどう判定するか」を示したものである。実ブラウザでその文字列を入力できるかどうかは別問題である。**

`<input type="number">` は、ブラウザ自身が入力を正規化・拒否する場合がある。挙動はブラウザ・OS・IMEにより異なる。

| 入力 | 検証ロジックの判定 | 実ブラウザでの入力可否 |
|---|---|---|
| `1` `10` `3` | 有効 | **入力できる** |
| `0` `11` | 範囲外 | 入力できる（`min` / `max` は送信時の制約であり、入力自体は妨げられない） |
| `-1` | 範囲外 | 入力できる |
| `1.5` | 整数でない | 入力できる（`step="1"` があっても入力は妨げられない） |
| `+5` | 有効（5） | **ブラウザにより異なる。** `+` を受け付けない場合がある |
| `007` | 有効（7） | **ブラウザにより異なる。** 先頭ゼロを除去する場合がある |
| `" 3 "`（前後空白） | 有効（3） | **ブラウザにより異なる。** 空白を除去して `3` として保持する場合がある |
| `1e2` | 整数でない | **ブラウザにより異なる。** 受け付ける場合と `value` が空文字になる場合がある |
| `abc` `３`（全角） | 未入力 | **多くのブラウザで入力できない**、または `value` が空文字になる |

| # | 仕様 |
|---|---|
| C6 | **`+5` `007` `前後空白` `1e2` は、ブラウザが正規化・拒否しても不具合としない** |
| C7 | 検証ロジックは、**どのような文字列が `value` から得られても、上表の通りに判定できること** |
| C8 | 実ブラウザで入力できない値については、**検証ロジックを直接呼び出して確認する**（17章 E-2群） |

**この区別が必要な理由 [必須B]：** ブラウザが `+5` を `5` に正規化した場合、画面上は正常に5個振れる。**これは検証ロジックの不具合ではなく、ブラウザの仕様である。** 区別せずにテストすると、「`+5` が入力できない＝バグ」と誤判定される。

**検証ロジックは、ブラウザの挙動に依存せず単体で正しく動くこと**を要件とする。将来ブラウザの挙動が変わっても、ロジック側で受け止められる。

### 4-3. エラーメッセージ [必須B] B3

| # | 条件 | メッセージ |
|---|---|---|
| E1 | 未入力（空欄） | **`個数を入力してください`** |
| E2 | 整数でない | **`1〜10の整数を入力してください`** |
| E3 | 範囲外 | **`1〜10個の範囲で指定してください`** |

**3種類を区別する [必須B]：** 利用者の対処がそれぞれ異なる（入力する／小数をやめる／範囲を確認する）。

### 4-4. エラー時の扱い [必須B] ← 重要

**入力エラーは、前回の正常な結果を破棄しない。**

| 対象 | エラー時の扱い |
|---|---|
| **アニメーション** | **開始しない** |
| **結果一覧** | **前回の正常な結果を維持する** |
| **合計値** | **前回の値を維持する** |
| **「振る」ボタン** | **有効のまま維持する** |
| **入力欄の内容** | **消さない**（修正できるようにする） |
| `isRolling` | `false` のまま変えない |

**前回結果を維持する理由 [必須B]：** Part 10（コピー失敗で変換結果を消さない）・Part 11（入力エラーでヒントを消さない）と同じ考え方である。**入力ミスは利用者の操作の問題であり、直前に正しく振った結果まで失わせる理由がない。**

（19章 U11）

## 5. 乱数生成仕様

### 5-1. 生成式 [必須A] A2

```js
function rollDieFromRandom(randomValue, sides) {
  return Math.floor(randomValue * sides) + 1;
}
```

| # | 仕様 |
|---|---|
| R1 | **結果は必ず `1 <= result <= sides`** |
| R2 | 結果は必ず整数 |
| R3 | **`Math.round()` を使わない** |
| R4 | `Math.ceil()` も使わない（`randomValue` が `0` のとき `1` にならない） |

### 5-2. `Math.round` を使った場合の誤り [必須B]

**`Math.round(Math.random() * 6) + 1` の実測（d6、20万回）：**

```
{1: 16818, 2: 33168, 3: 33207, 4: 33538, 5: 33720, 6: 33197, 7: 16352}
→ 範囲外（7）が 16352 件
```

| # | 問題 |
|---|---|
| 1 | **範囲外の `7` が出る**（全体の約8%） |
| 2 | **`1` と `7` の出現確率が、他の目の約半分**になる |

**範囲逸脱と分布の偏りが同時に起きる。受入テストで両方を確認する**（17章 B-9・B-10）。

### 5-3. 決定的にテストできる構造 [必須B] B2

**`Math.random()` の呼び出しと、乱数値から出目への変換を分離する。**

```js
// 乱数値から出目を決める（テスト可能な純粋関数）
function rollDieFromRandom(randomValue, sides) {
  return Math.floor(randomValue * sides) + 1;
}

// 実際のロールで呼ぶ
function rollDie(sides) {
  return rollDieFromRandom(Math.random(), sides);
}
```

| # | 仕様 |
|---|---|
| R5 | 変換関数は、任意の乱数値と面数を渡して結果を確認できること |
| R6 | 変換関数は**純粋関数**とする（状態の更新・DOM操作を行わない） |
| R7 | **大量試行による分布確認だけで合否を判定しない** |

**この分離が必要な理由 [必須B] B2：** `Math.random()` を関数内で直接呼ぶと、**「乱数 0 のとき 1 になるか」を確認できない。** 分布だけを見ても、`+1` の付け忘れ（0〜sides-1 になる）や面数の取り違えを検出しにくい。

### 5-4. 境界値の実測結果 [必須B]

**受入テストの期待値として用いる。**

| 面数 | `r = 0` | `r = 0.5` | `r = 0.9999999999999999`（1未満の最大値） |
|---|---|---|---|
| d4 | **1** | 3 | **4** |
| d6 | **1** | 4 | **6** |
| d8 | **1** | 5 | **8** |
| d10 | **1** | 6 | **10** |
| d12 | **1** | 7 | **12** |
| d20 | **1** | 11 | **20** |
| d100 | **1** | 51 | **100** |

#### 中間値の実測結果 [必須B]

| 面数 | `r = 0.25` | `r = 0.5` | `r = 0.75` | `r = 0.99` |
|---|---|---|---|---|
| d4 | 2 | 3 | 4 | 4 |
| d6 | 2 | 4 | 5 | 6 |
| d8 | 3 | 5 | 7 | 8 |
| d10 | 3 | 6 | 8 | 10 |
| d12 | 4 | 7 | 10 | 12 |
| d20 | 6 | 11 | 16 | 20 |
| d100 | 26 | 51 | 76 | 100 |

#### 誤りやすい期待値 [必須B] ← 注意

**`r = 1 / sides` を渡すと、出目は `1` ではなく `2` になる。**

| 面数 | `1 / sides` | `(1 / sides) * sides` | 出目 |
|---|---|---|---|

### 6-1. 生成 [必須A] A3

| # | 仕様 |

}

## 9. 1回の「振る」処理

### 9-1. 処理順 [必須A] / [必須B] B4 ← 本Partの中核

**乱数はアニメーション開始前に確定する。アニメーション中は結果を見せない。**

```
① 面数を取得する（<select> の値を Number() で数値化）
② 個数を取得し、検証する（4-2）
③ エラーがあれば、メッセージを表示して処理を中断する
   ・アニメーションを開始しない
   ・前回の結果・合計を維持する（4-4）
④ 出目を生成し、最終結果を内部で確定する（5章・6章）
⑤ 合計を算出する（7章）
⑥ isRolling = true にし、「振る」ボタンを無効化する
⑦ アニメーションを開始する（結果は表示しない）
⑧ アニメーション終了後、④⑤で確定済みの結果と合計を表示する
⑨ isRolling = false にし、「振る」ボタンを有効化する
```

#### この順序とする理由 [必須B] B4

| # | 理由 |
|---|---|
| 1 | **1クリック＝1回の抽選結果が明確になる**。抽選のタイミングが1箇所に固定される |
| 2 | **タイマーの実行回数に結果が依存しない**。アニメーションのコマ数や実行時間が変わっても出目は変わらない |
| 3 | **テストしやすい**。④の時点で結果が確定しているため、アニメーションを待たずに検証できる |
| 4 | **演出とロジックを分離できる**。アニメーションの変更が乱数結果に影響しない |

**やってはならない実装 [必須B] B4：**

| # | 誤った実装 | 問題 |
|---|---|---|
| NG1 | アニメーションの各フレームで乱数を生成し、**最後のフレームの値を結果とする** | フレーム数・実行時間で結果が変わる。テストできない |
| NG2 | アニメーション終了時に乱数を生成する | ④が⑧に移動し、演出とロジックが絡む |
| NG3 | アニメーション中に確定済みの結果を表示する | 「振っている最中に答えが見えている」状態になり、A6の演出が意味を失う |

### 9-2. アニメーション中の表示 [必須B]

| # | 仕様 |
|---|---|
| P1 | **確定した出目を表示しない**（NG3） |
| P2 | ロール開始時に、**指定された個数分のカードを「振っている」状態で表示する** |
| P3 | 各カードの出目欄には、確定値ではなくプレースホルダ（`?` 等）を表示する |
| P4 | **合計値は `—` にする**（前回の合計を残さない。新しいロールが進行中であることを示す） |
| P5 | アニメーション終了時に、プレースホルダを確定値へ差し替える |

**P4の理由 [必須B]：** アニメーション中に前回の合計が残っていると、**それが今回の結果だと誤読される。**

### 9-3. 連続実行 [必須A] A7

**何度でも連続してロールできる。** 回数の上限を設けない。

## 11. アニメーション仕様

### 11-1. 内容 [必須A] A6

**CSSアニメーションで、「振っている」と分かる程度の動きを付ける。**

| # | 仕様 |
|---|---|
| N1 | 回転・上下移動・拡大縮小などを組み合わせる |
| N2 | **CSSで実装する**（`@keyframes` ＋ クラス付与）。Canvas・物理演算・外部画像を使わない |
| N3 | **CSSアニメーションの時間を 0.6秒 とする**（推奨範囲 0.5〜0.8秒の中央） |
| N4 | **無限ループを禁止する**（`animation-iteration-count: infinite` を使わない） |
| N5 | 終了後に確実に停止し、確定値を表示する |
| N6 | **アニメーションの有無・長さで乱数結果が変わらない**（9-1） |
| N7 | **すべてのダイスカードのアニメーションを同時に開始する** |
| N8 | **`animation-delay` を使用しない** |
| N9 | **0.6秒後には、全カードのアニメーションが終了している** |

**N4の理由 [必須B]：** 無限ループは、終了処理の失敗時に**永久に結果が表示されない状態**を生む。回数を指定した有限のアニメーションとする。

### 11-1-1. CSSとJavaScriptの時間を一致させる [必須B] ← 必ず守る

**CSSアニメーションの時間と、JavaScript側の待ち時間を、ともに 0.6秒 に統一する。**

| 対象 | 通常時 | `prefers-reduced-motion: reduce` |
|---|---|---|
| CSSアニメーション | **0.6秒** | **なし**（アニメーションを適用しない） |
| JavaScript の待ち時間 | **0.6秒** | **0** |

| # | 仕様 |
|---|---|
| N10 | **`animation-delay` を使用しない。** カードごとに開始をずらさない |
| N11 | JavaScript側の待ち時間を定数として1箇所に定義し、**CSSの `animation-duration` と同じ値にする** |
| N12 | 0.6秒後に、**全カードのアニメーションが終了した状態**で確定値へ差し替える |

**`animation-delay` を禁止する理由 [必須B]：** カードごとに開始をずらすと、**最後のカードの終了時刻が「0.6秒 ＋ 最大delay」になる。** JavaScript側が0.6秒で結果を差し替えると、**まだ振っている最中のカードの出目が確定値に置き換わり、動きながら答えが見える状態**になる（9-2 P1 に反する）。

delayを使いつつ時刻を合わせるには、JavaScript側の待ち時間を「0.6秒＋最大delay」にするか、`animationend` を全カードで待つ必要がある。**いずれも実装が複雑になり、MVPで得られる見た目の効果に見合わない。**

**MVPでは全カード同時開始とする**（19章 U7）。

（19章 U7）

### 11-2. アニメーション中の再クリック [必須B] B5 ← 必ず確定する

**アニメーション中は「振る」ボタンを一時的に無効化する（案A）。**

| 案 | 内容 | 採否 |
|---|---|---|
| **A** | **アニメーション中はボタンを無効化する** | **採用** |
| B | 連打分を順番に処理する | 不採用 |
| C | 実行中のアニメーションを中断して新しいロールへ | 不採用 |

| # | 仕様 |
|---|---|
| N13 | `isRolling === true` の間、「振る」ボタンに `disabled` を設定する |
| N14 | アニメーション終了時に `disabled` を解除する |
| N15 | 無効化するのは「振る」ボタンのみ。面数・個数の変更は妨げない（8-6） |

**案Aを採用する理由 [必須B] B5：**

| # | 理由 |
|---|---|
| 1 | **1回の演出と1回の結果が対応する。** 案Bでは演出が追いつかず、案Cでは結果が見えないまま消える |
| 2 | **タイマーの多重起動を防げる。** 複数のアニメーションが重なり、終了処理が競合するのを避けられる |
| 3 | 無効化の期間が 0.6秒 と短く、操作の妨げになりにくい |

#### Part 12 と方針が異なる点 [必須B] ← 明記する

**Part 12（じゃんけん）では「連打防止のロックを実装しない」と定めた。本Partでは逆に、ロック（ボタンの無効化）を実装する。**

| | Part 12 | **Part 13（本Part）** |
|---|---|---|
| 処理 | **同期処理のみで完結する** | **非同期のアニメーションを含む** |
| ロック | **実装しない** | **実装する** |
| 理由 | 同期処理はクリック順に確実に処理される。ロックを入れると、かえってクリックが無視される | **非同期処理が重なると、タイマーの多重起動・終了処理の競合が起きる** |

**この違いは方針の揺れではなく、処理の性質の違いによる [必須B]。** 同期処理にロックは不要であり、非同期処理にはロックが必要である。

（19章 U6）

### 11-3. `prefers-reduced-motion` [必須B] B6

**`prefers-reduced-motion: reduce` の環境では、アニメーションを省略または大幅に短縮する。**

| # | 仕様 |
|---|---|
| N16 | CSSの `@media (prefers-reduced-motion: reduce)` で**アニメーションを適用しない** |
| N17 | **JavaScript側の待ち時間を 0 にする** |
| N18 | **結果は通常と同じように正しく表示される**（出目・合計・順序がすべて同じ） |
| N19 | **9-1の処理順は変更しない。** ④で結果を確定し、⑧で表示する流れは同じ |
| N20 | アニメーションを省略する場合も、`isRolling` の遷移は行う（⑥⑨） |

**N19の理由 [必須B]：** 処理順を分岐させると、**通常時と reduced-motion 時で異なるコードパスができ、片方だけ壊れる。** 変えるのは「CSSアニメーションを適用するか」と「待ち時間の値」の2点のみとする。

**N17が必要な理由 [必須B]：** CSSでアニメーションを無効にしても、JavaScript側が0.6秒待っていては**画面が止まったまま0.6秒待たされる**だけになる。**`matchMedia('(prefers-reduced-motion: reduce)')` で判定し、待ち時間を 0 にする。**

（19章 U8）

### 15-1. 結果の通知方法 [必須B] B10

**確定した結果を、1文にまとめて通知する。**

| 例 |
|---|
| `3個のd6を振りました。結果 4、2、6。合計12` |
| `1個のd20を振りました。結果 17。合計17` |

| # | 仕様 |
|---|---|
| AL1 | 通知は**アニメーション終了後**（9-1 ⑧）に1回だけ行う |
| AL2 | **アニメーション中は通知しない**（AC7） |
| AL3 | 通知用の要素は `aria-live="polite"` とする |
| AL4 | **ダイスカード群には `aria-hidden="true"` を付け、読み上げの重複を避ける** |
| AL5 | 通知用の要素は**視覚的に隠す**（`visually-hidden`）が、**DOMには残す**（`display: none` にしない） |
| AL6 | 合計値の表示領域は視覚的に表示したままとし、`aria-live` を付けない |

**この方式にする理由 [必須B] B10：** 10個振ると、カードが10枚＋合計1つが同時に更新される。**すべてを読み上げると11項目になり、実用に耐えない。** 1文にまとめれば、1回の読み上げで全情報が伝わる。

**AL5の理由：** 視覚的に隠した要素も、スクリーンリーダーの通常の読み進めで到達できる。**ロール直後の通知だけでなく、後から読み返すこともできる。**

## 16. 「確率確認に利用できる」の解釈 [必須B] B11

**課題文の「ゲームや確率確認などにも利用できる」は、以下でMVP要件を満たすと解釈する。**

| # | 満たす要素 |
|---|---|
| 1 | **面数を変更できる**（3章） |
| 2 | **複数個を同時に振れる**（6章） |
| 3 | **各ダイスの個別結果が分かる**（10-2） |
| 4 | **合計が分かる**（7章） |
| 5 | 何度でも連続して振れる（9-3） |

**統計・ヒストグラム・平均・期待値・大量試行はMVP外とする**（2-2 の3〜9）。

**理由 [必須B] B11：** 課題文のクリア条件5項目に統計機能は含まれていない。「確率確認**などにも利用できる**」は、**利用者が手動で試行と観察を行える状態**を指すと解釈するのが自然である。統計機能を実装すると、集計方法・試行回数・表示形式など新たな仕様判断が多数発生し、クリア条件から離れる。

（19章 U13）

### 19-1. アニメーション時間に関する確定（U7）

当初案では、11-1 N7 として **「各カードのアニメーション開始をずらしてよい（`animation-delay`）」** と記載していた。

**依頼者判断により、この方針を撤回し、全カード同時開始に確定した。**

#### 撤回の理由

JavaScript側の待ち時間を 0.6秒 に固定する場合、`animation-delay` を使うと**最後のカードの終了時刻が「0.6秒 ＋ 最大delay」になり、JS側の結果表示時刻とずれる。**

その結果、**まだ動いているカードの出目が確定値に置き換わり、「動きながら答えが見えている」状態**になる。これは 9-2 P1（アニメーション中は確定値を表示しない）に反する。

#### 確定内容

| # | 内容 |
|---|---|
| 1 | **`animation-delay` を使用しない** |
| 2 | **CSSアニメーション時間とJavaScriptの通常時待ち時間を、ともに 0.6秒 とする** |
| 3 | **0.6秒後には全カードのアニメーションが終了している** |
| 4 | **その後に確定済み結果へ差し替える** |
| 5 | **`prefers-reduced-motion: reduce` では、CSSアニメーションなし・JS待ち時間 0** |

**delayを使いつつ時刻を合わせる方法（待ち時間を「0.6秒＋最大delay」にする、全カードの `animationend` を待つ）も存在するが、実装が複雑になり、MVPで得られる見た目の効果に見合わない。**

### 19-2. 個数入力の検証とブラウザ挙動の区別（U3）

**`<input type="number">` は、ブラウザ自身が入力を正規化・拒否する場合がある。** そのため、受入テストを2群に分けた（17章 E章）。

| 群 | 対象 | 確認方法 |
|---|---|---|
| **E1群** | ブラウザ上で確実に入力できる値（`1` `10` `0` `11` `1.5` 空欄など） | **画面を操作して確認** |
| **E2群** | ブラウザが正規化・拒否し得る値（`+5` `007` 前後空白 `1e2` 全角など） | **検証ロジックを直接呼び出して確認** |

**ブラウザが `+5` を `5` に正規化したり、`1e2` を受け付けず `value` を空文字にしたりしても、それをJavaScript検証ロジックの不具合と判定しない**（4-2-1 C6・17章 E2群の注意）。

**確認すべきは「その文字列が渡されたときにロジックが正しく判定するか」である。** ブラウザの挙動はOS・IME・バージョンにより異なり、将来変わり得るため、**ロジック側がどのような文字列でも正しく判定できることを要件とする。**

## 1. 目的と対象範囲

### 1.1 目的 `[必須A]`

利用者が手元のCSVファイルをブラウザ内で読み込み、列を選んで絞り込み・集計し、棒グラフ、折れ線グラフ、円グラフとして確認できるようにする。作成したグラフはPNG画像として保存できるようにする。

### 1.2 対象利用者 `[必須A]`

- 表形式のデータを簡単に可視化したい利用者
- CSVやグラフの基本概念は理解しているが、コードを書かずに操作したい利用者
- 単一端末・単一ブラウザ内で一時的に分析する利用者

### 1.3 課題クリア条件 `[必須A]`

- UTF-8のCSVファイルを読み込み、行列データとして解析できる。
- 棒グラフ、折れ線グラフ、円グラフを表示できる。
- X軸／カテゴリ、Y軸／数値、凡例、グラフタイトルを設定できる。
- 読み込んだデータを1条件で絞り込み、合計、平均、件数で集計できる。
- 現在表示中のグラフをPNG画像として保存できる。

## 2. 画面構成

### 2.1 全体 `[必須A]`

画面は次の領域で構成する。

1. ヘッダー
2. 全体通知領域
3. データ読み込み・読み込み情報を統合したデータバー
4. 絞り込み・グラフ設定領域
5. グラフ表示・PNG保存領域
6. 集計結果領域
7. 元データプレビュー領域

広い画面の分析領域は、左列に分析条件パネル、右列にグラフパネルと集計結果パネルを縦に並べる。元データプレビューは分析領域の下へ全幅で配置する。

### 2.2 ヘッダー `[必須B]`

- アプリ名「データ分析・グラフ化ツール」を表示する。
- 用途を短く説明する文言を表示する。
- 「外部送信なし」の表示を維持し、デスクトップではタイトルの存在感を保ちながら上下余白を抑える。

### 2.3 全体通知領域 `[必須B]`

- 読み込み、解析、グラフ作成、PNG保存に関する成功、案内、エラーを表示する。
- エラーは色だけでなく、種類を示す文言または記号を伴わせる。
- 新しい通知を支援技術が認識できるよう、適切な `aria-live` を設定する。
- 通知を表示しても、回復可能な場合は利用可能な操作を維持する。
- エラーの視認性と通知機能を維持したまま、上下余白を必要以上に取らない。

### 2.4 データバー `[必須A]`

- データ読み込みと読み込み情報を1つのパネルへ統合する。
- 広い画面では「STEP 1／データ」、CSVファイル選択、サンプルCSV取得、ファイル名、総行数、絞り込み後行数、列数を横方向へ配置し、全体の高さはおおむね90〜110pxを目安とする。
- CSVファイル選択欄を表示する。
- 選択可能な形式がUTF-8のCSVであることと、5 MiB・データ10,000行・100列の上限を、ファイル選択欄付近の小さな補足として表示する。
- `sample-data.csv` を取得できるダウンロード導線を表示する。
- 必要以上に高さを取る大きなドロップ領域は設けない。
- ファイルの読み込み中は進行中であることを表示し、ファイル選択と重複する処理開始を無効化する。

### 2.5 データバー内の読み込み情報 `[必須A]`

独立した大きな情報カードは設けず、データバー内のコンパクトなラベルと値として次を表示する。

- ファイル名
- 総行数。ヘッダーを除くデータ行数とする。
- 絞り込み後の行数
- 列数

各値はHTML上で識別可能なラベルを持ち、色だけに依存させない。ファイル未読込時は未読込であることを表示し、長いファイル名はデータバーやページ幅を壊さない。

### 2.6 絞り込み・グラフ設定領域 `[必須A]`

次のフォーム部品を表示する。

- 絞り込み列
- 絞り込み値
- グラフ種類：棒グラフ、折れ線グラフ、円グラフ
- X軸／カテゴリ項目
- Y軸／数値項目
- 集計方法：合計、平均、件数
- 凡例を表示するチェックボックス
- グラフタイトル

各フォーム部品には常時識別できるラベルを付ける。プレースホルダーだけをラベルとして使用しない。

### 2.7 グラフ表示・保存領域 `[必須A]`

- Chart.jsが描画する `canvas` を配置する。
- グラフ未作成時は案内文を表示する。
- グラフ見出しの右側に「グラフを更新」と「PNGを保存」ボタンをこの順で横並びに配置し、狭い画面では重ならないよう折り返す。
- 視覚的なグラフと同じ集計値を、後述の集計結果領域でも確認できるようにする。

### 2.8 集計結果領域 `[必須B]`

- 広い画面では右列のグラフ直下へ配置し、右列の幅に収める。
- グラフに使用したカテゴリ、集計値を表形式で表示する。
- 集計方法、対象行数、Y軸項目を確認できる説明を付ける。
- 件数の場合はY軸の値を計算に使わないことが分かる表示にする。
- 結果がない場合は空の表を描画せず、理由を文章で表示する。
- 表領域の高さは最大約300pxとし、行数が少ない場合は内容に合わせて縮む。
- 行数が多い場合は表領域内だけを縦スクロールさせ、列が広い場合は同じ領域内だけを横スクロールさせる。
- スクロール中も列見出しを確認できるよう、テーブルヘッダーを表領域上部へ固定する。

### 2.9 元データプレビュー領域 `[必須A]`

- 読み込んだ元データをヘッダー付きの表で表示する。
- 先頭100データ行だけを表示し、100行を超える場合は「先頭100件を表示」等の文言を付ける。
- プレビューは絞り込み前の元データを対象とする。
- セクション見出しに表示件数と、状態が分かる「表示する」または「閉じる」操作を配置する。
- CSV読み込み成功後は折りたたみ状態とし、新しいCSVを読み込むたびに折りたたみへ戻す。展開状態は永続化しない。
- 開閉操作はキーボードで実行でき、状態を `aria-expanded` と関連付けた表示領域で支援技術へ伝える。
- 空値は空白のままにせず「（空値）」と表示する。
- 展開後の表領域は最大約320pxとし、行数や列数が多い場合は領域内だけを縦横スクロール可能にする。ページ全体の横スクロールは発生させない。

## 3. 初期状態と基本操作

### 3.1 初期状態 `[必須A]`

- ファイルは未読込である。
- 読み込み情報は未読込状態を示す。
- 設定フォーム、「グラフを更新」、「PNGを保存」は無効にする。
- グラフ、集計結果、データプレビューは未作成の案内状態にする。
- サンプルCSVの取得導線は利用可能にする。

### 3.2 読み込み成功 `[必須A]`

1. CSVを全体として解析・検証する。
2. 検証成功後だけ、新しいデータをアプリ状態へ確定する。
3. ファイル情報、列型、絞り込み候補、設定候補、プレビューを構築する。
4. 安全な初期候補がある場合だけ設定を自動選択する。
5. 安全なX軸・Y軸候補が揃いChart.jsが利用可能な場合は、初期設定による棒グラフと集計結果を自動作成する。数値列がない場合やChart.jsが利用不能な場合は自動作成しない。

### 3.3 初期候補 `[必須B]`

- X軸は先頭列を選択する。列がない場合は読み込み自体を失敗とする。
- Y軸は最初に判定された数値列を選択する。
- 絞り込み列は「絞り込みなし」を初期値とする。
- 絞り込み値は「すべて」を初期値とする。
- グラフ種類は棒グラフ、集計方法は合計、凡例は表示、タイトルは空を初期値とする。
- 数値列が1列もない場合は安全なY軸候補がないため自動選択せず、14.2の扱いとする。

### 3.4 設定変更と自動再描画 `[必須A]`

- 絞り込み列、絞り込み値、グラフ種類、集計方法、X軸、Y軸、凡例を変更した場合は、現在の設定からグラフと集計結果を直ちに自動再作成する。
- グラフタイトルは入力のたびに処理せず、最後の入力から約300 ms後に自動更新する。新しい入力時は直前の待機処理を取り消し、IME変換中は更新せず変換確定後に待機を開始する。
- 正常に同期再作成できる場合、設定変更と新グラフの間に空画面を表示しない。
- 作成条件を満たさない場合、旧グラフを現在有効な結果として扱わず、PNG保存を無効にしてグラフ領域と全体通知へ具体的な理由を表示する。
- 自動更新の成功通知は設定変更のたびに表示しない。失敗通知とCSV読み込み成功等の重要通知は維持し、`aria-live` への過剰な通知を避ける。
- 「グラフを更新」を実行すると現在の全設定から再描画し、自動更新失敗後も再試行できる。

### 3.5 新しいファイル `[必須A]`

- 新しいファイルの読み込み開始時点では、現在の正常なデータを保持する。
- 新しいファイルの読み込み・検証に成功した時点で、旧データ、旧設定、旧グラフ、旧集計結果を破棄して置き換える。
- 新しいファイルの読み込みに失敗した場合は、旧データと旧グラフを維持し、エラーを通知する。
- 読み込み中の二重操作を防止する。

## 4. CSVファイルの入力条件

### 4.1 対象ファイル `[必須A]`

- 拡張子が `.csv` の単一ファイルを対象とする。拡張子判定は大文字・小文字を区別しない。
- MIME typeは環境差があるため、単独の拒否条件にはしない。
- 文字コードはUTF-8とし、先頭にUTF-8 BOMがある場合は1つだけ除去する。
- UTF-8として正しく復号できないファイルは拒否する。
- JSON、Excel等は受け付けない。

### 4.2 入力上限 `[必須B]`

| 項目 | 上限 | 判定 |
| --- | ---: | --- |
| ファイルサイズ | 5 MiB（5,242,880 bytes） | 読み込み開始前に `File.size` で判定 |
| データ行数 | 10,000行 | ヘッダーを除き、空行を除外した行数で判定 |
| 列数 | 100列 | ヘッダー解析後に判定 |
| DOMプレビュー | 100行 | 元データ先頭から表示 |

上限超過時は一部だけを採用せず、ファイル全体を読み込み失敗とする。

### 4.3 空行 `[必須B]`

- ファイル末尾を含め、すべてのフィールドが空または空白文字だけの行は空行として読み飛ばす。
- クォート内の空白はフィールド内容として保持するが、その行の空行判定では前後空白を除いた結果を使用する。
- 空行を除いた最初の行をヘッダーとする。

## 5. CSV解析規則

### 5.1 基本規則 `[必須A]`

- 区切り文字はカンマ `,` とする。
- 行区切りはクォート外のLFまたはCRLFとする。
- CRだけの行区切りは不正形式とする。
- 1行目を列名として扱い、以降をデータ行として扱う。
- 末尾のカンマは空の最終フィールドを表す。
- 各データ行の列数はヘッダーの列数と完全に一致しなければならない。

### 5.2 ダブルクォート `[必須A]`

- フィールドの先頭文字が `"` の場合、そのフィールドをクォート済みフィールドとして解析する。
- クォート済みフィールド内のカンマは文字として扱う。
- クォート済みフィールド内の `""` は1つの `"` として扱う。
- 閉じクォートの直後にはカンマ、CRLF、LF、またはファイル終端だけを許可する。
- 閉じクォートがない、未クォートフィールド内に `"` がある、閉じクォート後に別の文字がある場合は不正形式とする。
- クォート内のCRまたはLFは `[MVP外]` とし、検出した時点でファイル全体を不正形式として拒否する。

### 5.3 ヘッダー `[必須B]`

- ヘッダー名はCSV解析後に前後の空白文字を除去する。
- ヘッダー名が空、または空白除去後に重複する場合は不正形式とする。
- ヘッダー名の大文字・小文字は区別する。
- データセルは解析後の文字列を保持し、表示時に前後空白を勝手に削除しない。

### 5.4 原子的な採用 `[必須B]`

- ファイル全体の解析、上限確認、ヘッダー確認、列数確認に成功した場合だけ採用する。
- 不正な行を飛ばす等の部分採用は行わない。
- 解析途中のデータを画面へ表示しない。

## 6. データ構造

### 6.1 CSVデータ `[必須B]`

```js
{
  fileName: "sample-data.csv",
  fileSize: 2048,
  headers: ["日付", "カテゴリ", "地域", "売上", "数量"],
  rows: [
    ["2026-01-01", "食品", "東日本", "12000", "3"]
  ],
  columnTypes: {
    "日付": "text",
    "カテゴリ": "text",
    "地域": "text",
    "売上": "number",
    "数量": "number"
  }
}
```

- `rows` はヘッダーを含まない二次元文字列配列とする。
- 各行の要素数は `headers.length` と一致する。
- 同名ヘッダーを禁止するため、`columnTypes` はヘッダー名をキーにできる。
- 読み込み後の元データは変更しない。

### 6.2 設定 `[必須B]`

```js
{
  chartType: "bar",
  xColumn: "カテゴリ",
  yColumn: "売上",
  aggregation: "sum",
  showLegend: true,
  title: "カテゴリ別売上",
  filterColumn: "",
  filterValue: "__ALL__"
}
```

許可値は次に限定する。

- `chartType`: `bar` / `line` / `pie`
- `aggregation`: `sum` / `average` / `count`
- `showLegend`: boolean
- `xColumn`, `yColumn`, `filterColumn`: 現在のヘッダー名または仕様で許可した空文字
- `filterValue`: 選択列に実在する値を表す内部キーまたは「すべて」を表す内部値

内部の「すべて」を表す値は、CSV内の実データと衝突しない方法で管理する。表示ラベルだけで状態を判定しない。

### 6.3 集計結果 `[必須B]`

```js
[
  { label: "食品", value: 32000, sourceRowCount: 3, validNumberCount: 3 },
  { label: "衣料", value: 18500.5, sourceRowCount: 2, validNumberCount: 2 }
]
```

- `label` は正規化後のX軸値とする。
- `value` は集計値、または有効な数値がない場合の `null` とする。
- `sourceRowCount` はグループに属する絞り込み後の行数とする。
- `validNumberCount` は合計・平均に使用した有効数値の数とする。件数では `sourceRowCount` と同じ値でよい。

## 7. 状態管理

### 7.1 状態 `[必須B]`

アプリは少なくとも次を区別して管理する。

```js
{
  dataset: null,
  config: { /* 6.2 */ },
  filteredRows: [],
  aggregateRows: [],
  chartInstance: null,
  isChartCurrent: false,
  isLoading: false,
  notification: null
}
```

### 7.2 状態遷移 `[必須B]`

- ファイル未読込、読み込み中、読込済み、読込エラーを区別する。
- `isLoading` 中は同じ非同期処理を開始できない。
- グラフ作成成功時だけ `chartInstance` と `aggregateRows` を現在値として確定し、PNG保存を有効にする。
- 設定変更時は自動再作成を行い、成功時だけ現在設定に対応するグラフとして `isChartCurrent` を `true` にする。タイトル入力の待機中および再作成失敗時は `false` としてPNG保存を無効にする。
- グラフ作成失敗時は不完全なグラフを残さず、PNG保存を無効にする。
- ページ再読み込み時にデータや設定を復元しない。

### 7.3 永続化 `[MVP外]`

- localStorage、IndexedDB、Cookie等へ読み込みデータや設定を保存しない。
- 読み込んだデータ、絞り込み、設定、グラフはページを閉じるか再読み込みすると失われる。

## 8. 列の型判定

### 8.1 数値の定義 `[必須B]`

データセルの前後空白を除去した文字列が、次の形式に完全一致し、JavaScriptの有限数へ変換できる場合を有効な数値とする。

```regex
^[+-]?(?:\d+(?:\.\d+)?|\.\d+)(?:[eE][+-]?\d+)?$
```

具体例：`10`、`-3.5`、`+.75`、`1e3` は有効。`1,000`、`¥100`、`10%`、`NaN`、`Infinity`、日付文字列は数値として扱わない。

### 8.2 列型の判定 `[必須A]`

- 空値でないセルが1件以上あり、そのすべてが8.1の有効な数値なら `number` とする。
- 空値でないセルがない列、または1件でも数値変換できない値を含む列は `text` とする。
- 空値とは前後空白を除去した結果が空文字となるセルを指す。
- 型判定は絞り込み前の全データ行を対象とし、設定変更で再判定しない。
- Y軸候補には `number` 列だけを表示する。
- X軸候補には全列を表示する。
- 絞り込み列候補には `text` 列だけを表示する。

## 9. 絞り込み

### 9.1 操作 `[必須A]`

- 絞り込み列では「絞り込みなし」または1つの `text` 列を選択できる。
- 列を選択すると、その列に存在する値から重複を除いた絞り込み値を構築する。
- 値の選択肢の先頭に「すべて」を表示する。
- 絞り込み列を変更した場合、絞り込み値を「すべて」へ戻す。
- `text` 列がない場合は絞り込み列を無効にし、その理由を案内する。

### 9.2 値の正規化 `[必須B]`

- 絞り込みとX軸グループ化では、セル値の前後空白を除去した文字列を比較値とする。
- 空値は内部で通常の文字列と衝突しないキーとして扱い、画面では「（空値）」と表示する。
- 値の選択肢は元データに最初に現れた順とする。
- 大文字・小文字、全角・半角は変換せず区別する。

### 9.3 適用 `[必須A]`

- 「すべて」の場合は全データ行を対象とする。
- 特定値の場合は、選択列の正規化値が完全一致する行だけを対象とする。
- 読み込み情報の絞り込み後行数を即時更新する。
- 集計は必ず絞り込み後の行に対して行う。
- 絞り込み結果が0件の場合はグラフ作成を禁止し、案内を表示する。

## 10. 集計計算

### 10.1 グループ化 `[必須A]`

- 絞り込み後の行を、選択したX軸列の正規化値ごとにグループ化する。
- グループの表示順は、絞り込み後データに最初に現れた順とする。
- X軸の空値グループは「（空値）」と表示する。

### 10.2 合計 `[必須A]`

- 各グループについて、選択Y軸列の有効な数値だけを加算する。
- 空値または防御的な再変換で有限数にならない値は除外する。
- 有効な数値が0件のグループは `null` とし、表では「データなし」と表示する。

### 10.3 平均 `[必須A]`

- 各グループの有効なY軸数値の合計を、有効数値件数で除算する。
- 空値は分母へ含めない。
- 有効な数値が0件のグループは `null` とする。
- 内部値とChart.jsへ渡す値は丸めず保持する。
- 表、ツールチップ等の表示は小数第2位まで四捨五入し、不要な末尾の0は付けない。`Intl.NumberFormat('ja-JP', { maximumFractionDigits: 2 })` 相当を使用する。

### 10.4 件数 `[必須A]`

- 各X軸グループに属する絞り込み後の行数を集計値とする。
- Y軸セルが空または数値変換不能でも件数へ含める。
- UI上のY軸選択は維持するが、件数計算には使用しない。

### 10.5 共通 `[必須B]`

- 集計前にX軸、Y軸、集計方法が現在の候補として有効か再検証する。
- 合計・平均の計算結果が有限数でない場合はグラフを作成せず、エラーを表示する。
- 集計結果表とグラフは同じ集計配列から生成する。

## 11. グラフ生成

### 11.1 共通 `[必須A]`

- 自動更新または「グラフを更新」を実行した時点の絞り込み、X軸、Y軸、集計方法、種類、凡例、タイトルを使用する。
- 作成前に入力条件を再検証する。
- 再作成時は既存のChart.jsインスタンスを適切に破棄してから新しいものを生成する。
- ラベルはX軸グループ、値は10章の集計結果とする。
- 単一データ系列だけを描画する。
- 凡例チェックの状態をChart.jsの凡例表示へ反映する。
- タイトルが空白だけならグラフ内タイトルを表示しない。
- Chart.jsの設定で `animation: false` とし、すべてのグラフ種類でアニメーションを無効にする。
- グラフ更新の処理完了時点で最終描画状態にし、直後のPNG保存でも画面と同じ完全なグラフを取得できるようにする。

### 11.2 棒グラフ `[必須A]`

- X軸にカテゴリ、Y軸に集計値を表示する縦棒グラフとする。
- 軸タイトルには選択列名と集計方法が分かる文言を表示する。

### 11.3 折れ線グラフ `[必須A]`

- X軸にカテゴリ、Y軸に集計値を表示する折れ線グラフとする。
- X軸値は文字列カテゴリとして扱い、日付順や数値順へ自動並べ替えしない。

### 11.4 円グラフ `[必須A]`

- X軸グループを円の区分、集計値を区分の大きさとして使用する。
- 軸は表示しない。
- 集計結果が1件以上あり、すべて有限の0以上で、少なくとも1件が0より大きい場合だけ描画する。
- `null`、負数、全件0を含む場合は描画せず、棒または折れ線への変更、設定変更を促す具体的な案内を表示する。

### 11.5 Chart.js読み込み失敗 `[必須B]`

- 初期化時とグラフ作成時にChart.jsが利用可能か確認する。
- 利用できない場合は設定やプレビューを可能な範囲で維持し、「グラフ機能を読み込めませんでした。」と通知する。
- グラフ作成とPNG保存を無効にし、未捕捉例外を発生させない。

## 12. PNG保存

### 12.1 保存条件 `[必須A]`

- 現在の設定に対応するグラフが正常に表示されている場合だけ保存できる。
- アニメーションを行わないため、グラフ作成処理が正常終了した直後から保存できる。
- グラフ未作成、作成失敗、タイトル更新待機中など、現在設定に対応する正常なグラフがない状態では保存を無効にする。
- 無効状態から保存を試みる経路があっても、案内を表示して処理を終了する。

### 12.2 画像内容 `[必須A]`

- Chart.jsのcanvasをPNGとして出力する。
- 出力前に白色の不透明背景を描画し、意図しない透明背景を防ぐ。
- 画面に表示中のグラフ種類、タイトル、凡例、ラベル、データを反映する。
- 集計結果表や設定UIは画像に含めない。

### 12.3 ファイル名 `[必須B]`

- グラフタイトルの前後空白を除去した値があれば基礎名に使用する。
- タイトルが空なら `data-visualizer` を使用する。
- 制御文字とファイル名に不適切な `\ / : * ? " < > |` は `_` に置換する。
- 末尾の空白とピリオドを除去し、基礎名を80文字以内に制限する。
- 正規化後に空なら `data-visualizer` を使用し、拡張子 `.png` を付ける。

### 12.4 保存失敗 `[必須B]`

- canvasの画像化、Blob生成、ダウンロード開始のいずれかに失敗した場合はエラーを通知する。
- 失敗後も現在のデータ、設定、グラフを維持し、再試行可能にする。
- 一時的なObject URLを使用する場合は使用後に解放する。

## 13. サンプルCSV

### 13.1 内容 `[必須B]`

実装時に `sample-data.csv` を同梱し、少なくとも次の列を含める。

- 日付
- カテゴリ
- 地域
- 売上
- 数量

複数の日付、カテゴリ、地域を含み、同一カテゴリに複数行があり、合計、平均、件数、絞り込みを確認できる内容とする。売上と数量は数値列として判定可能にする。

### 13.2 取得 `[必須B]`

- アプリ内のリンクまたはボタンから取得できる。
- サンプルはアプリへ自動読込せず、利用者が取得後にファイル選択する。
- 列順は「カテゴリ、地域、日付、売上、数量」とする。初期X軸は先頭の「カテゴリ」、初期Y軸は最初の数値列「売上」となり、初期集計は食品、衣料、雑貨の3区分を表示する。
- カテゴリ別売上の合計は、食品66,000、衣料84,000、雑貨48,000とする。
- 外部サイトへ遷移せず、同梱ファイルを取得する。

## 14. 入力検証とエラー処理

### 14.1 共通 `[必須B]`

- エラーは全体通知領域または関連フォーム付近に具体的な文言で表示する。
- エラー対象のフォーム部品には必要に応じて `aria-invalid` と `aria-describedby` を設定する。
- エラー発生時も、回復に必要な操作を継続できるようにする。
- 想定可能な失敗を未捕捉例外としてConsoleへ出さない。

### 14.2 エラー一覧 `[必須B]`

| 条件 | 期待動作 |
| --- | --- |
| ファイルが空、または空行だけ | 「CSVファイルが空です。」と通知し、採用しない |
| ヘッダーだけでデータ行がない | 「データ行がありません。」と通知し、採用しない |
| UTF-8でない | UTF-8で読み取れない旨を通知し、採用しない |
| 拡張子がCSVでない | CSVを選ぶよう通知し、採用しない |
| サイズ、行数、列数の上限超過 | 超過した上限を具体的に通知し、採用しない |
| ヘッダーが空または重複 | 該当理由を通知し、採用しない |
| 列数不一致 | 行番号と期待列数を通知し、採用しない |
| CSVのクォート等が不正 | 可能な範囲で行番号と理由を通知し、採用しない |
| クォート内改行 | 未対応形式であることを通知し、採用しない |
| `FileReader` 等の読み込み失敗 | 読み込めなかったことを通知し、現在の正常状態を維持する |
| 数値列が存在しない | データとプレビューは表示するが、グラフ設定・作成・保存を無効にして理由を通知する |
| 絞り込み結果が0件 | 件数を0と表示し、グラフ作成・保存を無効にして条件変更を促す |
| X軸、Y軸、種類、集計方法が不正または不足 | 関連項目を示してグラフを作成しない |
| 合計・平均に有効数値がない | データがない旨を表示し、該当条件ではグラフを作成しない |
| 円グラフに不適切な値 | 11.4の理由と変更方法を通知し、作成しない |
| Chart.jsを利用できない | 11.5の通知と無効化を行う |
| PNG保存失敗 | 保存できなかったことを通知し、状態を維持する |
| 非同期処理中の二重操作 | 重複処理を開始せず、進行中表示を維持する |

### 14.3 新しいファイルの失敗 `[必須B]`

既に正常なデータがある場合、新しいファイルの解析失敗を理由に旧データを消去しない。新ファイルは全体を不採用とし、旧データ、設定、グラフ、集計結果をそのまま維持する。

## 15. レスポンシブ対応

### 15.1 375px幅 `[必須B]`

- viewport幅375pxでページ全体の横スクロールを発生させない。
- データバーは見出し、ファイル選択、サンプル取得、読み込み情報を自然な縦または複数段配置にし、無理に横一列へ押し込まない。
- グラフ見出し付近の「グラフを更新」と「PNGを保存」は重ならず、必要に応じて折り返す。
- 800px以下では、分析条件、グラフ、集計結果、元データプレビューの順で縦配置する。
- 設定フォームは縦方向を基本とし、ラベル、入力、ボタンを重ねない。
- グラフは領域幅に追従し、凡例やラベルが操作不能な位置にはみ出さない。
- 幅の広い表は表のコンテナ内だけで横スクロールできる。
- 集計結果と展開した元データプレビューはそれぞれの高さ上限内でスクロールし、ページを不必要に縦長にしない。

### 15.2 広い画面 `[必須B]`

- データ読み込みと4つの読み込み情報を単一のコンパクトなデータバーへ統合し、分析条件とグラフをその直下に配置する。
- 分析条件パネルとグラフパネルの上端を揃えるが、高さは強制的に揃えない。
- 左列を分析条件、右列をグラフと集計結果の縦並びとし、集計結果がグラフ直下へ続くようにする。
- 元データプレビューは左右列の下へ全幅で配置する。
- 設定領域とグラフ領域を見比べやすく配置してよい。
- 読み込み情報、集計結果、プレビューが過度に横へ伸びないよう最大幅を設ける。
- 1024px以上でも主要操作と結果の対応が分かる。

### 15.3 長い文字列 `[必須B]`

- ファイル名、ヘッダー、カテゴリ値、タイトル等に長い文字列があってもページ幅を壊さない。
- 表セルは必要に応じて折り返しまたは表コンテナ内スクロールで収める。
- Chart.jsへ渡すラベルが長い場合もcanvasが親領域からはみ出さない。

## 16. アクセシビリティ

### 16.1 キーボード `[必須B]`

- ファイル選択、サンプル取得、全設定、グラフ更新、PNG保存をキーボードで操作でき、DOM順と視覚順が不自然にならない。
- 元データプレビューの開閉をキーボードで操作できる。
- `Tab` 順序は視覚的な操作順と大きく矛盾しない。
- フォーカス位置を見えるアウトライン等で判別できる。
- 無効な操作は `disabled` 等の標準状態で支援技術にも伝える。
- 元データプレビューの開閉状態を `aria-expanded` と `aria-controls` で伝える。

### 16.2 名前・関連付け `[必須B]`

- 全入力に明示ラベルを関連付ける。
- グラフ更新ボタンと保存ボタンは目的が分かる名前にする。
- エラー文を該当入力と関連付ける。
- 読み込み中の状態は文言と `aria-busy` 等で伝える。

### 16.3 非視覚的な結果確認 `[必須B]`

- canvasだけを結果の唯一の表現にしない。
- canvasにはグラフタイトルと設定内容が分かるアクセシブル名または説明を付ける。
- 集計結果表に見出しセルを設定し、カテゴリと値を読み上げ可能にする。
- 件数、エラー、成功通知を文字で表示する。

### 16.4 色への非依存 `[必須B]`

- エラー、選択状態、空値、処理中を色だけで伝えない。
- グラフ系列は1つだが、カテゴリ名と集計結果表により色を見分けなくても値を確認できる。

## 17. セキュリティとプライバシー

### 17.1 DOM出力 `[必須B]`

- CSVセル、ファイル名、ヘッダー、タイトルをHTML文字列として実行しない。
- テキスト出力には `textContent`、フォームの `value`、安全なDOM APIを使用する。
- イベント属性文字列や `eval`、`new Function` を使用しない。

### 17.2 ローカル処理 `[必須A]`

- CSV解析、集計、グラフ生成、PNG生成はブラウザ内で行う。
- 読み込みデータを外部API、分析サービス、ログ収集先へ送信しない。
- Chart.js 4.5.1とその `LICENSE.md` をローカル配置し、CDNや外部URLへ通信しない。
- Webフォント、外部画像等の外部リソースを必須にしない。

### 17.3 リソース保護 `[必須B]`

- 4.2の入力上限と100行プレビューにより、過大なDOM生成と基本的なリソース枯渇を抑制する。
- 読み込み中の二重処理を防ぐ。
- 古いChart.jsインスタンスと一時Object URLを解放する。

## 18. 対象外 `[MVP外]`

- JSON入力
- Excelファイル
- 複数ファイルの結合
- 複数Y軸
- 複数データ系列
- 散布図
- CSVの編集
- 加工後CSVの出力
- 設定や読み込みデータの永続化
- サーバー保存、共有、認証
- 高度な統計分析
- ダブルクォート内の改行
- 印刷専用レイアウト

## 19. 実装完了の判定条件

### 19.1 機能 `[必須A]`

- 正常なUTF-8 CSVを読み込み、列と行を正しく解析できる。
- 棒、折れ線、円の3種類を現在の設定から作成できる。
- 読み込み成功後の初期グラフと、各設定変更後のグラフ・集計結果が仕様どおり自動更新される。
- X軸、Y軸、凡例、タイトルを設定できる。
- 1列1値の絞り込みを解除も含めて操作できる。
- 合計、平均、件数を絞り込み後データへ適用できる。
- グラフと同じ結果を表で確認できる。
- 現在のグラフを不透明背景のPNGとして保存できる。
- サンプルCSVをアプリから取得できる。

### 19.2 品質 `[必須B]`

- 入力上限、CSV不正、数値列なし、0件、設定不足、Chart.js失敗、保存失敗、二重操作を仕様どおり処理する。
- 破損CSVを部分採用せず、新しいファイルの失敗時に正常な旧状態を維持する。
- 375pxと1024px以上で主要操作と結果確認ができる。
- キーボードで主要操作を完了できる。
- canvas以外の集計結果表がある。
- ユーザー入力がHTMLとして実行されず、読み込みデータの外部送信がない。
- アプリ由来の未捕捉例外がConsoleにない。
- 受入チェックリストの全項目を実ブラウザで確認できる。

### 19.3 技術構成 `[必須B]`

- Vanilla HTML/CSS/JavaScriptと、npmの `chart.js@4.5.1` パッケージから同梱した `dist/chart.umd.min.js` だけで動作する。
- ビルド、サーバー、データベース、認証を必要としない。
- `vendor/chart.umd.min.js` と `vendor/LICENSE.md` があり、画面またはソースからChart.js 4.5.1の採用とライセンスの所在を確認できる。
- 開発版やmasterブランチのビルドを使用していない。
- `[MVP外]` のUIや処理を追加していない。

## 20. 解釈を固定した事項

課題文を機能追加で広げず、実装差を防ぐため次のように固定する。

- 課題クリア条件の「CSVまたはJSON」はCSVで満たし、JSONは `[MVP外]` とする。
- グラフ種類を切り替えた時点で、同じデータと他の現在設定を使って自動再描画する。
- 「凡例」は単一系列の系列名と円グラフのカテゴリ凡例を指し、複数系列は扱わない。
- 「簡単な絞り込み」は1つの `text` 列と1つの完全一致値に限定する。
- 「画像など」はPNGだけで満たし、JPEG、SVG、PDF等は追加しない。
- 日付列は専用型にせず文字列として扱い、自動並べ替えや期間絞り込みを行わない。
- 件数集計でも、グラフ設定の一貫性のため数値Y軸の選択は維持する。数値列がないCSVはグラフ作成対象外とする。

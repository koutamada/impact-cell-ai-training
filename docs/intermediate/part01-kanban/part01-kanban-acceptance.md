# 中級編 Part 1：カンバン型タスク管理ボード 受入チェックリスト

- 対象仕様：`docs/intermediate/part01-kanban/part01-kanban-spec.md`
- 対象アプリ（将来）：`apps/intermediate/part01-kanban/`
- 判定方法：各項目を実際のブラウザで操作し、期待結果をすべて満たせば合格

---

## 0. 実施方法

### 0.1 前提

- 原則としてChromeまたはEdgeの現行安定版で実施する。
- 開発者ツールのConsoleとApplication（localStorage）を確認できる状態にする。
- 通常試験の開始前に、対象オリジンの `intermediate-part01-kanban` キーだけを削除して再読み込みする。他アプリの保存値は削除しない。
- 各項目の操作中に、Consoleへ未捕捉例外が出ていないことも確認する。

### 0.2 記録欄

各チェックボックスに結果を記録する。失敗時はブラウザ、画面幅、操作、期待結果との差、Console出力を併記する。

## A. 初回表示・画面構成

- [x] **A-01 初回起動** — 保存キーを削除して再読み込みする。→ アプリ名、通知領域、「タスクを追加」、3列、サンプルタスクが表示され、読み込みエラーは出ない。
- [x] **A-02 固定列** — ボードの見出しを左から確認する。→ 「未着手」「作業中」「完了」の3列がこの順で表示され、列を追加・編集・削除するUIはない。
- [x] **A-03 サンプル配置** — 各列を確認する。→ サンプルが合計3件以上あり、各列に1件以上ある。
- [x] **A-04 件数** — 各列の見出しと実際のカード数を数える。→ 3列すべてで件数が一致し、0件なら `0` と表示される。
- [x] **A-05 空列** — 後続試験または編集で1列を0件にする。→ 空状態の文言と、カードをドロップできる領域が残る。

## B. 新規作成

- [x] **B-01 モーダルを開く** — 「タスクを追加」をクリックする。→ 新規作成用モーダルが開き、タイトル、説明、期限、担当者、ステータス、保存、キャンセル、閉じるが表示される。
- [x] **B-02 初期値** — B-01直後の入力欄を確認する。→ テキスト項目と期限は空、ステータスは「未着手」、フォーカスはタイトル欄にある。
- [ ] **B-03 全項目を登録** — タイトル「受入テスト」、説明「詳細を確認する」、期限に有効な日付、担当者「田中」、ステータス「作業中」を入力して保存する。→ モーダルが閉じ、「作業中」の末尾に全入力内容を持つカードが追加され、同列件数が1増える。
- [ ] **B-04 任意項目なし** — タイトルだけを入力し、他の任意項目を空で保存する。→ 正常に追加され、空の説明・期限・担当者のために不自然な空ラベルが表示されない。
- [ ] **B-05 前後空白** — タイトルと担当者の前後に空白を付けて保存する。→ 前後空白を除去した文字列が表示され、内部の空白は維持される。
- [ ] **B-06 追加位置** — 同じステータスへ2件を順番に追加する。→ 追加した各カードは保存時点で対象列の末尾に入る。

## C. 入力検証

- [x] **C-01 空タイトル** — 新規モーダルでタイトルを空のまま保存する。→ 保存されずモーダルが開いたままで、「タイトルを入力してください。」がタイトル欄付近に表示される。
- [ ] **C-02 空白のみ** — タイトルに半角・全角空白だけを入力して保存する。→ C-01と同じエラーになり、カードは増えない。
- [x] **C-03 エラーの関連付け** — C-01の状態を開発者ツールで確認する。→ タイトル欄が `aria-invalid="true"` で、エラー文が `aria-describedby` により関連付けられ、フォーカスがタイトル欄にある。
- [x] **C-04 エラーから復帰** — C-01の後、有効なタイトルを入力して保存する。→ エラーが解消され、1件だけ追加される。
- [ ] **C-05 有効な日付** — 期限入力でブラウザが受理する日付を選んで保存する。→ `YYYY-MM-DD` 相当の同じ暦日がカードと保存データに反映される。

## D. モーダルのキャンセルと編集

- [ ] **D-01 カードクリック** — 任意カードのボタン以外の部分をクリックする。→ 編集モーダルが開き、全登録項目が現在値で設定される。
- [x] **D-02 編集ボタン** — 任意カードの編集ボタンをクリックする。→ 同じカードの編集モーダルだけが開き、削除等の別操作は起きない。
- [ ] **D-03 全項目編集** — タイトル、説明、期限、担当者、ステータスをすべて変更して保存する。→ 同じタスクが新しい内容で表示され、ステータス変更先の列末尾へ移り、旧列と新列の件数が更新される。
- [ ] **D-04 IDと日時** — D-03の前後でlocalStorageを比較する。→ `id` と `createdAt` は同一、`updatedAt` は新しい有限数になっている。
- [ ] **D-05 キャンセル** — 編集モーダルで値を変更し「キャンセル」を押す。→ モーダルが閉じ、表示・保存データとも変更されない。
- [ ] **D-06 閉じる** — 編集モーダルで値を変更し「閉じる」を押す。→ D-05と同じく変更されない。
- [ ] **D-07 Escape** — 編集モーダルで値を変更し `Escape` を押す。→ D-05と同じく変更されない。
- [ ] **D-08 背景クリック** — 編集モーダルの外側をクリックする。→ モーダルは閉じず、入力値も維持される。

## E. 削除

- [x] **E-01 削除確認** — 任意カードの削除ボタンを押す。→ 対象タイトルを含む確認が表示され、カードクリックによる編集モーダルは開かない。
- [ ] **E-02 削除キャンセル** — E-01でキャンセルする。→ カード、件数、保存データ、並び順は変わらない。
- [ ] **E-03 削除確定** — E-01で確定する。→ 対象カードだけが消え、列件数が1減り、保存データの `tasks` と `columnOrder` の双方から対象IDが消える。
- [x] **E-04 復元機能なし** — 削除後の画面を確認する。→ ゴミ箱、復元、UndoのUIはない。
- [ ] **E-05 全件削除後の再読み込み** — すべてのカードを削除し、再読み込みする。→ 3列は0件のままで、サンプルタスクは復活しない。

## F. 列間ドラッグ&ドロップ

- [x] **F-01 別列へ移動** — マウスで「未着手」のカードを「作業中」のカード領域へドラッグしてドロップする。→ カードが「作業中」へ移り、両列の件数が更新される。
- [ ] **F-02 ステータス保存** — F-01後にlocalStorageを確認する。→ 対象タスクの `status` が `doing`、IDの所属が `columnOrder.doing` となり、旧列にIDが残らない。
- [ ] **F-03 空列へ移動** — 移動先を0件にしてからカードをその列へドロップする。→ 空の列にも正常に入り、件数が0から1になる。
- [ ] **F-04 ドラッグ中のカード** — ドラッグを開始し、まだドロップしない。→ 対象カードが通常状態と視覚的に区別できる。
- [ ] **F-05 移動先表示** — カードを各列とカード間へ動かす。→ ドロップ可能な列と現在の挿入位置が、枠線またはプレースホルダー等で色以外からも判別できる。
- [ ] **F-06 キャンセル** — ドラッグを開始後、ドロップせず `Escape` を押すか領域外で終了する。→ 状態と保存データは変わらず、ドラッグ用の視覚表示がすべて消える。
- [ ] **F-07 操作部から開始しない** — 編集ボタンと削除ボタン上からポインタを動かしてドラッグを試す。→ カードのドラッグは開始されない。
- [ ] **F-08 同位置へのドロップ** — カードを元と同じ位置へ戻す。→ 順序、ステータス、`updatedAt`、保存データが変化しない。

## G. 同一列内の並べ替え

- [ ] **G-01 先頭へ** — 3件以上ある列の末尾カードを先頭へドロップする。→ そのカードが先頭になる。
- [ ] **G-02 カード間へ** — 同じ列のカードを別の2カードの間へドロップする。→ 表示された挿入位置どおりの順になる。
- [ ] **G-03 末尾へ** — 同じ列の先頭カードを末尾へドロップする。→ そのカードが末尾になる。
- [ ] **G-04 並び順保存** — G-01〜G-03後にlocalStorageを確認する。→ `columnOrder` のID順が画面順と一致し、対象タスクの `updatedAt` が更新されている。
- [ ] **G-05 件数不変** — 同一列内で並べ替える。→ 全列の件数とタスクの `status` は変わらない。

## H. 期限表示

試験日のローカル日付を基準とし、未完了タスクを4件作る。期限を「なし」「明日」「今日」「昨日」に設定する。

- [x] **H-01 期限なし** — 期限なしのカードを確認する。→ 日付が表示されないか「期限なし」と表示され、期限超過の強調はない。
- [x] **H-02 期限内** — 明日期限のカードを確認する。→ 日付が表示され、期限超過表示はない。
- [x] **H-03 期限当日** — 今日期限のカードを確認する。→ 日付に加えて「今日」等の文字で期限当日と分かる。
- [x] **H-04 期限超過** — 昨日期限の未着手または作業中カードを確認する。→ 「期限超過」の文字と視覚的強調がある。
- [ ] **H-05 完了済み** — H-04のカードを「完了」へ移動する。→ 期限日は表示されるが、期限超過の文言・強調は解除される。
- [ ] **H-06 ローカル暦日** — 現在のタイムゾーンで今日の日付を入力し再読み込みする。→ UTC日付へのずれがなく期限当日と判定される。

## I. 保存と復元

- [ ] **I-01 保存形式** — Applicationパネルで保存キーを確認する。→ キーは `intermediate-part01-kanban` で、値はJSON、`version: 1`、`initialized: true`、`tasks`、固定3配列の `columnOrder` を持つ。
- [x] **I-02 追加の復元** — タスクを追加して再読み込みする。→ 内容と追加先が復元される。
- [ ] **I-03 編集の復元** — 全項目を編集して再読み込みする。→ 編集後の内容が復元される。
- [x] **I-04 削除の復元** — タスクを削除して再読み込みする。→ 削除したタスクは復活しない。
- [ ] **I-05 列移動の復元** — 別列へドラッグして再読み込みする。→ 移動先の列に復元される。
- [ ] **I-06 並べ替えの復元** — 各列で順序を変更して再読み込みする。→ すべての列で変更後の順序が復元される。
- [ ] **I-07 データ整合性** — 一連の操作後のJSONを確認する。→ 各IDは一意で、対応ステータスの順序配列にちょうど1回だけ存在する。

## J. 破損データと保存失敗

各試験前に現在の正しい保存値を控え、終了後に復元する。

- [ ] **J-01 不正JSON** — 保存キーへ `{broken` を設定して再読み込みする。→ アプリは空の3列で起動し、「保存データを読み込めなかったため、空の状態で起動しました。」と通知し、未捕捉例外はない。
- [ ] **J-02 未知version** — 正常形式の `version` だけを `999` にして再読み込みする。→ J-01と同じ結果になる。
- [ ] **J-03 不正タスク** — `title` が空、未知status、重複IDのいずれかを含む保存値で再読み込みする。→ 部分採用せず全タスクが空になり、エラー通知が出る。
- [ ] **J-04 順序不整合** — 存在しないID、ID重複、statusと所属列の不一致のいずれかを `columnOrder` に作って再読み込みする。→ J-03と同じ結果になる。
- [ ] **J-05 破損値を即時上書きしない** — J-01後、何も操作せず保存キーを再確認する。→ 入れた破損値が自動的に正常値へ置換されていない。
- [ ] **J-06 読み取り例外** — DevTools等で `localStorage.getItem` が例外を投げる条件を作り再読み込みする。→ アプリが停止せず空状態とエラー通知になる。
- [ ] **J-07 保存例外** — DevTools等で `localStorage.setItem` が例外を投げる条件を作り、追加を試す。→ 保存失敗メッセージが表示され、追加は画面・メモリ上でも確定しない。
- [ ] **J-08 移動の保存失敗** — 保存失敗条件で列間移動または並べ替えを行う。→ カードは操作前の列・順序に戻り、件数も元のままになる。
- [ ] **J-09 失敗後の操作** — J-07後に保存可能な状態へ戻し、追加する。→ アプリを再読み込みしなくても追加・保存できる。
- [ ] **J-10 初回サンプルの保存失敗** — 保存キーが存在しない状態で `localStorage.setItem` が失敗する条件を作って再読み込みする。→ 3列のサンプルタスクは空状態へ戻らず表示され、全体通知領域に保存失敗メッセージが表示され、アプリを操作できる。失敗条件を維持したままサンプルの編集を試すと編集だけが元に戻りサンプルは表示されたままとなる。その後、保存可能な状態へ戻してタスクを追加する。→ サンプルを含む追加後の全状態が保存され、再読み込み後も復元される。

## K. レスポンシブ・長文

- [x] **K-01 375px表示** — DevToolsでviewportを幅375pxにする。→ ページ全体の横スクロールがなく、3列が縦積みになる。
- [ ] **K-02 375px主要操作** — 幅375pxで追加、カードクリック編集、削除、ステータス変更を行う。→ すべて完了でき、操作部が重ならない。
- [ ] **K-03 モーダル高さ** — 幅375pxかつ低いviewportでモーダルを開く。→ モーダルが画面外へ操作不能にはみ出さず、内部スクロールで全入力と各ボタンへ到達できる。
- [x] **K-04 広い画面** — 幅1024px以上にする。→ 3列が横並びになり、カードが対応列内に収まる。
- [ ] **K-05 長い文字列** — タイトル、説明、担当者に空白を含まない長い英数字を入力して保存する。→ 文字列が折り返され、カード、列、モーダル、ページ幅が壊れない。
- [x] **K-06 2行以内の説明** — 広い画面で表示が2行以内に収まる説明を登録する。→ 説明全文が表示され、「全文を表示」「折りたたむ」のいずれのボタンも表示されない。
- [x] **K-07 2行を超える説明** — 広い画面で表示が確実に3行以上となる説明を登録する。→ 初期状態では最大2行だけが表示され、説明直下に「全文を表示」ボタンが表示される。タイトル、期限、担当者は省略されない。
- [ ] **K-08 開閉操作** — K-07の「全文を表示」を押し、続けて「折りたたむ」を押す。→ 最初の操作で説明全文と「折りたたむ」が表示され、次の操作で最大2行表示と「全文を表示」へ戻る。展開時も長い英数字が折り返され、列幅を壊さない。
- [ ] **K-09 保存への非影響** — K-08の前後でlocalStorageの値と対象タスクの `updatedAt` を比較する。→ 開閉だけでは保存データと `updatedAt` が一切変化しない。
- [ ] **K-10 編集・ドラッグとの分離** — 開閉ボタンをクリックおよびキーボードで操作し、ボタン上からドラッグを試す。その後カード本体からドラッグ&ドロップする。→ 開閉時に編集モーダルやドラッグが始まらず、カード本体からのドラッグ&ドロップは正常に完了する。ボタンのアクセシブル名から対象タスクが分かり、展開状態も取得できる。
- [x] **K-11 375pxと幅変更** — viewportを375pxにして2行以内と2行超の説明を確認し、広い画面との間で幅を往復する。→ 各幅の実際の省略状態に応じて開閉ボタンの表示要否が更新され、375pxでも開閉でき、ページ全体の横スクロールは発生しない。

## L. キーボードとモーダルフォーカス

- [ ] **L-01 キーボード操作** — マウスを使わず `Tab`、`Shift+Tab`、`Enter`または`Space`で追加、カード編集、削除確認、保存、キャンセル、閉じるを操作する。→ 主要操作を完了でき、現在のフォーカスが見える。
- [ ] **L-02 フォーカストラップ** — モーダルを開き、先頭から末尾まで `Tab`、逆方向に `Shift+Tab` を繰り返す。→ フォーカスがモーダル外へ移らず内部を循環する。
- [ ] **L-03 背面操作防止** — モーダル表示中に背面の追加ボタンやカードへキーボード／ポインタで操作を試す。→ 背面は操作できない。
- [x] **L-04 フォーカス復帰** — 「タスクを追加」から開いたモーダルを閉じる。次に編集ボタンから開いて閉じる。→ それぞれ開いたボタンへフォーカスが戻る。
- [ ] **L-05 Escape** — モーダルで入力途中に `Escape` を押す。→ 保存せず閉じ、開いた要素へフォーカスが戻る。
- [x] **L-06 名前と構造** — アクセシビリティツリーを確認する。→ モーダルにdialogとしての名前とmodal状態があり、入力にラベル、各列に識別可能な見出し、アイコンボタンに対象を含む名前がある。

- [ ] **L-08 色への非依存** — 期限当日、期限超過、ドラッグ挿入位置を確認する。→ 色を見分けなくても文字、枠、形状等で状態を識別できる。

## M. セキュリティ

- [ ] **M-01 HTML文字列** — タイトルへ `<img src=x onerror=alert(1)>`、説明へ `<script>alert(1)</script>`、担当者へ `<b>担当</b>` を文字として入力し保存する。→ 文字列がそのままテキスト表示され、画像、太字、スクリプト実行、ダイアログ表示が発生しない。
- [ ] **M-02 再読み込み後** — M-01後に再読み込みする。→ 同じくテキストとして表示され、コードは実行されない。
- [x] **M-03 DOM実装確認** — Elementsとソースを確認する。→ ユーザー入力をイベント属性や実行可能なHTMLとして挿入していない。
- [x] **M-04 外部通信** — Networkパネルを開いて通常操作する。→ アプリ自身による外部API・CDN・Webフォントへの通信がない。

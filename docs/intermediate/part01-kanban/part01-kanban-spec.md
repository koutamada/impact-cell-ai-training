## 1. 目的と対象範囲

### 1.1 目的 [必須A]

タスクを「未着手」「作業中」「完了」の3列で可視化し、登録・編集・削除、列間移動、列内並べ替えを行えるカンバン型タスク管理ボードを作成する。操作結果はブラウザの `localStorage` に保存し、再読み込み後も復元する。

### 1.2 課題のクリア条件と対応箇所 [必須A]

| # | クリア条件 | 対応章 |
|---|---|---|
| C1 | 複数のステータス列を持つ | 3章 |
| C2 | タスクを追加・変更・削除できる | 6章・7章 |
| C3 | ドラッグ&ドロップで別の列へ移動できる | 8章 |
| C4 | 説明、期限、担当者などの詳細を登録できる | 4章・6章 |
| C5 | 再読み込み後もボードとタスクの状態を保持する | 5章・9章 |

### 1.3 MVP範囲 [必須A]

**含む**

- 固定3列と列別件数
- タスクの追加・編集・削除
- マウスによる列間ドラッグ&ドロップと列内並べ替え
- 編集画面のステータス選択による代替移動
- 期限状態の表示
- サンプルタスクを含む初期状態
- `localStorage` への保存・復元、破損時および保存失敗時の処理
- 375px幅を含むレスポンシブ表示と主要操作のキーボード対応

## 2. 固定値と用語

### 2.1 ステータス [必須A]

内部値と表示名を次に固定する。列の表示順もこの表の順とする。

| 内部値 | 表示名 |
|---|---|
| `todo` | 未着手 |
| `doing` | 作業中 |
| `done` | 完了 |

「カード」は画面上のタスク表示、「タスク」は保存対象のデータを指す。

### 2.2 時刻の表現 [必須B]

- `createdAt` / `updatedAt` は `Date.now()` 相当のUnix時刻（ミリ秒、有限数）で保持する。
- 追加時は両者を同じ値にする。
- 登録項目の編集、列間移動、列内並べ替えが確定したとき、対象タスクの `updatedAt` を更新する。
- 表示順だけが変わった場合も、実際に位置が変わったタスクの `updatedAt` を更新する。日時は画面表示しなくてよい。

## 3. 画面構成

### 3.1 全体構成 [必須A]

画面上から次の順に配置する。

1. アプリ名
2. 全体通知領域（保存・読み込みエラー等。通常時は空）
3. 「タスクを追加」ボタン
4. カンバンボード
5. 新規作成／編集で共用するモーダルダイアログ

### 3.2 ボード [必須A]

- 「未着手」「作業中」「完了」の3列を常に表示する。
- 各列見出しに表示名と現在のタスク件数を表示する。件数は `0` も省略しない。
- 各列にカード配置領域を設ける。0件でもドロップ可能な領域を維持し、空状態が分かる文言を表示する。
- カードの表示順は、保存された `columnOrder` の先頭から末尾の順とする。

### 3.3 タスクカード [必須A][必須B]

各カードに次を表示する。

- タイトル（必須）
- 説明（値がある場合）
- 期限（値がある場合。10章の期限状態も併記）
- 担当者（値がある場合）
- 編集ボタン
- 削除ボタン

カード本体のクリックで編集モーダルを開く。編集・削除ボタンの操作はカード本体クリックへ伝播させず、それぞれの操作だけを実行する。

#### 説明文の折りたたみ [必須A][必須B]

- カードの説明文は初期状態で最大2行まで表示する。タイトル、期限、担当者は折りたたまない。
- 折りたたみ状態で実際に2行を超えて省略される説明文に限り、説明文の直下に「全文を表示」ボタンを表示する。文字数による推測ではなく、描画後の要素寸法をJavaScriptで比較して省略の有無を判定する。
- 「全文を表示」を押すと説明文全体を表示し、ボタン表記を「折りたたむ」に変更する。「折りたたむ」を押すと最大2行表示へ戻す。
- 開閉は画面上だけの表示操作とし、タスクデータ、`updatedAt`、`columnOrder` を変更せず、localStorageへの保存も行わない。
- 再描画または再読み込み後は折りたたみ状態へ戻ってよい。
- 開閉ボタンの操作では編集モーダルを開かず、ドラッグを開始しない。開閉後もカードのドラッグ&ドロップを利用できる。
- 展開時を含め、空白のない長い英数字もカード内で折り返し、列幅を超えない。

### 3.4 モーダル [必須A]

新規作成と編集で同じモーダルを使用し、モードに応じた見出しを表示する。入力欄は次の順とする。

1. タイトル：テキスト入力、必須
2. 説明：複数行入力、任意
3. 期限：日付入力、任意
4. 担当者：テキスト入力、任意
5. ステータス：選択入力、必須、固定3択

「保存」「キャンセル」「閉じる」ボタンを設ける。削除操作はカード上の削除ボタンから行い、モーダル内には置かない。

## 4. データモデル

### 4.1 タスクオブジェクト [必須A][必須B]

```js
{
  id: string,            // 一意な非空文字列
  title: string,         // trim後に1文字以上
  description: string,   // 任意。未入力は空文字列
  dueDate: string,       // 任意。空文字列または YYYY-MM-DD
  assignee: string,      // 任意。未入力は空文字列
  status: 'todo' | 'doing' | 'done',
  createdAt: number,     // Unix時刻（ミリ秒）
  updatedAt: number      // Unix時刻（ミリ秒）
}
```

- タイトル、説明、担当者は保存時に前後の空白を除去する。内部の空白と改行は維持する。
- アプリ独自の文字数上限は設けない。長文は折り返し、カードやモーダルからはみ出させない。
- IDは `crypto.randomUUID()` が使用可能なら利用し、使用不可の場合は日時と乱数を組み合わせた非空文字列を生成する。配列indexをIDに使用しない。

### 4.2 並び順 [必須B]

タスクの順序はタスクオブジェクト内の数値ではなく、ステータス別ID配列 `columnOrder` で保持する。各タスクIDは、そのタスクの `status` と一致する配列にちょうど1回だけ存在しなければならない。

```js
columnOrder: {
  todo: ['task-id-1'],
  doing: ['task-id-2'],
  done: []
}
```

## 5. 状態管理

### 5.1 アプリケーション状態 [必須B]

```js
state = {
  tasks: [],
  columnOrder: { todo: [], doing: [], done: [] },
  initialized: true,
  modal: {
    open: false,
    mode: null,          // null | 'create' | 'edit'
    editingTaskId: null
  },
  draggingTaskId: null,
  expandedDescriptionIds: new Set() // 説明文を展開中のタスクID
}
```

`tasks`、`columnOrder`、`initialized` のみ永続化する。モーダル状態、入力途中の値、ドラッグ状態、説明文の展開状態、通知文は保存しない。

### 5.2 状態変更の原則 [必須B]

- 画面は常に確定済みの `state.tasks` と `state.columnOrder` から再描画する。
- 追加、編集、削除、移動、並べ替えは、変更後の状態を新たに組み立てて保存する。
- 保存に成功した場合だけ確定状態へ反映する。保存に失敗した場合は直前の確定状態を維持し、画面も元に戻してエラーを通知する。
- ただし、初回起動時のサンプル表示はこのロールバック規則の例外とし、初期状態の保存に失敗してもサンプルを画面上の操作可能な状態として維持する（9.2・9.5）。
- 件数は `columnOrder` から都度導出し、別の保存値として持たない。
- 説明文の開閉はタスクの状態変更として扱わない。開閉時は `updatedAt` を更新せず、保存処理を呼び出さない。

## 6. 新規作成・編集仕様

### 6.1 新規作成 [必須A]

1. 「タスクを追加」で空の新規作成モーダルを開く。
2. ステータスの初期値は `todo` とする。
3. 「保存」で11章の入力検証を行う。
4. 正常ならタスクを作成し、選択ステータス列の末尾へIDを追加して保存する。
5. 保存成功後にモーダルを閉じ、カード、列件数を更新する。

### 6.2 編集 [必須A]

1. カード本体または編集ボタンで、そのタスクの全登録項目を設定した編集モーダルを開く。
2. 「保存」で入力検証を行う。
3. ステータスが変わった場合は旧列からIDを除き、新列の末尾へ追加する。
4. `id` と `createdAt` は維持し、`updatedAt` を更新する。
5. 保存成功後にモーダルを閉じ、表示と件数を更新する。

### 6.3 保存せず閉じる [必須A][必須B]

「キャンセル」「閉じる」または `Escape` では入力途中の値を破棄して閉じる。保存やタスク変更は行わない。背景クリックでは閉じない（意図しない入力破棄を防ぐ）。

## 7. 削除仕様

### 7.1 削除 [必須A]

1. カードの削除ボタンで確認を表示する。確認文には対象タスクのタイトルを含める。
2. キャンセル時は何も変更しない。
3. 確定時は `tasks` と該当する `columnOrder` の双方から対象を除き、保存する。
4. 保存成功後にカードを消し、列件数を更新する。
5. ゴミ箱、復元、Undoは設けない。

## 8. ドラッグ&ドロップ仕様

### 8.1 対象操作 [必須A]

- 主対象はマウス操作とし、HTML標準の Drag and Drop API を使用してよい。
- カードを別列へドロップするとステータスを変更できる。
- 同じ列のカード間、先頭、末尾へドロップして表示順を変更できる。
- 空の列にもドロップできる。
- 実際の位置が変わらないドロップは状態変更・保存を行わない。

### 8.2 ドロップ位置 [必須B]

- ポインタ位置から挿入位置を決定し、ドロップ前に挿入位置を視覚表示する。
- 別列へ移動した場合は `status` を移動先の値へ更新し、旧列のIDを除去して移動先配列の決定位置へ挿入する。
- 同一列の場合はIDを一度除去してから決定位置へ挿入する。
- ドロップ確定後、対象タスクの `updatedAt` を更新して1回保存する。

### 8.3 視覚表現と誤操作対策 [必須A]

- ドラッグ中のカードを通常状態と区別する。
- ドロップ可能な列と現在の挿入位置を、色だけに依存しない枠線・プレースホルダー等で示す。
- 編集・削除・説明文開閉ボタン、リンク、フォーム部品からはドラッグを開始しない。
- ドラッグがキャンセルされた場合は状態を変更せず、すべてのドラッグ表示を解除する。

### 8.4 代替操作 [必須A]

タッチ端末またはドラッグ操作が困難な利用者は、編集モーダルのステータス選択で別列へ移動できる。同一列内の並べ替えに対するキーボード／タッチ専用UIは今回の要件に含めない。

## 9. localStorage仕様

### 9.1 保存キーと形式 [必須A][必須B]

- 保存キー：`intermediate-part01-kanban`
- JSON形式：

```js
{
  version: 1,
  initialized: true,
  tasks: [/* 4.1 のタスクオブジェクト */],
  columnOrder: {
    todo: [/* task id */],
    doing: [/* task id */],
    done: [/* task id */]
  }
}
```

`initialized` はサンプル表示済みかを表す。正常な保存データでは常に `true` とし、`tasks: []` でも初回扱いに戻さない。

### 9.2 初回起動とサンプル [必須A][必須B]

- 保存キーが存在しない場合だけ初回起動と判定する。
- 初回起動時に、操作を理解できるサンプルタスクを3件以上用意し、3列すべてに少なくとも1件表示する。
- サンプルは通常タスクと同じデータ構造で、編集、削除、移動、並べ替えができる。
- サンプルを含む初期状態を直ちに保存する。
- 初期状態の保存に失敗してもサンプルタスクは空状態へ戻さず画面に表示し、全体通知領域に9.5の保存失敗メッセージを表示する。アプリはサンプルを操作できる状態を維持する。
- 初期状態の保存失敗後に追加、編集、削除、移動、並べ替えを行った場合は、画面上に維持しているサンプルを含む変更後の全状態を保存する。保存に成功すればその変更を確定し、失敗すれば当該操作の直前（サンプルが表示された状態）へ戻す。
- 全件削除後は `initialized: true, tasks: []` を保存するため、再読み込みしてもサンプルは復活しない。

### 9.3 読み込みと検証 [必須B]

読み込み時は次をすべて検証する。

- ルートがnull・配列ではないオブジェクトである。
- `version === 1`、`initialized === true`、`tasks` が配列である。
- 各タスクが4.1の型・値条件を満たし、IDが重複していない。
- `columnOrder` が固定3キーの配列を持つ。
- すべてのIDが実在し、重複せず、各タスクの `status` と所属列が一致する。
- すべてのタスクIDが `columnOrder` のいずれかにちょうど1回現れる。

未知のルートフィールド、タスクフィールド、`columnOrder` キーは読み込み時に破棄し、定義済み項目だけで状態を再構築する。

### 9.4 破損データ [必須A][必須B]

JSON解析失敗、未知のバージョン、または9.3の不整合が1つでもある場合は、部分復旧せず全件不採用とする。アプリを停止させず空のボードで起動し、全体通知領域に「保存データを読み込めなかったため、空の状態で起動しました。」と表示する。

破損した値を自動で上書きしない。利用者が次に追加・編集・削除・移動・並べ替えを成功させた時点で、正しいversion 1データへ置き換える。

### 9.5 保存失敗 [必須B]

`JSON.stringify` と `localStorage.setItem` を `try/catch` で扱う。容量超過やアクセス拒否等で失敗した場合は変更を確定せず、「変更を保存できませんでした。ブラウザの保存設定または空き容量を確認してください。」と全体通知領域に表示する。アプリは引き続き操作可能であること。

初回サンプルの保存だけは、失敗してもサンプル表示そのものを変更前へ戻さない。サンプルを画面上に維持し、次の追加、編集、削除、移動、並べ替え時に、その操作後の全状態の保存を再試行する。この再試行に失敗した操作は通常どおり操作直前へ戻すが、初回サンプルは引き続き表示する。

## 10. 日付と期限表示

### 10.1 保存と表示 [必須A][必須B]

- 期限は `<input type="date">` が返すローカル暦日の `YYYY-MM-DD` 文字列として保存する。
- UTC日時へ変換して保存しない。時刻・タイムゾーン・締切時刻は扱わない。
- 表示上の「今日」は利用者環境のローカル日付から `YYYY-MM-DD` を組み立てて比較する。`toISOString()` のUTC日付を今日の判定に使わない。

### 10.2 期限状態 [必須A]

| 条件 | 状態 | 表示要件 |
|---|---|---|
| `dueDate === ''` | 期限なし | 期限表示を省略、または「期限なし」と表示 |
| `status !== 'done'` かつ期限 > 今日 | 期限内 | 日付を表示 |
| `status !== 'done'` かつ期限 = 今日 | 期限当日 | 「今日」等の文字を併記して区別 |
| `status !== 'done'` かつ期限 < 今日 | 期限超過 | 「期限超過」の文字と視覚的強調を表示 |
| `status === 'done'` | 完了 | 日付は表示するが期限超過として強調しない |

色だけで状態を伝えない。日付が変わったときの自動更新は、ページ再表示時には必須とするが、開きっぱなしの画面で日付をまたいだ瞬間の自動更新は対象外とする。

## 11. 入力検証

### 11.1 規則 [必須A][必須B]

| 項目 | 規則 |
|---|---|
| タイトル | `trim()` 後が空なら不正 |
| 説明 | 任意。文字列として保存 |
| 期限 | 空、または実在する `YYYY-MM-DD` の暦日 |
| 担当者 | 任意。文字列として保存 |
| ステータス | `todo` / `doing` / `done` のいずれか |

### 11.2 エラー表示 [必須A]

- 検証は保存操作時に行う。
- タイトルが空の場合は保存せず、タイトル欄の近くに「タイトルを入力してください。」と表示する。
- 不正な入力欄を `aria-invalid="true"` とし、エラー文を `aria-describedby` で関連付け、最初の不正欄へフォーカスを移す。
- 入力を修正して再度保存するとエラーを解消できる。エラー中もキャンセル、閉じる、`Escape` は使用できる。

## 12. レスポンシブ対応

### 12.1 必須条件 [必須A]

- 375px幅で横方向のページ全体スクロールを発生させず、追加、編集、削除、ステータス変更を行える。
- 広い画面では3列を横並びにする。
- 375pxを含む狭い画面では3列を縦積みにし、各列とカードの内容を読めるようにする。
- モーダルは画面内に収め、内容が高い場合はモーダル内部を縦スクロール可能にする。
- 長い英数字やURL相当の連続文字でも折り返し、カード、列、モーダル、ページ幅を破壊しない。
- タップ対象は隣接操作との誤操作が起きにくい大きさと間隔を持たせる。
- 幅変更後は、折りたたんだ説明文が実際に2行を超えるかを再判定し、開閉ボタンの表示要否を更新する。`resize` を利用する場合はデバウンスまたは `requestAnimationFrame` 等で実行頻度を抑える。

## 13. アクセシビリティ

### 13.1 主要操作 [必須A][必須B]

- 見出しを論理的な順序で使用し、各列を識別できる名前を持たせる。
- 追加、カード選択、編集、削除、モーダルの保存・キャンセル・閉じるはキーボードで操作できる。
- 説明文の「全文を表示」「折りたたむ」はキーボードで操作でき、対象タスク名を含むアクセシブル名と現在の展開状態を持つ。
- アイコンだけのボタンには操作対象を含むアクセシブル名を付ける。
- フォーカス表示を消さない。
- 列件数、期限状態、エラーは色だけに依存しない。

### 13.2 モーダルのフォーカス管理 [必須A]

- モーダルは `role="dialog"`、`aria-modal="true"` とし、見出しを関連付ける（ネイティブ `<dialog>` 使用時も同等の名前を持たせる）。
- 開いた直後はタイトル欄へフォーカスする。
- モーダル表示中は背面要素を操作できず、`Tab` / `Shift+Tab` のフォーカスをモーダル内に循環させる。
- `Escape` で保存せず閉じる。
- 閉じた後は、原則としてモーダルを開いた要素へフォーカスを戻す。編集対象が存在しなくなった場合は「タスクを追加」へ戻す。

### 13.3 状態通知 [必須B]

保存・読み込みエラーは見える文言で表示し、適切な `aria-live` 領域で通知する。ドラッグ&ドロップだけに依存せず、ステータス変更の代替操作を常に提供する。

## 14. エラー処理

| ケース | 期待動作 |
|---|---|
| タイトルが空 | モーダルを維持し、項目エラーを表示する |
| 読み込み値が破損 | 空状態で起動し、読み込みエラーを通知する |
| `localStorage` 読み書きが例外 | アプリを停止させず通知する |
| 変更の保存失敗 | 変更前の確定状態へ戻す |
| 初回サンプルの保存失敗 | サンプルと操作可能状態を維持して保存失敗を通知し、次の変更操作で変更後の全状態を再保存する。その操作の保存にも失敗した場合はサンプルを残して操作直前へ戻す |
| ドラッグ中に対象IDが見つからない | 状態を変更せずドラッグ表示を解除する |
| 存在しないタスクへの操作 | 例外で停止せず、再描画して安全に終了する |

コンソールに未捕捉例外を残さない。

## 15. セキュリティ

### 15.1 必須条件 [必須A][必須B]

- タイトル、説明、担当者、保存データ由来の値をHTMLとして解釈しない。
- テキスト表示は `textContent`、フォーム値はDOMの `value` プロパティ等、安全なAPIを使う。
- ユーザー入力をHTML文字列、イベント属性、JavaScript、CSSとして連結・実行しない。
- `localStorage` の内容を信頼せず、9.3の検証後に使用する。
- 外部へデータを送信しない。

## 16. 対象外 [MVP外]

- ユーザー登録、ログイン、権限管理
- 複数ユーザーでの共有、リアルタイム同期
- サーバー、データベース、クラウドへの保存
- 添付ファイル、コメント、タスク期限のリマインダー通知
- 列の追加・編集・削除、列名や列順のカスタマイズ
- ゴミ箱、復元、Undo
- 検索、絞り込み
- 優先度、タグ
- 外部カレンダー連携
- タッチ操作専用のドラッグ&ドロップ
- キーボードによる列内並べ替え専用UI
- 開いたまま日付をまたいだ瞬間の期限表示自動更新

## 17. 実装完了の判定条件

次をすべて満たしたときに実装完了とする。

1. 本書の [必須A] と [必須B] をすべて実装している。
2. `part01-kanban-acceptance.md` の全項目が対応ブラウザで合格する。
3. 375px幅と広い画面の双方で主要操作が完了できる。
4. 再読み込み後にタスク内容、ステータス、列内順序が復元される。
5. 通常操作、破損データ、保存失敗で未捕捉例外によりアプリが停止しない。
6. 外部ライブラリ、ビルド工程、対象外機能が追加されていない。
7. HTML/CSS/JavaScriptの実装ファイルと、本仕様書・受入チェックリスト以外の既存成果物を不必要に変更していない。

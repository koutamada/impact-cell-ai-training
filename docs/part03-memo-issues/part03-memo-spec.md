## 1. 目的・スコープ

### 1-1. 目的

タイトルと本文からなるメモを作成・編集し、検索・タグ付け・ピン留め・並び替えができるメモ管理アプリを、Vanilla HTML / CSS / JavaScript のみで実装する。入力内容は自動保存され、全データをJSONファイルとしてエクスポート／インポートできる。

高機能なノートアプリを作ることは目的ではない。**本書で確定した範囲を、確定した通りに動作させ、受入チェックリストで検証できる状態にすることが目的**である。

### 1-2. スコープ

課題文の8要件をすべて実装する。加えて、依頼者判断により削除・ゴミ箱・復元を実装する。要件は削らず、Markdown・タグ・検索の仕様を必要十分な範囲に限定することで実装量を制御する。

### 1-3. 技術方針

- Vanilla HTML / CSS / JavaScript のみ
- 外部ライブラリ・CDN・Webフォント・音声/画像ファイルを使用しない
- ビルド工程なし。`index.html` をブラウザで直接開いて動作する
- GitHub Pages で公開でき、公開環境でも同一に動作する（相対パス参照）
- Part 1・Part 2 とコードを共有しない。本Part単体で完結する
- Part 4 以降を見越した抽象化・共通化を行わない
- 対応ブラウザは最新版の Chrome / Safari（iOS含む）。それ以外は問わない

### 2-1. [必須B] 補足仕様の一覧

課題文に無いが、[必須A]を成立させるために必要と判断した事項。各章に詳細を記す。

| ID | 補足仕様 | 必要な理由 |
|---|---|---|
| B1 | メモの編集ができること | A7「入力内容を自動保存する」は編集操作の存在が前提 |
| B2 | 各メモに一意なIDを持たせること | 選択・ピン留め・削除・インポートのすべてが対象特定を必要とする |
| B3 | 各メモに `createdAt` / `updatedAt` を持たせること | A5のソートキーが必要 |
| B4 | 保存先と保存形式を確定すること | A7の保存先（15章） |
| B5 | ユーザー入力を安全に表示すること | A6のMarkdown変換はHTMLを生成するためXSSリスクがある（13章） |
| B6 | 空メモの一覧表示を定義すること | 新規作成直後は必ずタイトルも本文も空になる |
| B7 | インポートデータを検証すること | 外部ファイル読み込みで既存データが破壊されないようにする |
| B8 | メモ0件時の表示を定義すること | 初回起動時は必ず0件 |
| B9 | 保存失敗を利用者に伝えること | 自動保存は確認行為が無く、失敗が黙殺されるとデータを失う |
| B10 | 並び替えのタイブレーク条件を定義すること | 同値時の順序が実行ごとに変わらないようにする |

## 5. データモデル

### 5-1. メモオブジェクト [必須A][必須B][追加C]

```js
{
  id: string,          // 一意識別子（空文字不可）
  title: string,       // タイトル（空文字可）
  body: string,        // 本文。Markdown記法を含む生テキスト（空文字可）
  tags: string[],      // タグ。各要素は空でない文字列
  pinned: boolean,     // ピン留め状態
  trashed: boolean,    // ゴミ箱状態。true = ゴミ箱内
  createdAt: number,   // 作成日時（エポックミリ秒）
  updatedAt: number    // 更新日時（エポックミリ秒）
}
```

| フィールド | 区分 | 備考 |
|---|---|---|
| `id` | [必須B] B2 | `crypto.randomUUID()` で生成。未対応環境向けに `Date.now().toString(36) + Math.random().toString(36).slice(2)` をフォールバックとする |
| `title` | [必須A] A1 | 空文字可。一覧表示では「無題」と表示する（10-4） |
| `body` | [必須A] A1 | **Markdown変換後のHTMLを保存しない。生テキストのみを保存する** |
| `tags` | [必須A] A3 | 9章のルールで正規化済みの配列 |
| `pinned` | [必須A] A4 | |
| `trashed` | [追加C] C2 | 下記5-2の理由により `boolean` で確定 |
| `createdAt` | [必須B] B3 | 作成時に設定し、以後変更しない |
| `updatedAt` | [必須B] B3 | 7-4の規則で更新する |

### 5-2. ゴミ箱状態の表現を `trashed: boolean` に確定した理由

`deletedAt: number | null` ではなく `trashed: boolean` を採用する。

1. **本仕様に削除時刻を必要とする機能が無い。** 自動完全削除・削除履歴・削除日時での並び替えはいずれも実装対象外であり、`deletedAt` を持っても使い道がない
2. **インポート検証が単純になる。** Q30により厳格な型検証が必要だが、`typeof v === 'boolean'` の1行で済む。`number | null` は2種類の型を許す分岐が必要になり、検証が複雑化する
3. **不要な機能を誘発しにくい。** `deletedAt` があると「30日後に自動削除」等を実装したくなるが、これは実装対象外である

**本文が生テキストであるのと同じ理由で、`trashed` はメモオブジェクトの一部として保存する。** 通常メモとゴミ箱メモは同一のデータ集合（`notes` 配列）で管理し、`trashed` の値で表示先を振り分ける。配列を2つに分けない。

### 5-3. 保存・エクスポートのスキーマ [必須B]

localStorage への保存と、エクスポートファイルの内容は**同一のスキーマ**を用いる。これにより検証処理を共通化でき、エクスポート／インポートがバックアップ／復元として成立する。

```js
{
  version: 1,        // 整数。本仕様のスキーマバージョン
  notes: [ /* メモオブジェクトの配列 */ ]
}
```

- `version` は**整数の `1`** とする。文字列 `"1"` ではない
- `notes` は配列。0件（空配列）も正常な値である
- 通常メモとゴミ箱メモの両方を `notes` に含める

### 5-4. アプリの実行時状態（永続化しない）

| 項目 | 内容 |
|---|---|
| 選択中メモID | 編集ペインに表示しているメモの `id`。未選択は `null` |
| 表示モード | `normal`（通常一覧） / `trash`（ゴミ箱） |
| 検索文字列 | 検索欄の入力値 |
| 並び替え条件 | 10-3の4種のいずれか |
| 編集/プレビュー | 編集ペインの表示タブ |
| 保存状態 | 保存中 / 保存済み / 失敗 |

**これらは localStorage に保存しない。** 再読み込み時は初期状態（表示モード `normal`、検索文字列は空、並び替えは「更新日時：新しい順」、未選択、編集タブ）に戻る。

## 6. 画面構成

### 6-1. 全体レイアウト（PC：幅768px以上）

左右2ペイン構成とする。

```
┌──────────────────────────────────────────────┐
│ アプリタイトル      [エクスポート] [インポート]        │ ①ヘッダー
├──────────────────────────────────────────────┤
│ [新規メモ] [検索:____] [並び替え▼] [ゴミ箱]           │ ②ツールバー
├────────────────┬─────────────────────────────┤
│ ③メモ一覧        │ ④編集ペイン                     │
│                │                              │
│ 📌 会議メモ      │ [編集][プレビュー]   保存しました   │
│    タグ:仕事     │ ┌──────────────────────────┐ │
│ ─────────────  │ │ タイトル                    │ │
│    買い物リスト   │ ├──────────────────────────┤ │
│    タグ:私用     │ │ タグ（カンマ区切り）          │ │
│ ─────────────  │ ├──────────────────────────┤ │
│    無題         │ │ 本文                       │ │
│                │ │                            │ │
│                │ └──────────────────────────┘ │
│                │                    [削除]      │
└────────────────┴─────────────────────────────┘
```

### 6-2. 各領域の仕様

| # | 領域 | 内容 | 区分 |
|---|---|---|---|
| ① | ヘッダー | アプリ名、エクスポートボタン、インポート（file input） | [必須A] A8 |
| ② | ツールバー | 新規メモボタン、検索欄、並び替えセレクト、ゴミ箱表示切替 | [必須A] A2/A5, [追加C] C5 |
| ③ | メモ一覧 | 表示モードに応じた一覧。各行に選択操作とピン留めトグル | [必須A] A4 |
| ④ | 編集ペイン | 選択中メモの編集／プレビュー、保存状態表示、削除ボタン | [必須A] A1/A6/A7, [追加C] C1 |

### 6-3. 一覧の各行に表示する内容 [必須B]

| 項目 | 内容 |
|---|---|
| ピン留め表示・トグル | ピン留め状態を示すアイコン等。クリックで切替（通常一覧のみ） |
| タイトル | 空の場合は「無題」（10-4） |
| 本文抜粋 | **Markdown生テキストの先頭部分をそのまま表示**（記法除去処理は作らない）。長い場合は省略表示する |
| タグ | そのメモのタグをチップ風に表示 |
| 選択状態 | 選択中の行が視覚的に判別できること |

### 6-4. 表示モードの切替 [追加C]

| モード | 一覧の内容 | 編集ペイン | 検索欄 |
|---|---|---|---|
| `normal` | `trashed === false` のメモ | 編集可能。削除ボタンを表示 | 有効 |
| `trash` | `trashed === true` のメモ | **読み取り専用**。復元・完全削除ボタンを表示 | **無効化する** |

**[必須B] モード切替時の挙動：**

- 切替時に**選択中メモを未選択に戻す**（モードをまたいで同じメモが選択されたままになるのを防ぐ）
- 切替時に**検索文字列をクリアする**。ゴミ箱表示中は検索欄を `disabled` にする（C4により、ゴミ箱内検索は実装しない）
- 通常一覧へ戻ったとき、検索文字列は空の状態から再開する
- 切替の直前に、デバウンス待機中の編集内容を確定保存する（7-3）

### 6-5. 編集ペインの表示（`normal` モード）

| 要素 | 内容 |
|---|---|
| 編集／プレビュー切替 | 2つのタブ。同時2画面表示は行わない。初期は「編集」 |
| タイトル入力欄 | 1行テキスト |
| タグ入力欄 | 1行テキスト（カンマ区切り、9章） |
| 本文入力欄 | 複数行テキスト（`textarea`） |
| プレビュー | 本文をMarkdown変換して表示（12章）。タイトル・タグも表示してよい |
| 保存状態表示 | 「保存中…」「保存しました」「保存できませんでした」（7-5） |
| 削除ボタン | 確認後にゴミ箱へ移動（11章） |

### 6-6. 編集ペインの表示（`trash` モード）

| 要素 | 内容 |
|---|---|
| メモ内容 | タイトル・タグ・本文を**読み取り専用**で表示する。入力欄を編集可能な状態にしない（C8） |
| 復元ボタン | 押すと即座に復元（確認ダイアログ不要） |
| 完全削除ボタン | 確認後に完全削除（C7） |
| 削除ボタン | **表示しない** |
| 編集/プレビュー切替 | 表示しない。本文はMarkdown変換した結果、または生テキストのいずれかで表示してよい |

### 6-7. 未選択時・0件時の表示 [必須B] B8

| 状況 | 表示 |
|---|---|
| メモが0件（`normal`） | 一覧領域に「メモがありません」等のメッセージ |
| ゴミ箱が0件（`trash`） | 一覧領域に「ゴミ箱は空です」等のメッセージ |
| 検索結果が0件 | 一覧領域に「該当するメモがありません」（8-4） |
| メモ未選択 | 編集ペインに「メモを選択してください」等のメッセージ。入力欄を表示しない、または無効化する |

## 7. メモ作成・編集・自動保存

### 7-1. 新規メモの作成 [必須A] A1

| # | 仕様 | 区分 |
|---|---|---|
| N1 | 「新規メモ」ボタンを押すと、空のメモを1件作成する | [必須A] |
| N2 | 作成時の値は `title: ""`、`body: ""`、`tags: []`、`pinned: false`、`trashed: false`、`createdAt`／`updatedAt` は現在時刻 | [必須B] |
| N3 | 作成した時点で一覧に表示され、localStorageに保存される | [必須B] |
| N4 | 作成したメモを選択状態にし、編集ペインを「編集」タブにしてタイトル入力欄にフォーカスする | [必須B] |
| N5 | タイトルが空の間、一覧では「無題」と表示する。**実データの `title` に「無題」を書き込まない** | [必須B] B6 |
| N6 | 空のまま他のメモへ移動しても、**自動削除しない** | [必須B] |
| N7 | `trash` モード表示中は新規メモを作成できない（ボタンを無効化する） | [必須B] |

### 7-2. 編集 [必須B] B1

| # | 仕様 |
|---|---|
| E1 | タイトル・タグ・本文を編集できる |
| E2 | 編集内容は7-3の規則で自動保存される |
| E3 | タイトル・本文の入力に文字数上限を設けない |
| E4 | 編集内容は一覧の表示（タイトル・抜粋・タグ）にも反映される |
| E5 | `trash` モードのメモは編集できない（C8） |

**[必須B] 一覧表示の更新タイミング：** 入力のたびに一覧を再描画すると、タイトル変更時に「タイトル昇順」で並び順が入力中に動いてしまう。**一覧の並び順の再計算は、保存が確定したタイミングで行う**こと。表示文言のみの更新は随時行ってよい。

### 7-3. 自動保存 [必須A] A7

| # | 仕様 | 区分 |
|---|---|---|
| S1 | 入力停止から**約500ms後**に保存する（デバウンス方式） | [必須A] |
| S2 | 次の場合は、デバウンス待機中でも**即座に確定保存する** | [必須B] |
| | ・別のメモへ切り替えるとき | |
| | ・表示モードを切り替えるとき | |
| | ・ページが非表示になるとき（`visibilitychange` で `hidden`） | |
| | ・ページを離れるとき（`pagehide` 等） | |
| | ・エクスポートを実行する直前 | |
| | ・インポートを実行する直前 | |
| | ・削除・復元・完全削除を実行する直前 | |
| S3 | ピン留めの切替・削除・復元・完全削除は、デバウンスを経由せず**即座に保存する** | [必須B] |
| S4 | 手動保存ボタンは実装しない | 確定事項 |

**S2が無いと「入力してすぐタブを閉じると内容が消える」という、A7の趣旨に反する不具合が発生する。** 受入チェックリストで確認する。

**[必須B] IME入力中の扱い：** デバウンス方式のため、日本語変換の未確定文字列が保存される場合があるが、確定後の入力で上書きされるため実害はない。本文・タイトル入力欄について特別な対処は不要である（**検索欄は別途対処が必要。8-3参照**）。

### 7-4. `updatedAt` の更新規則 [必須B]

| 操作 | `updatedAt` |
|---|---|
| タイトル・本文・タグの変更 | **更新する** |
| ピン留めの切替 | **更新しない** |
| ゴミ箱へ移動（削除） | **更新しない** |
| 復元 | **更新する**（C11、復元時刻へ） |
| 完全削除 | 該当なし |
| インポート | ファイル内の値をそのまま用いる（更新しない） |

**ピン留めで `updatedAt` を更新しない理由：** ピン留めは内容の変更ではない。更新すると「更新日時：新しい順」で並び順が意図せず変わり、利用者が混乱する。

**[必須B]** 実際に値が変化していない場合（同じ文字を打ち消して元に戻した等）は `updatedAt` を更新しなくてよいが、更新しても不具合とはしない。

### 7-5. 保存状態の表示 [必須A] A7

編集ペイン内に簡潔に表示する。作り込みは不要。

| 状態 | 表示例 |
|---|---|
| 未保存の変更がある（デバウンス待機中〜書き込み中） | 保存中… |
| 保存が完了した | 保存しました |
| 保存に失敗した | 保存できませんでした |

- 保存完了表示は、一定時間後に消してもよいし、残したままでもよい
- 保存失敗の表示は、次の保存が成功するまで残す（16-2）

## 8. 検索

### 8-1. 検索対象 [必須A] A2

以下**すべて**を対象とする。

| 対象 | 備考 |
|---|---|
| タイトル | |

### 10-1. ピン留め操作 [必須A] A4

| # | 仕様 |

| # | 条件 | 内容 |
|---|---|---|
| 1 | 更新日時：新しい順 | `updatedAt` 降順。**デフォルト** |
| 2 | 更新日時：古い順 | `updatedAt` 昇順 |
| 3 | 作成日時：新しい順 | `createdAt` 降順 |
| 4 | タイトル：昇順 | 下記10-4の規則 |

- ドラッグ＆ドロップによる手動並び替えは実装しない
- 並び替え条件は永続化しない。再読み込みでデフォルトに戻る

### 10-4. タイトル昇順の詳細規則 [必須B]

| # | 規則 |
|---|---|
| T1 | 比較には `localeCompare` を用い、ロケールに `'ja'` を指定する（例：`a.title.localeCompare(b.title, 'ja')`）。指定しないとブラウザにより順序が変わる |
| T2 | **タイトルが空文字のメモ（一覧上「無題」と表示されるもの）は、グループ内の末尾に置く** |
| T3 | 空タイトルのメモが複数ある場合、その中の順序はT4のタイブレークで決める |

### 10-5. タイブレーク条件 [必須B] B10

**すべての並び替え条件について、比較値が同一の場合は `id` の昇順で決定する。**

```

これが無いと、同一の更新日時を持つメモ（例：インポート直後）の順序が実行のたびに変わり、受入テストで判定できなくなる。

### 10-6. 一覧の並び順（`trash` モード） [追加C]

| `---` | `---` という文字列がそのまま表示される |

| `~~打ち消し~~` | `~~打ち消し~~` という文字列がそのまま表示される |
| `- [ ] タスク` | **箇条書きになり、項目の中身が `[ ] タスク` と表示される**（`- ` は対応記法のため） |
| `  - ネスト` | 行頭に空白があるため箇条書きと判定せず、段落として `  - ネスト` が表示される |

### 12-5. 変換処理の順序 [必須B] ← セキュリティ上の必須事項

**以下の順序を厳守する。順序を誤るとXSSが成立する、または記法が機能しなくなる。**

```
① 本文全体をHTMLエスケープする
   & → &amp;   （最初に処理する）
   < → &lt;
   > → &gt;
   " → &quot;
   ' → &#39;

② エスケープ済みテキストを行単位でブロック解析する
   コードブロック → 見出し → リスト → 段落

③ 各ブロックの内容にインライン記法を適用する
   インラインコード → 太字 → 斜体

④ 生成したHTML文字列を innerHTML で挿入する
```

**① を最初に行う理由：** ユーザー入力に含まれる `<script>` 等をこの時点で無害化する。②③でMarkdown記法から生成するタグは、この処理の後に追加されるため、エスケープの影響を受けない。

**順序を逆にしてはならない理由：** ②③を先に行うと、生成した `<h1>` や `<strong>` までエスケープされ、記法が一切機能しなくなる。

**`&` を最初に処理する理由：** 先に `<` → `&lt;` を行うと、後続の `&` 処理でその `&` が `&amp;` に変換され、`&amp;lt;` となって壊れる。

### 12-6. ブロック解析の詳細規則 [必須B]

| 記法 | 判定条件 | 備考 |
|---|---|---|
| コードブロック | 行が ```` ``` ```` のみからなる行で開始し、次の ```` ``` ```` のみの行、または本文末尾までを内容とする | **内容にインライン記法を適用しない。** 改行をそのまま保持する |
| 見出し | 行頭が `# ` / `## ` / `### `（**記号の直後に半角スペース1個が必要**） | `#見出し`（スペース無し）は見出しにしない。`#### ` はH4のため非対応（段落扱い） |
| 箇条書き | 行頭が `- `（半角ハイフン＋半角スペース） | 連続する行を1つの `<ul>` にまとめる。行頭に空白がある行は対象外 |
| 番号付きリスト | 行頭が `数字 + . + 半角スペース`（例：`1. `） | 連続する行を1つの `<ol>` にまとめる。番号は `<ol>` の既定の採番に従うため、入力の数値と一致しなくてよい |
| 段落 | 上記のいずれにも該当しない連続行 | 空行で段落を区切る。段落内の単一改行は `<br>` に変換する |

### 12-7. インライン記法の詳細規則 [必須B]

**適用順序：インラインコード → 太字 → 斜体**

| 記法 | 規則 |
|---|---|
| インラインコード | `` ` `` で囲まれた同一行内の範囲。最短一致とする。**内容に太字・斜体を適用しない** |
| 太字 | `**` で囲まれた範囲。最短一致 |
| 斜体 | `*` で囲まれた範囲。最短一致 |

**太字を斜体より先に処理する理由：** 先に斜体を処理すると `**太字**` の最初の `*` が斜体の開始と解釈され、`*<em>太字</em>*` のような誤変換になる。

**[必須B]** 対応が閉じていない記法（`**閉じていない`）は、記法文字を含む通常テキストとして表示する。エラーにしない。

### 12-8. 空の本文

本文が空の場合、プレビューは空の表示（または「本文がありません」等）とする。エラーにしない。

### 14-3. インポートデータの検証 [必須B] B7

**厳格に検証する。不足項目の補完や `Boolean()` 等による曖昧な型変換を行わない。**

本アプリから正しくエクスポートされたJSONを復元する用途に限定する。

#### ルート構造の検証

| # | 検証項目 |
|---|---|
| C-1 | ファイル内容がJSONとして正常に解析できること |
| C-2 | 解析結果がオブジェクトであること（配列・`null` は不可） |
| C-3 | `version` が存在し、**整数の `1`** であること（文字列 `"1"` は不可） |
| C-4 | `notes` が存在し、**配列**であること |

#### 各メモの検証（`notes` の全要素について）

| # | 項目 | 検証条件 |
|---|---|---|
| C-5 | 要素そのもの | オブジェクトであること（`null`・配列は不可） |
| C-6 | `id` | `string` 型で、**空文字でない**こと |
| C-7 | `title` | `string` 型であること（空文字は可） |
| C-8 | `body` | `string` 型であること（空文字は可） |
| C-9 | `tags` | **配列**であり、**全要素が `string` 型**であること。各タグは空文字でなく、`tag === tag.trim()` が成立し、同一メモ内に完全一致する重複がないこと（空配列は可） |

| C-11 | `trashed` | `boolean` 型であること |

#### 検証の扱い

| C-15 | **1件でも不正なメモが含まれる場合、インポート全体を拒否する**（部分インポートは行わない） |

**C-19の理由：** 将来スキーマを拡張した際、古いバージョンのアプリでも読み込める余地を残すため。ただし `version` が `1` でなければC-3で拒否されるため、実質的に問題は生じない。

## 15. localStorage

### 15-1. 保存仕様 [必須B] B4

| 項目 | 仕様 |
|---|---|
| ストレージ | localStorage（IndexedDBは使用しない） |
| **キー** | **`part03-memo.notes`** |
| 値 | 5-3のスキーマ（`{ version: 1, notes: [...] }`）を `JSON.stringify` した文字列 |
| 保存単位 | **全メモを1キーにまとめて保存する。** メモごとにキーを分けない |
| 保存タイミング | 7-3の規則に従う |

**エクスポートファイルと同一スキーマにする理由：** 検証処理を共通化でき、保存データの構造とバックアップの構造が一致するため、動作確認時に開発者ツールで内容を照合しやすい。

### 15-2. 読み込み [必須B]

ページ読み込み時に1回実行する。

| # | 仕様 |
|---|---|
| LD1 | localStorage へのアクセスと `JSON.parse` を `try / catch` で囲む |
| LD2 | キーが存在しない場合、メモ0件の状態で正常に起動する（初回起動時） |
| LD3 | 解析に失敗した場合、または構造が不正な場合、**メモ0件の状態で起動し、画面に警告を表示する**（例：「保存データを読み込めませんでした」） |
| LD4 | 白画面・エラーで停止しない |

**[必須B] 読み込み時と、インポート時の扱いの違い：**

| | 検証失敗時の動作 | 理由 |
|---|---|---|
| localStorage読み込み | 空の状態で起動し、警告を表示する | 起動不能にできないため。利用者はここから作業を再開できる |
| インポート | 拒否し、既存データを一切変更しない | 既存データという守るべき対象が存在するため |

読み込み時の検証は、14-3ほど厳格である必要はない。**構造が想定と違えば空で起動する**という扱いでよい。

### 15-3. 保存失敗時 [必須B] B9

| # | 仕様 |
|---|---|
| SV1 | 書き込みを `try / catch` で囲む |
| SV2 | 失敗した場合、**画面に「保存できませんでした」等の簡潔な警告を表示する** |
| SV3 | **保存失敗を黙って無視しない**（コンソールエラーのみで済ませない） |
| SV4 | 失敗してもアプリは可能な範囲で動作を継続する |
| SV5 | 警告表示は、次の保存が成功するまで残す |

**SV2〜SV3の理由：** 自動保存は「保存ボタンを押す」という確認行為が無いため、失敗が黙殺されると、利用者は保存されたと思い込んでページを閉じ、データを失う。

**容量について：** localStorage は同一オリジンあたり概ね5MB程度の制限がある。通常利用では問題にならないが、インポートで大量のデータを読み込んだ場合に上限へ達する可能性がある。その場合もSV2の警告で対応する。容量の事前チェックは実装しない。

## 付録：実装者へ渡す際の注意事項

実装依頼時、以下を省略せず伝えること。

1. **出力ファイルは `apps/part03-memo/` 配下の `index.html` / `style.css` / `app.js` の3つのみ。** その他のファイルを作成しない
2. **フレームワーク・外部ライブラリ・CDN・Webフォントを使わない**
3. **本仕様書19章に列挙した機能を追加しない。** 仕様に無い機能を思いついても実装せず、提案にとどめる
4. **Markdownは12-3の10種のみ対応する。** CommonMark互換を目指さない。非対応記法は記法文字ごと通常テキストとして表示する
5. **Markdown変換は「①エスケープ（`&` を最初に）→ ②ブロック解析 → ③インライン変換 → ④innerHTML挿入」の順序を厳守する。** 順序を逆にするとXSSが成立する
6. **インライン変換は「インラインコード → 太字 → 斜体」の順に行う**（順序を誤ると `**太字**` が誤変換される）
7. **タイトル・タグ・本文抜粋は `textContent` で表示する。`innerHTML` にユーザー入力を連結しない**
8. **localStorageのキーは `part03-memo.notes`。** 値は `{ version: 1, notes: [...] }`
9. **ゴミ箱状態は `trashed: boolean`。** `deletedAt` は使わない。通常メモとゴミ箱メモを同じ `notes` 配列で管理する
10. **自動保存は500msデバウンス。** メモ切替・モード切替・ページ非表示・ページ離脱・エクスポート/インポート/削除の直前には即座に確定保存する
11. **ピン留めの切替では `updatedAt` を更新しない。復元では更新する**
12. **インポートは厳格検証。** 不足項目を補完せず、`Boolean()` 等の型変換もせず、1件でも不正なら全体を拒否し、既存データを一切変更しない
13. **エクスポートは検索中でも全件。ゴミ箱メモも含める**
14. **検索は `compositionstart` / `compositionend` を考慮し、日本語変換中に検索を実行しない**
15. **ピン留めは常に一覧上部。検索中も同じ。ゴミ箱ではグループ分けしない**
16. **並び替えは4種のみ。同値時は `id` でタイブレークする。タイトル昇順では空タイトルを末尾に置き、`localeCompare('ja')` を使う**
17. **幅768px未満では一覧と編集を1画面ずつ切り替える。幅375pxで崩れないこと**
18. **`outline: none` を単独で指定しない**
19. **Part 1・Part 2 のコードを再利用せず、Part 4 以降を見越した共通化もしない**

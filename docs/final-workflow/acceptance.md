# FlowDesk 受入チェック

最終更新: 2026-09-28

結果は、サーバー側の自動・統合試験と公開画面での手動確認を分けて記録します。`PASS（API）`は権限・状態遷移がサーバー側で成立したこと、`PASS（画面）`はGitHub Pagesの公開画面で表示または操作を確認したことを表します。

## 防御・表示確認

| 項目 | 結果 | 根拠・残作業 |
|---|---|---|
| フロントエンドにService Role Keyがない | PASS | 静的検査・コード確認 |
| ユーザー値を`innerHTML`へ挿入しない | PASS | 静的検査 |
| 通常テーブル更新による状態遷移回避を拒否 | PASS（API） | DML権限とRPCロール検査 |
| 別ユーザーの案件ID直接取得を拒否 | PASS（API） | 一般ユーザーBで0件を確認 |
| 同時編集の`version`不一致 | PASS（画面） | 案件 #10 を2タブで編集し、先行更新だけが保存され正本が保護されることを確認。SQLSTATE補正後、古い版の送信には「他の操作により案件が更新されました。再読み込みしてください。」が即時表示された |
| 無効ユーザーの既存セッション | PASS（画面・静的検査） | 一般ユーザーBのログイン中に管理側で無効化し、再読み込み時にログイン画面へ戻って「このアカウントは業務システムを利用できません。管理者へ確認してください。」と表示されることを確認。再有効化後の再ログインにも成功。RPCの有効ユーザー検査も静的検査済み |

| 存在しない・削除済み案件の表示 | PASS（画面） | 削除済み案件 #10 を別タブの古い一覧から開き、案件内容を表示せず「案件が存在しないか、閲覧権限がありません。」を表示。一覧と画面全体は維持された |
| 却下・差し戻し理由の空欄拒否 | PASS（画面） | 案件 #6・#7で空欄送信後も承認待ちのまま状態が変わらないことを確認 |
| 10 MiB超・許可外形式の添付拒否 | PASS（画面・静的検査） | 案件 #9 でTXTと10MiB超PDFが画面上で拒否され、添付・履歴が増えないことを確認。DB・Storageの同一制約も静的検査で確認 |
| 375px表示 | PASS（画面・静的検査） | iPhone Safariの100%表示でログイン、管理者ダッシュボード、案件一覧、案件詳細、管理画面を確認。管理画面本体は画面幅に収まり、幅のある表だけが横スクロール可能。560px以下のCSSも静的検査済み |

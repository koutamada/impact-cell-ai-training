| B13 | `JSON.parse` / `JSON.stringify` の往復で入力と結果が一致しないケースを明記すること | 数値精度・重複キー・キー順で入力と異なる出力になり、不具合と誤認される |

## 3. 入力仕様

### 3-1. 入力欄 [必須A] A1

| # | 仕様 |
|---|---|
| I1 | **`<textarea>` を用いる** |
| I2 | 等幅フォントで表示する（`font-family: ui-monospace, monospace` 等。Webフォントは使わない） |
| I3 | 折り返しは既定のまま（`soft`）とする |
| I4 | `spellcheck="false"` を指定する（JSONに対する赤波線を抑止する） |
| I5 | 初期状態は空。プレースホルダで入力例を示してよい |

### 3-2. 実行契機 [必須B] B1

**入力の変更に追従して、自動的に検証・整形・表示を行う。整形ボタンは設けない。**

課題文が「JSON形式のテキストを入力すると、読みやすい形に整形して表示する」としているため、**入力そのものが実行契機**であると解釈する。

| # | 契機 | イベント |
|---|---|---|
| T1 | テキストエリアの入力 | `input` |
| T2 | IME変換の確定 | `compositionend` |

| # | 仕様 |
|---|---|
| T3 | **デバウンス 300ms を入れる**（10-3） |
| T4 | **`compositionstart` から `compositionend` までの間は処理を実行しない** |
| T5 | すべての契機が同一の再処理を通る（契機ごとに別処理を書かない） |
| T6 | デバウンス待機中は前回の表示が残る。待機後に**必ず全体を再描画する**（9章） |

**T4の理由 [必須B]：** 日本語入力の未確定文字列に対して構文チェックが走ると、入力中ずっとエラーが表示される。JSONに日本語を含む場面（文字列値）は多い。

（14章 U1・U11）

### 3-3. 入力値の扱い [必須B] B2

**テキストエリアに入力された原文を、加工せずそのまま `JSON.parse()` に渡す。**

| # | 仕様 |
|---|---|
| V1 | **前後の空白・改行・タブを除去しない。** 原文をそのまま検証・整形の入力とする |
| V2 | **全角スペース等を除去・変換しない** |
| V3 | テキストエリアの表示内容も当然書き換えない |
| V4 | 正規のJSONホワイトスペースを含む入力（例：`  {"a":1}  `）は、**`JSON.parse()` 自身に判定させる**（JSON仕様上、値の前後のホワイトスペースは許容されるため、そのまま正しいJSONとして解析される） |

**入力を正規化しない理由 [必須B] B2：**

1. **JSONが許可するホワイトスペースは、スペース（U+0020）・水平タブ（U+0009）・改行（U+000A）・復帰（U+000D）の4種に限定される。** 全角スペース（U+3000）などをアプリ側で除去すると、**本来は不正なJSONを正しいJSONとして受理してしまう**
2. **前方の改行・空白を除去してから解析すると、`JSON.parse()` の `position` から算出した行・列が、利用者がテキストエリア上で見ている位置とずれる**（5-3）
3. JSON**検証**ツールである以上、入力を暗黙に修正・正規化せず、**原文そのものを判定対象とする**のが適切である

### 3-4. 空入力 [必須B] B2

| # | 仕様 |
|---|---|
| V5 | **入力が空、またはJSONホワイトスペースのみで構成される場合、エラーとしない** |
| V6 | 結果領域を空にし、「JSONを入力してください」等の案内を表示する |
| V7 | エラーメッセージを表示しない |
| V8 | コピー・保存ボタンを無効化する（8-3・9-4） |

**空判定の方法 [必須B]：**

```
判定に用いるホワイトスペースは、JSONが許可する4種のみとする
  U+0020（スペース） / U+0009（タブ） / U+000A（LF） / U+000D（CR）

例： /^[ \t\n\r]*$/.test(入力) が true なら「空」と判定する
```

| # | 仕様 |
|---|---|
| V9 | **この判定のために作った文字列を `JSON.parse()` へ渡さない。** 判定はあくまで判定に留め、解析には原文を渡す |
| V10 | **全角スペース（U+3000）を空判定のホワイトスペースに含めない** |

**V10の理由 [必須B]：** 全角スペースのみの入力を「空」として案内表示にしてしまうと、3-3の理由1と矛盾する。**全角スペースはJSONのホワイトスペースではないため、原文として `JSON.parse()` に渡し、構文エラーとして報告する**のが正しい。

**空入力をエラーにしない理由 [必須B]：** 起動直後と、入力を全消去した直後は必ず空になる。ここでエラーを出すと、正常な操作の途中でエラーが表示される。

### 3-5. 文字数上限 [必須B] B2/B11

**入力が 1,000,000 文字を超える場合、検証・整形を行わずエラーを表示する。**

- メッセージ：`入力が大きすぎます（100万文字まで）`
- テキストエリアに `maxlength` は設定しない（貼り付け時に無言で切り詰められ、利用者が気づけないため）
- 判定はJavaScript側で行う

（14章 U2）

## 4. JSON検証仕様

### 4-1. 検証方法 [必須A] A2

| # | 仕様 |
|---|---|
| C1 | **標準の `JSON.parse()` を用いる。自前のJSONパーサを実装しない** |
| C2 | `try / catch` で例外を捕捉する |
| C3 | 例外が発生しなければ「正しいJSON」、発生すれば「正しくないJSON」と判定する |
| C4 | `JSON.parse()` の戻り値を整形（6章）に用いる |

**`JSON.parse` を使う理由：** 標準APIであり外部ライブラリに当たらない。RFC 8259 準拠の判定をブラウザに委ねられ、自前パーサより正確である。

### 4-2. 許可する値の範囲 [必須B] B3

**トップレベルの型を制限しない。`JSON.parse()` が受け付けるものはすべて「正しいJSON」として扱う。**

| 入力 | 判定 |
|---|---|
| `{"a": 1}` | 正しい |
| `[1, 2, 3]` | 正しい |
| `"文字列"` | **正しい** |
| `123` | **正しい** |
| `true` / `false` | **正しい** |
| `null` | **正しい** |
| `{a: 1}`（キーが引用符なし） | 正しくない |
| `[1, 2, 3,]`（末尾カンマ） | 正しくない |
| `{'a': 1}`（シングルクォート） | 正しくない |
| `NaN` / `Infinity` / `undefined` | 正しくない |
| `// コメント` を含む | 正しくない |

**トップレベルをオブジェクト・配列に限定しない理由 [必須B]：** RFC 8259 ではトップレベルは任意の値でよく、`JSON.parse` もそれに従う。限定すると「`JSON.parse` は通るがアプリはエラー」という独自仕様になり、開発支援ツールとして混乱を招く。

（14章 U3）

### 4-3. 往復で入力と結果が一致しないケース [必須B] B13

**`JSON.parse` → `JSON.stringify` の往復では、入力と完全に同じ文字列に戻らない場合がある。これは仕様であり、不具合ではない。**

| # | ケース | 入力 | 整形結果 | 理由 |
|---|---|---|---|---|
| 1 | **数値の精度** | `12345678901234567890` | `12345678901234567000` | JavaScript の数値は倍精度浮動小数点であり、有効桁数を超える整数は丸められる |
| 2 | **数値の表記** | `1.0` / `1e3` / `0.50` | `1` / `1000` / `0.5` | 数値として解釈された後に再出力されるため |
| 3 | **重複キー** | `{"a":1,"a":2}` | `{"a": 2}` | 後に現れたキーが優先され、1つに統合される |
| 4 | **整数風キーの順序** | `{"b":1,"2":2,"1":3}` | `{"1": 3, "2": 2, "b": 1}` | JavaScript のオブジェクトは、整数インデックスとして解釈できるキーを昇順で先頭に並べる |
| 5 | **Unicodeエスケープ** | `"\u3042"` | `"あ"` | 解析時に実際の文字へ変換される |

**上記のうち3・4は、キー順の維持（6-3）に影響する。仕様書に明記しないと「並び順が壊れた」と誤認される。**

**これらをエラー・警告として表示しない [必須B]。** 正常な整形結果である。

（14章 U12）

## 5. エラー仕様

### 5-1. 表示する内容 [必須A] A3

エラー時、以下の3つを表示する。

| # | 内容 | 例 |
|---|---|---|
| M1 | **固定の見出し文言** | `JSONの構文が正しくありません` |
| M2 | **位置情報**（取得できた場合のみ） | `3行目 5列目付近` |
| M3 | **`JSON.parse()` の例外メッセージ（原文）** | `Unexpected token } in JSON at position 42` |

### 5-2. 例外メッセージの扱い [必須B] B4

**`JSON.parse()` の例外メッセージは、ブラウザごとに文言・形式が大きく異なる。**

| ブラウザ | メッセージの例 |
|---|---|
| Chrome / Edge | `Unexpected token } in JSON at position 42` |
| Safari | `Unexpected token '}'` |
| Firefox | `JSON.parse: unexpected character at line 3 column 5 of the JSON data` |

| # | 仕様 |
|---|---|
| M4 | **例外メッセージを「主メッセージ」として単独で表示しない。** 必ずM1の固定文言を主として示し、原文は補助情報として併記する |
| M5 | **原文の内容・形式を仕様化しない。** ブラウザが返した文字列をそのまま表示する |
| M6 | 原文の表示は `textContent` で行う |
| M7 | 原文を解析して独自の日本語メッセージに翻訳しない（[MVP外]） |

**M4の理由 [必須B] B4：** 原文は英語であり、ブラウザによっては位置情報も含まない。それだけでは「利用者が問題を把握できる」（A3）に届かない。一方、開発支援ツールとして原文は有用なため、補助として残す。

（14章 U4）

### 5-3. 位置情報の算出 [必須B] B4

**行・列は、例外メッセージから抽出した文字位置をもとに、`JSON.parse()` に渡した原文から自前で算出する。**

```
① 例外メッセージから文字位置を抽出する
   /position (\d+)/ に一致すれば、その数値を position とする

② position が取得できた場合、行と列を算出する
   line   = 原文の先頭から position までに含まれる \n の個数 + 1
   column = position - （position より前にある最後の \n の位置）
   ・いずれも1始まり

③ position が取得できない場合、位置情報を表示しない
   （M1 と M3 のみを表示する）
```

| # | 仕様 |
|---|---|
| M8 | **位置の算出には、テキストエリアの原文（`JSON.parse()` に渡した文字列そのもの）を用いる。** 空白除去などの加工を施した文字列を基準にしない |
| M9 | 位置は「付近」として示す（例：`3行目 5列目付近`）。`JSON.parse` が報告する位置は、実際の誤りの位置と1〜数文字ずれることがある |
| M10 | **位置が取得できないブラウザがあることを前提とし、取得できなくても表示が破綻しないこと** |
| M11 | 入力欄の該当箇所を選択・ハイライトする機能は実装しない（[MVP外]） |

**M8が必要な理由 [必須B] B4：** `JSON.parse()` が返す `position` は、渡した文字列の先頭からのオフセットである。**先頭の改行や空白を除去した文字列を渡すと、`position` の基準がテキストエリアの原文とずれ、算出した行番号が利用者の見ている行番号と一致しなくなる。** 3-3で原文をそのまま渡す仕様としているため、**原文を基準に算出すれば、行・列はテキストエリア上の位置とそのまま対応する。**

### 5-4. エラー時の結果領域 [必須B] B5

| # | 仕様 |
|---|---|
| M12 | **前回の整形結果を消し、結果領域を空にする** |
| M13 | コピー・保存ボタンを無効化する |
| M14 | 入力が正しいJSONに戻ったら、エラー表示を消して結果を表示する |

**M12の理由 [必須B] B5：** 古い整形結果を残すと、**現在の入力に対応しない内容が表示されたままになる**。利用者はそれをコピーしたり保存したりしかねない。開発支援ツールとして、表示内容と入力内容は常に対応していなければならない。

### 5-5. エラー一覧 [必須B]

| # | 条件 | 表示 |
|---|---|---|
| ER1 | `JSON.parse` が例外を投げた | M1 ＋ M2（取得できた場合）＋ M3 |
| ER2 | 入力が100万文字を超える（3-5） | `入力が大きすぎます（100万文字まで）` |
| ER3 | コピーに失敗した（7-4） | `コピーできませんでした` |
| ER4 | ファイル保存に失敗した（8-4） | `ファイルを保存できませんでした` |

### 5-6. 表示上の要件 [必須B]

| # | 仕様 |
|---|---|
| MS1 | エラー領域は、エラーが無いときも高さを確保し、表示のたびにレイアウトが上下に動かないこと |
| MS2 | 色だけでエラーを表現しない（文言を必ず表示する） |
| MS3 | エラー領域に `role="alert"` を付与する |
| MS4 | 正しいJSONのときは、エラー領域を空にする |
| MS5 | 例外メッセージ（原文）は、主メッセージより小さい文字・淡い色で補助的に示す |

## 6. 整形仕様

### 6-1. 整形方法 [必須A] A4

**`JSON.stringify(parsed, null, 2)` を用いる。**

| # | 仕様 |
|---|---|
| F1 | 第2引数（replacer）は `null` とする |
| F2 | 第3引数は数値の `2`（2スペースインデント） |
| F3 | 自前の整形処理は実装しない |

### 6-2. インデント [必須B] B6

**2スペース固定。** インデント幅の変更UIは実装しない（[MVP外]）。タブ文字は用いない。

（14章 U6）

### 6-3. キー順 [必須B] B6

**`JSON.parse` の結果のプロパティ順をそのまま用いる。並べ替えは行わない。**

ただし4-3の4（整数風キーの昇順前倒し）と3（重複キーの統合）により、**入力と順序が一致しない場合がある**。これは JavaScript の言語仕様であり、本アプリで補正しない。

### 6-4. 改行コード [必須B] B6

**`JSON.stringify` が出力する改行は `\n` のみである。** 変換・追加を行わない。

ファイル保存時も `\n` のまま出力する（CRLFに変換しない。8-2）。

### 6-5. 結果の表示 [必須A] A4

| # | 仕様 |
|---|---|
| F4 | `<pre>` 要素に表示する（空白とインデントを保持するため） |
| F5 | **折り返さない**（`white-space: pre`）。長い行は横スクロールで見る |
| F6 | 等幅フォントで表示する |
| F7 | 利用者は編集できない |
| F8 | 結果領域には**整形済みの内容のみ**を表示する。エラーメッセージを混在させない |

**F5で折り返さない理由 [必須B]：** JSONはインデントで階層を表す。折り返すと行頭の位置がずれ、階層構造が読み取れなくなる。

## 7. シンタックスハイライト仕様

### 7-1. 分類 [必須A] A5

**以下の6種を視覚的に区別する。**

| # | 分類 | 対象 | 例 |
|---|---|---|---|
| 1 | **キー** | `:` が続く文字列 | `"name"` |
| 2 | **文字列** | キー以外の文字列 | `"太郎"` |
| 3 | **数値** | 数値リテラル | `42`、`-1.5`、`1e3` |
| 4 | **boolean** | `true` / `false` | `true` |
| 5 | **null** | `null` | `null` |
| 6 | **記号** | `{` `}` `[` `]` `,` `:` | — |

**キーと文字列を別の色にする [必須A]。** 課題文が「キーや値などを視覚的に区別できる」としているため、この2つが同色では要件を満たさない。

### 7-2. 生成手順 [必須B] B7 ← セキュリティ上の必須事項

**以下の順序を厳守する。**

```
① JSON.stringify で整形済み文字列を得る

② 整形済み文字列を、正規表現でトークンに分割しながら走査する

③ 各トークンについて
   ・トークンのテキストを HTMLエスケープする
   ・分類に応じた <span class="..."> で包む

④ トークンに一致しなかった部分（記号・空白・改行）についても
   ・必ず HTMLエスケープしてから連結する

⑤ 組み立てた文字列を innerHTML に代入する
```

| # | 仕様 |
|---|---|
| H1 | **エスケープ対象は `&` `<` `>` `"` `'` の5文字。`&` を最初に処理する** |
| H2 | **`&` を先に処理しないと、後続の変換で生成した `&lt;` の `&` が二重変換される** |
| H3 | **マッチした部分だけでなく、マッチしなかった部分もエスケープする** |
| H4 | `innerHTML` に代入してよいのは、**この手順で自前生成した文字列のみ** |
| H5 | 整形済み文字列そのものを `innerHTML` に代入しない |

**H3が最重要である [必須B] B7：** 正規表現のマッチ部分だけをエスケープし、非マッチ部分を素通しする実装は容易に書けてしまう。**JSONの構造上、`<` は文字列値の中にしか現れないため一見安全に見えるが、キー名の中にも現れ得る。** マッチ・非マッチの両方をエスケープすること。

**エスケープを先に行い、その後に正規表現でトークン化する方式を採らない理由：** エスケープ後は `"` が `&quot;` になり、文字列リテラルを検出する正規表現が著しく複雑になる。**トークン化 → 各トークンをエスケープ → 組み立て、の順が安全かつ単純である。**

### 7-3. トークンの判定 [必須B]

整形済みJSON（`JSON.stringify` の出力）のみを対象とするため、以下で十分である。

| 分類 | 判定 |
|---|---|
| 文字列 | `"` で始まり、`\` によるエスケープを考慮して `"` で閉じるまで |
| キー | 上記の文字列のうち、**直後に（空白を挟んで）`:` が続くもの** |
| 数値 | `-?\d+(\.\d+)?([eE][+-]?\d+)?` |
| boolean | `true` または `false` |
| null | `null` |
| 記号 | 上記以外の `{` `}` `[` `]` `,` `:` |

参考となる正規表現（実装者はこれと同等の判定を行うこと）：

```
/"(?:\\.|[^"\\])*"(\s*:)?|-?\d+(?:\.\d+)?(?:[eE][+-]?\d+)?|\btrue\b|\bfalse\b|\bnull\b/g
```

**文字列の判定で `\\.` を含めること [必須B]。** これが無いと、`"a\"b"` のようなエスケープされた引用符で文字列の終端を誤判定する。

### 7-4. 配色 [必須B]

| # | 仕様 |
|---|---|
| H6 | 6分類それぞれに異なる見た目を与える（色のほか、太さの違いを併用してよい） |
| H7 | **すべての分類で、背景色とのコントラスト比 4.5:1 以上を確保する** |
| H8 | 記号は他より控えめな色にしてよいが、読めなくならないこと |
| H9 | 装飾のためのアニメーション・背景画像を使わない |

### 7-5. 大きな結果でのハイライト [必須B] B11

**整形済み文字列が 200,000 文字を超える場合、シンタックスハイライトを行わず、プレーンテキストとして表示する。**

- そのことを結果領域の上部に通知する（例：`結果が大きいため、シンタックスハイライトを省略しました`）
- 整形・コピー・保存は通常どおり動作する
- 通知は警告であり、エラーではない

**理由 [必須B]：** 20万文字を超えるとトークン化と大量の `<span>` 生成でDOMノード数が数万規模になり、描画が数秒単位で固まる。**A4（整形表示）とA6・A7（コピー・保存）は満たしたまま、A5のみを段階的に省略する。**

（14章 U7）

### 7-6. 安全性 [必須B] B12

**入力に含まれる `<script>alert(1)</script>` や `<img src=x onerror=alert(1)>` は、文字列としてそのまま表示されること。**

これは文字列値だけでなく、**キー名に含まれる場合も同様である**（13章 J）。

## 8. コピー仕様

### 8-1. コピー対象 [必須A] A6 / [必須B] B8

**コピーするのは、整形済みのプレーンなJSON文字列である。**

| # | 仕様 |
|---|---|
| P1 | **`JSON.stringify(parsed, null, 2)` の戻り値そのものをコピーする** |
| P2 | **ハイライト用の `<span>` タグを含むHTMLをコピーしない** |
| P3 | 結果領域の `innerHTML` や `outerHTML` を取得してコピーしない |
| P4 | **整形済み文字列を変数として保持しておき、それをコピーする**（DOMから読み戻さない） |

**P4の理由 [必須B] B8：** DOMの `textContent` から読み戻す実装でも見た目上は動くが、7-5でハイライトを省略した場合や、将来的な表示上の加工が入った場合に、コピー内容と整形結果が食い違う。**唯一の正となる文字列を1つ保持する。**

### 8-2. コピー方法 [必須B]

| # | 仕様 |
|---|---|
| P5 | **`navigator.clipboard.writeText()` を用いる** |
| P6 | `document.execCommand('copy')` によるフォールバックは実装しない |
| P7 | 失敗した場合は `try / catch`（または `Promise` の `catch`）で捕捉し、ER3のメッセージを表示する |

**[必須B] 動作環境に関する注記：** `navigator.clipboard` は**セキュアコンテキスト（httpsまたはlocalhost）でのみ利用できる**。`file://` で `index.html` を直接開いた場合、ブラウザによっては利用できない。**GitHub Pages（https）では動作する。** ローカル確認時にコピーが失敗しても、公開環境で動作すれば要件を満たす（13章 G-7）。

（14章 U8）

### 8-3. 実行できる条件 [必須B] B9

| 状態 | コピーボタン |
|---|---|
| 正しいJSONが整形されている | **有効** |
| 入力が空 | 無効（`disabled`） |
| JSONが正しくない | 無効（`disabled`） |
| 入力が文字数上限を超えている | 無効（`disabled`） |

**不正なJSONのときはコピーできない [必須B]。** コピーすべき整形結果が存在しないため。

### 8-4. 結果の通知 [必須B]

| # | 条件 | メッセージ |
|---|---|---|
| P8 | 成功 | `コピーしました` |
| P9 | 失敗 | `コピーできませんでした` |

| # | 仕様 |
|---|---|
| P10 | メッセージは数秒後に自動的に消してよい |
| P11 | 成功メッセージの領域に `role="status"`（または `aria-live="polite"`）を付与する |
| P12 | 失敗メッセージはエラー領域（`role="alert"`）に表示する |

### 9-1. 保存内容 [必須A] A7

**8-1と同じ、整形済みのプレーンなJSON文字列を保存する。** ハイライトHTMLを保存しない。

### 9-2. 保存方法 [必須B] B10

| # | 仕様 |

### 9-4. 実行できる条件 [必須B] B9

### 9-5. 失敗時 [必須B]

## 10. 大量データ時の考慮

### 10-1. 想定する規模 [必須B] B11

| 項目 | 値 |
|---|---|
| 入力の上限 | **1,000,000 文字**（3-5） |
| シンタックスハイライトの上限 | **200,000 文字**（7-5） |
| 快適に動作する目安 | **10万文字程度** |

### 10-2. 段階的な縮退 [必須B] B11

| 入力規模 | 挙動 |
|---|---|
| 〜20万文字（整形後） | 検証・整形・ハイライト・コピー・保存のすべてが動作する |
| 20万文字超〜100万文字 | **ハイライトのみ省略**。検証・整形・コピー・保存は動作する |
| 100万文字超 | 検証・整形を行わず、ER2 のエラーを表示する |

**A5（ハイライト）を先に落とし、A4・A6・A7 を維持する [必須B]。** ハイライトは表示上の補助であり、整形結果そのものより優先度が低い。

### 10-3. デバウンス [必須B] B11

**入力に 300ms のデバウンスを入れる。**

1文字ごとに `JSON.parse` → `JSON.stringify` → トークン化 → DOM生成を行うと、大きなJSONで入力が引っかかる。

（14章 U11）

### 10-4. 実装しない最適化

| # | 内容 | 理由 |
|---|---|---|
| 1 | Web Worker による解析 | 実装が複雑になる。10-2の縮退で十分 |
| 2 | 仮想スクロール | [MVP外]。`<pre>` の素朴な表示で足りる |
| 3 | 結果の差分更新 | 全体を作り直す方が単純で、誤りが混入しにくい |

### 10-5. 判定基準 [必須B]

**受入テストでは、次の3点で判定する。秒数は目標であり、厳格な合否条件としない。**

| # | 判定基準 |
|---|---|
| J1 | **長時間UIが固まらない**（入力後、画面が応答しないまま放置される状態にならない） |
| J2 | **入力が実用不能なほど引っかからない**（文字を続けて打てる） |
| J3 | **20万文字を超える整形結果でハイライトが省略され、その旨が通知される**（客観的に確認できる） |

**J3のみ厳格な合否条件とする。**

### 14-1. 入力の正規化に関する確定（3-3・5-3）

**検証・整形の前に入力を正規化しない。テキストエリアの原文をそのまま `JSON.parse()` に渡す。**

当初案では「前後の空白（半角・全角・改行・タブ）を除去してから解析する」としていたが、以下の理由により**正規化しない仕様に確定した**。

| # | 理由 |
|---|---|
| 1 | **JSONが許可するホワイトスペースは4種（U+0020 / U+0009 / U+000A / U+000D）に限定される。** 全角スペース等をアプリ側で除去すると、本来不正なJSONを正しいJSONとして受理してしまう |
| 2 | **前方の改行・空白を除去してから解析すると、`JSON.parse()` の `position` から算出した行・列が、利用者がテキストエリア上で見ている位置とずれる** |
| 3 | JSON**検証**ツールである以上、入力を暗黙に修正・正規化せず、原文そのものを判定するのが適切である |

**空判定のみ例外とする。** 入力が空またはJSONホワイトスペースのみかを確認する処理は設けてよいが、**その判定用の文字列を `JSON.parse()` へ渡さない**（3-4 V9）。空判定に全角スペースを含めない（3-4 V10）。

## 付録：実装者へ渡す際の注意事項

1. **出力ファイルは `apps/part08-json-formatter/` 配下の `index.html` / `style.css` / `app.js` の3つのみ**
2. **フレームワーク・外部ライブラリ・CDN・外部API・Webフォントを使わない**
3. **本仕様書2-2の[MVP外]機能を追加しない。** 思いついても実装せず、提案にとどめる
4. **構文チェックは標準の `JSON.parse()` を使う。自前パーサを実装しない**
5. **トップレベルの型を制限しない。** `"文字列"` `123` `true` `null` も正しいJSONとして扱う
6. **整形は `JSON.stringify(parsed, null, 2)`。** 自前の整形処理を書かない
7. **整形ボタンを設けない。** 入力に追従して自動実行し、300msデバウンスを入れる
8. **`compositionstart`〜`compositionend` の間は処理を実行しない**（IME対策）
9. **入力を正規化しない。テキストエリアの原文をそのまま `JSON.parse()` に渡す。** 前後の空白・改行・タブを除去しない。全角スペース等も除去・変換しない
9b. **空判定のみ、JSONホワイトスペース4種（U+0020 / U+0009 / U+000A / U+000D）で行ってよい。全角スペースを含めない。判定用に作った文字列を `JSON.parse()` へ渡さない**
10. **空入力はエラーにしない。** 結果領域を空にし、案内を表示してボタンを無効化する
11. **エラーの主メッセージは日本語固定。** `JSON.parse` の原文は補助として併記し、原文の内容に依存した処理を書かない
12. **行・列は、`JSON.parse()` に渡した原文を基準に自前で算出する。** 加工した文字列を基準にしない（行番号がテキストエリア上の位置とずれる）。位置が取得できないブラウザでも破綻しないこと
13. **エラー時は前回の整形結果を消す**（古い結果を残さない）
14. **ハイライトは「トークン化 → 各トークンをエスケープ → span で包む → 連結」の順。** エスケープを先に全体へ適用してからトークン化しない
15. **正規表現の非マッチ部分（記号・空白・改行）も必ずエスケープする**
16. **エスケープ対象は `&` `<` `>` `"` `'` の5文字。`&` を最初に処理する**
17. **文字列の判定に `\\.` を含める**（`"a\"b"` で終端を誤判定しないため）
18. **キーと文字列値を別の色にする**
19. **整形後が20万文字を超える場合、ハイライトを省略して通知する。** 整形・コピー・保存は動作させる
20. **コピー・保存の対象は、変数として保持した整形済みプレーン文字列。** DOMから読み戻さない。`innerHTML` を渡さない
21. **`navigator.clipboard.writeText()` を使う。`execCommand` のフォールバックは実装しない。失敗を捕捉して通知する**
22. **保存は `Blob` ＋ `<a download>`、MIMEは `application/json`、BOMを付けない、`URL.revokeObjectURL()` で解放する**
23. **不正JSON・空入力・上限超過のときはコピー・保存ボタンを `disabled` にする**
24. **結果領域に `aria-live` を付けない。** エラー領域は `role="alert"`、コピー通知は `role="status"`
25. **テキストエリア内でTabキーを奪わない**（タブ文字挿入の独自処理を実装しない）
26. **`outline: none` を単独で指定しない**
27. **テキストエリアのフォントサイズは16px以上**（iOSの自動ズーム防止）
28. **幅768px以上で2ペイン、768px未満で縦積み。375pxでページ全体に横スクロールを出さない**
29. **Part 1〜7 のコードを流用せず、Part 9 以降を見越した共通化もしない**

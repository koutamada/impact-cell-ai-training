## 3. エンコード／デコード仕様

### 3-1. 採用するAPI [必須A] A2/A3 / [必須B] B1

| 操作 | 使用するAPI |
|---|---|
| エンコード | **`encodeURIComponent()`** |
| デコード | **`decodeURIComponent()`** |

**`encodeURIComponent()` を採用する理由 [必須B] B1：**

| # | 理由 |
|---|---|
| 1 | 課題文は「URLそのもの」ではなく**「URLなどで使用する文字列」**の変換を求めている。クエリ値・パス要素といった**文字列単位**の用途に合う |
| 2 | `encodeURI()` は `? & = # / : @ $ + , ;` などの予約文字を**エンコードしない**。クエリ値として使うと `&` や `=` がパラメータ区切りと解釈され、壊れる |
| 3 | 開発作業で必要になる場面の大半は、パラメータ値のエンコードである |

**`encodeURI()` との切替UIは実装しない**（[MVP外]。2-2 の1）。課題文に選択の要求がないため。

### 3-2. エンコードの挙動 [必須A] A2

`encodeURIComponent()` は、**以下の文字をエンコードしない。**

```
A-Z  a-z  0-9  -  _  .  !  ~  *  '  (  )
```

上記以外はすべて `%XX` 形式（UTF-8バイト列の16進表記）に変換される。

| 入力 | 出力 |
|---|---|
| `hello world` | `hello%20world` |
| `あいう` | `%E3%81%82%E3%81%84%E3%81%86` |
| `a&b=c?d` | `a%26b%3Dc%3Fd` |
| `/` | `%2F` |
| `%` | `%25` |
| `+` | `%2B` |
| `#` | `%23` |
| `!` `'` `(` `)` `*` `~` | **変換されない**（そのまま） |

**`!` `'` `(` `)` `*` `~` がエンコードされない点を仕様書に明記する [必須B]。** RFC 3986 ではこれらの一部が予約文字（sub-delims）だが、**`encodeURIComponent` は仕様上これらを残す。** 明記しないと「エンコード漏れ」と誤認される。

**この挙動を補正しない [必須B]。** 標準APIの結果をそのまま出力する。

### 3-3. デコードの挙動 [必須A] A3

| 入力 | 出力 |
|---|---|
| `%E3%81%82` | `あ` |
| `%20` | 半角スペース |
| `%2F` | `/` |
| `%3F` | `?` |
| `%26` | `&` |
| `%25` | `%` |
| `hello%20world` | `hello world` |

### 3-4. `+` の扱い [必須B] B2 ← 必ず確認すべき仕様

**`+` は `+` のまま扱い、空白へ自動変換しない。**

| 操作 | 入力 | 出力 |
|---|---|---|
| デコード | `a+b` | **`a+b`**（空白にしない） |
| デコード | `a%2Bb` | `a+b` |
| エンコード | `a+b` | `a%2Bb` |
| エンコード | `a b` | `a%20b` |

**この方針とする理由 [必須B] B2：**

| # | 理由 |
|---|---|
| 1 | `decodeURIComponent("a+b")` は標準仕様上 `a+b` を返す。**標準APIの挙動をそのまま採用する** |
| 2 | `+` を空白とみなすのは `application/x-www-form-urlencoded`（HTMLフォーム送信）の規則であり、**URLエンコード一般の規則ではない** |
| 3 | 自動変換すると、本当に `+` を含む文字列（数式・電話番号・メールアドレスの別名など）が壊れる |

**フォームURLエンコード専用の変換は実装しない**（[MVP外]。2-2 の7）。

**この挙動は利用者が誤解しやすいため、受入テストに明示的に含める**（14章 C-10）。

### 3-5. 変換の前後で入力を加工しない [必須B]

| # | 仕様 |
|---|---|
| T1 | 入力文字列の前後の空白を除去しない |
| T2 | 改行を除去・変換しない（改行は `%0A` としてエンコードされる） |
| T3 | Unicode正規化（NFC/NFKC等）を行わない |
| T4 | 大文字小文字を変換しない |

**T1〜T4の理由 [必須B]：** 開発ツールとして、**入力した文字列がそのまま変換されること**が信頼の前提である。暗黙の加工は、変換結果が合わない原因を追いにくくする。

**`%2f` のような小文字の16進表記もデコードできる**（標準APIの挙動）。エンコード時の出力は大文字（`%2F`）になる。

## 4. 入力仕様

### 4-1. 入力欄 [必須A] A1

| # | 仕様 |
|---|---|
| I1 | **`<textarea>` を用いる** |
| I2 | 等幅フォントで表示する（Webフォントは使わない） |
| I3 | 折り返す（`wrap="soft"`。既定のまま） |
| I4 | `spellcheck="false"` を指定する |
| I5 | `maxlength` を設定しない |
| I6 | 初期状態は空。プレースホルダで入力例を示してよい |

### 4-2. 実行方式 [必須A] A2/A3 / [必須B]

**「エンコード」「デコード」の2ボタンによる明示実行とする。リアルタイム変換は実装しない。**

| # | 仕様 |
|---|---|
| T5 | 入力欄の下（またはPCでは右）に「エンコード」「デコード」の2ボタンを置く |
| T6 | ボタンを押した時点で変換を実行する |
| T7 | 入力の変更では変換を実行しない |
| T8 | デバウンス処理は不要（リアルタイム変換をしないため） |
| T9 | IME入力中の特別な処理は不要（変換はボタン押下時のみのため） |

**明示実行とする理由 [必須B]：** 課題文が「エンコードを**実行できる**」「デコードを**実行できる**」としており、**2つの異なる操作を利用者が選ぶ**構造である。リアルタイム変換では、どちらを実行するかを決められない。

### 4-3. 空入力 [必須B] B6

**空文字の変換は正常な操作として扱い、エラーにしない。結果も空文字とする。**

| # | 仕様 |
|---|---|
| I7 | 入力が空文字のとき、エンコード・デコードのいずれもエラーにしない |
| I8 | 結果欄を空にする |
| I9 | エラーメッセージを表示しない |
| I10 | **コピーボタンを無効化する**（8-3） |
| I11 | 「エンコード結果」等の操作表示（5-4）は更新してよい |

**エラーにしない理由 [必須B] B6：** `encodeURIComponent("")` も `decodeURIComponent("")` も空文字を返し、例外を投げない。**標準APIが正常に処理するものをアプリ側でエラーにするのは、開発ツールとして不自然である。** 起動直後と入力を全消去した直後は必ず空になるため、そこでエラーが出るのも不適切である。

**UI上の分かりやすさとの整合 [必須B]：** 空入力で何も起きないと「ボタンが効いていない」と見えるおそれがあるため、**コピーボタンの無効化**と**操作表示の更新**により、実行されたことが分かるようにする。

### 4-4. 入力の文字数上限 [必須B]

**上限を設けない。**

**理由：** リアルタイム変換を行わず、変換はボタン押下時の1回のみである（4-2 T7）。`encodeURIComponent` の処理は文字数に対して線形であり、極端に大きな入力でも一時的に待たされるだけで、継続的な負荷にはならない。

（16章 U12）

## 5. 結果表示仕様

### 5-1. 結果欄 [必須A] A4 / [必須B]

**読み取り専用の `<textarea>` を用いる。**

| # | 仕様 |
|---|---|
| R1 | `<textarea readonly>` とする |
| R2 | 利用者は編集できない |
| R3 | **折り返す**（`wrap="soft"`） |
| R4 | 等幅フォントで表示する |
| R5 | 内容が長い場合、結果欄の内部で縦スクロールする |
| R6 | 利用者が手動で選択・コピーすることも妨げない |

**`<output>` ではなく `<textarea readonly>` を採用する理由 [必須B]：**

| # | 理由 |
|---|---|
| 1 | エンコード結果は**空白を含まない非常に長い1行**になりやすい（`%E3%81%82%E3%81%84...`）。`textarea` は折り返し・内部スクロール・範囲選択がネイティブで機能する |
| 2 | 開発ツールとして、**結果を手動で部分選択したい**場面がある |
| 3 | `readonly` により編集は防げる |

### 5-2. 折り返し [必須B]

**結果は折り返す。折り返さずに横スクロールさせない。**

**理由：** エンコード結果には空白が含まれないため、折り返さないと**1行が画面幅を大きく超え、横スクロールが常態化する**。375px幅では特に読めなくなる。

**折り返しは表示上のものであり、コピー内容に改行を混入させない [必須B]**（8-1）。

### 5-3. 変換エラー時の扱い [必須B] B5 ← 重要

**変換（エンコード／デコード）がエラーになった場合、結果欄を空にする。前回成功した結果を残さない。**

| # | 仕様 |
|---|---|
| R7 | 変換エラー時は結果欄を空文字にする |
| R8 | コピーボタンを無効化する |
| R9 | 操作表示（5-4）もエラーであることが分かる状態にする |

**古い結果を残さない理由 [必須B] B5：** 残すと、**現在の入力に対応しない結果が表示されたままになる。** 利用者はそれをコピーして使う可能性があり、開発ツールとしては危険である。**表示内容と入力内容は常に対応していなければならない。**

**本節は変換エラーにのみ適用する [必須B]。** **コピー失敗にはこの扱いを適用しない**（6-6）。コピー失敗は変換結果の正しさとは無関係であり、結果を消してはならない。

### 5-4. 最後に実行した操作の表示 [必須B] B7

**結果欄のラベル（または直上）に、最後に実行した操作を表示する。**

| 状態 | 表示例 |
|---|---|
| 未実行 | `結果` |
| エンコード成功 | `エンコード結果` |
| デコード成功 | `デコード結果` |
| エラー | `結果`（エラーはメッセージ領域に表示。6章） |

| # | 仕様 |
|---|---|
| R10 | 表示は1行のテキストとし、`textContent` で設定する |
| R11 | 装飾・アイコン・アニメーションを追加しない |

**必要な理由 [必須B] B7：** ボタンが2つあり、結果欄は共通である。**どちらを押した結果が表示されているか分からないと、エンコード結果をデコード結果と誤読する。** 特に、`%25` のようにエンコードとデコードで見た目が似た結果になる場合に問題となる。

## 6. エラー仕様

### 6-1. エラーとなるケース [必須A] A5 / [必須B] B3

#### デコード時

`decodeURIComponent()` が `URIError` を投げるケース。

| # | 入力 | 理由 |
|---|---|---|
| 1 | `%` | パーセントの後に16進2桁がない |
| 2 | `%G1` | 16進として不正な文字 |
| 3 | `%E3%81` | UTF-8シーケンスが不完全（3バイト必要なところ2バイト） |
| 4 | `%C0%80` | 冗長なUTF-8符号化（overlong） |
| 5 | `%FF` | UTF-8として不正なバイト |
| 6 | `%ED%A0%80` | サロゲート領域のコードポイント |
| 7 | `abc%` | 文字列末尾の不完全なパーセント |

#### エンコード時 [必須B] B4 ← 見落としやすい

**エンコードでも例外が発生し得る。**

| # | 入力 | 理由 |
|---|---|---|
| 1 | 孤立したサロゲート（`\uD800` 単独など） | `encodeURIComponent` が `URIError` を投げる |

**エンコードは常に成功すると仮定してはならない [必須B] B4。** 孤立サロゲートは、他のツールからのコピー＆ペーストや、壊れたデータの調査時に実際に入力され得る。**エンコード処理も `try / catch` で囲む。**

### 6-2. エラーメッセージ [必須A] A5

**ブラウザ依存の例外文をそのまま主メッセージにしない。** 利用者向けには安定した文言を用いる。

| # | 条件 | 主メッセージ |
|---|---|---|
| E1 | デコードに失敗した | **`URLデコードできません。入力文字列を確認してください。`** |
| E2 | エンコードに失敗した | **`URLエンコードできません。入力文字列を確認してください。`** |
| E3 | コピーに失敗した | **`コピーできませんでした。`** |
| E4 | コピー対象が空 | （8-3によりボタンが無効のため発生しない） |

### 6-3. エラー種別の区別 [必須B] B3

**「不正なパーセントエンコード」と「不完全なUTF-8シーケンス」を区別しない。両方とも E1 の同一メッセージとする。**

| # | 理由 |
|---|---|
| 1 | **`decodeURIComponent` はどちらの場合も同じ `URIError` を投げ、種別を判別する情報を返さない** |
| 2 | 区別するには**自前のパーセントデコード解析を実装する**必要があり、「自前の文字コード変換を実装しない」方針（2-3）に反する |
| 3 | 利用者にとっての対処は「入力文字列を確認する」で同じであり、区別の実益が乏しい |

**一方、Clipboard API の失敗（E3）は区別する [必須B]。** 原因も対処もまったく異なる（入力の問題ではなく実行環境の問題）ため、同じメッセージにすると利用者が入力を疑ってしまう。

（16章 U9）

### 6-4. 例外原文の補助表示 [必須B]

**`URIError` の `message` を、補助情報として併記する。**

| # | 仕様 |
|---|---|
| E5 | 主メッセージ（6-2）を主として示し、原文はその下に補助的に表示する |
| E6 | **原文の内容・形式を仕様化しない。** ブラウザが返した文字列をそのまま表示する |
| E7 | 原文の表示は `textContent` で行う |
| E8 | 原文を解析して独自メッセージに翻訳しない（[MVP外]） |
| E9 | 主メッセージより小さい文字・淡い色で表示する |

**補助表示を残す理由 [必須B]：** 開発支援ツールであり、`URI malformed` のような原文は原因調査の手がかりになる。ただし英語かつブラウザ依存であるため、単独では A5 を満たさない。

（16章 U10）

### 6-5. 表示上の要件 [必須B]

| # | 仕様 |
|---|---|
| MS1 | メッセージ領域は、メッセージが無いときも高さを確保し、表示のたびにレイアウトが上下に動かないこと |
| MS2 | 色だけでエラーを表現しない（文言を必ず表示する） |
| MS3 | エラー領域に `role="alert"` を付与する |
| MS4 | 変換が成功したら、エラーメッセージを消す |
| MS5 | **変換エラー時のみ**、入力欄に `aria-invalid="true"` を設定し、変換成功時に解除する。**コピー失敗では設定しない**（6-6） |

### 6-6. 変換エラーとコピー失敗の状態遷移 [必須B] ← 必ず分けて実装する

**変換エラーとコピー失敗は、性質がまったく異なる。同じメッセージ領域を使う場合でも、状態の扱いを分ける。**

| # | 変換エラー | コピー失敗 |
|---|---|---|
| 原因 | **入力文字列**が不正 | **実行環境**（セキュアコンテキストでない、権限拒否など） |
| 変換結果の正しさ | 結果が存在しない | **結果は正しく生成されている** |
| 利用者の対処 | 入力を直す | 再試行する、または手動でコピーする |

#### 状態の扱い [必須B]

| 対象 | 変換エラー時 | **コピー失敗時** |
|---|---|---|
| 結果欄の内容 | **空にする**（5-3 R7） | **消さない。正常な変換結果をそのまま維持する** |
| コピーボタン | **無効化する**（8-3） | **有効のまま維持する**（再試行できる） |
| 入力欄の `aria-invalid` | **`true` を設定する**（MS5） | **設定しない** |
| 結果ラベル（5-4） | エラーが分かる状態にする | **`エンコード結果` / `デコード結果` を維持する** |
| メッセージ | `URLデコードできません。…` / `URLエンコードできません。…` | `コピーできませんでした。` |
| 変換の成功状態 | 破棄する | **破棄しない** |

**コピー失敗で変換成功状態を破棄しない理由 [必須B]：** 例えば `hello world` をエンコードして `hello%20world` が正しく生成された後、Clipboard API だけが失敗した場合、**変換結果そのものは正しい。** これを消すと、利用者は正しい結果を失い、変換をやり直す必要が生じる。さらに、**手動での選択コピーという回避手段まで奪ってしまう。**

#### アクセシビリティ上の扱い [必須B]

| # | 仕様 |
|---|---|
| CE1 | **変換エラーは入力欄と `aria-describedby` で関連付ける**（AC9） |
| CE2 | **コピー失敗は入力内容のエラーではないため、入力欄のエラー説明として扱わない。** `aria-describedby` による入力欄との関連付けを行わない |
| CE3 | 同じメッセージ領域を使ってよいが、**表示中のメッセージがどちらの種類かを内部状態として保持し、`aria-invalid` と `aria-describedby` の設定を出し分ける** |
| CE4 | コピー失敗用に新しいUI要素・領域を追加しない |

**CE2・CE3の理由 [必須B]：** 支援技術の利用者にとって、`aria-invalid` と `aria-describedby` は「この入力欄に問題がある」という意味を持つ。コピー失敗でこれらを設定すると、**入力に問題があると誤って伝わり、利用者が入力を直そうとしてしまう。**

#### メッセージの遷移 [必須B]

| # | 仕様 |
|---|---|
| CE5 | 変換に成功したら、変換エラーのメッセージを消す（MS4） |
| CE6 | コピーに成功したら、コピー失敗のメッセージを消す |
| CE7 | **コピー失敗のメッセージは、変換エラーのメッセージを消さない前提で扱う。** ただし同一領域を使う場合、後から発生した方を表示してよい |
| CE8 | いずれの場合も、**表示中のメッセージと内部状態（`aria-invalid` の有無）を一致させる** |

## 7. Unicode仕様

### 7-1. 方針 [必須B]

**JavaScript標準APIがUTF-8パーセントエンコードを行うことを前提とし、自前の文字コード変換を実装しない。**

`TextEncoder` / `TextDecoder` による独自実装、バイト列の手組み、`escape` / `unescape`（非推奨）は使用しない。

### 7-2. 対応する文字 [必須A] A2/A3

| 種別 | 例 | 動作 |
|---|---|---|
| 日本語 | `あいう` | `%E3%81%82%E3%81%84%E3%81%86` |
| 全角文字 | `ＡＢＣ` `！` | UTF-8としてエンコードされる。**半角に正規化しない** |
| 絵文字（サロゲートペア） | `😀` | `%F0%9F%98%80` |
| ZWJ結合絵文字 | `👨‍👩‍👧` | 各コードポイントがエンコードされる（ZWJ は `%E2%80%8D`） |
| 結合文字 | `か`＋`゛`（U+3099） | 各コードポイントがエンコードされる。**合成・分解を行わない** |
| 国旗絵文字 | `🇯🇵` | 地域表示子2つがエンコードされる |

### 7-3. 往復の一致 [必須B]

**エンコードした結果をデコードすると、元の文字列に完全に戻ること。**

| # | 仕様 |
|---|---|
| U1 | エンコード → デコードで元の文字列と一致する |
| U2 | Unicode正規化を行わないため、`か`＋`゛`（2コードポイント）は往復後も2コードポイントのまま |
| U3 | 見た目が同じでも正規化形が異なる文字列は、別の文字列として扱われる |

### 7-4. 孤立サロゲート [必須B] B4

**孤立したサロゲート（対になっていない `\uD800`〜`\uDFFF`）はエンコードできず、`URIError` になる。** 6-1の通りエラーとして扱う。

## 8. コピー仕様

### 8-1. コピー対象 [必須A] A4 / [必須B] B8

**コピーするのは、変換結果のプレーンな文字列である。**

| # | 仕様 |
|---|---|
| P1 | **変換結果を変数として保持し、それをコピーする** |
| P2 | **結果欄のDOMから読み戻さない** |
| P3 | 表示上の折り返し（5-2）による改行を混入させない |
| P4 | HTMLタグを含めない |

**P1・P2の理由 [必須B] B8：** DOMの `value` から読み戻す実装でも見た目上は動くが、**唯一の正となる文字列を1つ保持する**方が、表示上の加工が将来入った場合にも食い違わない。

### 8-2. コピー方法 [必須B]

| # | 仕様 |
|---|---|
| P5 | **`navigator.clipboard.writeText()` を用いる** |
| P6 | **`document.execCommand('copy')` によるフォールバックを実装しない** |
| P7 | 失敗した場合は `catch` で捕捉し、E3 のメッセージを表示する |
| P8 | **失敗を黙って無視しない** |

**フォールバックを実装しない理由 [必須B]：** `document.execCommand` は非推奨APIであり、対応対象ブラウザ（最新 Chrome / Safari）では `navigator.clipboard` が利用できる。**不要な互換処理を増やさない方針**（基本方針）に従う。

**[必須B] 動作環境に関する注記：** `navigator.clipboard` は**セキュアコンテキスト（https または localhost）でのみ利用できる**。`file://` で `index.html` を直接開いた場合、ブラウザによっては失敗する。**GitHub Pages（https）では動作する。** ローカル確認時に失敗しても、公開環境で動作すれば要件を満たす（14章 F-7）。

（16章 U11）

### 8-3. 実行できる条件 [必須B] B9

| 状態 | コピーボタン |
|---|---|
| 変換に成功し、結果が1文字以上ある | **有効** |
| 未実行（起動直後） | 無効（`disabled`） |
| 結果が空文字（空入力を変換した） | 無効（`disabled`） |
| 変換がエラーになった | 無効（`disabled`） |

**空の結果をコピーできないようにする理由 [必須B]：** クリップボードを空文字で上書きすると、利用者が直前にコピーしていた内容を失う。

### 8-4. 結果の通知 [必須B]

| # | 条件 | メッセージ |
|---|---|---|
| P9 | 成功 | `コピーしました` |
| P10 | 失敗 | `コピーできませんでした。` |

| # | 仕様 |
|---|---|
| P11 | 成功メッセージは数秒後に自動的に消してよい |
| P12 | 成功メッセージの領域に `role="status"`（または `aria-live="polite"`）を付与する |
| P13 | 失敗メッセージはエラー領域（`role="alert"`）に表示する |
| P14 | **コピーに失敗しても、結果欄の内容・コピーボタンの有効状態・結果ラベルを維持する**（6-6） |
| P15 | **コピー失敗時に入力欄へ `aria-invalid` を設定しない**（6-6 CE2） |
| P16 | **コピー失敗後、同じ結果に対してもう一度コピーを実行できる**（再試行可能） |

### 16-1. 変換エラーとコピー失敗の状態遷移の明確化

当初案では、5-3（エラー時に結果欄を空にする・コピーボタンを無効化する）と MS5（`aria-invalid` を設定する）が、**変換エラーとコピー失敗のどちらに適用されるかを区別していなかった。**

**Clipboard API の失敗は、変換結果や入力内容のエラーではない。** 例えば `hello world` をエンコードして `hello%20world` が正しく生成された後、Clipboard API だけが失敗した場合、**変換結果そのものは正しい状態である。**

**依頼者判断により、以下で確定した**（6-6）。

| 対象 | 変換エラー時 | コピー失敗時 |
|---|---|---|
| 結果欄の内容 | 空にする | **消さない** |
| コピーボタン | 無効化する | **有効のまま維持する**（再試行可能） |
| 入力欄の `aria-invalid` | `true` を設定する | **設定しない** |
| 結果ラベル | エラーが分かる状態にする | **維持する** |
| 変換の成功状態 | 破棄する | **破棄しない** |

**アクセシビリティ上の扱いも分離した**（AC9・AC9b）。

- **変換エラー**は入力欄と `aria-describedby` で関連付ける
- **コピー失敗**は入力内容のエラーではないため、入力欄のエラー説明として扱わない

**コピー失敗用に新しいUI要素は追加しない。** 同じメッセージ領域を使い、**内部状態で種別を保持して `aria-invalid` と `aria-describedby` の設定を出し分ける**（CE3）。

**この分離が必要な理由：** `aria-invalid` と `aria-describedby` は支援技術に「この入力欄に問題がある」と伝える。コピー失敗でこれらを設定すると、**入力に問題があると誤って伝わり、利用者が正しい入力を直そうとしてしまう。** また、結果を消すと**手動での選択コピーという回避手段まで奪う。**

8. **エンコードも `try / catch` で囲む。** 孤立サロゲートで `URIError` になる
9. **変換エラー時は結果欄を空にし、コピーボタンを無効化し、入力欄に `aria-invalid="true"` を設定する。** 前回の結果を残さない
9b. **コピー失敗時は上記のいずれも行わない。** 結果欄の内容・コピーボタンの有効状態・結果ラベルを維持し、`aria-invalid` を設定しない（再試行できる状態を保つ）
9c. **`aria-describedby` による入力欄との関連付けは、変換エラーのメッセージにのみ適用する。** コピー失敗のメッセージは入力欄のエラー説明として扱わない
9d. **同じメッセージ領域を使ってよいが、表示中のメッセージが変換エラーかコピー失敗かを内部状態として保持し、`aria-invalid` と `aria-describedby` を出し分ける。** コピー失敗用に新しいUI要素を追加しない
10. **空入力はエラーにしない。結果も空文字とし、コピーボタンを無効化する**
11. **エラーの主メッセージは日本語固定。** 例外の原文は補助として併記し、原文の内容に依存した処理を書かない
12. **デコードのエラー種別を区別しない。** Clipboard失敗のみ別メッセージ
13. **結果欄のラベルに「エンコード結果」「デコード結果」を出し分ける**
14. **コピー対象は変数として保持した結果文字列。** DOMから読み戻さない
15. **`navigator.clipboard.writeText()` を使う。`execCommand` のフォールバックは実装しない。失敗を捕捉して通知する**
15b. **コピー失敗によって変換成功状態を破棄しない**（9b・9c）
16. **結果が空・未実行・エラーのときはコピーボタンを `disabled` にする**
17. **結果欄は `<textarea readonly>` で折り返す。** ページ全体を横スクロールさせない
18. **結果欄に `aria-live` を付けない。** エラーは `role="alert"`、コピー通知は `role="status"`
19. **`innerHTML` を使用しない。** 結果は `value`、メッセージは `textContent` で設定する
20. **テキストエリア内でTabキーを奪わない**（タブ文字挿入の独自処理を実装しない）
21. **`outline: none` を単独で指定しない**

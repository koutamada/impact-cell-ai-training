## 1. 要件整理

### 1-1. クリア条件 → 必須要件への分解

| ID | 必須要件 | 由来 |
|---|---|---|
| A1 | 長さ・重量・温度の3カテゴリの変換に対応する | 「最低3カテゴリの変換に対応する」＋基本方針 |
| A2 | 各カテゴリで最低5種類の単位を扱える | 「各カテゴリにつき最低5種類の単位」 |
| A3 | 数値を変更すると変換結果がリアルタイムに更新される | 「リアルタイムに更新される」 |
| A4 | 変換カテゴリ・変換元単位・変換先単位を選択できる | 「カテゴリと変換元・変換先の単位を選択できる」 |
| A5 | 不正な入力値を検出し、適切なメッセージを表示する | 「不正な入力値を検出し、適切なメッセージを表示する」 |
| A6 | 変換元と変換先に同じ単位を選択できる。その場合は同値を表示する | 基本方針 |
| A7 | カテゴリ変更時に、そのカテゴリの単位一覧へ切り替わる | 基本方針 |
| A8 | PC・スマートフォン双方で利用できるレスポンシブUI | 基本方針 |

### 1-2. [必須B] 補足仕様の一覧

| ID | 補足仕様 | 必要な理由 |
|---|---|---|
| B1 | 入力を受け付ける数値形式を正規表現レベルで定義すること | A5の「不正」の境界が決まらないと、検出も受入テストもできない |
| B2 | 「未入力・入力途中」と「不正入力」を区別すること | A3のリアルタイム更新では、`-` や `.` を打った瞬間にエラーが出る。区別しないと入力中ずっと赤字が出る |
| B3 | 各カテゴリの基準単位と換算係数を確定すること | A1・A2の変換ロジックそのもの |
| B4 | 変換の計算順序を固定すること | 浮動小数点誤差の出方が実装者ごとに変わるのを防ぐ |
| B5 | 結果の丸めと文字列化のルールを1つに定めること | 単位変換は極小値・極大値が容易に発生する |
| B6 | 同一単位選択時に変換計算を通さないこと | A6の「同値を表示する」を誤差なく保証するため |
| B7 | リアルタイム更新の発火契機を列挙すること | A3・A4の組み合わせ。単位変更時に更新されないと成立しない |
| B8 | 全角数字を半角へ正規化すること | 日本語入力環境では全角数字が入りやすく、正規化しないと正当な入力が不正扱いになる |
| B9 | IME変換中はエラーメッセージを出さないこと | A3のリアルタイム更新と日本語入力が競合し、未確定文字列でエラーが点滅する |
| B10 | 入力値の絶対値上限を定めること | 上限が無いと結果が `Infinity` になり、表示が破綻する |

## 5. 各単位の変換仕様

### 5-1. 変換の基本方式 [必須B] B3/B4

**長さ・重量は「基準単位への換算係数」方式、温度は「基準単位への変換式」方式とする。**

```
① 変換元の値を基準単位の値に変換する
② 基準単位の値を変換先の単位に変換する
```

**計算順序を固定する [必須B] B4：**

```
長さ・重量：
  base   = value * fromFactor
  result = base / toFactor

  ・「value * (fromFactor / toFactor)」の形にしない
    （係数同士の除算を先に行うと誤差の出方が変わる）
```

### 5-2. 長さの換算係数（基準単位：m） [必須A]

| 単位 | 1単位あたりのm数（`factor`） | 備考 |
|---|---|---|
| mm | `0.001` | |
| cm | `0.01` | |
| m | `1` | 基準単位 |
| km | `1000` | |
| in | `0.0254` | 国際インチ（定義値・厳密） |
| ft | `0.3048` | 国際フィート（定義値・厳密） |

### 5-3. 重量の換算係数（基準単位：kg） [必須A]

| 単位 | 1単位あたりのkg数（`factor`） | 備考 |
|---|---|---|
| mg | `0.000001` | |
| g | `0.001` | |
| kg | `1` | 基準単位 |
| oz | `0.028349523125` | 常用オンス（定義値・厳密。`0.45359237 / 16`） |
| lb | `0.45359237` | 常用ポンド（定義値・厳密） |
| t | `1000` | メートルトン |

**係数は上表の値をそのまま定数として持つこと。** `0.0283` のような概数に丸めない。

### 5-4. 温度の変換式（基準単位：K） [必須A]

**温度は加減算を含むため、係数方式では変換できない。** 単位ごとに双方向の式を持つ。

#### 変換元 → K

| 変換元 | 式 |
|---|---|
| ℃ | `K = C + 273.15` |
| ℉ | `K = (F + 459.67) * 5 / 9` |
| K | `K = K` |
| °R | `K = R * 5 / 9` |
| °Ré | `K = Re * 1.25 + 273.15` |

#### K → 変換先

| 変換先 | 式 |
|---|---|
| ℃ | `C = K - 273.15` |
| ℉ | `F = K * 9 / 5 - 459.67` |
| K | `K = K` |
| °R | `R = K * 9 / 5` |
| °Ré | `Re = (K - 273.15) * 0.8` |

**[必須B] 式の記述形式：** `5 / 9` `9 / 5` `1.25` `0.8` を上表の通りに用いる。`0.5555...` のような概数に置き換えない。

#### 検証用の基準値

実装後、以下が一致することを確認する（12章 D）。

| ℃ | ℉ | K | °R | °Ré |
|---|---|---|---|---|
| 0 | 32 | 273.15 | 491.67 | 0 |
| 100 | 212 | 373.15 | 671.67 | 80 |
| -40 | -40 | 233.15 | 419.67 | -32 |
| -273.15 | -459.67 | 0 | 0 | -218.52 |

### 5-5. 同一単位選択時 [必須A] A6 / [必須B] B6

**変換元と変換先が同じ単位の場合、変換計算を通さず、入力値をそのまま結果とする。**

計算を通すと `0.1 → 0.1000000000000000055...` のような誤差が生じ得るため、**入力値の数値をそのまま8章の表示ルールに渡す**。

（例：`0.1 m → 0.1 m` は `0.1` と表示される）

### 5-6. 浮動小数点誤差への対応 [必須B]

| # | 対策 |
|---|---|
| P1 | 5-1の計算順序を固定する（`value * fromFactor` → `/ toFactor`） |
| P2 | 同一単位選択時は計算を通さない（5-5） |
| P3 | **結果は必ず有効数字12桁に丸めてから表示する**（8-2） |
| P4 | 換算係数・変換式に概数を用いない（5-2〜5-4） |

**P3が誤差対策の主体である。** 単位変換では `1 in → cm` が `2.5400000000000005` のような値になり得るが、有効数字12桁の丸めにより `2.54` と表示される。

**限界を明記する：** 本アプリは任意精度演算を目的とせず、有効数字12桁の範囲で妥当な結果を提供する。それを超える精度は保証しない。

## 6. 入力・エラー仕様

### 6-1. 入力値の前処理 [必須B] B8

検証の前に、以下の正規化を行う。

| # | 処理 |
|---|---|
| N1 | 前後の空白（半角・全角）を除去する |
| N2 | **全角数字 `０`〜`９` を半角 `0`〜`9` に変換する** |
| N3 | **全角ピリオド `．` を半角 `.` に変換する** |
| N4 | **全角ハイフン `－`、全角マイナス `−` を半角 `-` に変換する** |
| N5 | 文字列中の空白（間の空白）は除去しない（不正入力として検出させる） |

**N2〜N4の理由 [必須B] B8：** 日本語入力環境では全角数字が入りやすい。正規化しないと、利用者が正しく数値を打ったつもりでもエラーになり、A5の「適切なメッセージ」が実質的に機能しなくなる。

**正規化は検証と計算のためのみに行い、入力欄の表示文字列は書き換えない**（入力中に文字が勝手に変わると混乱するため）。

### 6-2. 入力状態の3分類 [必須B] B2

正規化後の文字列を、次の3つに分類する。**この分類が入力仕様の中核である。**

| 分類 | 条件 | 結果欄 | メッセージ |
|---|---|---|---|
| **(1) 未入力** | 空文字列 | 空欄 | **表示しない** |
| **(2) 入力途中** | `-` `+` `.` `-.` `+.` のいずれかに完全一致 | 空欄 | **表示しない** |
| **(3-a) 有効** | 6-3の正規表現に合致し、6-4のいずれにも該当しない | 変換結果 | 表示しない |
| **(3-b) 不正** | 上記以外、または6-4に該当 | 空欄 | **表示する**（6-5） |

**(1)(2)でメッセージを出さない理由 [必須B] B2：** A3のリアルタイム更新では、`-5` と打つ過程で必ず `-` の状態を経由する。ここでエラーを出すと、正常な入力の途中で毎回エラーが表示される。

### 6-3. 有効な数値形式 [必須B] B1

**次の正規表現に完全一致するものを有効とする。**

```
^[+-]?(\d+(\.\d*)?|\.\d+)$
```

| 形式 | 例 | 判定 |
|---|---|---|
| 整数 | `0` `5` `123` | 有効 |
| 小数 | `1.5` `0.001` `12.34` | 有効 |
| 負数 | `-5` `-1.5` | 有効 |
| 正符号付き | `+5` `+1.5` | 有効 |
| 先頭小数点 | `.5` `-.5` | 有効（`0.5` `-0.5` として扱う） |
| 末尾小数点 | `1.` `-1.` | **有効**（`1` `-1` として扱う） |
| 先頭ゼロ | `007` `0.50` | 有効 |
| 指数表記 | `1e5` `1E-3` | **不正** |
| 二重小数点 | `1.2.3` | 不正 |
| 二重符号 | `--5` `+-5` | 不正 |
| 数値以外 | `abc` `5m` `一` | 不正 |
| 間に空白 | `1 5` | 不正 |
| 記号のみ（完全一致以外） | `-abc` `..` | 不正 |
| カンマ区切り | `1,000` | **不正** |

**指数表記を不正とする理由：** 入力形式を1つの正規表現で定義でき、判定と受入テストが一意になる。単位変換の用途で利用者が指数表記を手入力する必要は乏しい。

**末尾小数点 `1.` を有効とする理由：** Part 4 の電卓と同じ扱いに揃える。`1.5` と打つ過程で `1.` を経由するため、ここを不正にするとリアルタイム更新でエラーが点滅する。

### 6-4. 数値としての追加検証 [必須B] B10

6-3に合致した後、`Number()` に変換して以下を検証する。

| ID | 条件 | 判定 |
|---|---|---|
| V1 | `Number.isFinite()` が false | 不正 |
| V2 | 絶対値が `1e15` 以上 | 不正（範囲外） |
| V3 | **温度カテゴリで、絶対零度を下回る値** | 不正（6-6） |

### 6-5. エラーメッセージ [必須A] A5

**メッセージは1度に1つだけ表示する。** 複数該当する場合は下表の上から優先する。

| # | 条件 | メッセージ |
|---|---|---|
| M1 | 6-3に合致しない（`abc`、`1.2.3`、`1e5` など） | `数値を入力してください` |
| M2 | 絶対値が `1e15` 以上（V2） | `入力できる範囲を超えています` |
| M3 | 温度が絶対零度を下回る（V3） | `絶対零度（<単位ごとの下限>）を下回る値は入力できません` |

**[必須B] 表示上の要件：**

| # | 仕様 |
|---|---|
| MS1 | メッセージ領域は、メッセージが無いときも高さを確保し、表示のたびにレイアウトが上下に動かないこと |
| MS2 | エラー時は結果欄を空にする（3-4 R3） |
| MS3 | 色だけでエラーを表現しない（文言を必ず表示する） |
| MS4 | メッセージ領域に `role="alert"` を付与する |
| MS5 | 入力が有効に戻ったら、メッセージは即座に消える |

### 6-6. 絶対零度の扱い [必須B] V3

**温度カテゴリでは、絶対零度を下回る値を不正として扱う。**

**変換元単位ごとの下限値：**

| 変換元単位 | 下限値 | メッセージ例 |
|---|---|---|
| ℃ | `-273.15` | `絶対零度（-273.15℃）を下回る値は入力できません` |
| ℉ | `-459.67` | `絶対零度（-459.67℉）を下回る値は入力できません` |
| K | `0` | `絶対零度（0K）を下回る値は入力できません` |
| °R | `0` | `絶対零度（0°R）を下回る値は入力できません` |
| °Ré | `-218.52` | `絶対零度（-218.52°Ré）を下回る値は入力できません` |

| # | 仕様 |
|---|---|
| AZ1 | **判定は変換元の値に対して行う。** 変換先の値は判定しない（変換元が有効なら変換先も必ず絶対零度以上になる） |
| AZ2 | 下限値と**等しい場合は有効**（`-273.15℃` は変換できる） |
| AZ3 | 判定は温度カテゴリのみ。長さ・重量では負数を有効とする |
| AZ4 | 変換元単位を変更したら、下限値も切り替わる。同じ入力値でも単位によって有効／不正が変わる |

**AZ4の例：** 入力値 `-300` は、℃ では不正だが、℉ では有効（`-300℉ ≈ 88.7K`）。

**この扱いは確定事項である**（13章 U1）。長さ・重量では負数を許容しながら温度のみ物理的な下限で弾く非対称な設計となるが、依頼者の判断によりこの仕様で確定した。

### 6-7. 長さ・重量における負数 [必須B]

**負数を有効な入力として受け付け、そのまま変換する。**

`-5 m → -500 cm` のように、符号を保って変換する。物理的な妥当性は判定しない（長さ・重量に「負の下限」は定義できないため）。

### 6-8. IME入力中の扱い [必須B] B9

| # | 仕様 |
|---|---|
| IME1 | **`compositionstart` から `compositionend` までの間は、結果の更新とメッセージの表示を行わない** |
| IME2 | `compositionend` の時点で、正規化・検証・変換を実行する |
| IME3 | 変換確定前の未確定文字列に対してエラーメッセージを出さない |

**理由：** 日本語入力がONの状態で数字を打つと、未確定の全角文字列が `value` に現れる。A3のリアルタイム更新がそのまま走ると、`数値を入力してください` が入力中に点滅する。Part 1〜4 で対処してきた日本語環境特有の問題と同種である。

## 8. 数値表示仕様

### 8-1. 適用範囲 [必須B]

**この章のルールは、変換結果の表示にのみ適用する。** 入力欄の文字列には適用しない（利用者が入力した `1.50` や `007` はそのまま表示される）。

### 8-2. 丸め [必須B] B5

```
① Number.isFinite(result) が false → 結果欄を空にし、
   「入力できる範囲を超えています」を表示する

② 有効数字12桁に丸める
   result = Number(result.toPrecision(12))
```

**②が浮動小数点誤差対応の主体である**（5-6 P3）。

### 8-3. 文字列化 [必須B] B5

**丸めた値 `v` を、次の手順で文字列にする。実装者が解釈する余地を残さないため、この通りに適用すること。**

**方針：固定小数点表記・指数表記のいずれにおいても、有効数字12桁を保持する。**

```
G1. v === 0 の場合、"0" を返して終了する
    （-0 === 0 が true のため、-0 もここで "0" になる）

G2. 1e-9 <= Math.abs(v) < 1e15 の場合 → 固定小数点表記（G3へ）
    それ以外の場合                    → 指数表記（G6へ）

【固定小数点表記】
G3. 小数部の桁数を決める
    exponent = Math.floor(Math.log10(Math.abs(v)))
    decimals = Math.min(Math.max(12 - exponent - 1, 0), 100)
    s = v.toFixed(decimals)

    ・「有効数字12桁ぶんの小数部」を確保する桁数になる
    ・例: v = 100        → exponent = 2   → decimals = 9   → "100.000000000"
          v = 0.3        → exponent = -1  → decimals = 12  → "0.300000000000"
          v = 2.8349523125e-8 → exponent = -8 → decimals = 19
                              → "0.0000000283495231250"
          v = 999999999999 → exponent = 11 → decimals = 0  → "999999999999"

G4. s に "." が含まれる場合、小数部末尾の "0" を繰り返し除去する
G5. 末尾が "." になった場合、その "." を除去する
    → 結果を返す（"-0" になった場合は "0" を返す）

【指数表記】
G6. s = v.toExponential(11)
    ・仮数部の小数部を11桁とし、有効数字12桁となる
    例: 1e-10 → "1.00000000000e-10"

G7. 仮数部の小数部末尾の "0" を除去し、末尾が "." になれば除去する
    ・指数部（"e-10" の部分）は変更しない
    例: "1.00000000000e-10" → "1e-10"
        "1.23450000000e+18" → "1.2345e+18"
        "2.83495231250e-10" → "2.8349523125e-10"
    → 結果を返す
```

**G3で小数部の桁数を計算する理由 [必須B]：** 固定小数点表記で `toFixed(12)` を固定桁数として用いると、`0.0000000283495231250` のような小さい値で小数部が12桁に切られ、**有効数字が5桁程度まで落ちる**。一方、指数表記はG6で有効数字12桁を保持するため、**同じ値でも表記方式によって精度が変わるという不整合が生じる**。G3の計算により、両表記の有効桁数を12桁で揃える。

**`toFixed()` の桁数を無条件に大きくしてはならない [必須B]：** `(0.3).toFixed(20)` は `"0.29999999999999998890"` となり、浮動小数点の誤差が表面化する。G3の計算式で得た桁数を用いること。

| # | 禁止事項 | 理由 |
|---|---|---|
| NG1 | `String(v)` / `v.toString()` / テンプレートリテラルによる直接の文字列化 | `Math.abs(v) < 1e-6` の値で意図せず指数表記になり、G2の境界と食い違うため |
| NG2 | `toPrecision()` の戻り値をそのまま表示に用いる | 末尾に不要な `0` が残るため |
| NG3 | `toFixed()` の桁数を12固定にする、または無条件に大きい値にする | 前者は小さい値で有効桁数が落ち、後者は浮動小数点誤差が表面化するため（8-3 G3） |

### 8-4. 桁区切り

**桁区切り（`1,000,000`）は実装しない。** 課題文に無く、小数点との併用で表示ルールが複雑になる。

### 8-5. 表示例と表示領域の要件

| 変換 | 結果の値 | 表示 |

### 13-1. U5b について（U5変更に伴う調整）

U5で指数表記を有効数字12桁に揃えたことにより、当初の固定小数点表記の規則（`toFixed(12)` の固定桁数）との間に不整合が生じた。

`0.001 oz → t` の結果 `2.8349523125e-8` は、8-3 G2 の閾値により固定小数点表記の対象となるが、`toFixed(12)` では `0.000000028350` となり**有効数字が5桁まで落ちる**。一方、これがわずかに小さい値であれば指数表記となり有効数字12桁で表示される。**同一の精度で計算した結果が、表記方式の違いだけで精度が変わることになる。**

このため、固定小数点表記側の小数部桁数を有効数字12桁ぶんに合わせて算出する規則（8-3 G3）へ変更した。**これはU5の確定内容と整合を取るための調整であり、新たな機能追加ではない。**

11. **計算順序は `base = value * fromFactor` → `result = base / toFactor` に固定する。** 係数同士を先に割らない
12. **温度は5-4の式を通す。** `5 / 9` `9 / 5` `1.25` `0.8` を概数に置き換えない
13. **変換元と変換先が同じ単位の場合、計算を通さず入力値をそのまま結果にする**（誤差を出さないため）
14. **結果は `Number(result.toPrecision(12))` で丸めてから文字列化する**

15b. **固定小数点表記・指数表記のいずれも有効数字12桁を保つ。** 指数表記は `toExponential(11)`、固定小数点表記は `toFixed()` の桁数を `Math.min(Math.max(12 - Math.floor(Math.log10(Math.abs(v))) - 1, 0), 100)` で算出する。**`toFixed(12)` の固定桁数にしない**（小さい値で有効桁数が落ちるため）
15c. **仮数部・小数部の末尾の不要な `0` を除去する。** 指数部（`e-10` の部分）は変更しない

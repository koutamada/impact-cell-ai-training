## 3. CSVの読み込み

### 3-1. ファイル選択 [必須A] A1

| # | 仕様 |
|---|---|
| F1 | **`<input type="file">` を用いる**。`accept=".csv,text/csv"` を指定する |
| F2 | 複数ファイルの同時選択は許可しない（`multiple` を指定しない） |
| F3 | 選択をキャンセルした場合は何もしない（エラーにしない） |
| F4 | **同じファイルを続けて選択できるよう、読み込み処理の後に `input` の `value` をクリアする** |
| F5 | ドラッグ＆ドロップは実装しない（[MVP外]） |

### 3-2. 拡張子の検証 [必須B]

**ファイル名の拡張子が `.csv`（大文字小文字を区別しない）でない場合は読み込まず、エラーを表示する。**

`accept` 属性はダイアログのフィルタに過ぎず、利用者が「すべてのファイル」を選べば任意のファイルが渡ってくる。

（14章 U1）

### 3-3. ファイルサイズの上限 [必須B]

**20MB を超えるファイルは読み込まず、エラーを表示する。**

テキスト全体を文字列として保持し、さらにセル配列と検索用インデックス（10-3）を持つため、それ以上のサイズではブラウザのメモリを圧迫し、A5の「極端に操作性が低下しない」を満たせなくなる。

（14章 U2）

### 3-4. 文字コード [必須B] B4

| # | 仕様 |
|---|---|
| E1 | **UTF-8 のみを対象とする。** 読み込みは `File.text()` または `FileReader.readAsText(file, 'UTF-8')` を用いる |
| E2 | 文字コードの自動判定は行わない（[MVP外]） |
| E3 | **BOM付きUTF-8に対応する。** 先頭の `U+FEFF` を1文字だけ除去してから解析する |
| E4 | **デコード結果に置換文字 `U+FFFD` が含まれる場合、警告を表示する**（例：`UTF-8として読み取れない文字が含まれています。ファイルの文字コードをご確認ください`） |
| E5 | E4は警告であり、読み込み自体は継続する |

**E3が必要な理由：** Excel が出力するUTF-8 CSVにはBOMが付くことが多い。除去しないと**最初の列名の先頭に不可視文字が混入し**、ヘッダーの表示と比較がずれる。

**E4が必要な理由 [必須B] B4：** 日本語環境ではShift_JISのCSVが非常に多い。UTF-8として読むと全面的に文字化けするが、アプリとしてはエラーにならないため、**警告が無いと利用者は「壊れたアプリ」と受け取る**。原因が文字コードにあることを伝える。

## 4. CSV解析仕様

**外部パーサを使わず自前で実装する。RFC 4180 を基準としつつ、対応範囲を以下に限定する。**

### 4-1. 解析方式 [必須B] B1

**テキスト全体を1文字ずつ走査する状態機械として実装する。**

```
禁止：text.split('\n') で行に分割してから、各行を split(',') する
```

**禁止する理由：** 引用符で囲まれた値の中には改行もカンマも含まれ得る。行分割を先に行うと、`"住所1丁目\n2番地"` のような値で行が分断され、復元できない。

### 4-2. 状態機械の定義 [必須B]

状態は2つ。

| 状態 | 説明 |
|---|---|
| **通常** | 引用符の外 |
| **引用符内** | `"` で開始した値の中 |

| 状態 | 入力文字 | 動作 |
|---|---|---|
| 通常 | `"`（フィールドの先頭） | 引用符内へ移行する（`"` は値に含めない） |
| 通常 | `"`（フィールドの途中） | **文字 `"` として値に追加する**（4-4 参照） |
| 通常 | `,` | フィールドを確定する |
| 通常 | `\r\n` / `\n` / `\r` | フィールドと行を確定する |
| 通常 | その他 | 値に追加する |
| 引用符内 | `""` | **文字 `"` 1つを値に追加する**（エスケープ） |
| 引用符内 | `"`（次が `"` でない） | 引用符を閉じ、通常へ戻る |
| 引用符内 | `,` | **値に追加する**（区切りとしない） |
| 引用符内 | 改行 | **値に追加する**（行を分けない。`\r\n` は `\n` に正規化する） |
| 引用符内 | その他 | 値に追加する |

### 4-3. 改行コード [必須B]

**`\r\n` / `\n` / `\r` の3種すべてを行区切りとして受け付ける。**

引用符内の改行は値として保持し、**`\r\n` と `\r` は `\n` に正規化して保持する**（表示時の扱いを1通りにするため）。

### 4-4. 引用符に関する非標準ケース [必須B]

RFC 4180 では不正だが、実データでは発生する。**エラーにせず、以下の通り扱う。**

| ケース | 例 | 扱い |
|---|---|---|
| 引用符で囲まれていない値の中の `"` | `a"b` | 文字 `"` としてそのまま値に含める |
| 閉じ引用符の後に文字が続く | `"ab"cd` | `abcd` として扱う（閉じた後の文字を値に追加する） |
| **閉じられていない引用符** | `"abc` （ファイル末尾まで） | ファイル末尾までを1つの値として確定し、**警告を表示する** |
| 引用符の直前・直後の空白 | ` "abc"` | 引用符が先頭でないため、通常の値 ` "abc"` として扱う（空白も引用符も文字） |

**値の前後の空白を自動で除去しない [必須B]。** CSVの値として意味を持つ可能性があるため、解析段階では加工しない。

### 4-5. 行の確定と空行 [必須B]

| # | 仕様 |
|---|---|
| R1 | **ファイル末尾の改行は、余分な空行を生じさせない**（`a,b\n` は1行） |
| R2 | **途中の空行（`\n\n`）は、1列すべてが空文字の行として保持する。** 自動で除去しない |
| R3 | R2の行は、列数不足として4-8の補完対象になる |

**R2で空行を除去しない理由：** 除去すると行番号が元ファイルとずれ、利用者がテキストエディタで突き合わせられなくなる。

### 4-6. 列数の決定 [必須B] B3

**列数 N は、ヘッダー行ではなく、CSV全体の最大列数とする。**

```
N = ヘッダー行を含むすべての行の中での、最大の列数
```

| # | 仕様 |
|---|---|
| W1 | 解析をファイル末尾まで完了させてから N を求める（途中で確定しない） |
| W2 | ヘッダー行の列数が N より少ない場合でも、**データ行の値を破棄しない** |

**ヘッダー行の列数を N としない理由 [必須B] B3：** ヘッダーより列数が多いデータ行の超過分を破棄すると、**利用者に見えないままデータが失われる**。ビューアの役割はファイルの内容を確認することであり、内容を欠落させてはならない。

### 4-7. ヘッダー [必須B] B2

| # | 仕様 |
|---|---|
| H1 | **1行目を常にヘッダーとして扱う**（ヘッダー有無の切替UIは設けない） |
| H2 | **ヘッダーの列数が N より少ない場合、不足分を `列N` の形式で自動補完する**（`列3` `列4` …。番号は1始まりの列位置） |
| H3 | ヘッダーのセルが**空文字**の場合も、表示上は同じく `列3` のように**列番号で代替する**（1始まり） |
| H4 | ヘッダー名が重複していても許容する。**列は名前ではなく列インデックスで識別する** |
| H5 | ヘッダー行しか存在しない場合、テーブルはヘッダーのみ表示し、データ0件として扱う（11-4） |
| H6 | H2による自動補完が発生した場合、**警告を表示する**（11-3 WR4） |

**H2の例：**

```
名前,年齢
田中,30,東京
```

→ N = 3。ヘッダーは `名前` / `年齢` / **`列3`** となり、`東京` は破棄されず3列目に表示される。

### 4-8. 全行の列数を揃える [必須B] B3

| # | 仕様 |
|---|---|
| C1 | **すべてのデータ行を、末尾に空文字を補って N 列にそろえる** |
| C2 | **超過分の破棄は行わない**（4-6により、N は最大列数なので超過は発生しない） |
| C3 | **元の列数がヘッダー行の元の列数と異なる行が1行でもあった場合、警告を表示する**（例：`5行で列数がヘッダー行と一致しませんでした`） |
| C4 | 該当行も通常どおりテーブルに表示する（読み込みを中断しない） |

**C3の判定は「ヘッダー行の元の列数」との比較で行う [必須B]。** H2で補完した後の N と比較すると、ヘッダーを補完したケースで警告が出なくなってしまう。

### 4-9. 解析結果の例

#### 例1：引用符・セル内改行・エスケープ・空セル

入力：

```
名前,備考,数量
田中,"住所1丁目
2番地",10
佐藤,"引用符""付き",5
鈴木,,
```

結果（ヘッダーを除く3データ行、N = 3）：

| # | 名前 | 備考 | 数量 |
|---|---|---|---|
| 1 | 田中 | `住所1丁目\n2番地` | 10 |
| 2 | 佐藤 | `引用符"付き` | 5 |
| 3 | 鈴木 | （空） | （空） |

#### 例2：列数が揃わない場合（4-6・4-7・4-8）

入力：

```
名前,年齢
田中,30,東京
佐藤

鈴木,25,大阪,営業部
```

結果（N = 4。ヘッダーの元の列数は2）：

| # | 名前 | 年齢 | **列3** | **列4** |
|---|---|---|---|---|
| 1 | 田中 | 30 | 東京 | （空） |
| 2 | 佐藤 | （空） | （空） | （空） |
| 3 | （空） | （空） | （空） | （空） |
| 4 | 鈴木 | 25 | 大阪 | 営業部 |

- ヘッダーは `列3` `列4` が自動補完される（H2）
- 3行目は空行だが、全列が空の行として保持される（R2）
- **値は1つも破棄されない**
- 警告が2つ表示される：ヘッダーの自動補完（WR4）と、列数不一致の行数（WR2）

## 5. データモデル

### 5-1. 読み込み結果 [必須B]

```js
{
  fileName: string,      // 選択されたファイル名
  headers: string[],     // 表示用のヘッダー。長さ N（4-7で補完済み）
  rows: string[][],      // データ行。各行の長さは必ず N（4-8で補正済み）
  searchIndex: string[], // 行ごとの検索用文字列（小文字化済み）。長さは rows と同じ
  numericColumns: boolean[] // 列ごとの数値列判定。長さ N
}
```

**`N` はヘッダー行の列数ではなく、CSV全体の最大列数である**（4-6）。`headers` の長さは常に `N` であり、不足分は `列3` のように補完済みの状態で保持する。

**`rows` は読み込み後に変更しない（不変とする）[必須B]。** 並び替えも絞り込みも、後述の「表示順の配列」を作り替えることで実現する。

### 5-2. 表示状態 [必須B]

```js
{
  query: string,         // 検索文字列
  sortColumn: number|null, // 並び替え対象の列インデックス
  sortDirection: 'asc'|'desc',
  page: number,          // 現在ページ（1始まり）
  viewOrder: number[]    // 絞り込み＋並び替え後の rows のインデックス配列
}
```

**`viewOrder` が本アプリの中核である。** 行データそのものを複製・並び替えせず、**インデックスの配列だけを操作する**ことで、大量データでもコピーコストが発生しない。

### 5-3. 行番号 [必須B]

**テーブルの先頭列に行番号を表示する。値は「元CSVにおけるデータ行の番号」（ヘッダーを除いて1始まり）とする。**

並び替えても絞り込んでも、この番号は変わらない。元ファイルとの突き合わせができるようにするため。

`rows` のインデックス `i` に対して、行番号は `i + 1` である。

（14章 U9）

### 5-4. 永続化

**localStorage を使用しない。** 再読み込みするとファイルは読み込まれていない状態に戻る（[MVP外]）。

## 7. テーブル表示仕様

### 7-2. ヘッダー固定 [必須B]

| # | 仕様 |
|---|---|

| T6 | **ページ全体（`body`）に横スクロールを発生させない**（11-1 RS1） |
| T7 | 横スクロール中もヘッダーの縦固定が機能すること |

### 7-4. セルの表示 [必須B]

| # | 仕様 |
|---|---|
| T8 | **セルは折り返さず1行で表示し、幅に収まらない場合は末尾を省略する**（`white-space: nowrap; overflow: hidden; text-overflow: ellipsis;`） |
| T9 | 列に最大幅を設ける（例：24rem）。全体が極端に横長になるのを防ぐ |

## 8. ソート仕様

### 8-1. 操作 [必須A] A3

| # | 仕様 |
|---|---|
| S1 | 列名（ヘッダーセル内のボタン）をクリックすると並び替える |
| S2 | **未ソートの列を初めてクリックしたときは昇順** |
| S3 | 同じ列を再度クリックすると降順、さらにクリックすると昇順に戻る（**昇順↔降順のトグル**） |
| S4 | **ソート解除の状態には戻らない**（3回目のクリックで元の順序に戻す挙動は実装しない） |
| S5 | 別の列をクリックすると、その列の昇順になる（前の列のソートは解除される） |
| S6 | 複数列ソートは実装しない（[MVP外]） |
| S7 | 並び替え後、**1ページ目に戻る** |
| S8 | 現在のソート列と方向を、ヘッダーに視覚的に示す（`▲` `▼` 等）。**記号だけでなく `aria-sort` でも示す**（12-2 AC4） |

（14章 U8）

### 8-2. 型判定 [必須B] B5

**判定は列単位で行い、読み込み時に1回だけ計算して `numericColumns` にキャッシュする。**

```
ある列が数値列である条件：
  その列の「空でないセル」が1つ以上存在し、
  かつ、そのすべてが数値として解釈できる
```

**数値として解釈できる条件：**

```
前後の空白を除去した文字列が、次の正規表現に完全一致する
  /^[+-]?(\d+(\.\d+)?|\.\d+)$/
```

| 入力 | 数値扱い |
|---|---|
| `10` `-3` `+5` `0.5` `.5` | ○ |
| `1,000` | **×**（カンマ区切りは数値としない） |
| `1e5` | **×**（指数表記は非対応） |
| `10円` `A10` | × |
| `０１２`（全角） | ×（正規化しない） |
| （空文字） | 判定対象外（空セルとして扱う） |

**列単位で判定する理由 [必須B]：** 値ごとに判定すると、数値と文字列が混在した列で「数値と文字列のどちらが先か」を別途決める必要が生じ、順序が直感的でなくなる。**1つでも非数値のセルがあれば、その列は文字列列として扱う。**

**カンマ区切りを数値としない理由：** CSVの区切り文字と紛らわしく、`"1,000"` が引用符付きで1セルに入っている場合と、区切られて2セルになっている場合を利用者が混同する。

（14章 U6）

### 8-3. 比較規則 [必須B] B5

| 列の種類 | 比較方法 |
|---|---|
| 数値列 | `Number()` に変換して数値比較 |
| 文字列列 | **`a.localeCompare(b, 'ja')`** |

**`localeCompare` にロケール `'ja'` を指定する理由 [必須B]：** 指定しないとブラウザの既定ロケールに依存し、日本語の並び順が環境ごとに変わる。

### 8-4. 空セルの扱い [必須B] B5

**空文字のセルは、昇順・降順のいずれでも常に末尾に置く。**

理由：空は「値がない」ことを表し、大小の順序に位置づけるべきではない。降順で空が先頭に来ると、値のある行が画面外に押し出される。

（14章 U7）

### 8-5. タイブレーク [必須B] B5

**比較値が同一の場合、元の行番号（`rows` のインデックス）の昇順とする。**

これにより並び替えは安定ソートとなり、同じ操作を繰り返しても順序が変わらない。受入テストで判定できるようにするために必須である。

### 8-6. ソートの対象 [必須B] B8

**絞り込み後のデータ全体に対して並び替える。現在表示中のページだけを並び替えない。**

## 9. 絞り込み仕様

### 9-1. 検索欄 [必須A] A4

| # | 仕様 |
|---|---|
| Q1 | **全列を対象とする単一の検索欄**とする（列ごとの入力欄は設けない。[MVP外]） |
| Q2 | `<input type="text">` を用いる |
| Q3 | 空文字のときは絞り込みを行わず、全行を対象とする |

### 9-2. 一致条件 [必須B] B6

| 項目 | 仕様 |
|---|---|
| 対象 | **行のいずれかのセルに含まれていれば一致**（行番号は対象外） |
| 一致 | 部分一致 |
| 大文字小文字 | **区別しない**（両者を小文字化して比較） |
| 全角／半角 | 正規化しない（`ﾒﾓ` と `メモ` は別物） |
| ひらがな／カタカナ | 正規化しない |
| 複数語 | **入力文字列全体をそのまま1つの検索文字列として扱う**（スペース区切りのAND検索は行わない。[MVP外]） |
| 前後の空白 | 検索文字列の前後空白を除去してから比較する |

**セルを連結した文字列に対して検索する [必須B]：** 各行のセルを区切り文字（`\n` 等）で連結し小文字化した文字列を `searchIndex` として読み込み時に作る（10-3）。**セル境界をまたいだ誤ヒットを避けるため、連結には値に現れにくい文字を用いる。**

### 9-3. 実行契機 [必須B] B6

| # | 仕様 |
|---|---|
| Q4 | **入力に応じてリアルタイムに絞り込む** |
| Q5 | **デバウンス 200ms を入れる**（10-4） |
| Q6 | **`compositionstart` から `compositionend` までの間は絞り込みを実行しない**（IME対策） |
| Q7 | `compositionend` の時点で絞り込みを実行する |
| Q8 | 絞り込み後、**1ページ目に戻る** |
| Q9 | 絞り込み後も、現在の並び替え条件を維持する |

**Q6の理由 [必須B]：** 日本語変換の未確定文字列で絞り込みが走ると、結果が激しく入れ替わり操作しづらい。大量データでは無駄な全走査も発生する。

（14章 U11）

### 9-4. 結果0件 [必須B]

**「該当する行がありません」等のメッセージをテーブル領域に表示する。** ヘッダー行は表示したままとする。

空のテーブルだけを表示すると、データが無いのか絞り込みの結果なのか区別できない。

### 9-5. 適用順序 [必須B] B8

**絞り込み → 並び替え → ページ切り出し の順に適用する。**

```
rows（不変）
  ↓ 絞り込み（searchIndex に対する部分一致）
一致した行インデックスの配列
  ↓ 並び替え（8章の規則）
viewOrder
  ↓ ページ切り出し（page と 1ページ件数）
DOMへ描画する行（最大100行）
```

**並び替え・絞り込みは常にデータ全体に対して行い、その後に表示ページを切り出す。** ページ内だけで並び替え・絞り込みを行ってはならない。

## 10. 大量データ対策

### 10-1. 描画方式 [必須A] A5 / [必須B] B7

| # | 仕様 |
|---|---|
| P1 | **全行を一度にDOMへ描画してはならない** |
| P2 | **ページネーションを採用する** |
| P3 | **1ページあたり100行**（10-2） |
| P4 | DOMに存在する `<tr>` は、ヘッダーを除き最大100行 |
| P5 | 再描画時は `<tbody>` の内容を作り直す。`DocumentFragment` に組み立ててから一度だけ挿入する |
| P6 | 仮想スクロール（無限スクロール）は実装しない（[MVP外]） |

**ページネーションを採用する理由：** 仮想スクロールはスクロール位置の管理・ヘッダー固定との併用・スマートフォンでの慣性スクロールなど考慮点が多く、Vanilla実装では複雑さに見合わない。**ページネーションはDOM件数を確実に上限で抑えられる。**

### 10-2. ページ送り [必須B]

| # | 仕様 |
|---|---|
| P7 | 「先頭」「前」「次」「末尾」の4ボタンを設ける |
| P8 | 現在ページと総ページ数を表示する（例：`2 / 13 ページ`） |
| P9 | 1ページ目では「先頭」「前」を、最終ページでは「次」「末尾」を**無効化する**（`disabled`） |
| P10 | 総ページ数は `Math.max(1, Math.ceil(該当行数 / 100))` とする |
| P11 | 該当行が0件でも「1 / 1 ページ」と表示し、破綻させない |
| P12 | ページ番号の直接入力・1ページ件数の変更UIは実装しない（[MVP外]） |
| P13 | ページ移動時、テーブルコンテナの縦スクロール位置を先頭に戻す |

（14章 U3）

### 10-3. 検索用インデックス [必須B] B7

**読み込み時に、行ごとに「全セルを連結して小文字化した文字列」を作り、`searchIndex` として保持する。**

絞り込みのたびに全セルを走査して `toLowerCase()` すると、5万行×20列で毎回100万回の変換が発生する。**事前に1回だけ計算しておくことで、絞り込みは行あたり1回の `indexOf` で済む。**

トレードオフとして、元データとほぼ同量のメモリを追加で消費する。3-3のサイズ上限（20MB）はこれを織り込んだ値である。

### 10-4. デバウンス [必須B] B7

**検索入力に 200ms のデバウンスを入れる。**

1文字ごとに全行の走査と再描画を行うと、大量データで入力が引っかかる。Part 5（単位変換）はデバウンス禁止だったが、**あちらは計算量が定数、本Partは行数に比例する**ため、方針が異なる。

### 10-5. 受け入れ目安 [必須B] B9

**代表的な受入テストのデータ量を「5万行 × 20列（およそ10MB）」とする。**

#### 性能目標（参考値）

| 操作 | 目標 |
|---|---|
| ファイル読み込みから初回表示まで | 5秒程度 |
| 列名クリックによる並び替え | 2秒程度 |
| 検索文字列の入力（デバウンス後） | 1秒程度 |
| ページ送り | 0.5秒程度 |

**上表は性能目標であり、厳格な合否条件ではない [必須B]。** 端末性能・ブラウザ・OSにより実測値は大きく変動する。**秒数をわずかに超えただけで NG とはしない。**

#### 合否の判定基準 [必須B]

**受入テストでは、次の4点で判定する。**

| # | 判定基準 |
|---|---|
| J1 | **長時間UIが固まらない**（操作後、画面が応答しないまま放置される状態にならない） |
| J2 | **検索入力が実用不能なほど引っかからない**（文字を入力し続けられる） |
| J3 | **ページ送りが明らかに遅延しない**（押してから表示が切り替わるまでに待たされる感覚がない） |
| J4 | **DOM上のデータ行が最大100行に抑えられている**（10-1 P4。開発者ツールで確認できる） |

**J4のみ客観的に測定できる基準である。** J1〜J3は体感による判定とし、性能目標の秒数はその際の参考として用いる。目標を大きく超える（例：数倍かかる、操作が数秒間受け付けられない）場合に NG とする。

### 10-6. 実装しない最適化

| # | 内容 | 理由 |
|---|---|---|
| 1 | Web Worker による解析 | 実装が複雑になる。目安を満たせれば不要 |
| 2 | ストリーミング解析（分割読み込み） | 同上 |
| 3 | 並び替え結果のキャッシュ | 同上 |

## 11. エラー仕様

### 11-1. エラーと警告の区別 [必須B] B12

| 種別 | 意味 | 表示 |
|---|---|---|
| **エラー** | 読み込みを行わない／中断する | テーブルを表示しない。メッセージのみ |
| **警告** | 読み込みは成功したが、注意すべき点がある | テーブルを表示したうえで、メッセージを併記する |

### 11-2. エラー一覧 [必須B] B12

| # | 条件 | メッセージ |
|---|---|---|
| ER1 | 拡張子が `.csv` でない（3-2） | `CSVファイル（.csv）を選択してください` |
| ER2 | ファイルサイズが20MBを超える（3-3） | `ファイルが大きすぎます（20MBまで）` |
| ER3 | ファイルサイズが0バイト | `ファイルが空です` |
| ER4 | 内容が空文字、または改行のみ | `CSVの内容が空です` |
| ER5 | ファイルの読み込みに失敗した（`FileReader` のエラー） | `ファイルを読み込めませんでした` |

**エラー時は、前のファイルのデータを表示したままにしない [必須B]。** 6-5の初期化を行い、未読み込み状態（6-3）に戻す。どのファイルの内容を見ているのか分からなくなるため。

### 11-3. 警告一覧 [必須B] B12

| # | 条件 | メッセージ |
|---|---|---|
| WR1 | 置換文字 `U+FFFD` を含む（3-4 E4） | `UTF-8として読み取れない文字が含まれています。ファイルの文字コードをご確認ください` |
| WR2 | 列数がヘッダー行と一致しない行がある（4-8 C3） | `◯行で列数がヘッダー行と一致しませんでした` |
| WR3 | 閉じられていない引用符がある（4-4） | `閉じられていない引用符があります。解析結果をご確認ください` |
| WR4 | ヘッダーを自動補完した（4-7 H2・H6） | `ヘッダーの列数が不足していたため、列◯以降を自動で補いました` |

**複数の警告が同時に発生し得る。その場合はすべて表示する [必須B]。** エラーは1つだけ表示する（読み込みを中断するため、後続の判定に進まない）。

### 11-4. ヘッダーのみのCSV [必須B]

**エラーではない。** ヘッダー行をテーブルに表示し、データ0件として扱う。

| # | 仕様 |
|---|---|
| Z1 | 状態表示は `0行 N列` |
| Z2 | テーブル本体に「データ行がありません」等のメッセージを表示する |
| Z3 | 検索欄・ページ送りは表示するが、ページ送りは無効化される（P9・P11） |
| Z4 | 列名クリックによる並び替えは実行できてよい（結果は0行のまま） |

### 11-5. 表示上の要件 [必須B]

| # | 仕様 |
|---|---|
| MS1 | メッセージ領域は、メッセージが無いときも高さを確保し、表示のたびにレイアウトが上下に動かないこと |

### 14-1. U4 の補足

**列数 N は「ヘッダー行の列数」ではなく「CSV全体の最大列数」である**（4-6）。これに伴い、次の点が仕様全体に波及している。

| 影響先 | 内容 |
|---|---|
| ヘッダー | 不足分を `列3` `列4` … として自動補完する（4-7 H2） |
| 状態表示の列数 | 補完後の N を表示する（6-4） |
| データモデル | `headers` の長さは常に N（5-1） |
| 警告 | 列数不一致（WR2）に加え、ヘッダー補完（WR4）の警告を新設（11-3） |
| 列数不一致の判定 | **補完後の N ではなく、ヘッダー行の「元の」列数と比較する**（4-8 C3）。補完後と比較すると警告が出なくなる |

### 14-2. U12 の補足

10-5 の秒数は**性能目標であり、合否条件ではない**。受入テストG章は、体感による3基準（J1〜J3）と、客観的に測定できる1基準（J4：DOM上のデータ行が100行以下）で判定する。**J4のみ厳格な合否条件とする。**

目標を**大きく**超える場合（数倍かかる、数秒間操作を受け付けない等）は NG として原因を調査する（G-10）。

## 付録：実装者へ渡す際の注意事項

1. **出力ファイルは `apps/part07-csv-viewer/` 配下の `index.html` / `style.css` / `app.js` の3つのみ**
2. **フレームワーク・外部ライブラリ・CDN・外部API・Webフォントを使わない。CSVパーサも自前で実装する**
3. **本仕様書2-2の[MVP外]機能を追加しない。** 思いついても実装せず、提案にとどめる
4. **CSV解析は1文字ずつ走査する状態機械で実装する。** `split('\n')` → `split(',')` を使わない（引用符内の改行・カンマで壊れる）
5. **`""` は `"` 1つにする。引用符内のカンマ・改行は値に含める。`\r\n` `\r` は `\n` に正規化する**
6. **先頭のBOM（`U+FEFF`）を1文字だけ除去する**
7. **ファイル末尾の改行で余分な空行を作らない**
8. **1行目は常にヘッダー。ただし列数 N は「ヘッダー行の列数」ではなく「CSV全体の最大列数」。** 解析を最後まで終えてから N を求める
8b. **ヘッダーが N より短い場合、不足分を `列3` `列4` … として自動補完する。データ行の超過セルを破棄しない**
8c. **全データ行を空文字で N 列に揃える。途中の空行は全列空の行として保持する**
8d. **列数不一致の判定は「ヘッダー行の元の列数」と比較する**（補完後の N と比較しない）。列数不一致の警告と、ヘッダー補完の警告を別々に出す
9. **`rows` は読み込み後に変更しない。** 並び替え・絞り込みはインデックス配列（`viewOrder`）の操作で行う
10. **適用順序は「絞り込み → 並び替え → ページ切り出し」。** ページ内だけで並び替え・絞り込みをしない
11. **全行を一度にDOMへ描画しない。** 1ページ100行、`DocumentFragment` で一括挿入する
12. **数値列の判定は列単位で読み込み時に1回だけ行い、キャッシュする**
13. **文字列比較は `localeCompare(b, 'ja')` を使う**（ロケール指定を省略しない）
14. **空セルは昇順・降順とも常に末尾。同値のタイブレークは元の行インデックス昇順**
15. **初回クリックは昇順、以降は昇順↔降順のトグル。解除状態は作らない**
16. **絞り込みは読み込み時に作った小文字化済み `searchIndex` に対して行う**
17. **検索は 200ms デバウンス。`compositionstart`〜`compositionend` の間は実行しない**
18. **並び替え・絞り込みの後は1ページ目に戻す**
19. **セル値・ヘッダー名・ファイル名は `textContent` で設定する。`innerHTML` に連結しない**
20. **`title` 属性は `setAttribute` で設定する**
21. **`<th>` に直接クリックイベントを付けず、内部の `<button>` で並び替える。`aria-sort` を更新する**
22. **状態表示に `aria-live="polite"` を付け、テーブル本体には付けない**
23. **別ファイル選択時は検索・並び替え・ページ・メッセージ・前データをすべて初期化する**
24. **エラー時は前のファイルのテーブルを残さない**
25. **`outline: none` を単独で指定しない**
26. **入力欄のフォントサイズは16px以上**（iOSの自動ズーム防止）
27. **幅375pxでページ全体に横スクロールを出さない。テーブルはコンテナ内でスクロールさせる**
27b. **10-5の秒数は性能目標であり合否条件ではない。** 厳格に守るべきは「DOM上のデータ行を最大100行に抑える」ことと、UIが長時間固まらない・検索入力が引っかからない・ページ送りが明らかに遅延しないこと
28. **Part 1〜6 のコードを流用せず、Part 8 以降を見越した共通化もしない**

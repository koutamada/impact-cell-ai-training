## 1. 要件整理

### 1-1. クリア条件 → 必須要件への分解

| ID | 必須要件 | 由来（クリア条件） |
|---|---|---|
| R1 | 新規タスクをテキストで入力し、一覧に追加できる | 「新しいタスクを登録できる」 |
| R2 | 各タスクの完了 / 未完了を相互に切り替えられる（元に戻せる） | 「完了・未完了に切り替えられる」 |
| R3 | 個別のタスクを削除できる | 「不要になったタスクを削除できる」 |

R2は「切り替え」なので、**未完了→完了だけでなく完了→未完了も必ず動くこと**が条件に含まれます。

## 2. 実装仕様

### 2-1. 技術制約 [必須]

- Vanilla HTML / CSS / JavaScript のみ
- 外部ライブラリ・CDN・フォントの外部読み込みなし（オフラインでも動作すること）
- ビルドツールなし。`index.html` をブラウザで直接開いて動作すること
- JavaScript は `app.js` に集約。HTML内に `onclick` 等のインラインJSを書かない
- CSSは `style.css` に集約。HTML内に `style` 属性を書かない
- ES2015+ の標準構文で可（トランスパイル不要）

### 2-2. 状態モデル [必須]

アプリの状態は「タスク配列」1つのみ。

```js
// タスク1件
{
  id: string,        // 一意なID
  title: string,     // タスク本文（trim済み、1文字以上）
  completed: boolean // true = 完了
}
```

- ID生成：`crypto.randomUUID()` を使用。未対応環境向けに簡易フォールバックを持つ
  （例：`Date.now().toString(36) + Math.random().toString(36).slice(2)`）
- ID は削除・再追加をまたいで重複しないこと
- タスク本文は追加時に `trim()` した値を保持する

### 2-3. 永続化仕様 [必須]

- ストレージ：`localStorage`
- キー：`part01-todo.tasks` （→ 5章「こちらで決めてよい事項」参照）
- 値：タスク配列を `JSON.stringify` した文字列
- **保存タイミング：状態が変わるすべての操作の直後**（追加 / 完了切替 / 削除）
- 読み込みタイミング：ページ読み込み時に1回

読み込み時の防御 [必須]：

- `localStorage` へのアクセス、および `JSON.parse` を `try / catch` で囲む
- パースに失敗した場合、配列でなかった場合は **空配列として起動し、画面は正常に表示する**（白画面・エラーで停止しない）
- 各要素について `title` が文字列であることを確認し、`completed` は `Boolean()` で正規化する。`id` が無い要素には生成して補う

保存時の防御 [必須]：

- 書き込みも `try / catch`。失敗（容量超過・プライベートモード等）してもアプリは動作継続する

### 2-4. 描画方式 [必須]

- 状態配列を元に **リスト全体を再描画する** 方式で問題ありません（今回の規模では最も安全かつ単純）
- **DOM生成に `innerHTML` でユーザー入力を連結しない。** タスク本文は必ず `textContent` で設定する（XSS対策・6章参照）

### 2-5. 想定する関数構成 [任意・目安]

Codexの実装が読みやすくなるための目安であり、この通りでなくても構いません。

```
loadTasks()          // localStorage から復元（失敗時は []）
saveTasks()          // localStorage へ保存
render()             // tasks から一覧を再描画
addTask(title)       // 追加 → save → render
toggleTask(id)       // completed 反転 → save → render
deleteTask(id)       // 除去 → save → render
```

## 3. 画面・操作仕様

### 3-1. 画面構成 [必須]

上から順に、単一画面（ページ遷移なし）で構成します。

1. **ヘッダー**：アプリタイトル（例：「タスク管理」）
2. **入力エリア**：1行テキスト入力 + 「追加」ボタン（横並び）
3. **タスク一覧**：タスクが0件のときは代わりに空状態メッセージを表示
4. （任意）残タスク件数の表示

各タスク行の構成 [必須]：

| 要素 | 内容 |
|---|---|
| チェックボックス | 完了状態の切替（`<input type="checkbox">`） |
| タスク本文 | 登録した文言 |
| 削除ボタン | その行のタスクを削除 |

### 3-2. 操作仕様 [必須]

| # | 操作 | 挙動 |
|---|---|---|
| O1 | 入力欄に文字を入れて「追加」ボタンをクリック | 一覧に未完了タスクとして追加。入力欄を空にする |
| O2 | 入力欄で Enter キー | O1と同じ挙動 |
| O3 | 空文字 / 空白のみで追加 | **追加しない**。エラーで停止もしない（無反応 or 短い注意表示） |
| O4 | チェックボックスをクリック | 完了 ⇄ 未完了 を切り替え。即座に保存 |
| O5 | 削除ボタンをクリック | その行のみ削除。他タスクは影響を受けない |
| O6 | ページ再読み込み | 直前の一覧・完了状態が復元される |

追加後のフォーカス [任意]：入力欄にフォーカスを残すと連続入力しやすい（推奨）。

完了タスクの見た目 [必須]：完了と未完了が**一目で区別できること**。
（打ち消し線＋文字色を薄くする、が一般的。手段は問わない）

新規タスクの追加位置：リスト末尾（→ 5章参照）。

### 3-3. デザイン要件 [必須ライン]

R5は「装飾の作り込み」ではなく「一般的なアプリとして使える水準」を求めるものです。以下を最低ラインとします。

- コンテンツを中央寄せし、最大幅を設ける（600px前後）
- 要素間に十分な余白があり、詰まって見えない
- 本文フォントサイズ 16px 以上
- ボタン・チェックボックスのクリック領域が十分（高さ40px前後）
- ボタンに hover / focus のスタイルがある（フォーカスリングを消さない）
- 幅375px（スマホ相当）で横スクロールが発生せず、崩れない
- 背景色・文字色のコントラストが十分

[任意]：角丸、影、トランジション、色のアクセント。時間をかけすぎない。

## 4. 保持すべきデータ

### 4-1. 永続化する [必須]

| フィールド | 型 | 用途 |
|---|---|---|
| `id` | string | 完了切替・削除の対象特定 |
| `title` | string | 表示するタスク本文 |
| `completed` | boolean | 完了状態の復元 |

### 4-2. 永続化しない [必須]

- 入力欄に打ちかけの文字列
- スクロール位置、フォーカス位置などのUI状態

### 4-3. 任意で持ってもよい [任意]

- `createdAt`（数値タイムスタンプ）：並び順を安定させたい場合に有用。今回は必須ではありません。追加する場合も画面には表示しない

## 5. こちらで決めてよい事項（課題文から一意に決まらない）

| # | 論点 | 推奨案 | 備考 |
|---|---|---|---|
| D1 | localStorage のキー名 | `part01-todo.tasks` | Part別に接頭辞を分けておくと、同一ドメインに複数Partをデプロイしても衝突しない |

## 6. 見落としやすい境界ケース

Codexに実装させる際、および自分で確認する際の重点箇所です。

### 6-1. 必ず対処が必要 [必須]

| # | ケース | 期待する挙動 |
|---|---|---|
| E1 | **日本語入力（IME）変換確定のEnter** | 変換確定のEnterでタスクが登録されてしまわないこと。`keydown` で `event.isComposing === true` の場合は無視する。**日本語環境では最も踏みやすい不具合** |
| E2 | 空文字・半角/全角スペースのみで追加 | 追加されない |
| E3 | 前後に空白を含む入力（` 買い物 `） | `trim()` した状態で保存・表示される |
| E4 | `<script>alert(1)</script>` を本文として入力 | **そのまま文字列として表示される**（スクリプトが実行されない・タグが消えない）。`textContent` を使っていれば自動的に満たされる |
| E5 | 非常に長い1単語（例：`あ`×200文字、URL文字列） | 折り返して表示され、横スクロールや崩れが起きない（`overflow-wrap: anywhere` 等） |
| E6 | 同じ文言のタスクを複数登録 | それぞれ独立して切替・削除できる（IDで識別しているか） |
| E7 | localStorage の値が壊れている | 空の状態で正常起動する（手動で不正値を入れて確認） |
| E8 | タスク0件 | 空のリストではなく、空状態のメッセージが出る |
| E9 | 削除直後の再描画 | 残ったタスクの完了状態がずれない（indexではなくidで操作しているか） |

### 6-2. 確認しておくとよい [任意]

- 「追加」ボタンの連打で空タスクが増えない
- タスク30〜50件でも表示が破綻しない
- ブラウザの戻る/進むで壊れない
- 別タブで開いた同じアプリとの整合（今回は同期不要。片方の変更がもう片方に即反映されなくてよい）

## 1. 目的・スコープ

加算・減算・乗算・除算に対応した電卓を、Vanilla HTML / CSS / JavaScript のみで実装する。ボタン操作とPCキーボードの双方から入力でき、計算履歴を表示し、ゼロ除算などの計算不能ケースを適切に処理する。

**本アプリは逐次計算方式（電卓方式）である。** 演算子の優先順位による計算は行わない。詳細は8章。

関数電卓化・高機能化は目的ではない。**本書で確定した範囲を、確定した通りに動作させ、受入チェックリストで検証できる状態にすることが目的**である。

### 技術方針

- Vanilla HTML / CSS / JavaScript のみ。外部ライブラリ・CDN・Webフォントを使用しない
- ビルド工程なし。`index.html` をブラウザで直接開いて動作する
- GitHub Pages で公開でき、公開環境でも同一に動作する（相対パス参照）
- Part 1〜3 とコードを共有しない。本Part単体で完結する
- Part 5 以降を見越した抽象化・共通化を行わない
- 対応ブラウザは最新版の Chrome / Safari（iOS含む）

## 3. 補足仕様と追加機能

### 3-1. [必須B] 補足仕様の一覧

| ID | 補足仕様 | 必要な理由 |
|---|---|---|
| B1 | 内部状態モデルと状態遷移を定義すること | 電卓は「直前に何を押したか」で同じキーの意味が変わる。定義しないと挙動が一意に決まらない |
| B2 | 演算子の優先順位を確定すること（逐次計算） | A1が四則演算である以上 `2 + 3 × 4` が入力可能。結果を決めないと実装できない |

| B5 | エラー状態と復帰手段を定義すること | 復帰できないとアプリが操作不能になる |
| B6 | 履歴の記録タイミングと表記形式を定めること | A4の「計算内容」の中身。逐次計算では通常の数式表記と結果が食い違う |
| B7 | キーボードとボタンが同一の内部処理を通ること | 別実装だと同じ操作で異なる結果になる |
| B8 | 負数が計算結果として現れた場合、次の計算に使えること | A3の連続計算が成立しない |

## 6. 数値と表示のルール

### 6-1. 入力可能な桁数 [必須B] B3

| # | 仕様 |
|---|---|
| D1 | **入力中の数値に含まれる数字文字（`0`〜`9`）の総数が12に達したら、以降の数字入力を無視する** |
| D2 | 小数点 `.` は桁数に数えない |
| D3 | 先頭の `0`（`0.5` の `0` など）は桁数に数える |
| D4 | 上限に達した状態で数字を押しても、エラーにせず単に無視する |
| D5 | 小数点は、上限に達していても入力できる（すでに `.` を含む場合を除く） |

**この上限は「利用者が手で入力する値」にのみ適用される。** 計算結果には適用せず、結果は6-3のルールに従う。

### 6-2. 数値入力のルール [必須B]

| # | 入力 | 結果 |
|---|---|---|
| I1 | 初期状態（`0` 表示）で `0` を押す | `0` のまま（`00` にしない） |
| I2 | 初期状態で `5` を押す | `5`（先頭の0を置き換える） |
| I3 | `0` の状態で `.` を押す | `0.` |
| I4 | 何も入力していない状態で `.` を押す | `0.`（先頭に0を補う） |
| I5 | すでに `.` を含む数値に `.` を押す | **無視する**（エラーにしない） |
| I6 | `3.` の状態で `=` や演算子を押す | `3` として計算する（エラーにしない） |

**負数を直接入力する手段は設けない。** `±` ボタンは実装しない。負数は計算結果としてのみ現れる（`3 − 5 = −2`）。

**[必須B] B8：計算結果が負数になった場合、その値をそのまま次の計算の左辺として使えること。**

### 6-3. 計算結果の表示ルール [必須B] B4

**計算結果は、以下の手順を上から順に適用する。**

```
① Number.isFinite(result) が false → エラー（9章）
   （Infinity / -Infinity / NaN）

② 有効数字12桁に丸める
   result = Number(result.toPrecision(12))

③ Math.abs(result) >= 1e12 → エラー
   （整数部が13桁以上となり、通常の電卓表示として扱えない）

④ result !== 0 かつ Math.abs(result) < 1e-12 → エラー
   （本アプリの扱う非ゼロ値の下限を下回る）

⑤ 共通フォーマット処理（6-3-1）で文字列化する
```

**②の有効数字12桁丸めが、浮動小数点誤差への対応（Q27）と桁数上限の両方を担う。** ③④はその丸め結果に対する範囲チェックであり、②を通した後に判定することで、単純な文字列長判定で起きる不自然さ（負号や `0.000000...` の扱い）を回避する。

### 6-3-1. 共通フォーマット処理 [必須B] B4

**数値を表示用文字列に変換する処理を、単一の関数として実装する。** 実装者による解釈の差を生まないため、以下の手順を上から順に、この通りに適用すること。

#### 入力

②の丸めを適用し、③④の範囲チェックを通過した数値 `v`。
（`v` は有限であり、`v === 0` または `1e-12 <= Math.abs(v) < 1e12` を満たす）

#### 手順

```
F1. v === 0 の場合、文字列 "0" を返して終了する
    （JavaScriptでは -0 === 0 が true のため、-0 もここで "0" になる）

F2. s = v.toPrecision(12) とし、有効数字12桁の文字列を得る
    先頭の負号があれば取り外して別に保持する

F3. s を仮数部と指数部に分ける（e / E がなければ指数は0）
    仮数部の小数点より前の数字の個数を k とする
    （小数点がなければ仮数部の全桁数）
    仮数部から小数点を除いた数字列を digits とする
    指数部を符号付き整数 e として読み、p = k + e とする

F4. digits と p から、文字列操作だけで通常の10進表記を組み立てる
    ・p <= 0："0." ＋ 0を(-p)個 ＋ digits
    ・0 < p < digitsの長さ：digitsの先頭p桁 ＋ "." ＋ 残りの桁
    ・p >= digitsの長さ：digits ＋ 0を(p - digitsの長さ)個
    展開後の文字列を Number に変換し直さない

F5. 小数点がある場合に限り、小数部末尾の "0" を繰り返し除去する
    その後、末尾が "." なら除去する。整数部の末尾0は除去しない
    例: "0.300000000000" → "0.3"、"8.00000000000" → "8"

F6. 保持していた負号を付け直す
    結果が "-0" なら "0" を返し、それ以外は結果をそのまま返す
```

**実装方法は上記の `toPrecision(12)` と文字列による小数点移動に固定する。** 最新版Chrome / Safariで共通のECMAScript標準処理を使用し、ロケール依存の数値書式APIは使用しない。6-3②の `Number(result.toPrecision(12))` は維持し、表示処理ではその数値を有効数字12桁の文字列へ戻して指数表記を展開する。小数部を一律12桁に丸め直さないため、2進浮動小数点由来の余分な桁を表示せず、小さい値の有効数字も保持する。

#### 禁止事項 [必須B]

| # | 禁止する実装 | 理由 |
|---|---|---|
| NG1 | `String(v)` / `v.toString()` / テンプレートリテラル `` `${v}` `` による直接の文字列化 | `Math.abs(v) < 1e-6` の値で指数表記（`1e-7` 等）になるため |
| NG2 | `v.toPrecision(n)` の戻り値をそのまま表示に用いる | 同じく指数表記になり得るほか、`8.00000000000` のような末尾0が残るため |
| NG3 | 共通フォーマット処理に `toFixed()` を使用する | 一律の小数桁数では、大きい値に2進浮動小数点由来の余分な桁が現れ、小さい値の有効数字も失われるため |
| NG4 | 正規表現以外の方法で末尾0を「見た目だけ」隠す（CSS等） | 履歴・サブディスプレイと表示が食い違うため |

#### 適用範囲 [必須B]

**以下のすべてで、この共通フォーマット処理を用いる。**

| 適用先 | 該当章 |
|---|---|
| メインディスプレイに表示する計算結果 | 5-4 |
| 逐次計算の途中結果（S4で演算子を押したときの表示） | 7-3・8-1 |
| サブディスプレイに含まれる数値 | 11-2 |
| 履歴に含まれるすべての数値（左辺・右辺・途中結果・最終結果） | 10-2 |

**適用しないもの：** 利用者が入力中の値（`currentInput` の文字列）は、この処理を通さず**そのまま表示する**。`0.` や `1.50` のような入力途中の状態を保つ必要があるため（6-2 I3・I4）。この処理は、**計算によって生成された数値、およびオペランドとして確定した数値にのみ適用する。**

#### オペランド確定時の変換 [必須B]

`currentInput` は「入力中の文字列」であり、「確定したオペランド」ではない。両者を次のように区別する。

| タイミング | 扱い |
|---|---|
| 利用者が数字・小数点を入力している間 | **`currentInput` の文字列をそのまま**メインディスプレイに表示する。`1.50` は `1.50`、`3.` は `3.` と表示される |
| 演算子または `=` によって**オペランドとして確定**するとき | **`Number(currentInput)` に変換し、共通フォーマット処理（F1〜F6）を適用する。** 得られた整形済み文字列を `expression`・サブディスプレイ・履歴に格納する |

**確定のタイミングは、7-3の状態遷移表で `accumulator` または `expression` に値を格納する瞬間である。** 具体的には次の3か所。

| # | 契機 | 確定するオペランド |
|---|---|---|
| 1 | S2 で演算子を押す | 左辺（`currentInput`） |
| 2 | S4 で演算子を押す | 右辺（`currentInput`）。あわせて途中結果も格納する |
| 3 | S4 で `=` を押す | 右辺（`currentInput`）。あわせて最終結果も格納する |

S1・S5 で演算子を押した場合の左辺は、すでに整形済みの数値（`0` または直前の計算結果）であるため、その値をそのまま用いる。

**メインディスプレイの表示は、確定によって書き換えない。** 演算子を押した直後（S3）のメイン表示は、7-3の表の通り変化しないため、`1.50` と入力して `+` を押した時点ではメインは `1.50` のままでよい。整形済みの `1.5` はサブディスプレイと履歴にのみ現れる。

#### 適用例

| 入力 | 入力中のメイン表示 | 履歴 |
|---|---|---|
| `1` `.` `5` `0` `+` `2` `.` `0` `0` `=` | `1.50` → `2.00` | **`1.5 + 2 = 3.5`** |
| `3` `.` `+` `2` `=` | `3.` → `2` | **`3 + 2 = 5`** |
| `0` `.` `5` `0` `×` `4` `=` | `0.50` → `4` | `0.5 × 4 = 2` |

**10-2の「履歴内のすべての数値は共通フォーマット処理で整形する」は、上記の確定タイミングで整形された文字列を用いることを意味する。** 履歴の生成時に改めて整形し直す必要はない。

### 6-5. 表示部の堅牢性 [必須B]

- `1e-12 <= |v| < 1e12` の範囲の値を有効数字12桁・指数表記なしで表示した場合の最大表示長は**26文字**（例：`-0.00000000000123456789123`）である。先頭の負号1文字＋`0.`の2文字＋小数部の先行0が最大11文字＋有効数字最大12文字となる。幅375pxでも、この最大表示長が読める大きさで1行に収まり、レイアウト崩れ・横スクロール・はみ出しが発生しないこと
- 桁区切り（`1,234,567`）は**実装しない**
- 指数表記は**実装しない**

## 7. 内部状態モデルと状態遷移

### 7-1. 内部状態変数 [必須B] B1

| 変数 | 型 | 内容 |
|---|---|---|
| `currentInput` | string | メインディスプレイに表示する数値。**文字列で保持する**（`0.` や先頭0の扱いが単純になる） |
| `accumulator` | number \| null | 確定済みの左辺の値 |
| `pendingOperator` | string \| null | 保留中の演算子 |
| `expression` | string[] | 構築中の式の部品。履歴とサブディスプレイの表示に用いる（10-2） |
| `state` | string | 下記の論理状態 |

### 7-2. 論理状態 [必須B] B1

| ID | 状態 | 説明 |
|---|---|---|
| **S1** | 初期 | 起動直後、または `AC` 直後。表示 `0`、左辺なし、保留演算子なし |
| **S2** | 数値入力中（演算子なし） | 1つ目の数値を入力している |
| **S3** | 演算子入力直後 | 演算子を押し、右辺がまだ入力されていない |
| **S4** | 右辺入力中 | 演算子の後に数値を入力している |
| **S5** | 結果表示中 | `=` を押して計算が確定した直後 |

## 8. 計算仕様

### 8-1. 逐次計算方式 [必須B] B2

**本アプリは逐次計算方式である。演算子の優先順位による計算は行わない。**

演算子を押した時点で、それまでの計算を確定する。

```
入力：5 + 3 × 2 =

5 → メイン表示 5
+ → accumulator=5、pendingOperator=＋
3 → メイン表示 3
× → この時点で 5＋3 を計算。accumulator=8、メイン表示 8、pendingOperator=×
2 → メイン表示 2
= → 8×2 を計算。メイン表示 16
```

**結果は 16 である**（通常の数式の優先順位では 11 だが、本アプリは逐次計算のため 16 となる）。

**この方式であることを、仕様書・履歴表記の双方で利用者に伝わるようにする**（10章）。

### 8-2. 計算の実行 [必須A] A1

| 演算子 | 処理 |
|---|---|
| `+` | `accumulator + Number(currentInput)` |
| `−` | `accumulator - Number(currentInput)` |
| `×` | `accumulator * Number(currentInput)` |
| `÷` | `accumulator / Number(currentInput)` |

計算後、必ず6-3の表示ルールを適用する。エラー条件に該当した場合はS6へ遷移する。

### 8-3. 連続した計算 [必須A] A3

以下の2つを満たすこととする。

| # | 内容 | 例 |
|---|---|---|
| K1 | `=` を押さずに演算子を続けられる（逐次計算） | `5 + 3 × 2 =` → `16` |
| K2 | 計算結果を次の計算の左辺として使える | `5 + 3 =` の後に `× 2 =` → `16` |

**`=` の連続押下によるリピート計算は実装しない**（7-3の `=` / S5 の通り）。

## 10. 履歴

### 10-1. 記録のタイミング [必須A] A4

| # | 仕様 |
|---|---|
| H1 | **`=` を押して計算が確定したときのみ、履歴を1件記録する** |
| H2 | 演算子を押して途中計算が確定しただけでは記録しない |
| H3 | エラーになった計算は記録しない（ER5） |
| H4 | `5 + 3 × 2 =` は**1件**として記録する（3件に分割しない） |

### 10-2. 履歴の表記形式 [必須B] B6

**通常の演算子優先順位による数式と誤認されない形式を用いる。**

`5 + 3 × 2 = 16` という表記は使用しない。通常の数式として読むと 11 になり、アプリが誤計算したように見えるためである。

#### 表記ルール

演算が1つの場合は通常の数式と同じ形式、2つ以上の場合は**途中結果を `→` で示す**。

| 入力 | 履歴の表記 |
|---|---|
| `5 + 3 =` | `5 + 3 = 8` |
| `5 + 3 × 2 =` | `5 + 3 → 8 × 2 = 16` |
| `5 + 3 × 2 ÷ 4 =` | `5 + 3 → 8 × 2 → 16 ÷ 4 = 4` |
| `12 ÷ 4 =` | `12 ÷ 4 = 3` |
| `5 + 3 =` の後に `× 2 =` | （2件目として）`8 × 2 = 16` |

#### 構築アルゴリズム [必須B]

`expression` 配列を用いて構築する。

```
① 演算子を押してS3へ入る（S1/S2/S5から）
   expression = [表示中の値]

② S4で演算子を押した（途中計算が確定した）
   expression に「演算子」「右辺」を追加
   さらに「→」「計算結果」を追加

③ S4で = を押した
   expression に「演算子」「右辺」を追加
   履歴行 = expression.join(" ") + " = " + 結果
```

**動作例（`5 + 3 × 2 =`）：**

| 操作 | `expression` |
|---|---|
| `5` `+` | `["5"]` |
| `3` `×` | `["5", "+", "3", "→", "8"]` |
| `2` `=` | `["5", "+", "3", "→", "8", "×", "2"]` → 履歴行 `5 + 3 → 8 × 2 = 16` |

**表記に用いる記号 [必須B]：** 演算子は画面のボタンと同じ `+` `−` `×` `÷` を用いる。途中結果の区切りは `→` を用いる。

**数値の表記：** 履歴内のすべての数値は、6-3-1の共通フォーマット処理で整形した文字列を用いる。**整形はオペランドが確定した時点で行い、`expression` には整形済みの文字列を格納する**（6-3-1「オペランド確定時の変換」）。したがって `1.50 + 2.00 =` の履歴は `1.5 + 2 = 3.5` となり、`3. + 2 =` の履歴は `3 + 2 = 5` となる。

### 10-3. 表示 [必須A] A4

| # | 仕様 |
|---|---|
| H5 | **新しい履歴を上に表示する**（新しい順） |
| H6 | 履歴が0件のときは「履歴はありません」等のメッセージを表示する |
| H7 | 履歴の各行が長い場合、折り返す、または省略表示する。横スクロールを発生させない |
| H8 | 履歴領域は、件数が増えたら縦スクロールできること |
| H9 | 履歴の表示は `textContent` で行う。`innerHTML` に文字列を連結しない |

### 10-4. 件数の上限 [必須B]

**上限は50件とする。** 50件を超えた場合、**最も古い履歴から削除する**。

### 10-5. 履歴のクリア [追加C] C3

| # | 仕様 |
|---|---|
| H10 | 履歴領域に「履歴をクリア」ボタンを設ける |
| H11 | 押すと**履歴を全件削除する** |
| H12 | **1件ずつの削除は実装しない** |

**実装しない。**

## 11. サブディスプレイ [追加C] C2

### 11-1. 目的

逐次計算方式では、`5 + 3 × 2` と入力している途中で「今どこまで計算が確定したか」がメインディスプレイから読み取れない。**現在の左辺と保留中の演算子を利用者が把握できるようにするための補助表示**である。

**履歴とは別物であり、高機能化を意図したものではない。**

### 11-2. 表示内容 [追加C]

**サブディスプレイには、構築中の `expression` と保留中の演算子を表示する。**

| 状態 | 表示内容 | 例 |
|---|---|---|
| S1（初期・AC直後） | **空** | （空） |
| S2（数値入力中） | **空** | （空） |
| S3（演算子入力直後） | `expression` ＋ 保留中の演算子 | `5 +` |
| S4（右辺入力中） | S3と同じ（変化させない） | `5 +` |
| S5（結果表示中） | 今回確定した式に `=` を付けたもの | `5 + 3 → 8 × 2 =` |
| S6（エラー） | **空**（ER4） | （空） |

**動作例（`5 + 3 × 2 =`）：**

| 操作 | サブディスプレイ | メインディスプレイ |
|---|---|---|
| （初期） | （空） | `0` |
| `5` | （空） | `5` |
| `+` | `5 +` | `5` |
| `3` | `5 +` | `3` |
| `×` | `5 + 3 → 8 ×` | `8` |
| `2` | `5 + 3 → 8 ×` | `2` |
| `=` | `5 + 3 → 8 × 2 =` | `16` |

### 11-3. 表示上の仕様 [必須B]

| # | 仕様 |
|---|---|
| SD1 | メインディスプレイより**小さい文字**で、その上部に表示する |
| SD2 | メインディスプレイの視認性を損なわないこと |
| SD3 | 表示が長くなった場合、右側（最新部分）が見えるようにする、または省略表示する。横スクロールを発生させない |
| SD4 | 空のときも表示領域の高さを確保し、レイアウトが上下に動かないこと |

### 12-3. Enterキーとフォーカスの競合対策 [必須B] ← 実装で必ず踏む問題

**ボタンにフォーカスがある状態で `Enter` を押すと、ブラウザの既定動作でそのボタンがクリックされる。** `Enter` に `=` を割り当てると、「数字ボタンをクリックした後に `Enter` を押すと、`=` ではなくその数字が再入力される」という不具合が発生する。

**対策として、以下のいずれかを必ず実装する：**

- `Enter` のキーイベントで `preventDefault()` を呼び、既定動作を抑止する
- ボタンのクリック処理の後にフォーカスを外す（`blur()`）

**受入チェックリストで確認する（16章 F-9）。**

## 付録：実装者へ渡す際の注意事項

実装依頼時、以下を省略せず伝えること。

1. **出力ファイルは `apps/part04-calculator/` 配下の `index.html` / `style.css` / `app.js` の3つのみ。** その他のファイルを作成しない
2. **フレームワーク・外部ライブラリ・CDN・Webフォントを使わない**
3. **本仕様書15章に列挙した機能を追加しない。** 仕様に無い機能を思いついても実装せず、提案にとどめる
4. **本アプリは逐次計算方式。** `2 + 3 × 4` は **20**。演算子優先順位による計算を実装しない
5. **7-3の状態遷移表の通りに実装する。** 6状態（S1〜S6）× 6入力種別のすべてを表の通りに動かす
6. **`5 + =` は何もしない。`=` の連続押下も何もしない**（リピート計算なし）
7. **`=` の後に数字を押すと新しい計算が始まる**（結果に追記しない）
8. **`=` の後に演算子を押すと結果が左辺になる**（連続計算）
9. **演算子を続けて押すと、後から押した演算子で上書きする**
10. **エラー判定は「有限でない値」「絶対値1e12以上」「0でなく絶対値1e-12未満」の3条件。** ゼロ除算を個別判定しない
11. **エラー状態からの復帰は `AC` のみ。** 他のすべての入力を無視する
12. **計算結果は `Number(result.toPrecision(12))` で丸めてから範囲チェックする。** 順序を逆にしない
13. **数値の文字列化は6-3-1の共通フォーマット処理で行う。** `v.toPrecision(12)` → 符号・仮数・指数の分離 → 文字列操作で通常の10進表記へ展開 → 小数部末尾0・末尾小数点の除去 → 負号復元・`-0` は `0`。`toFixed()` や数値の直接文字列化による表示、ロケール依存の書式APIは使わない。この処理をメイン表示・途中結果・サブディスプレイ・履歴で共通利用する。入力中の `currentInput` には適用しない
13b. **`currentInput` は入力中はそのまま表示し（`1.50`、`3.`）、演算子または `=` でオペランドとして確定する瞬間に `Number()` 変換＋共通フォーマット処理を適用して `expression`・サブディスプレイ・履歴に格納する。** `1.50 + 2.00 =` の履歴は `1.5 + 2 = 3.5`
13c. **指数表記・桁区切りを使わない**
14. **入力の桁数上限は数字12文字。** 小数点は数えない
15. **履歴は `=` 確定時のみ1件記録する。** 逐次計算の途中で複数件に分割しない
16. **履歴の表記は `5 + 3 → 8 × 2 = 16` 形式。** `5 + 3 × 2 = 16` と書かない（通常の数式として読むと誤りに見えるため）
17. **履歴は localStorage に保存しない。** 上限50件、古いものから削除
18. **「履歴をクリア」は履歴のみ全件削除し、計算状態に一切影響を与えない**
19. **サブディスプレイは構築中の式を表示する**（11-2の表の通り）
20. **キーボードとボタンは同一の内部処理を通す。** 別実装にしない
21. **`Enter` の既定動作を抑止する、またはボタンクリック後に `blur()` する**（フォーカス競合対策）
22. **メインディスプレイに `aria-live="polite"` を付け、履歴とサブディスプレイには付けない**
23. **`outline: none` を単独で指定しない**

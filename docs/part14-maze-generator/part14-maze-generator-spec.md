## 3. アルゴリズム仕様

### 3-1. 採用するアルゴリズム [必須A] A1/A6

**深さ優先探索（Recursive Backtracker / DFS）を採用する。**

```
① 開始セル（0, 0）を選び、訪問済みにする
② 現在セルの隣接セルのうち、未訪問のものを候補として列挙する
③ 候補があれば
   ・ランダムに1つ選ぶ
   ・現在セルと選んだセルの間の壁を取り除く（両側）
   ・現在セルをstackへ積む
   ・選んだセルへ移動し、訪問済みにする
④ 候補がなければ、stackから1つ取り出して現在セルとする（バックトラック）
⑤ 全セルを訪問するまで②〜④を繰り返す
```

### 3-2. 実装方式：明示的stack [必須B] B1

**再帰関数ではなく、明示的な `stack` 配列を用いた反復処理とする。**

| 観点 | 再帰 | **明示的stack（採用）** |
|---|---|---|
| コールスタック | セル数に比例して深くなる | 使わない |
| 大きな迷路 | **スタックオーバーフローの懸念** | 影響を受けない |
| デバッグ | スタックトレースが深くなる | stackの中身を直接確認できる |
| 実装量 | ほぼ同じ | ほぼ同じ |

**実測：30×30（900セル）でのstack最大深さは 623、最大ステップ数は 1793。** 現行サイズでは再帰でも動作するが、**明示的stackであれば、将来サイズを増やしても構造上の上限に当たらない。**

（21章 U1）

### 3-3. 「単純な乱数だけではない」の判定条件 [必須B] B2

**以下をすべて満たすことを、A6の判定条件とする。**

| # | 条件 |
|---|---|
| G1 | **訪問管理が存在する**（各セルに `visited` があり、全セルが訪問済みになる） |
| G2 | **隣接セルの列挙が存在する**（上下左右の範囲内かつ未訪問のセルを候補とする） |
| G3 | **壁の除去が隣接セル間で行われる**（両側の壁を同時に消す） |
| G4 | **stack によるバックトラックが存在する** |
| G5 | **生成結果が完全迷路である**（3-4） |

**禁止する実装 [必須A] A6：**

| # | 禁止 | 理由 |
|---|---|---|
| NG1 | **セルごとにランダムに壁をON/OFFするだけ** | 到達不能セルが生じ、迷路として成立しない。課題文が明示的に禁止している |
| NG2 | 迷路パターンをあらかじめ用意して選ぶ | 「自動生成」ではない |

### 3-4. 完全迷路の性質 [必須A] / [必須B] B4

**DFSで生成した迷路（難易度処理前）は、以下を満たす。**

| # | 性質 |
|---|---|
| P1 | **全セルが到達可能**（STARTからすべてのセルへ行ける） |
| P2 | **STARTからGOALへ必ず到達できる** |
| P3 | **セル間の経路が一意**（ループがない） |

**グラフとしての判定方法 [必須B] B4：**

```
頂点 V = rows × cols（セル）
辺 E = 隣接セル間で壁が取り除かれている箇所の数（通路数）

完全迷路（木）であることの判定：
  ① E === V - 1
  ② STARTからの到達可能セル数 === V（連結）

①と②を両方満たすとき、そのグラフは「木」である
→ 全セル到達可能かつ経路が一意
```

**「見た目が迷路っぽい」では判定しない [必須B] B4。** 上記2条件は決定的に判定でき、実装の誤りを確実に検出できる。

**実測結果：** 10×10 / 20×20 / 30×30 の各サイズで200回ずつ生成し、**すべての回で `E === V-1`・全セル到達可能・GOAL到達可能・壁整合・全セル訪問済みが成立した**（600回中600回）。

### 3-5. 範囲外への移動の禁止 [必須B]

**隣接セルの候補を列挙する際、グリッドの範囲外を候補に含めない。**

```
nr < 0 || nr >= rows || nc < 0 || nc >= cols → 候補から除外
```

**この結果、外周の壁は取り除かれない**（3-6）。

### 3-6. 外周壁 [必須B]

**外周（グリッドの最外周）の壁は、生成時にも難易度処理時にも取り除かない。**

| # | 仕様 |
|---|---|
| P4 | 最上段のセルの `top`、最下段の `bottom`、最左列の `left`、最右列の `right` は**常に `true`** |
| P5 | 難易度処理の対象は**内部の隣接セル間の壁のみ**（5-2） |

## 4. 迷路データ構造

### 4-1. セル [必須B] B3

```js
{
  visited: boolean,  // 生成時の訪問管理に使う
  top: boolean,      // true = 壁あり、false = 通路
  right: boolean,
  bottom: boolean,
  left: boolean
}
```

**迷路全体は `grid[row][col]` の2次元配列とする。**

### 4-2. 壁の整合性 [必須B] B3 ← 必ず守る

**隣接するセル間の壁情報は、常に一致していなければならない。**

| 関係 | 常に成立すること |
|---|---|
| 横 | `grid[r][c].right === grid[r][c+1].left` |
| 縦 | `grid[r][c].bottom === grid[r+1][c].top` |

| # | 仕様 |
|---|---|
| W1 | **壁を取り除くときは、必ず両側を同時に `false` にする** |
| W2 | **片側だけ消えた状態を作らない** |
| W3 | 生成時（3-1 ③）・難易度処理時（5-2）の**両方**でW1を守る |

**片側だけ消えると何が起きるか [必須B] B3：** 描画では壁が消えて見えるのに、到達可能性の判定では壁があることになる（またはその逆）。**「見えているのに通れない」通路が生じ、迷路として破綻する。**

**受入テストで全セルの整合性を確認する**（17章 C-4）。

### 4-3. 通路数の数え方 [必須B]

**重複して数えないため、各セルについて `right` と `bottom` のみを見る。**

```js
for (r) for (c) {
  if (c + 1 < cols && grid[r][c].right === false) count += 1;
  if (r + 1 < rows && grid[r][c].bottom === false) count += 1;
}
```

**`left` と `top` も数えると、すべての通路を2回数えてしまう [必須B]。**

### 4-4. `visited` の扱い [必須B]

| # | 仕様 |
|---|---|
| W4 | `visited` は生成アルゴリズムの内部状態である |
| W5 | 生成後、全セルが `visited: true` になっている |
| W6 | 描画には使用しない |

## 5. サイズ仕様・難易度仕様

### 5-1. サイズ [必須A] A2

**`<select>` で3段階から選ぶ。**

| 内部値 | 表示名 | セル数 | 内部壁の総数（実測） |
|---|---|---|---|
| `10` | **小（10×10）** | 100 | 180 |
| `20` | **中（20×20）** | 400 | 760 |
| `30` | **大（30×30）** | 900 | 1740 |

| # | 仕様 |
|---|---|
| S1 | **初期値は `20`（20×20）** |
| S2 | 行数と列数は常に同じ（正方形） |
| S3 | 任意の行列数を入力するUIは実装しない（[MVP外]。2-2 の14） |
| S4 | **`select.value` は文字列のため、`Number()` で数値へ変換する** |

**`<select>` を採用する理由 [必須B]：** 不正値の検証が不要になり、スマートフォンでも扱いやすく、**Canvasの内部解像度との整合（8章）を3パターンだけ考慮すればよい。**

### 5-2. 難易度 [必須A] A5

**DFSで生成した完全迷路から、追加で壁を取り除くことで難易度を変える。**

| 内部値 | 表示名 | 追加除去率 | 迷路の性質 |
|---|---|---|---|
| `hard` | **むずかしい** | **0%** | 完全迷路のまま（`E = V - 1`） |
| `normal` | **ふつう** | **8%** | 少量のループ・迂回路がある |
| `easy` | **かんたん** | **18%** | 複数経路が多い |

**除去率の基準は「DFS生成後に残っている内部壁の数」に対する割合とする [必須B]。**

| # | 仕様 |
|---|---|
| D1 | **初期値は `normal`（ふつう）** |
| D2 | **難易度処理はDFS生成後に行う**（生成中に壁を余分に消さない） |
| D3 | **対象は内部の隣接セル間の壁のみ。外周壁を取り除かない**（3-6） |
| D4 | **同じ壁を二重に処理しない**（対象の列挙時に各ペアを1回だけ数える。4-3と同じ方式） |
| D5 | **すでに通路になっている箇所を対象に含めない**（残っている壁のみを対象とする） |
| D6 | **壁の除去は到達不能セルを作らない**（除去は接続を増やす操作であり、原理的に連結性を壊さない） |
| D7 | 除去する壁は**ランダムに選ぶ**（5-2-2の方式による） |
| D8 | **除去する壁の数は切り捨てで求める**（5-2-1） |

### 5-2-1. 除去する壁数の丸め規則 [必須B] ← 必ず固定する

```js
const removeCount = Math.floor(remainingWalls.length * ratio);
```

| # | 仕様 |
|---|---|
| D9 | **`Math.floor`（切り捨て）を用いる。** `Math.round` `Math.ceil` を使わない |
| D10 | `remainingWalls` は、**DFS生成後に残っている内部壁のみ**を集めた配列（5-2 D3・D5） |
| D11 | `removeCount` が対象数を超えることはない（`ratio < 1` のため） |

#### 期待除去数（実測） [必須B]

**DFS生成後に残る内部壁の数は、サイズごとに常に一定である。**

```
残存内部壁 = 内部壁の総数 − 通路数
           = 内部壁の総数 − (V − 1)
```

DFS基本迷路の通路数は常に `V - 1`（3-4）であるため、**残存壁数は生成のたびに変わらない。**

| サイズ | 内部壁の総数 | 残存内部壁 | **ふつう（8%）** | **かんたん（18%）** |
|---|---|---|---|---|
| 10×10 | 180 | **81** | **6** | **14** |
| 20×20 | 760 | **361** | **28** | **64** |
| 30×30 | 1740 | **841** | **67** | **151** |

**実測：** 各サイズ・各難易度で50回ずつ生成し、**実際の除去数が上表と一致しないケースは0件**であった。また、残存壁数の種類はサイズごとに1通りのみ（10×10なら常に81）であった。

**この数値は決定的である [必須B]。** 乱数に依存しないため、**受入テストで固定値として判定できる**（17章 E-13〜E-15）。

### 5-2-2. 除去対象のランダム選択方法 [必須B] ← 必ず固定する

**`randomFn` を用いた Fisher–Yates シャッフルで対象を並べ替え、先頭から `removeCount` 件を取る。**

```js
// 残存壁の配列を Fisher–Yates でシャッフルする
for (let i = walls.length - 1; i > 0; i -= 1) {
  const j = Math.floor(randomFn() * (i + 1));
  const tmp = walls[i];
  walls[i] = walls[j];
  walls[j] = tmp;
}
// 先頭から removeCount 件を取り除く
```

| # | 仕様 |
|---|---|
| D12 | **`randomFn` を使用する。`Math.random()` を直接呼ばない**（6-1 R3） |
| D13 | **`array.sort(() => randomFn() - 0.5)` を使用しない** |
| D14 | **同一シードなら、DFS生成＋難易度処理まで含めて同一の迷路が再現できること** |
| D15 | シャッフルの代わりに「重複を許さずランダムに `removeCount` 件を選ぶ」方式を採ってもよいが、**D12〜D14を満たすこと** |

#### `sort` によるシャッフルを禁止する理由 [必須B]

**`array.sort(() => random() - 0.5)` は一様なシャッフルにならない。**

**実測（10要素を10万回シャッフルし、元の先頭要素が各位置に来た回数）：**

| 方式 | 分布 | 最小 | 最大 | 差 |
|---|---|---|---|---|
| **`sort` 方式** | 19435 / 13768 / 8866 / 7596 / 6814 / 7482 / 8142 / 8518 / 9206 / 10173 | 6814 | **19435** | **12621** |
| **Fisher–Yates** | 9810 / 10125 / 9939 / 10179 / 9971 / 10027 / 9914 / 10003 / 10020 / 10012 | 9810 | 10179 | **369** |

**`sort` 方式では、元の先頭要素が先頭に残る確率が約2倍**になっている。実装が短く一見動くため採用されやすいが、**壁の除去位置が迷路の一部に偏る。**

#### 決定性の実測 [必須B]

| 確認内容 | 結果 |
|---|---|
| 同一シード・同一難易度で2回生成 | **完全に一致** |
| 異なるシード・同一難易度 | **別の迷路になる** |
| 同一シード・異なる難易度 | 別の迷路になる |

**DFS生成と難易度処理の両方で同じ `randomFn` を使うことで、生成全体が決定的になる [必須B]。**

### 5-3. 除去率の実測根拠 [必須B] B5

**20×20 で、除去率ごとに100回ずつ生成した実測値。**

| 除去率 | 追加通路数 | 総通路数 | 最短経路長（平均） | 最短経路長（範囲） |
|---|---|---|---|---|
| **0%（むずかしい）** | 0.0 | 399.0 | **153.5** | 62〜248 |
| 5% | 18.0 | 417.0 | 74.9 | 48〜130 |
| **8%（ふつう）** | **28.0** | **427.0** | **58.5** | 40〜98 |
| 10% | 36.0 | 435.0 | 55.2 | 40〜82 |
| 15% | 54.0 | 453.0 | 47.2 | 38〜70 |
| **18%（かんたん）** | **64.0** | **463.0** | **44.5** | 38〜62 |
| 25% | 90.0 | 489.0 | 41.0 | 38〜50 |
| 30% | 108.0 | 507.0 | 39.5 | 38〜52 |

**8% と 18% を選んだ理由 [必須B] B5：**

| # | 理由 |
|---|---|
| 1 | **0% → 8% で最短経路長が 153.5 → 58.5 と大きく変わる。** 体感の差が出やすい |
| 2 | 8% → 18% でも 58.5 → 44.5 と差が残る |
| 3 | **25%以上は最短経路長がほぼ横ばい**（41.0 → 39.5）になり、除去率を上げても難易度が変わらなくなる |
| 4 | 30%まで上げると通路が多すぎ、**迷路というより開けた広間**に近づく |

**3段階での実測（各サイズ100回）：**

| サイズ | 難易度 | 追加通路数 | 総通路数 | 最短経路長（平均） | 行き止まりの数 |
|---|---|---|---|---|---|
| 10×10 | むずかしい | 0.0 | 99.0 | 47.3 | 11.8 |
| 10×10 | ふつう | 6.0 | 105.0 | 27.6 | 9.9 |
| 10×10 | かんたん | 14.0 | 113.0 | 22.2 | 7.5 |
| 20×20 | むずかしい | 0.0 | 399.0 | 151.0 | 42.1 |
| 20×20 | ふつう | 28.0 | 427.0 | 60.9 | 33.5 |
| 20×20 | かんたん | 64.0 | 463.0 | 44.5 | 25.0 |
| 30×30 | むずかしい | 0.0 | 899.0 | 321.4 | 91.9 |
| 30×30 | ふつう | 67.0 | 966.0 | 90.0 | 72.4 |
| 30×30 | かんたん | 151.0 | 1050.0 | 66.7 | 53.0 |

**すべてのサイズ・難易度で、追加通路数と行き止まりの数が単調に変化している。**

（21章 U4）

### 5-4. 難易度について保証しないこと [必須B] B5 ← 重要

**「かんたんの方が必ず最短経路が短い」ことを保証しない。仕様にもテストにも含めない。**

**実測：** 20×20 で「かんたん」と「ふつう」を独立に100組生成したところ、**10組（10%）で、かんたんの最短経路の方が長かった。**

**理由：** 最短経路長は元のDFS迷路の形に大きく依存する。「むずかしい」の範囲は 62〜248、「ふつう」は 40〜98 と幅が重なる。**壁除去によって短くなる傾向はあるが、個々の生成結果で必ず成立するわけではない。**

**受入テストで判定するのは、仕様として確実に保証できる構造のみとする [必須B]：**

| 判定する（構造） | 判定しない（傾向） |
|---|---|
| むずかしい：`E = V - 1` | 最短経路長の大小 |
| ふつう：むずかしいより通路数が多い | 体感の難しさ |
| かんたん：ふつうより通路数が多い | 分岐の見え方 |
| いずれも全セル到達可能 | |

**実際の難しさは、17章 P（実使用による最終確認）で人間が確認する [必須B]。**

**この二段構えが本Partの要点である。** 構造的な違いは自動テストで、体感的な難易度は人間が判定する。**「人間には難しく見える」を無理に自動テスト化すると、保証できない条件を仕様に書くことになる。**

### 5-5. サイズ・難易度変更時の挙動 [必須B]

**変更しただけでは再生成しない。「新しい迷路を生成」ボタンを押したときに、現在の設定で生成する。**

| 方式 | 評価 |
|---|---|
| **ボタン押下時に生成（採用）** | サイズと難易度を両方変えてから1回で生成できる。意図しない生成が起きない |
| 変更時に即時生成 | サイズを変えた瞬間に生成され、続けて難易度を変えると**2回生成される**。無駄が生じる |

| # | 仕様 |
|---|---|
| S5 | サイズ・難易度を変更しても、**表示中の迷路は変わらない** |
| S6 | 次回の生成から新しい設定が反映される |
| S7 | 初回表示時は、初期設定（20×20・ふつう）で1回だけ自動生成する（12-2） |

## 6. 乱数仕様

### 6-1. 乱数関数の注入 [必須B] B6


### 6-3. 境界値での動作 [必須B]

**実測（5×5）：**

| `randomFn` | 全セル訪問 | 通路数 | 壁整合 |
|---|---|---|---|
| 常に `0` を返す | **true** | 24（= V-1） | **不一致0件** |
| 常に `0.9999999999999999` を返す | **true** | 24（= V-1） | **不一致0件** |

**候補配列の添字は `Math.floor(randomFn() * candidates.length)` で求める [必須B]。** `Math.round` を使うと**配列の範囲外**（`undefined`）を参照する。

## 8. Canvas描画仕様

### 8-1. 採用理由 [必須A] A3

**`<canvas>` を1つ使い、JavaScript で壁・通路・START・GOAL を描画する。**

| # | 理由 |
|---|---|
| 1 | 格子状の迷路の描画に適している |
| 2 | 30×30 = 900セル分のDOM要素を作らずに済む |
| 3 | 10×10〜30×30 では十分軽量 |

### 8-2. 責務の分離 [必須B] B9

**迷路生成ロジックとCanvas描画ロジックを分離する。**

```
generateMaze(rows, cols, randomFn)          → 迷路データを返す
removeExtraWalls(grid, rows, cols, ratio, randomFn) → 迷路データを変更する
drawMaze(canvas, grid, rows, cols)          → 迷路データを描画する
```

| # | 仕様 |
|---|---|
| C1 | **生成関数はCanvasに触らない** |
| C2 | **描画関数は迷路データを変更しない** |
| C3 | **Canvasの描画内容を状態として読み戻さない**（`getImageData` 等を使わない） |
| C4 | 迷路データを唯一の正とする（12-1 S2） |

### 8-3. 内部解像度と表示サイズ [必須B] B7 ← 重要

**CSS表示サイズ・`canvas.width/height`・`devicePixelRatio` の3つを明確に扱う。**

```
① CSS表示サイズを決める（cssSize）
   ・コンテナの幅と、PCでの最大幅から算出する
   ・375px幅でもはみ出さない値にする

② devicePixelRatio を取得する
   const dpr = window.devicePixelRatio || 1;

③ 内部解像度を設定する
   canvas.width  = Math.round(cssSize * dpr);
   canvas.height = Math.round(cssSize * dpr);

④ CSS側で表示サイズを固定する
   canvas.style.width  = cssSize + "px";
   canvas.style.height = cssSize + "px";

⑤ 描画座標をスケールする
   ctx.setTransform(dpr, 0, 0, dpr, 0, 0);
   （以降は cssSize を基準とした座標で描画できる）
```

| # | 仕様 |
|---|---|
| C5 | **`canvas.width` / `canvas.height` を CSS だけで変えない** |
| C6 | **CSSで縮小するだけの実装をしない**（内部解像度とのずれでぼやける） |
| C7 | サイズ変更時・生成時に、上記①〜⑤をやり直す |
| C8 | `canvas.width` に代入すると内容がクリアされる。**代入は描画前に行う** |

**C6の理由 [必須B] B7：** `canvas.width = 600` のまま CSS で `width: 300px` にすると、高DPI環境では逆に鮮明になるが、**低DPI環境では縮小されて線がぼやける。** `devicePixelRatio` を掛けて内部解像度を決めることで、**どの環境でも1CSSピクセルあたりの解像度が一定になる。**

### 8-4. 描画内容 [必須A] A3

| # | 仕様 |
|---|---|
| C9 | セルを正方形として、格子状に描画する |
| C10 | 壁がある辺のみ線を引く |
| C11 | 外周は常に線が引かれる（3-6） |
| C12 | START（0,0）と GOAL（rows-1, cols-1）に背景色と文字（`S` / `G`）を描画する |
| C13 | **30×30 でも壁が判別できる線幅とする**（8-5） |
| C14 | 描画前にCanvasをクリアする |

### 8-5. セルサイズと線幅 [必須B]

| # | 仕様 |
|---|---|
| C15 | セルの1辺の長さは `cssSize / cols` で求める |
| C16 | 線幅はセルサイズに応じて決める。**30×30 でも線が消えたり潰れたりしないこと** |
| C17 | 線の座標を0.5ピクセルずらす等、にじみを抑える処理を行ってよい |

**375px幅・30×30 の場合、コンテナ幅を約343pxとするとセルは約11.4px [必須B]。** この大きさで壁が判別できることを受入テストで確認する（17章 K-4）。

### 8-6. 描画のタイミング [必須B]

| # | 契機 |

### 21-1. 除去する壁数と期待値（U12）

**DFS基本迷路の通路数は常に `V - 1` であるため、残存内部壁の数はサイズごとに一定である。**

| サイズ | 内部壁の総数 | 残存内部壁 | ふつう（8%） | かんたん（18%） |
|---|---|---|---|---|
| 10×10 | 180 | 81 | **6** | **14** |
| 20×20 | 760 | 361 | **28** | **64** |
| 30×30 | 1740 | 841 | **67** | **151** |

**実測：** 各サイズ・各難易度で50回ずつ確認し、**実際の除去数が上表と一致しないケースは0件**であった。残存壁数の種類もサイズごとに1通りのみであった。

**この値は乱数に依存しないため、受入テストで固定値として判定できる**（17章 E-13〜E-17）。

### 21-2. Fisher–Yates を用いる根拠（U13）

**`array.sort(() => random() - 0.5)` は一様なシャッフルにならない。**

**実測（10要素を10万回シャッフルし、元の先頭要素が各位置に来た回数）：**

| 方式 | 最小 | 最大 | 差 |
|---|---|---|---|
| `sort` 方式 | 6814 | **19435** | **12621** |
| Fisher–Yates | 9810 | 10179 | **369** |

**`sort` 方式では、元の先頭要素が先頭に残る確率が約2倍になる。** 壁の除去位置が迷路の一部に偏るため、採用しない。

**あわせて、DFS生成と難易度処理の両方で同じ `randomFn` を使うことで、生成全体が決定的になる。** 実測で、同一シードなら難易度処理まで含めて完全に一致することを確認した（17章 E-21）。

### 21-3. 確率的な条件を合否判定に用いない（U6・U14）

**以下は必須条件としない。**

| 項目 | 理由 |
|---|---|
| 「連続10回すべて異なる迷路になる」（G-2） | 偶然の一致は仕様上許容する。**正しい実装がテストで落ち得る** |
| 「生成時間が1ms未満」（M-2） | ブラウザの計測値は端末・DevToolsの状態で変動する |

**代わりに判定するもの：**

| 項目 | 判定方法 |
|---|---|
| 乱数処理の正しさ | **決定的テスト**（同一シード → 同一迷路、異なるシード → 異なる迷路） |
| 性能 | **体感**（即座に生成され、操作を妨げる遅延がない） |

**Part 9〜13で確立した「保証できる構造だけをテストし、体感は人間が判定する」方針の延長である。**

## 3. 入力仕様

### 3-1. 入力欄 [必須A] A1

| # | 仕様 |
|---|---|
| I1 | **`<textarea>` を用いる** |
| I2 | 折り返しは既定のまま（`soft`）とする |
| I3 | 初期状態は空。プレースホルダで案内を示してよい |
| I4 | `maxlength` は設定しない（貼り付け時に無言で切り詰められ、利用者が気づけないため） |

### 3-2. 更新契機 [必須A] A7 / [必須B] B8

**入力の変更に追従して自動的に分析する。分析ボタンは設けない。**

課題文は「入力と同時、または分析ボタン押下」としており、**どちらでもよい**。リアルタイム方式を採用する。

| # | 契機 | イベント |
|---|---|---|
| T1 | テキストエリアの入力 | `input` |
| T2 | IME変換の確定 | `compositionend` |

| # | 仕様 |
|---|---|
| T3 | **デバウンス 250ms を入れる**（11-3） |
| T4 | **`compositionstart` から `compositionend` までの間は分析を実行しない** |
| T5 | すべての契機が同一の分析処理を通る（契機ごとに別処理を書かない） |
| T6 | デバウンス待機中は前回の結果が残る。待機後に**全項目を再計算・再描画する** |
| T7 | **入力を削除して空にしたら、すべての結果を0（およびランキングを空）に戻す** |

**T4の理由 [必須B] B8：** 日本語入力の未確定文字列は `value` に現れるため、変換中に分析が走ると、確定前の文字が文字数・単語数に混入し、数値が激しく変動する。日本語文章の分析ツールでは常時発生する。

（16章 U1・U14）

### 3-3. 入力値の扱い [必須B]

| # | 仕様 |
|---|---|
| V1 | **テキストエリアの原文をそのまま分析対象とする。** 前後の空白・改行を除去しない |
| V2 | テキストエリアの表示内容を書き換えない |
| V3 | 改行コードの正規化のみ、行数・段落数の計算内部で行う（6-1） |

**V1の理由：** 前後の空白・改行も文字数・行数の計測対象である。除去すると計測結果が入力と一致しなくなる。

### 3-4. 空入力 [必須B] B9

| # | 仕様 |
|---|---|
| V4 | 入力が空文字の場合、**エラーとしない** |
| V5 | 文字数・単語数・行数・段落数・各文字種をすべて **0** と表示する |
| V6 | 頻出単語ランキングは空とし、「単語がありません」等の案内を表示する |
| V7 | エラーメッセージを表示しない |

**空入力をエラーにしない理由：** 起動直後と、入力を全消去した直後は必ず空になる。

### 3-5. 文字数上限 [必須B] B10

**入力が 100,000 文字（書記素クラスター。4章）を超える場合、分析を行わずエラーを表示する。**

- メッセージ：`文章が長すぎます（10万文字まで）`
- 上限超過時は、すべての結果を空にする（前回の結果を残さない）
- 判定はJavaScript側で行う

**上限を設ける理由：** `Intl.Segmenter` による単語分割は文字数に対して線形以上のコストがかかり、上限が無いと貼り付け1回でブラウザが応答しなくなる。

（16章 U13）

## 4. 文字数の定義

### 4-1. 計数単位 [必須B] B1

**文字数は「書記素クラスター（grapheme cluster）」単位で数える。**

```
Intl.Segmenter(undefined, { granularity: "grapheme" })
```

| 方式 | `"👨‍👩‍👧"` | `"が"`（か＋濁点の合成） | 採否 |
|---|---|---|---|
| `str.length`（UTF-16コード単位） | 8 | 2 | **採用しない** |
| `[...str].length`（コードポイント） | 5 | 2 | **採用しない** |
| **書記素クラスター** | **1** | **1** | **採用する** |

**書記素クラスターを採用する理由 [必須B] B1：** 「文字数」は利用者が画面上で数える単位と一致すべきである。`.length` はサロゲートペアを2として数え、絵文字1個が2文字・8文字になる。**文章分析ツールとして、利用者の直感と食い違う数値を主指標にすべきではない。**

**`.length` やコードポイント数を併記しない [MVP外]。** 課題文に要求がない。

**`Intl.Segmenter` に依存する点に注意 [必須B]：** 文字数は `Intl.Segmenter` を必須とするため、**非対応環境では文字数・空白を除いた文字数も算出できない**。非対応時の扱いは5-5にまとめる。

（16章 U2）

### 4-2. 表示する2つの文字数 [必須A] A2

| # | 指標 | 定義 |
|---|---|---|
| 1 | **総文字数** | 入力されたすべての書記素クラスターの数。**空白・タブ・改行を含む** |
| 2 | **空白を除いた文字数** | 総文字数から、7-2で「空白」に分類される書記素を除いた数 |

**両方を表示する [必須A]。** 課題文の「文字数」がどちらを指すかは明示されていないが、文章分析ツールとして両方が必要である。

### 4-3. 改行の扱い [必須B]

**改行は総文字数に含める。** 空白を除いた文字数からは除く（8-2で改行は「空白」カテゴリに分類されるため）。

**改行コードの正規化 [必須B]：**

```
文字数の計算に先立ち、\r\n と \r を \n に置換する
  normalized = text.replace(/\r\n/g, "\n").replace(/\r/g, "\n")
```

**この正規化により、CRLF・CR・LF はいずれも「改行1文字」として数えられる。**

| 元の改行コード | 本ツールの文字数 |
|---|---|
| `あ\r\nい`（CRLF） | **3**（`あ` ＋ 改行1 ＋ `い`） |
| `あ\rい`（CR） | 3 |
| `あ\nい`（LF） | 3 |

**注意：** 元の文字列を JavaScript の `str.length` で数えると、`"あ\r\nい"` は4（`\r` と `\n` が別のコード単位）となる。**これは「元文字列上のコード単位数」であり、本ツールが表示する「文字数」ではない。** 本ツールは4-1の通り書記素クラスター単位で数え、かつ上記の正規化を経るため、**改行コードの違いで文字数が変わらない。**

| 入力 | 総文字数 | 空白を除いた文字数 |
|---|---|---|
| `あい` | 2 | 2 |
| `あ い` | 3 | 2 |
| `あ\nい` | 3 | 2 |
| `\n` | 1 | 0 |

（16章 U3）

## 5. 単語数の定義

### 5-1. 分割方法 [必須A] A3 / [必須B] B2

**`Intl.Segmenter` の単語分割を用いる。**

```
new Intl.Segmenter("ja", { granularity: "word" })
```

| # | 仕様 |
|---|---|
| W1 | **ロケールは `"ja"` に固定する** |
| W2 | セグメントのうち **`isWordLike === true` のものだけを「単語」とする** |
| W3 | 単語数は、`isWordLike` なセグメントの**総数**（重複を含む延べ数） |
| W4 | 外部の形態素解析ライブラリ・辞書を使用しない |
| W5 | 自前の単語分割ロジックを実装しない |

**ロケールを `"ja"` に固定する理由 [必須B] B2：** 日本語を含む文章を主対象とするため。`"ja"` を指定しても、英語部分は空白と語境界で正しく分割される。**利用者がロケールを切り替えるUIは実装しない**（[MVP外]）。

### 5-2. `isWordLike` による分類 [必須B] B2

`Intl.Segmenter` は、各セグメントに `isWordLike` フラグを付与する。

| セグメントの例 | `isWordLike` | 単語として数える |
|---|---|---|
| `今日` `天気` `いい` | `true` | ○ |
| `Hello` `world` | `true` | ○ |
| `123` `3.14` | `true` | ○ |
| `は` `の` `です`（助詞・助動詞） | `true` | **○**（5-4） |
| `、` `。` `!` `?` | `false` | × |
| `（半角スペース）` `（改行）` | `false` | × |
| `-` `/` `@` | `false` | × |

**句読点・記号・空白は `isWordLike === false` となるため、自動的に単語数から除外される [必須B]。** 独自の除外リストを実装する必要はない。

### 5-3. 分割結果の例 [必須B]

入力：`今日は良い天気です。Hello world 123`

| セグメント | `isWordLike` |
|---|---|
| `今日` | true |
| `は` | true |
| `良い` | true |
| `天気` | true |
| `です` | true |
| `。` | false |
| `Hello` | true |
| （空白） | false |
| `world` | true |
| （空白） | false |
| `123` | true |

→ **単語数 = 8**

**具体的な分割結果はブラウザのICU実装に依存する [必須B]。** 上表は目安であり、`今日は` が1セグメントになる、`良い` が `良` と `い` に分かれる等の差異があり得る。**受入テストでは「概ね妥当な単語数になること」を判定基準とし、特定の数値との完全一致を条件にしない**（15章 C）。

### 5-4. 助詞・助動詞の扱い [必須B] B2

**単語数には、助詞（`は` `の` `を`）・助動詞（`です` `ます`）を含むすべての `isWordLike` セグメントを数える。単語数から stop word を除外しない。**

**一方、頻出単語ランキングでは固定の stop word を除外する（9-6）。** 単語数とランキングで扱いを分ける。

| 対象 | stop word の除外 |
|---|---|
| **単語数**（5-1 W3） | **除外しない** |
| **頻出単語ランキング**（9章） | **除外する**（9-6の固定38語＋9-6-2のひらがな1文字） |

**扱いを分ける理由 [必須B] B2：** 「単語数」は文章に含まれる語の延べ数であり、助詞を除くと文章量の指標として正しくなくなる。一方「頻出単語ランキング」は**文章の内容を把握するための情報**であり、助詞・助動詞が上位を占めると目的を果たさない（9-6）。

（16章 U7）

### 5-5. `Intl.Segmenter` 非対応環境 [必須B] B3

**フォールバックを実装しない。**

本ツールは `Intl.Segmenter` を2つの用途で用いる。

| 用途 | 影響する項目 |
|---|---|
| 書記素分割（`granularity: "grapheme"`） | 総文字数、空白を除いた文字数、文字種集計 |
| 単語分割（`granularity: "word"`） | 単語数、頻出単語ランキング |

**文字種集計は書記素クラスター単位で判定する（8-2）ため、書記素分割にも依存する。**

#### 非対応時の各項目の扱い [必須B]

| 項目 | 非対応時 |
|---|---|
| **総文字数** | **「対応していません」と表示** |
| **空白を除いた文字数** | **「対応していません」と表示** |
| **単語数** | **「対応していません」と表示** |
| **文字種集計** | **「対応していません」と表示**（6カテゴリの数値を出さない） |
| **頻出単語ランキング** | **「対応していません」と表示** |
| **行数** | **通常どおり計算・表示する** |
| **段落数** | **通常どおり計算・表示する** |

**行数・段落数のみ計算できる理由 [必須B]：** この2つは改行コードの正規化と `\n` による分割のみで算出でき（6章・7章）、`Intl.Segmenter` に依存しない。

#### 実装上の仕様

| # | 仕様 |
|---|---|
| W6 | 起動時に `typeof Intl.Segmenter === "function"` を確認する |
| W7 | 利用できない場合、上表の通りに表示を切り替える |
| W8 | エラーで停止しない。コンソールに未処理の例外を出さない |
| W9 | **書記素・単語のいずれについても、簡易フォールバック（`str.length`・空白区切り等）を実装しない** |
| W10 | 非対応であることを、メッセージ領域にも1度だけ通知する（例：`このブラウザは文字単位の解析に対応していません。行数と段落数のみ表示します`） |
| W11 | 上限判定（3-5）は書記素数で行うため、非対応時は上限判定も行わない。入力の長短にかかわらず、行数・段落数は表示する |

**W9の理由 [必須B] B3：** 空白区切りによる単語分割は日本語で機能せず、「1文章＝1単語」という無意味な結果になる。文字数を `str.length` で代用すると、絵文字が2文字・8文字と数えられ、4-1で否定した挙動になる。**誤った数値を出すより、対応していないことを明示する方がツールとして正しい。**

対応対象ブラウザ（最新 Chrome / Safari）はいずれも `Intl.Segmenter` に対応しているため、通常この分岐には入らない。

（16章 U5）

## 6. 行数の定義

### 6-1. 改行コードの正規化 [必須B] B4

**行数・段落数の計算に先立ち、`\r\n` と `\r` を `\n` に置換する。**

```
normalized = text.replace(/\r\n/g, "\n").replace(/\r/g, "\n")
```

これにより、改行コードの違いで行数が変わらない。

### 6-2. 行数 [必須A] A4

| # | 仕様 |
|---|---|
| L1 | **空入力（空文字）のときは 0 行** |
| L2 | 空文字でない場合、**行数 = `\n` の個数 + 1** |
| L3 | **途中の空行を1行として数える** |
| L4 | **末尾の改行の後にできる空行も1行として数える** |

| 入力 | 行数 |
|---|---|
| `（空）` | **0** |
| `あ` | 1 |
| `あ\nい` | 2 |
| `あ\nい\n` | **3** |
| `\n` | **2** |
| `あ\n\nい` | 3 |
| `あ\r\nい`（CRLF） | 2 |

**L4の理由 [必須B] B4：** 「改行の個数 + 1」という定義は単純で一意に決まり、**利用者が改行キーを押した回数と対応する**。テキストエディタの行番号表示とも一致する。

**L1（空入力を0行）の理由：** 「何も入力されていない状態」を1行と表示するのは、他の統計（文字数0・単語数0）と整合しない。

（16章 U9）

## 7. 段落数の定義

### 7-1. 段落の定義 [必須A] A5 / [必須B] B5

**1行以上の空行で区切られたテキストブロックを1段落とする。**

| # | 仕様 |
|---|---|
| P1 | **空白文字のみからなる行も「空行」として扱う** |
| P2 | **連続する複数の空行は、1つの区切りとして扱う**（空段落を作らない） |
| P3 | 先頭・末尾の空行は段落を生じさせない |
| P4 | **空入力のときは 0 段落** |
| P5 | 空行のみで構成される入力も 0 段落 |
| P6 | 空行が1つも無い入力（改行があってもよい）は 1 段落 |

**P1で「空白のみの行」を空行とする理由 [必須B] B5：** 実際の文章では、段落の区切りにスペースやタブが残っていることがある。見た目上は空行であり、利用者は段落の区切りと認識する。

### 7-2. 判定方法 [必須B]

```
① 6-1の正規化を行う
② \n で行に分割する
③ 各行について、空白文字のみ（または空文字）なら「空行」と判定する
   判定に用いる空白：/^\s*$/ に一致するか
   ・\s は半角スペース・タブ・全角スペース（U+3000）等を含む
④ 空行でない行が連続する塊を1段落として数える
```

| 入力 | 段落数 |
|---|---|
| `（空）` | **0** |
| `あ` | 1 |
| `あ\nい` | **1**（空行が無いので1段落） |
| `あ\n\nい` | 2 |
| `あ\n\n\n\nい` | **2**（連続空行は1区切り） |
| `\n\nあ\n\n` | **1**（先頭・末尾の空行は段落を生まない） |
| `あ\n   \nい`（空白のみの行） | **2** |
| `\n\n\n` | **0** |

（16章 U10）

## 8. 文字種集計仕様

### 8-1. 方針 [必須A] A8 / [必須B] B6

**各文字を排他的に6カテゴリのいずれか1つに分類し、6カテゴリの合計が総文字数（4-2）と一致する設計とする。**

**排他的にする理由 [必須B] B6：** 合計が総文字数と一致することで、**分類漏れ・二重計上を利用者自身が検算できる**。カテゴリが重複していると、数値の意味が曖昧になる。

### 8-2. カテゴリ定義 [必須A] A8

**判定は書記素クラスター単位で行い、クラスターの先頭コードポイントで分類する。**

#### 判定手順 [必須B]

**以下の順に判定し、最初に一致した時点で分類を確定する。順序を変えると結果が変わる。**

```
① 空白        /\s/u                     → 空白
② 数字        /\p{Nd}/u                 → 数字
③ 英字        /\p{Script=Latin}/u       → 英字
④ 日本語      /[\p{Script=Hiragana}\p{Script=Katakana}\p{Script=Han}\u30FC\u3005]/u
                                        → 日本語
⑤ 絵文字      /\p{Extended_Pictographic}|\p{Regional_Indicator}/u
                                        → その他
⑥ 記号・句読点 /[\p{P}\p{S}]/u           → 記号・句読点
⑦ 上記以外                               → その他
```

#### カテゴリ一覧（6カテゴリ・排他）

| # | カテゴリ | 該当する判定 | 例 |
|---|---|---|---|
| 1 | **空白** | ① | 半角スペース、タブ、改行、全角スペース（U+3000） |
| 2 | **数字** | ② | `0`〜`9`、全角 `０`〜`９` |
| 3 | **英字** | ③ | `A`〜`z`、全角 `Ａ`〜`ｚ` |
| 4 | **日本語** | ④ | ひらがな、カタカナ、漢字、長音符 `ー`、踊り字 `々` |
| 5 | **記号・句読点** | ⑥ | `、` `。` `！` `?` `(` `+` `@` `#` |
| 6 | **その他** | ⑤・⑦ | **絵文字**、ハングル、キリル文字、制御文字など |

### 8-3. 絵文字の扱い [必須B] B6

**絵文字は「記号・句読点」ではなく「その他」に分類する。**

`😀` の Unicode 一般カテゴリは `So`（Symbol, other）であり、⑥の `\p{S}` に一致してしまう。**そのため、⑤で絵文字を先に判定して「その他」へ振り分ける。**

| # | 仕様 |
|---|---|
| E1 | 判定には `\p{Extended_Pictographic}` を用いる |
| E2 | **国旗絵文字（`🇯🇵`）は先頭コードポイントが地域表示子であり `Extended_Pictographic` に一致しないため、`\p{Regional_Indicator}` も併せて判定する** |
| E3 | E1・E2に一致したものは「その他」に分類する |
| E4 | 絵文字を独立したカテゴリとして表示しない（6カテゴリを維持する） |

**既知の副作用として、`©` `®` `™` `‼` なども `Extended_Pictographic` に含まれるため「その他」に分類される [必須B]。** これは分類が一意に定まる範囲での割り切りであり、仕様通りの動作とする。

**絵文字を独立カテゴリにしない理由：** 課題文の「英数字・記号・空白など」に絵文字は含まれておらず、カテゴリを増やすのは課題文にない機能追加にあたる。「その他」に含めれば、8-1の「合計＝総文字数」は維持される。

### 8-4. 全角英数字の扱い [必須B] B6

**全角英字は「英字」に、全角数字は「数字」に含める。**

`\p{Script=Latin}` は全角ラテン文字（U+FF21〜）を含み、`\p{Nd}` は全角数字（U+FF10〜）を含むため、8-2の判定②③で自動的にそうなる。**半角・全角で別カテゴリにしない。**

（16章 U12）

### 8-5. 改行・タブの扱い [必須B]

**改行・タブは「空白」カテゴリに含める。** `/\s/u` に一致するため、8-2の判定①で自動的にそうなる。

### 8-6. 日本語カテゴリ [必須B] B6

**日本語文字を独立したカテゴリとして表示する。**

課題文は「英数字・記号・空白など」と例示しており、日本語文字を明示していない。しかし、**日本語文章では大半の文字が日本語文字であり、これを「その他」に入れると集計がほぼ意味を持たなくなる**。8-1の「合計＝総文字数」を成立させるためにも必要である。

### 8-7. 表示 [必須A] A8

| # | 仕様 |
|---|---|
| N1 | 6カテゴリそれぞれの文字数を表示する |
| N2 | **6カテゴリの合計を表示し、総文字数と一致することを利用者が確認できるようにする** |
| N3 | 各カテゴリが0でも項目を隠さない（0と表示する） |
| N4 | グラフによる可視化は実装しない（[MVP外]） |

## 9. 頻出単語ランキング仕様

### 9-1. 対象 [必須A] A6

**5章で得た「`isWordLike === true` のセグメント」の集合を集計対象とする。**

単語数（5-1 W3）と同じ分割結果を用いる。**別の分割方法で集計しない。**

**ただし、ランキングの集計時に2種類の除外を行う。固定38語の stop word（9-6）と、ひらがな1文字の語（9-6-2）である。** 除外はランキングにのみ適用し、**単語数には一切影響させない。**

処理の順序：

```
① 単語分割（5-1）             → isWordLike なセグメントの配列
② 単語数を確定する（5-1 W3）   → ①の総数。ここで除外を行わない
③ 集計キーを作る（9-2）        → NFKC ＋ 小文字化
④ 固定38語を除外する（9-6）    → ③のキーがリストに含まれる語を集計から外す
⑤ ひらがな1文字を除外する（9-6-2）→ ③のキーがひらがな1書記素のみの語を集計から外す
⑥ 出現回数を集計する
⑦ 頻度順・同率時は初出順で並べる（9-5）
⑧ 上位10件を表示する（9-4）
```

**②が④・⑤より前にあることが重要である [必須B]。** 順序を逆にすると、**除外した語のぶん画面の「単語数」が減ってしまう。** 除外の対象はランキングの集計のみであり、単語数の確定は除外前に行う。

**④と⑤の順序は結果に影響しない**（どちらも集計対象から外すだけ）。実装しやすい順でよい。

### 9-2. 集計キーの正規化 [必須B] B7

**同じ語とみなす判定は、以下で正規化した文字列（集計キー）で行う。**

```
key = segment.normalize("NFKC").toLowerCase()
```

| 正規化 | 効果 | 例 |
|---|---|---|
| `NFKC` | 全角と半角を統一する | `ＡＢＣ` → `ABC`、`１２３` → `123`、`ｱ` → `ア` |
| `toLowerCase()` | 英字の大文字小文字を同一視する | `Apple` `APPLE` `apple` → `apple` |

**NFKC を用いる理由 [必須B] B7：** 全角英数字と半角英数字を別の単語として数えると、同じ語が複数の順位に分散し、ランキングとして意味を持たなくなる。

（16章 U6）

### 9-3. 表示する表記 [必須B] B7

**表示には正規化後のキーではなく、その語が文章中で最初に出現したときの元の表記を用いる。**

| 入力 | 集計キー | 表示 |
|---|---|---|
| `Apple` が2回、`apple` が1回（`Apple` が先） | `apple` | **`Apple`**（3回） |
| `ＡＢＣ` が1回、`ABC` が2回（`ＡＢＣ` が先） | `abc` | **`ＡＢＣ`**（3回） |

**元の表記を用いる理由 [必須B] B7：** 正規化後のキー（`apple`）を表示すると、**文章中に存在しない表記が結果に現れる**。分析ツールとしては、実際に書かれていた形を示す方が正しい。

**「最初に出現した表記」を代表とする理由：** 「最も多い表記」を選ぶ方法もあるが、同数の場合の決定方法が別途必要になる。**初出は常に一意に定まる。**

### 9-4. 件数 [必須A] A6

**上位10件を表示する。**

- 単語の種類が10未満の場合は、存在する分だけ表示する
- 件数の変更UIは実装しない（[MVP外]）

### 9-5. 並び順 [必須B] B7

| # | 規則 |
|---|---|
| R1 | **出現回数の降順** |
| R2 | **同数の場合は、文章中で先に出現した語を上位とする**（初出位置の昇順） |

**R2が必要な理由 [必須B] B7：** 日本語文章では同数の語が多数生じる。タイブレークを定めないと、順序が実行環境やオブジェクトのキー順に依存し、**受入テストで判定できなくなる。**

### 9-6. stop word の除外 [必須B] B7

#### 目的

**文章中で頻繁に使われる内容語を把握しやすくすること。**

助詞・助動詞は日本語文章で必然的に高頻度となるため、除外しないとランキングが `の / は / に / が / を / た / と / て / だ` などで占められ、**文章の内容を把握するという目的を果たさない。**

#### 適用範囲 [必須B]

| # | 仕様 |
|---|---|
| SW1 | **除外は頻出単語ランキングにのみ適用する** |
| SW2 | **単語数（5-1 W3）には一切影響させない。** stop word も単語数には含まれる |
| SW3 | 文字数・文字種集計・行数・段落数にも影響させない |
| SW4 | **判定はランキング用の正規化キー（9-2の `normalize("NFKC").toLowerCase()`）に対して行う** |
| SW5 | **外部の形態素解析・品詞判定を使用しない。固定リストとの完全一致のみで判定する** |
| SW6 | 部分一致・前方一致で判定しない（`のみ` は `の` を含むが、stop word ではない） |

#### stop word リスト [必須B]

**以下の38語を固定リストとする。実装者はこのリストを独断で増減してはならない。**

```
の  は  に  が  を  と  て  で  も  へ  や
から  まで  より
です  ます
た  だ  である
いる  ある  する  した  して
ない  な
こと  もの
これ  それ  あれ
って  か  っ  い  さん  れ  し
```

| 分類 | 語 | 語数 |
|---|---|---|
| 格助詞・係助詞・接続助詞など | `の` `は` `に` `が` `を` `と` `て` `で` `も` `へ` `や` | 11 |
| 複合助詞 | `から` `まで` `より` | 3 |
| 丁寧の助動詞 | `です` `ます` | 2 |
| 断定・過去の助動詞 | `た` `だ` `である` | 3 |
| 高頻度の補助用言 | `いる` `ある` `する` `した` `して` | 5 |
| 否定・形容動詞語尾 | `ない` `な` | 2 |
| 形式名詞 | `こと` `もの` | 2 |
| 指示語 | `これ` `それ` `あれ` | 3 |
| **口語助詞・終助詞** | **`って` `か`** | **2** |
| **活用語尾・分割断片** | **`っ` `い` `れ` `し`** | **4** |
| **接尾辞** | **`さん`** | **1** |
| **合計** | | **38** |

**リストの整理について [必須B]：** 重複はなく、38語すべてを採用した。いずれもひらがなのみで構成されるため、NFKC正規化・小文字化を経ても表記は変わらず、表記揺れの統合は不要である。

#### 後半7語の追加経緯 [必須B]

`って` `か` `っ` `い` `さん` `れ` `し` の7語は、**実装後に実データで確認した際、ランキング上位が活用語尾・機能語の断片で占められたことを受けて追加した**（16章 16-5）。

**ただし「実データで頻出した」という事実だけを追加理由としていない。** 各語について、次項の追加基準を個別に満たすことを確認したうえで追加している。

同じ観測で上位に現れた `よう` は、**追加していない**。「用がある」「酔う」「様」など、ひらがな表記で内容語となる用法が存在し、基準3（判断が分かれる語は追加しない）に該当するためである。**判断保留とし、別の文章で再びノイズとして観測された時点で、あらためて追加を判断する。**

#### stop word の追加基準 [必須B]

**新たに語を追加する場合、以下の3条件を「すべて」満たすことを確認する。**

| # | 基準 |
|---|---|
| 1 | **日本語の文法上、その表記が機能語・活用語尾・接尾辞・分割断片としてしか成立しない** |
| 2 | **同音の内容語が存在する場合、それらは漢字・カタカナ表記が標準である**（例：`し` に対する 詩・氏・市・四） |
| 3 | **判断が分かれる語は追加しない**（precision を優先し、recall は追求しない） |

| # | 運用上の規則 |
|---|---|
| 4 | **「実データで頻出した」という事実だけでは追加理由にしない。** 頻度は検討のきっかけに過ぎず、追加の必要条件ですらない |
| 5 | 基準1〜3の適用は依頼者が判断する。**実装者が独断で追加しない**（SW9） |
| 6 | 基準3に該当する語は「判断保留」とし、本仕様書に記録する |

**基準3を置く理由 [必須B]：** ノイズが残ることの損失（読みにくい）より、**重要な内容語を誤って消すことの損失（文章の主題が見えなくなる）の方が大きい**。ランキングの目的は文章内容の把握であり、内容語を失うと目的そのものが損なわれる。

### 9-6-2. ひらがな1文字の除外ルール [必須B] B7

**固定38語の除外に加え、「ひらがな1文字だけで構成される語」をランキングから除外する。**

これは個別語の列挙ではなく、**限定された一般条件による除外ルール**である。

#### 適用範囲 [必須B]

| # | 仕様 |
|---|---|
| HR1 | **除外は頻出単語ランキングにのみ適用する** |
| HR2 | **単語数（5-1 W3）には一切影響させない。** ひらがな1文字の語も単語数には含まれる |
| HR3 | 文字数・文字種集計・行数・段落数にも影響させない |
| HR4 | 固定38語の除外（9-6）と**併用する**。どちらか一方に置き換えない |
| HR5 | 判定はランキング用の正規化キー（9-2）に対して行う |

#### 判定方法 [必須B]

**「ひらがなの書記素が1つだけで構成される語」を除外する。**

```
① 語（正規化キー）を書記素クラスターに分割する
   Intl.Segmenter(undefined, { granularity: "grapheme" })

② 書記素が1つだけであることを確認する
   2つ以上なら除外しない

③ その書記素の先頭コードポイントが、ひらがなであることを確認する
   /\p{Script=Hiragana}/u に一致するか

④ ②③をともに満たす場合のみ、ランキングから除外する
```

| # | 仕様 |
|---|---|
| HR6 | **`.length` による単純な文字列長判定を用いない。** 4-1で定めた書記素クラスター単位の方針と整合させる |
| HR7 | **この変更のために外部形態素解析ライブラリ等を追加しない。** 既存の `Intl.Segmenter` を用いる |
| HR8 | 小書き文字（`っ` `ゃ` `ゅ` `ょ` `ぁ` 等）はひらがなであり、除外対象となる |
| HR9 | 濁点・半濁点が結合文字として表現された語（`か`＋`゛`）は1書記素であり、先頭コードポイントがひらがなのため除外対象となる |

#### 除外する／しない [必須B]

| 除外する | 除外しない |
|---|---|
| `よ` `ら` `し` `れ` `か` `っ` `い` `な` `て` `に` `を` | `ふぐ` `まり` `たこ` `うた` `ここ` `いつ` `なぜ`（**ひらがな2文字以上**） |
| （ひらがな1文字すべて） | `ネコ` `パン`（カタカナ） |
| | `胃` `蚊` `本` `雨`（漢字1文字） |
| | `A`（英字1文字） |
| | `1`（数字1文字） |

**「1文字以下」ではなく「ひらがな1文字のみ」である [必須B]。** 漢字・カタカナ・英字・数字の1文字語を一律除外してはならない。

#### 2文字以上へ拡張しない [必須B] ← 重要

**ひらがな2文字以上を除外する処理を、いかなる形でも追加してはならない。**

| # | 理由 |
|---|---|
| 1 | **`ふぐ` `まり` `たこ` `うた` など、ひらがな2文字でも文章の重要な内容語・主題語になり得る** |
| 2 | `ここ` `いつ` `なぜ` など、意味を持つ短いひらがな語が失われる |
| 3 | 一律除外の範囲を広げるほど、9-6の基準3（precision優先）と衝突する |

**閾値は「1文字」に固定する。実装者が閾値を変更・パラメータ化しない。**

#### このルールを採用した理由 [必須B]

**「今回の文章でたまたま `よ` `ら` が頻出したから、その2語を除外語に追加した」のではない。** 1文字ひらがなという**限定された一般条件**を採用したものである。

| # | 理由 |
|---|---|
| 1 | 実データで `よ` `ら` 等の1文字ひらがなが、ランキングのノイズとして残った |
| 2 | ただし、**個別語を際限なく固定リストへ追加する方式は採らない**（リスト肥大化と、他文章での重要語消失を招く） |
| 3 | **2文字以下を一律除外すると、`ふぐ` `まり` `たこ` `うた` 等の重要な内容語を失う** |
| 4 | **1文字ひらがなに限定すれば、副作用を大幅に抑えながら、分割断片・機能語ノイズを一般ルールで減らせる** |
| 5 | precision を優先し、**2文字以上にはルールを拡張しない** |

**日本語において、ひらがな1文字が単独で内容語として機能する場面は極めて限られる。** 同音の内容語（胃・蚊・血・目・手）はいずれも漢字表記が標準であり、9-6の追加基準2と同じ考え方に立つ。

#### 固定38語との関係 [必須B]

| # | 仕様 |
|---|---|
| HR10 | **固定38語を削除・整理・縮小しない**（9-6のリストをそのまま維持する） |
| HR11 | 本ルールにより38語の一部（`の` `は` `に` `が` `を` `と` `て` `で` `も` `へ` `や` `た` `だ` `な` `か` `っ` `い` `れ` `し`）が実質的に重複して除外されるが、**問題としない** |
| HR12 | 重複を理由に固定リストから語を削らない。**2つの仕組みを併用する** |

**重複を許容する理由：** 固定リストは「特定の語」を、本ルールは「一般条件」を担当する。片方を削ると、もう片方の変更時に予期しない穴が生じる。

#### 本ルールを理由に固定リストへ語を追加しない [必須B]

**`よう` `そう` `この` などを、今回の判断で stop word へ追加してはならない。**

- `よう` は **9-6の通り「判断保留」の状態を維持する**
- 本ルールは1文字ひらがなのみを対象とし、2文字以上の語には一切関与しない

### 9-6-3. 文字種・文字数による除外の適用範囲 [必須B]

**採用するのは「ひらがな1文字のみ」の除外に限る**（9-6-2）。

**以下は採用しない。**

| # | 不採用とするルール | 理由 |
|---|---|---|
| 1 | ひらがな**2文字以下**の一律除外 | `ふぐ` `まり` `たこ` `うた` を失う |
| 2 | ひらがな**3文字以下**の一律除外 | さらに `ことば` `きもち` `こども` 等を失う |
| 3 | ひらがなのみの語を**長さを問わず**除外 | ひらがな中心の文章で壊滅する |
| 4 | **文字種を問わない**1文字語の一律除外 | `胃` `蚊` `本` `雨` `A` `1` を失う |
| 5 | 語長によるスコア重み付け | 再現性が低く、受入テストで判定できない |

**除外の判断は、固定38語との完全一致（9-6）と、ひらがな1文字ルール（9-6-2）の2つのみで行う**（SW5・SW6・HR5）。

#### 実装上の注意 [必須B]

| # | 注意点 |
|---|---|
| SW7 | リストは `Set` として保持し、キーの完全一致で判定する |
| SW8 | **`である` `した` `して` は、`Intl.Segmenter` の分割によっては `で`＋`ある`、`し`＋`た`、`し`＋`て` に分かれ、リストと一致しないことがある。** その場合でも `で` `ある` `し` `た` `て` は個別に除外されるため、実用上の影響は小さい |
| SW9 | **ノイズとなる語がランキングに残っていても、実装者はリストを独断で追加しない。** 依頼者へ報告し、追加基準に照らした判断を仰ぐ |
| SW10 | 38語は本仕様書に記載した内容と完全に一致させる。**実装者が「似た語」を補完しない** |

#### 除外しないもの [必須B]

**以下は除外しない。**

| # | 対象 | 扱い |
|---|---|---|
| 1 | **漢字・カタカナ・英字・数字の1文字語**（`胃` `蚊` `本` `雨` `ネコ` `A` `1`） | **除外しない。** 文字種を問わない「1文字なら除外」というルールは採用しない（9-6-3） |
| 2 | **ひらがな2文字以上の語**（`ふぐ` `まり` `たこ` `うた` `ここ` `いつ` `なぜ`） | **除外しない**（9-6-2「2文字以上へ拡張しない」） |
| 3 | **数字のみの語**（`123`） | **除外しない** |
| 4 | 英語その他の言語の機能語（`the` `a` `is` など） | **除外しない。** 日本語以外について大規模な stop word 辞書を独断で追加しない |
| 5 | `よう` | **除外しない**（判断保留） |

**句読点・記号・空白は、5-2の時点で `isWordLike === false` として既に除外されている。** ランキング用の追加処理は不要である。

### 9-8. 表示する語が0件のとき [必須B]

以下のいずれの場合も、「単語がありません」等の案内を表示する。空のリストだけを表示しない。

| # | 状況 |
|---|---|
| 1 | 単語が1つも無い（記号・空白のみの入力など） |
| 2 | **単語はあるが、そのすべてが stop word だった**（例：`これはそれです` のみ） |

**2の場合でも、単語数は0にならない [必須B]。** 単語数には stop word が含まれるため（SW2）、「単語数は5だがランキングは空」という状態が正常に起こり得る。

### 9-9. 既知の制約 [必須B] ← 実装者・受入担当者は必読

**頻出単語ランキングには、以下の原理的な制約がある。これらは不具合ではなく、本ツールの設計上の前提である。**

| # | 制約 |
|---|---|
| K1 | **本ツールは外部形態素解析・品詞解析を使用しない**（2-3の技術方針）。この制約は課題の前提であり、変更しない |
| K2 | **`Intl.Segmenter` は単語境界を返すが、品詞情報を持たない。** ある語が名詞なのか助詞なのか活用語尾なのかを、実行時に判別する手段がない |
| K3 | **K1・K2の結果、内容語と機能語を完全には区別できない。** 固定リストとの完全一致という、表記に基づく判定しか行えない |
| K4 | **活用語尾・分割断片がランキングに残ることがある。** `Intl.Segmenter` は形態素境界で分割するため、`し` `れ` `っ` のような語が独立した単語として現れる |
| K5 | **固定 stop word（38語）を用いても、文章によってはノイズが残る。** 38語はあらゆる文章を網羅するものではない |
| K6 | **本ランキングは「完全な内容語抽出」ではなく、「簡易的な頻出語分析」である。** 課題文A6の要求水準を、本仕様書ではこの水準として定義する |
| K7 | **ひらがな1文字の内容語・意図的な表記も、ランキングから除外される**（9-6-2）。文章によっては、ひらがな1文字そのものに意味を持たせている場合があり得るが、それも除外される |
| K8 | **除外はあくまで表記に基づく機械的な判定であり、文脈を考慮しない。** 同じ表記が、ある文章では機能語、別の文章では内容語であっても区別できない |

**K7の副作用の位置づけ [必須B]：** この副作用は、「ひらがな2文字以下を一律除外する」場合（`ふぐ` `まり` `たこ` `うた` `ここ` `いつ` `なぜ` を失う）と比べて**限定的である**。K6の「簡易的な頻出語分析」という要求水準のもとで、**許容する設計判断とする**。

### 9-9-1. ノイズが見つかったときの対応 [必須B]

**ランキングにノイズが残っていることを発見しても、実装者が独断で stop word を追加してはならない**（SW9）。

| # | 手順 |
|---|---|
| 1 | 依頼者へ報告する |
| 2 | 依頼者が、9-6の追加基準（3条件）に照らして個別に判断する |
| 3 | 基準を満たす語のみ追加する。**基準3（判断が分かれる語は追加しない）に該当する語は「判断保留」として記録する** |
| 4 | 「実データで頻出した」という事実だけを追加理由にしない |

**K6の位置づけを明記する理由 [必須B]：** ランキングの要求水準を「完全な内容語抽出」と解釈すると、**文章を変えるたびにノイズが見つかり、そのつど stop word を追加する圧力がかかる。** リストが肥大化するほど、どこかの文章で重要な内容語を誤って消す確率が上がる（9-6 基準3）。**要求水準を仕様書上で定義しておくことが、リストの肥大化を防ぐ歯止めとなる。**

### 11-5. 判定基準 [必須B] B10

**性能目標と合否条件を分離する。**

#### 性能目標（参考値）

| 操作 | 目標 |
|---|---|
| 30,000文字の文章を貼り付けてから結果表示まで | 1秒程度 |
| 30,000文字の状態で文字を追加入力（デバウンス後） | 1秒程度 |

**上表は性能目標であり、厳格な合否条件ではない [必須B]。** 端末性能・ブラウザにより実測値は変動する。**秒数をわずかに超えただけで NG とはしない。**

#### 合否の判定基準 [必須B]

| # | 判定基準 | 種別 |
|---|---|---|
| J1 | **長時間UIが固まらない**（貼り付け後、画面が応答しないまま放置される状態にならない） | 体感 |
| J2 | **入力が実用不能なほど引っかからない**（文字を続けて打てる） | 体感 |
| J3 | **10万文字を超える入力でエラーが表示され、結果が空になる** | **厳格な合否条件** |
| J4 | **入力を空にしたとき、すべての結果が0に戻る** | **厳格な合否条件** |

**J3・J4のみ厳格な合否条件とする。** J1・J2は体感による判定とし、性能目標の秒数を参考に用いる。目標を大きく超える（数倍かかる、数秒間操作を受け付けない）場合に NG とする。

### 16-1. `Intl.Segmenter` 非対応時の扱いの修正（U5）

当初案では「単語数とランキングのみ非対応とし、その他の統計は通常表示」としていたが、**文字数（4-1）と文字種集計（8-2）も書記素分割に依存しており、`Intl.Segmenter` なしでは仕様どおり計算できない**という仕様内部の矛盾があった。

**依存関係を整理し、非対応時の扱いを確定した。**

| 用途 | 影響する項目 | 非対応時 |
|---|---|---|
| 書記素分割 | 総文字数、空白を除いた文字数、文字種集計 | 対応していません |
| 単語分割 | 単語数、頻出単語ランキング | 対応していません |
| （非依存） | 行数、段落数 | 通常どおり計算 |

**「対応していません」の箇所に `0` を表示しない**（10-2b）。0 は「計算した結果0だった」を意味し、「計算できない」とは別である。

### 16-2. CRLFの文字数に関する修正（U3）

当初案の「`\r\n` は2文字として数える」という記述は、**その直後に定めた正規化仕様（`\r\n` → `\n`）および受入項目B-9と矛盾していた。**

**正規化を経るため、CRLF・CR・LF はいずれも改行1文字として数える**（4-3）。あわせて、「元文字列上のコード単位数（`str.length`）」と「本ツールが表示する文字数」を混同しない表現に改めた。

### 16-3. 絵文字の文字種に関する修正（U11）

当初案では記号・句読点の判定に `\p{S}` を用いていたため、**`😀`（一般カテゴリ `So`）が「記号・句読点」に分類され、受入項目F-11の「その他」という期待と矛盾していた。**

**F-11の期待（絵文字＝その他）を採用し、判定順に絵文字判定を追加した**（8-2 ⑤・8-3）。

- 判定順：空白 → 数字 → 英字 → 日本語 → **絵文字** → 記号・句読点 → その他
- 絵文字判定は `\p{Extended_Pictographic}` に加え、**国旗絵文字のために `\p{Regional_Indicator}` も併用する**
- 絵文字は独立カテゴリにせず「その他」に分類し、**6カテゴリの排他性と「合計＝総文字数」を維持する**
- 既知の副作用として、`©` `®` `™` `‼` も「その他」に分類される

### 16-4. 頻出単語ランキングの stop word 除外（U7・実装後の変更）

実装後に長文で確認したところ、ランキングが `の / は / に / が / を / た / と / て / だ` などの助詞・助動詞でほぼ占められ、
**「頻出単語ランキング」として利用者が期待する、文章内容を把握するための情報になっていなかった。**

当初仕様（stop word を一切除外しない）には忠実だが、A6の意図を満たさないため、依頼者判断により以下を変更した。

| 対象 | 変更前 | 変更後 |
|---|---|---|
| 単語の定義（`Intl.Segmenter` ＋ `isWordLike`） | — | **変更なし** |
| 単語数 | stop word を含む | **変更なし**（含む） |
| 頻出単語ランキング | stop word を含む | **固定31語の stop word を除外する** |

**注：この時点のリストは31語である。** 後の第2次変更（16-5）で7語を追加し、**現行の確定リストは38語**である（9-6）。

**変更の要点：**

- 除外は**ランキングにのみ**適用し、単語数・文字数・文字種・行数・段落数には影響させない（9-6 SW1〜SW3）
- 判定は**ランキング用の正規化キー（NFKC ＋ 小文字化）**に対する完全一致で行う（SW4・SW6）
- **外部形態素解析・品詞判定を使用せず、固定リストのみで判定する**（SW5）
- **1文字語・数字を一律除外するルールは追加しない**（9-6 除外しないもの）
- **日本語以外の大規模な stop word 辞書を独断で追加しない**（同上）
- stop word をユーザーが編集するUIは[MVP外]のまま

**リストは実装者による増減を禁止する**（9-6）。分割の都合で活用語尾（`し` `れ` 等）が残る可能性があるが、**実装者は独断で追加せず、依頼者へ報告する**（SW9）。

### 16-5. stop word の7語追加と追加基準の明文化（U7・実装後の第2次変更）

16-4 の変更を実装した後、実データで再確認したところ、**固定31語の除外自体は正しく機能した**が、ランキング上位が次の語で占められた。

```
僕 / って / か / っ / い / さん / れ / し / 清水 / よう
```

これは 9-6 SW9 で想定していた「分割による活用語尾・機能語断片が残る」問題が実際に発生したものである。

#### 検討した3案

| 案 | 内容 | 評価 |
|---|---|---|
| A | 観測語まで固定リストを個別に拡張し続ける | 追加基準が無いとリストが肥大化し、**重要な内容語を消す確率が単調に上がる**。不採用 |
| B | 31語のまま維持し、断片が残ることを既知の制約として許容する | 誠実だが、**上位10件の大半がノイズという状態はA6として機能していない**。不採用 |
| **C** | **ごく限定的な語のみ追加し、残りは既知の制約として許容する** | **採用** |

#### 検討したが採用しなかったヒューリスティック

**「ひらがなのみで構成された1〜2文字（または1〜3文字）の語を一律除外する」案を検討したが、採用しなかった。**

`ふぐ` `まり` `たこ` `うた` など、**短いひらがな語でも文章の重要な内容語・主題語になり得る**ためである。文字種と文字数だけで内容語と機能語を判別することはできず、precision優先の方針と衝突する（9-6）。

#### 確定した内容

| # | 内容 |
|---|---|
| 1 | **7語を追加**（`って` `か` `っ` `い` `さん` `れ` `し`）。31語 → **38語** |
| 2 | **`よう` は追加しない（判断保留）。** ひらがな表記で内容語となる用法（用・酔う・様）が存在し、基準3に該当する |
| 3 | **追加基準の3条件を仕様化した**（9-6） |
| 4 | **「実データで頻出した」という事実だけでは追加理由にしないことを明記した**（9-6 運用規則4） |
| 5 | **文字種・文字数による一律除外を採用しないことを明記した**（9-6） |
| 6 | **既知の制約を9-9として明文化した** |
| 7 | **ランキング見出し直下に注記1行を追加した**（10-4） |
| 8 | **実データによる最終目視確認を受入テストN章として追加した** |

#### 7語を選んだ根拠

**「今回の実データで頻出したから」を根拠としていない。** 各語が、日本語の文法上、機能語・活用語尾・接尾辞・分割断片としてしか成立しないことを個別に確認した。

| 語 | 根拠 |
|---|---|
| `って` | 引用・話題提示の口語助詞。この表記で成立する内容語が存在しない |
| `か` | 終助詞・副助詞。同音語（課・科・蚊）はいずれも漢字表記が標準 |
| `っ` | 促音の分離による分割アーティファクト。単独では語ですらない |
| `い` | 形容詞語尾・連用形の断片。「胃」はほぼ漢字表記 |
| `さん` | 敬称の接尾辞。単独で意味を持たない。人名側は残るため主題情報は失われない |
| `れ` | 受身・可能の助動詞「れる」の断片。この表記の内容語が存在しない |
| `し` | 「する」の連用形・接続助詞。同音語（詩・氏・市・四）は漢字表記が標準 |

#### 残る副作用の受容

38語のうち、`か` `い` `し` `れ` `な` `た` `だ` `と` `て` `で` などは、**極めてまれにひらがな表記の内容語と衝突し得る**。しかしいずれも同音の内容語は漢字表記が標準であり、**衝突の可能性は実用上無視できる**と判断した。

### 16-6. ひらがな1文字の除外ルール追加（U7・実装後の第3次変更）

16-5 の変更（固定38語）を実装した後、実データで再確認したところ、**38語の除外自体は正しく機能した**が、`よ` `ら` などの**ひらがな1文字**のセグメントがランキングに残った。

#### 検討と判断

| 案 | 内容 | 判断 |
|---|---|---|
| 個別追加 | `よ` `ら` を固定リストへ追加する | **不採用。** 際限のない個別追加になり、リスト肥大化と他文章での重要語消失を招く |
| 2文字以下の一律除外 | ひらがな2文字以下を除外 | **不採用。** `ふぐ` `まり` `たこ` `うた` `ここ` `いつ` `なぜ` を失う |
| **1文字ひらがなの除外** | **ひらがな1文字だけの語を除外** | **採用** |

#### 採用理由

**「今回の文章でたまたま `よ` `ら` が出たから、その2語を除外語に追加した」のではない。** 1文字ひらがなという**限定された一般条件**を採用したものである。

| # | 理由 |
|---|---|
| 1 | 実データで `よ` `ら` 等の1文字ひらがながランキングノイズとして残った |
| 2 | ただし、個別語を際限なく stop word へ追加する方式は採らない |
| 3 | 2文字以下を一律除外すると `ふぐ` `まり` `たこ` `うた` 等の重要な内容語を失う |
| 4 | 1文字ひらがなに限定すれば、副作用を大幅に抑えながら、分割断片・機能語ノイズを一般ルールで減らせる |
| 5 | precision を優先し、**2文字以上にはルールを拡張しない** |

#### 確定した内容

| # | 内容 |
|---|---|
| 1 | **ひらがな1文字だけで構成される語をランキングから除外する**（9-6-2） |
| 2 | 判定は**書記素クラスター1つ**＋**ひらがな**。`.length` による判定を用いない（HR6） |
| 3 | **単語数には影響させない**（HR2）。処理順は9-1の①〜⑧ |
| 4 | **固定38語は削除・縮小せず、併用する**（HR10〜HR12） |
| 5 | **ひらがな2文字以上への拡張を禁止する**（9-6-2・9-6-3） |
| 6 | **`よう` `そう` `この` を今回の判断で追加しない。`よう` は判断保留を維持する** |
| 7 | 副作用（ひらがな1文字の内容語も除外される）を K7 として明記した |
| 8 | 画面注記は変更しない（10-4） |

9c. **2種類の除外（固定38語・ひらがな1文字）を、単語数・文字数・文字種・行数・段落数に波及させない。** 単語数を確定してからランキングの除外を行う（9-1の処理順①〜⑧）

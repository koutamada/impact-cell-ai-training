## 3. ゲーム状態

### 3-1. 保持する状態 [必須B]

```js
{
  difficulty: string,   // 'easy' | 'normal' | 'hard'
  min: number,          // 現在の難易度の最小値
  max: number,          // 現在の難易度の最大値
  answer: number,       // 正解（min 以上 max 以下の整数）
  attempts: number,     // 挑戦回数
  status: string        // 'playing' | 'cleared'
}
```

| 項目 | 説明 |
|---|---|
| `difficulty` | 選択中の難易度 |
| `min` / `max` | `difficulty` から導かれる範囲（4-1） |
| `answer` | ゲーム開始時に生成する。**画面に表示しない**。再生成時は、**上書きする前の値を「直前の正解」として保持し、重複回避に用いる**（5-4） |
| `attempts` | 6章の規則で加算する |
| `status` | `playing`＝回答受付中、`cleared`＝正解済み |

**直前の正解を保持するための専用フィールドは必須ではない [必須B]。** 再生成の直前に現在の `answer` をローカル変数へ退避すれば足りる。初回はまだ `answer` が存在しないため、`null` 等と比較して重複回避を行わない（5-4 R7）。

### 3-2. 状態遷移 [必須B]

```
        ページ読み込み
              ↓
        [playing]  ← 難易度変更 ─┐
         │      ↑                │
   正解した│      │「もう一度遊ぶ」  │（どの状態からでも）
         ↓      │                │
        [cleared] ─────────────┘
```

| 遷移 | 契機 | 動作 |
|---|---|---|
| 初期化 → `playing` | ページ読み込み | 初期難易度で新しいゲームを開始（5章） |
| `playing` → `cleared` | 予想が正解と一致 | 8章 |
| `cleared` → `playing` | 「もう一度遊ぶ」 | 9章。**直前の正解と同じ値にならないよう再抽選する**（5-4） |
| `playing` / `cleared` → `playing` | 難易度変更 | 4-4。**直前の正解が新しい範囲内なら再抽選する**（5-4・5-6） |

### 3-3. `answer` を画面に出さない [必須B]

| # | 仕様 |
|---|---|
| G1 | 正解の値を、正解するまで画面に表示しない |
| G2 | HTMLの属性（`data-*` 等）にも埋め込まない |
| G3 | 正解時には表示してよい（8-2） |

**G2の理由：** 開発者ツールで簡単に見えてしまうと、ゲームとして成立しない。**JavaScript の変数としてのみ保持する**（`app.js` を読めば分かるが、それは本Partの範囲外とする）。

### 3-4. 永続化

**localStorage を使用しない。** 再読み込みで新しいゲームが始まる（[MVP外]。2-2 の6）。

## 4. 難易度仕様

### 4-1. 難易度と範囲 [必須A] A5 / [必須B] B1

**3段階を固定とする。**

| 値 | 表示名 | 範囲 | 候補数 |
|---|---|---|---|
| `easy` | **かんたん** | **1〜10** | 10 |
| `normal` | **ふつう** | **1〜50** | 50 |
| `hard` | **むずかしい** | **1〜100** | 100 |

| # | 仕様 |
|---|---|
| D1 | **最小値・最大値はいずれも正解になり得る**（両端を含む。5-1） |
| D2 | 利用者が任意の最小値・最大値を設定する機能は実装しない（[MVP外]。2-2 の1） |
| D3 | 難易度を増やす・範囲を変更するUIは実装しない |

### 4-2. 難易度の選択UI [必須A] A5

**`<select>` を用いる。**

| # | 仕様 |
|---|---|
| D4 | 選択肢は「かんたん（1〜10）」のように、**表示名と範囲を併記する** |
| D5 | `<label>` を関連付ける（15章 AC2） |
| D6 | 初期値は **かんたん**（5-2） |

**`<select>` を採用する理由 [必須B]：** 3択であり、375px幅でも1行に収まる。ラジオボタンは各項目に44px以上のタップ領域が必要になり、縦方向を圧迫する。

（18章 U3）

### 4-3. 現在の範囲の表示 [必須A] A5 / [必須B]

**現在の範囲を、入力欄の近くに常時表示する。**

| 表示例 |
|---|
| `1 〜 10 の数字を当ててください` |

| # | 仕様 |
|---|---|
| D7 | 難易度を変更したら即座に更新する |
| D8 | `textContent` で設定する |

**必要な理由 [必須B]：** 範囲が分からないと、利用者は何を入力してよいか判断できない。**A5の「範囲を変えることで難易度を変更できる」は、範囲が利用者に見えて初めて成立する。**

### 4-4. ゲーム途中の難易度変更 [必須B] B9 ← 必ず決める

**難易度を変更した時点で、新しいゲームとして扱う。**

| # | 動作 |
|---|---|
| D9 | **新しい範囲で正解を再生成する** |
| D10 | **挑戦回数を 0 に戻す** |
| D11 | **ヒントを初期状態に戻す** |
| D12 | **エラーメッセージを消す** |
| D13 | **入力欄を空にする** |
| D14 | **入力欄と「予想する」ボタンを有効化する** |
| D15 | **`status` を `playing` にする**（`cleared` の状態からでも `playing` に戻す） |
| D16 | 現在の範囲表示を更新する（4-3 D7） |
| D17 | **確認ダイアログを表示しない**（[MVP外]。2-2 の16） |

**D15が重要である [必須B] B9：** 正解後（`cleared`）に難易度を変更した場合も、**「もう一度遊ぶ」を押さずにそのまま新しいゲームが始まる。** ここを定義しないと、入力欄が無効なまま新しい範囲が表示され、操作不能になる。

**確認ダイアログを出さない理由：** 難易度変更は明示的な操作であり、誤操作の可能性が低い。確認を挟むと、難易度を試しながら遊ぶ流れが妨げられる。

## 5. ランダム生成仕様

### 5-1. 生成式 [必須A] A1 / [必須B] B2

**以下の式を用いる。**

```js
answer = Math.floor(Math.random() * (max - min + 1)) + min;
```

| # | 仕様 |
|---|---|
| R1 | **`min` と `max` の両方を含む整数**を生成する |
| R2 | **範囲外の値を生成しない** |
| R3 | `Math.random()` を用いる（暗号学的乱数は不要） |

**誤りやすい実装 [必須B] B2：**

| 誤った式 | 問題 |
|---|---|
| `Math.floor(Math.random() * (max - min)) + min` | **`max` が絶対に出ない** |
| `Math.round(Math.random() * (max - min)) + min` | **両端の出現確率が他の半分になる** |
| `Math.ceil(Math.random() * max)` | `min` が1以外のときに範囲外になる |

**上記はいずれも一見動作するため、受入テストで検出する**（16章 B）。

### 5-2. ゲーム開始の契機 [必須B] B3

**ページ表示時に、初期難易度で自動的にゲームを開始する。**

| # | 仕様 |
|---|---|
| R4 | ページ読み込み時に正解を生成し、**すぐに予想できる状態にする** |
| R5 | 「ゲーム開始」ボタンは設けない |
| R6 | 初期難易度は **かんたん（1〜10）** |
| R7 | 初期状態の挑戦回数は 0 |
| R8 | 初期状態のヒントは案内文（7-4） |

**「ゲーム開始」ボタンを設けない理由 [必須B] B3：** 課題文に開始操作の要求がない。**ページを開いた瞬間から遊べる方が、ゲームとして自然である。** 開始ボタンは操作を1つ増やすだけで、得るものがない。

**初期難易度を「かんたん」とする理由：** 初回利用時に少ない試行で正解でき、**ヒントの意味とゲームの流れをすぐ理解できる。**

（18章 U2・U4）

### 5-3. 正解の再生成 [必須B]

以下の契機で、正解を新しく生成する。

| # | 契機 | 直前の正解との重複回避 |
|---|---|---|
| 1 | ページ読み込み時（5-2） | **行わない**（直前の正解が存在しないため） |
| 2 | 「もう一度遊ぶ」を押したとき（9章） | **行う** |
| 3 | 難易度を変更したとき（4-4） | **行う**（ただし5-5の例外あり） |

### 5-4. 直前の正解との連続回避 [必須B] ← 必ず実装する

**新しいゲームを開始する際、直前のゲームと同じ正解が生成された場合は再抽選し、連続して同じ正解にならないようにする。**

| # | 仕様 |
|---|---|
| R5 | 新しい正解を生成する前に、**直前の正解の値を保持しておく** |
| R6 | 生成した候補が直前の正解と等しい場合、**別の値になるまで生成をやり直す** |
| R7 | 初回（ページ読み込み時）は直前の正解が存在しないため、**通常生成する** |
| R8 | **直前の値を除外したうえで、残りの候補が等確率で選ばれること**（5-5） |

#### 実装方式 [必須B]

**「同じ場合のみ再生成する」棄却法（rejection sampling）を用いる。**

```js
let candidate;
do {
  candidate = Math.floor(Math.random() * (max - min + 1)) + min;
} while (candidate === previousAnswer);
answer = candidate;
```

| # | 仕様 |
|---|---|
| R9 | **等しくなくなるまで繰り返す**（`while` ループ） |
| R10 | 候補数（`max - min + 1`）は現行の3難易度でいずれも10以上であり、**ループが終了しないことは実質的に起こらない** |
| R11 | 試行回数の上限を設けない（上限を設けると、上限到達時に直前と同じ値を返す実装になり、R6に反する） |

**候補数が1の場合は本ルールが成立しないが、現行の難易度（10 / 50 / 100）はいずれも候補数が2以上であるため、その状況は発生しない [必須B]。**

### 5-5. 乱数分布を歪めない実装 [必須B] ← 重要

**「直前の値だけを除外し、それ以外の候補は等確率で選ばれる」ことを保証する。**

#### 採用してはならない実装 [必須B]

| # | 誤った実装 | 問題 |
|---|---|---|
| NG1 | **1回だけ振り直して、結果をそのまま採用する**（`if` で1回だけ再生成） | **直前と同じ値が出る確率が残る**（`1/n²`）。R6を満たさない。さらに他の値の確率が `(n+1)/n²` となり、**均等でもない** |
| NG2 | 直前の値が出たら、隣の値（`+1` など）に置き換える | 隣の値の出現確率が2倍になる。**分布が明確に歪む** |
| NG3 | 直前の値が出たら、範囲の中央値などの固定値にする | 特定の値に偏る |
| NG4 | 試行回数の上限を設け、上限到達時に直前と同じ値を返す | R6を満たさない |

**NG1は「1回振り直せば十分」と考えて書かれやすく、しかも大半のケースで期待通り動くため、見落とされやすい [必須B]。** 受入テストでは乱数列を制御し、同じ値が複数回続くケースを決定的に確認する（15章 B-8）。

#### 等確率になる代替実装 [任意]

以下も等確率であり、ループを使わない。**採用してもよいが、必須ではない。**

```js
// 直前の値を除いた (n-1) 個から等確率で選ぶ
const n = max - min + 1;
let r = Math.floor(Math.random() * (n - 1)) + min;
if (r >= previousAnswer) { r += 1; }
answer = r;
```

**ただし、この方式は `previousAnswer` が範囲内にある場合にのみ正しい。** 範囲外の場合は補正が不要であり、条件分岐が増える。**5-4の棄却法の方が単純で誤りにくいため、そちらを推奨する。**

### 5-6. 難易度変更時の例外 [必須B]

**難易度を変更した結果、直前の正解が新しい範囲の外になる場合は、重複回避を行わず通常生成する。**

| 例 | 直前の正解 | 新しい範囲 | 扱い |
|---|---|---|---|
| かんたん → むずかしい | `7` | 1〜100 | `7` は範囲内 → **重複回避を行う** |
| むずかしい → かんたん | `80` | 1〜10 | `80` は範囲外 → **通常生成**（同値になり得ないため） |
| ふつう → かんたん | `3` | 1〜10 | `3` は範囲内 → **重複回避を行う** |

**理由 [必須B]：** 直前の正解が新しい範囲外であれば、生成される候補と一致することは原理的にない。**5-4の棄却法をそのまま適用しても結果は同じ**（`while` 条件が最初から偽になる）ため、**実装上は分岐を設けなくてよい。** 本節は挙動の説明であり、追加の条件分岐を求めるものではない。

## 6. 入力仕様

### 6-1. 入力欄 [必須A] A2 / [必須B] B4

**`<input type="number">` を用いる。**

| # | 仕様 |
|---|---|
| I1 | `type="number"` とする |
| I2 | `inputmode="numeric"` を指定する（スマートフォンで数値キーボードを表示する） |
| I3 | `step="1"` を指定する |
| I4 | **`min` / `max` 属性に現在の範囲を設定し、難易度変更時に更新する** |
| I5 | `<label>` を関連付ける |
| I6 | 初期状態は空 |

**`type="number"` を採用する理由 [必須B] B4：**

| # | 理由 |
|---|---|
| 1 | 本Partの目的は**ゲームロジック**であり、任意の文字列を検証する仕組みは主眼ではない |
| 2 | スマートフォンで数値キーボードが出る |
| 3 | `min` / `max` / `step` により、ブラウザ側のスピナー操作が範囲内に収まる |

**注意：`type="number"` は不正な入力があると `value` が空文字になる [必須B]。** そのため `abc` を入力しても「空欄」として扱われる。**6-3のメッセージは、この挙動を前提として設計する。**

（18章 U5）

### 6-2. 妥当性の判定 [必須B] B4

**`value` を文字列として取得し、以下の順に判定する。**

```
① 前後の空白を除去する
② 空文字なら「未入力」
③ 整数の形式でなければ「整数でない」
   /^[+-]?\d+$/ に完全一致するか
④ Number() に変換し、min 以上 max 以下でなければ「範囲外」
⑤ 上記をすべて通過したものを、有効な予想値とする
```

| 入力 | 判定 | 備考 |
|---|---|---|
| `5` | 有効（範囲内なら） | |
| `1` `10` | 有効 | 両端を含む |
| （空欄） | 未入力 | |
| `1.5` | 整数でない | `type="number"` でも `step="1"` を無視して入力できる場合がある |
| `-3` | 範囲外 | 形式としては整数 |
| `0` | 範囲外（`min` が1のため） | |
| `11`（かんたん時） | 範囲外 | |
| `1e2` | **整数でない** | 正規表現に一致しないため |
| `abc` | 未入力 | `type="number"` により `value` が空文字になるため |
| `１２`（全角） | 未入力 | 同上 |
| ` 5 `（前後空白） | 有効 | ①で除去する |

**全角数字を半角へ正規化しない [必須B]。** `type="number"` は全角数字を受け付けず `value` が空文字になるため、正規化しても効果がない。

**`1e2` を整数として扱わない [必須B]。** 正規表現による判定で弾く。ブラウザによっては `type="number"` が `1e2` を受け付けるため、**JavaScript側の判定が必要である。**

（18章 U12）

### 6-3. エラーメッセージ [必須B] B4

**3種類を区別する。**

| # | 条件 | メッセージ |
|---|---|---|
| E1 | 未入力（空欄） | `数字を入力してください` |
| E2 | 整数でない | `整数を入力してください` |
| E3 | 範囲外 | `1 〜 10 の範囲で入力してください`（数値は現在の範囲を反映する） |

**3種類に分ける理由 [必須B]：** 利用者の対処がそれぞれ異なる（入力する／小数をやめる／範囲を確認する）。**同一メッセージにすると、範囲外の入力に対して「入力してください」と出て、何が悪いか分からない。**

**E3のメッセージに現在の範囲を含める [必須B]。** 難易度によって範囲が変わるため、固定文言にしない。

### 6-4. エラー時のゲーム状態 [必須B] B10 ← 重要

**入力エラーは、ゲームの進行に影響させない。**

| 対象 | エラー時の扱い |
|---|---|
| **挑戦回数** | **増やさない**（7章） |
| **ヒント表示** | **変更しない。前回のヒントを維持する** |
| **正解** | 再生成しない |
| **入力欄の内容** | **消さない**（利用者が修正できるようにする） |
| **入力欄と予想ボタン** | 有効のまま維持する |
| `status` | 変更しない |

**ヒントを維持する理由 [必須B] B10：** 例えば「もっと大きい数字です」と表示されている状態で、うっかり `0` を入力してエラーになったとする。**このときヒントが消えると、利用者は直前の手掛かりを失う。** エラーは入力の問題であり、**ゲームの状態は何も変わっていない。**

**入力欄を消さない理由：** 打ち間違いを修正するには、入力内容が残っている方が早い。

### 6-5. Enterキー [必須A] A2 / [必須B]

**入力欄でEnterを押したとき、「予想する」ボタンと同じ動作をする。**

| # | 仕様 |
|---|---|
| I7 | 入力欄と「予想する」ボタンを `<form>` で囲み、`submit` イベントで処理する |
| I8 | `submit` の既定動作を `preventDefault()` で抑止する（ページ遷移を防ぐ） |
| I9 | 「予想する」ボタンは `type="submit"` とする |
| I10 | **`isComposing` が `true` のときは送信しない**（IME変換確定のEnterで誤送信しないため） |
| I11 | `status` が `cleared` のときは、入力欄とボタンが無効なため送信されない |

**I8を怠るとページがリロードされ、ゲーム状態がすべて失われる [必須B]。**

**I10について [必須B]：** `type="number"` では通常IMEが起動しないが、環境によっては全角入力モードになる場合がある。**Part 1 で対処した問題と同種であり、1行の判定で防げる。**

（18章 U11）

## 7. 挑戦回数仕様

### 7-1. 加算の条件 [必須A] A4 / [必須B] B5

**範囲内の妥当な整数を送信したときだけ +1 する。**

| 操作 | 挑戦回数 |
|---|---|
| 範囲内の整数を送信（不正解） | **+1** |
| **範囲内の整数を送信（正解）** | **+1**（正解した試行も1回として数える） |
| 空欄で送信 | **増やさない** |
| 整数でない値を送信 | **増やさない** |
| 範囲外の値を送信 | **増やさない** |
| 同じ値を繰り返し送信 | **+1**（重複を検出しない） |

**正解した試行を数える理由 [必須B] B5：** 「3回目で当てた」という表現と一致する。**正解を数えないと、1回で当てたときに「0回」となり不自然である。**

**同じ値の重複送信を検出しない [必須B]：** 重複判定には過去の予想を保持する必要があり、履歴機能（[MVP外]）に踏み込む。同じ値を送れば同じヒントが出るだけで、実害がない。

### 7-2. 表示 [必須A] A4/A6

| # | 仕様 |
|---|---|
| C1 | 挑戦回数を画面に常時表示する（例：`挑戦回数：3回`） |
| C2 | 加算のたびに更新する |
| C3 | ゲーム開始時・再ゲーム時・難易度変更時は 0 に戻す |
| C4 | `textContent` で設定する |
| C5 | **数値は等幅で表示する**（`font-variant-numeric: tabular-nums`）。桁が増えても表示が横に揺れない |

### 7-3. 上限

**挑戦回数に上限を設けない。** ライフ制・ゲームオーバーは実装しない（[MVP外]。2-2 の9）。

## 8. ヒント仕様・正解時仕様

### 8-1. ヒントの文言 [必須A] A3 / [必須B] B6

| 条件 | 表示 |
|---|---|
| 予想値 **<** 正解値 | **`もっと大きい数字です`** |
| 予想値 **>** 正解値 | **`もっと小さい数字です`** |
| 予想値 **=** 正解値 | 正解メッセージ（8-2） |

**この文言とする理由 [必須B] B6：** 「大きいです」「小さいです」だけでは、**予想値が大きいのか、正解が大きいのかが曖昧**になる。「もっと大きい数字です」は、**利用者が次に取るべき行動**を示しており、解釈が一通りに定まる。

| # | 仕様 |
|---|---|
| H1 | ヒントは1行のテキストとする |
| H2 | `textContent` で設定する |
| H3 | 予想値そのものをヒントに含めてよい（例：`5 より大きい数字です`）。**ただし必須ではない** |
| H4 | 距離の遠近を示す表現（「かなり近い」等）を追加しない（[MVP外]。2-2 の11） |

### 8-2. 正解時の表示 [必須A] A4/A6 / [必須B] B7

| # | 仕様 |
|---|---|
| W1 | **正解であることと、正解の数字を表示する** |
| W2 | **挑戦回数を表示する** |
| W3 | 例：`正解！ 7 でした。3回で当てました` |
| W4 | ヒント表示領域に表示してよい（別領域を新設しなくてよい） |

**W1・W2を1つのメッセージにまとめる理由 [必須B] B7：** 結果と回数が同時に伝わり、**支援技術にも1回の読み上げで伝わる**（15章 AC5）。

### 8-3. 正解時の画面状態 [必須A] A6 / [必須B] B7

| # | 仕様 |
|---|---|
| W5 | **入力欄を無効化する**（`disabled`） |
| W6 | **「予想する」ボタンを無効化する**（`disabled`） |
| W7 | **「もう一度遊ぶ」ボタンを有効化（または表示）する** |
| W8 | 難易度選択は**有効のまま維持する**（4-4により、変更すれば新しいゲームが始まる） |
| W9 | `status` を `cleared` にする |
| W10 | エラーメッセージが表示されていれば消す |

**W5・W6の理由 [必須B]：** 正解後に追加で予想できると、挑戦回数が意味を失う。**「正解までに何回挑戦したか」（A4）を確定させるために、回答受付を止める必要がある。**

### 8-4. 正解時のフォーカス移動 [必須B] B11

**正解したら、「もう一度遊ぶ」ボタンへフォーカスを移す。**

**理由 [必須B] B11：** 入力欄が `disabled` になるため、**そのままではフォーカスが失われ、キーボード利用者は Tab で位置を探し直すことになる。** 次の操作は「もう一度遊ぶ」であり、そこへ移すのが自然である。

## 9. 再ゲーム仕様

### 9-1. 「もう一度遊ぶ」 [必須A] A6 / [必須B] B8

| # | 動作 |
|---|---|
| N1 | **同じ難易度のまま、新しい正解を生成する**（難易度を変えない） |
| N2 | **挑戦回数を 0 に戻す** |
| N3 | **ヒントを初期状態（案内文）に戻す** |
| N4 | **エラーメッセージを消す** |
| N5 | **入力欄を空にする** |
| N6 | **入力欄と「予想する」ボタンを有効化する** |
| N7 | `status` を `playing` にする |
| N8 | **ページのリロードを必須にしない**（`location.reload()` を使わない） |

**N8の理由 [必須B] B8：** リロードは初期難易度に戻ってしまい、N1（同じ難易度を維持する）と矛盾する。また、体感的にも遅い。

### 9-2. 「もう一度遊ぶ」ボタンの状態 [必須B]

| 状態 | ボタン |
|---|---|
| `playing`（回答受付中） | **無効化する**（`disabled`）、または非表示 |
| `cleared`（正解済み） | **有効** |

**`playing` 中に無効化する理由 [必須B]：** 途中でリセットする機能は課題文にない。有効にしておくと、誤って押して進行中のゲームが消える。

**「無効化」と「非表示」のどちらでもよい [必須B]。** ただし**非表示にする場合、表示・非表示でレイアウトが上下に動かないようにする**（領域の高さを確保する）。

### 9-3. 再ゲーム時のフォーカス移動 [必須B] B11

**「もう一度遊ぶ」を押したら、入力欄へフォーカスを移す。**

**理由：** 次の操作は予想の入力である。**キーボード・スクリーンリーダー利用者が、すぐ入力を始められる。**

### 18-1. 正解の連続回避に関する変更（U14）

#### 変更の内容

当初案では、5-3に **「同じ正解が連続することを避ける処理は実装しない」**（理由：回避処理を入れるとかえって偏りが生じる）と記載していた。

**依頼者判断により、この方針を撤回し、連続回避を実装する仕様へ変更した。**

| 対象 | 変更前 | 変更後 |
|---|---|---|
| ページ読み込み時 | 通常生成 | **変更なし**（直前の正解が存在しないため） |
| 「もう一度遊ぶ」 | 通常生成 | **直前と同じなら再抽選する** |
| 難易度変更 | 通常生成 | **直前と同じなら再抽選する**（直前の正解が新範囲外なら通常生成。5-6） |

#### 当初案の懸念への対応

当初案が挙げていた「偏りが生じる」という懸念は、**実装方式によっては現実の問題となる。** そのため、5-5として**分布を歪めない実装方針**を明文化した。

| 方式 | 分布 | 採否 |
|---|---|---|
| **棄却法**（異なる値になるまで繰り返す） | **直前の値を除いた残りが等確率** | **採用** |
| 1回だけ振り直す | 直前の値が `1/n²` の確率で残り、他も不均等 | **不採用**（NG1） |
| 隣の値へ置き換える | 隣の値が2倍になる | 不採用（NG2） |
| 固定値へ置き換える | 特定の値に偏る | 不採用（NG3） |
| 上限付き再試行 | 上限到達時に直前と同じ値が出る | 不採用（NG4） |

**棄却法は「直前の値だけを除外し、それ以外は等確率」を厳密に満たす。** したがって、当初案の懸念は**実装方式を指定することで解消される。**

#### 検証方針

**乱数値の列を制御する決定的な受入テストで、生成式と棄却法の制御フローを確認する**（B-1〜B-13）。実際の乱数による分布確認は参考とし、厳格な合否条件には用いない。

| # | 確認内容 |
|---|---|
| 1 | 乱数値`0`、`1`未満の最大近似値、中間値で、最小・最大・期待する中間整数が生成されること（B-1〜B-4） |
| 2 | `Math.floor`と`(max - min + 1)`を用い、`Math.round`を用いないこと（B-5・B-6） |
| 3 | 最初の候補が直前値なら再抽選し、異なる値が出た時点で採用すること（B-7・B-9） |
| 4 | **直前値と同じ候補が2回続いても、さらに再抽選すること**（B-8）。これがNG1を決定的に検出する |
| 5 | 直前値が新範囲外なら、最初の候補を通常どおり採用すること（B-10） |
| 6 | ソースコード上、NG2〜NG4の実装になっていないこと（B-11〜B-13） |

**4が最も重要である。** NG1（1回だけ振り直す）は通常のランダム試行では見落とされ得るが、同じ候補を2回続けて与えることで確実に検出できる。

## 付録：実装者へ渡す際の注意事項

1. **出力ファイルは `apps/part11-number-guess/` 配下の `index.html` / `style.css` / `app.js` の3つのみ**
2. **フレームワーク・外部ライブラリ・CDN・外部API・Webフォントを使わない**
3. **本仕様書2-2・10-4の[MVP外]機能を追加しない。** 思いついても実装せず、提案にとどめる
4. **乱数は `Math.floor(Math.random() * (max - min + 1)) + min`。** `Math.round` や `(max - min)` にしない（両端が出ない／偏る）
4b. **新しいゲームの正解は、直前の正解と同じにならないよう再抽選する。** 実装は棄却法（`do { … } while (candidate === previousAnswer)`）とする
4c. **1回だけ振り直して結果を採用する実装にしない。** 直前と同じ値が残り、分布も歪む
4d. **直前の値が出たときに `+1` や固定値へ置き換えない。試行回数の上限も設けない**
4e. **初回（ページ読み込み時）は直前の正解が無いため、通常生成する**
5. **正解の値をHTMLの属性・DOMに埋め込まない**
6. **ページ表示時に自動でゲームを開始する。** 初期難易度は「かんたん」
7. **入力は `<input type="number" inputmode="numeric" step="1">`。`min` / `max` を難易度に応じて更新する**
8. **妥当性は JavaScript 側で判定する。** trim → `/^[+-]?\d+$/` に完全一致 → 範囲チェックの順
9. **エラーは3種類（未入力・整数でない・範囲外）を区別する。** 範囲外のメッセージに現在の範囲を含める
10. **入力エラーでは、挑戦回数を増やさず、ヒントも変更せず、入力内容も消さない**（ゲーム状態を一切変えない）
11. **エラー領域とヒント領域を別々にする**（同じ領域にするとエラーでヒントが消える）
12. **挑戦回数は、範囲内の整数を送信したときのみ +1。正解した試行も数える**
13. **ヒントは「もっと大きい数字です」「もっと小さい数字です」。** 「大きいです」等の曖昧な文言にしない
14. **正解時は、正解値と挑戦回数を1つの文で表示し、入力欄と「予想する」を無効化し、「もう一度遊ぶ」を有効化する**
15. **正解時は「もう一度遊ぶ」へ、再ゲーム時は入力欄へフォーカスを移す**
16. **「もう一度遊ぶ」で `location.reload()` を使わない。** 同じ難易度のまま新しい正解を生成する
17. **難易度変更は即座に新しいゲームとして扱う。** `cleared` 状態からでも `playing` に戻す。確認ダイアログを出さない
18. **Enterは `<form>` の `submit` で処理し、`preventDefault()` する。`isComposing` 中は送信しない**
19. **ヒント領域に `aria-live="polite"`、エラー領域に `role="alert"`。挑戦回数と範囲表示には `aria-live` を付けない**
20. **`innerHTML` を使用しない。** すべて `textContent` で設定する
21. **`outline: none` を単独で指定しない**
22. **入力欄・`<select>` のフォントサイズは16px以上**（iOSの自動ズーム防止）
23. **PCでは最大幅を設けて間延びさせない。375pxで横スクロールを出さない**
24. **挑戦回数は `font-variant-numeric: tabular-nums` で等幅表示する**

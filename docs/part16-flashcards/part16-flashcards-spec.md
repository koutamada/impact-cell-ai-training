## 0. 本書の読み方

### 0.1 要件区分

各項目に以下の区分を付す。

| 区分 | 意味 | 実装義務 |
|---|---|---|
| **[必須A]** | 課題文が明示している要件 | 必須 |
| **[必須B]** | 課題文が明示していないが、[必須A] を破綻なく成立させるために必要な補完設計 | 必須 |
| **[任意]** | 実装してもしなくてもよい | 任意 |
| **[MVP外]** | 本パートでは実装しない | 実装禁止 |

### 0.2 実装者への基本指示

- **スコープを厳守すること。** 本書に記載のない機能を追加してはならない。
- **解釈の余地を残さないこと。** 本書に判断が委ねられている記述はない。曖昧に感じた箇所があれば、実装で埋めずに仕様書側の不備として報告すること。
- 外部ライブラリ・CDN・外部API・Webフォントを使用しない。
- Part 1〜15 のコードを流用しない。過剰な共通化をしない。
- `innerHTML` / `eval` / `new Function` を使用しない。

```

  style.css

```

## 1. 要件整理

### 1.1 課題のクリア条件と対応箇所 [必須A]

| # | クリア条件 | 対応章 |
|---|---|---|
| C1 | 「問題」と「答え」の2面を持つカードを作成できる | 6章 |
| C2 | 作成したカードを保存し、一覧管理できる | 4章・7章・8章 |
| C3 | 登録済みカードからランダムに問題を出題できる | 10章 |
| C4 | 操作によってカードの表面・裏面を切り替えられる | 11章 |
| C5 | 正解・不正解など、簡単な学習状況を記録できる | 12章・13章 |

### 1.2 「一覧管理」の解釈 [必須B]

課題文の「一覧管理」を、本アプリでは **「登録済みカードの一覧表示」＋「不要カードの削除」** と定義する。**編集は含めない。**

- 編集を含めない理由：クリア条件は「作成できる」「保存し、一覧管理できる」であり、編集は明示されていない。編集を導入すると、編集モードの状態、保存／キャンセル、ID維持、学習記録の維持、編集中に当該カードが出題された場合の扱い、といった仕様が連鎖的に必要になる。これは課題要件の充足に寄与しない複雑性である。
- 削除を含める理由：誤登録したカードを削除できないと、そのカードがランダム出題に永続的に混ざり続け、C3・C5 の実用性を損なう。削除は「一覧管理」の最小構成要素として必要と判断する。

### 1.3 MVP範囲 [必須A][必須B]

**含む**

- カード登録（問題・答えの2入力）
- localStorage への保存・復元
- カード一覧表示（問題・答え・正解数・不正解数）
- カード削除（確認あり）
- 学習モード（ランダム出題・表裏切替・正解／不正解記録・自動次問）
- カード単位の学習状況（正解数・不正解数）
- 全体集計（総回答数・正解数・不正解数・正解率）
- 破損データ／保存失敗時の整合性処理

**含まない（詳細は 21章）**

編集、並び替え、検索、タグ、カテゴリ、お気に入り、苦手カード優先、間隔反復（SM-2 / Leitner / Anki方式）、出題順モード切替、音声読み上げ、画像カード、Markdown、CSV、JSON入出力、Undo、学習履歴、セッション管理、学習記録リセット、3Dフリップアニメーション、タイマー、スコア、認証、クラウド同期、サーバー保存、PWA。

## 2. カードデータ構造

### 2.1 カードオブジェクト [必須A]

```js
{
  id: string,             // 一意ID（3章）
  question: string,       // 問題（trim済み・空文字不可）
  answer: string,         // 答え（trim済み・空文字不可）
  correctCount: number,   // 正解数（0以上の整数）
  incorrectCount: number, // 不正解数（0以上の整数）
  createdAt: number       // 作成時刻（Date.now() のミリ秒値）
}
```

### 2.2 採用しないフィールド [必須B]

| フィールド | 不採用の理由 |
|---|---|
| `updatedAt` | 編集機能が MVP外 であるため、カード内容が更新されることがない。採点による `correctCount` / `incorrectCount` の変化は「学習」であって「カード内容の更新」ではなく、一覧の並び順（8章：作成順固定）にも影響させない。保持しても参照される箇所がない。 |
| `lastStudiedAt` 等 | 学習履歴が MVP外（18章）。日時付き回答履歴は保存しない。 |

### 2.3 学習状況の保持方式 [必須A]

**カード単位で `correctCount` / `incorrectCount` を保持する方式を採用する。**

課題文が例示した `{ cards: [...], studyStats: ... }` のようなカードと分離した集計オブジェクトは**採用しない。**

理由：

1. カードを削除したとき、そのカードの学習記録も同時に消える必要がある（課題20章）。カード内に持てば削除だけで自動的に整合する。分離すると削除処理で2箇所を同期する必要が生じ、片方だけ保存に成功する破綻ケースが生まれる。
2. 一覧にカードごとの正解数・不正解数を表示する必要がある（課題5章）。カード内にあれば結合処理が不要。
3. 全体集計（総回答数・正解数・不正解数・正解率）は `cards` からの導出値として毎回計算できる（13章）。冗長に保存すると、保存された集計値と `cards` の実データが食い違う状態を作り得る。

**全体集計は保存しない。** 常に `cards` から導出する。

### 2.4 バリデーション規則 [必須B]

読み込み時に、各カードが以下をすべて満たすことを検証する。

| 項目 | 条件 |
|---|---|
| カード自体 | `typeof card === 'object' && card !== null && !Array.isArray(card)` |
| `id` | `typeof === 'string'` かつ `length > 0` |
| `question` | `typeof === 'string'` かつ `trim().length > 0` |
| `answer` | `typeof === 'string'` かつ `trim().length > 0` |
| `correctCount` | `Number.isInteger()` かつ `>= 0` |
| `incorrectCount` | `Number.isInteger()` かつ `>= 0` |
| `createdAt` | `Number.isFinite()` |
| `id` の一意性 | `cards` 配列内で重複しない |

1件でも違反した場合の扱いは 15.2 に定める（**全件不採用**）。

## 3. ID採番

### 3.1 方式の比較 [必須A]

| 候補 | 一意性 | 削除・並び替え耐性 | 判定 |
|---|---|---|---|
| `crypto.randomUUID()` | 実質衝突しない | 影響なし | **採用** |
| 日時＋乱数 | 実用上十分だが同一ミリ秒での衝突を乱数長に依存 | 影響なし | フォールバックとして採用 |
| 連番（保存されたカウンタ） | 保存カウンタが破損・巻き戻ると衝突 | 影響なし | 不採用 |
| 配列 index | **削除・並び替えでズレる** | なし | **禁止** |

**配列 index を ID 代わりに使ってはならない。** 削除によって後続カードの index が変化し、「現在出題中のカード」の同定が壊れるためである（14章・20章）。

### 3.2 `crypto.randomUUID()` の利用条件 [必須B]

`crypto.randomUUID()` は **secure context 限定**の API である。

| 環境 | secure context | 利用可否 |
|---|---|---|
| GitHub Pages（`https://`） | ○ | 利用可 |
| `http://localhost` / `http://127.0.0.1` | ○ | 利用可 |
| **`file://` でHTMLを直接開く** | ×（多くのブラウザで `crypto.randomUUID` が `undefined`） | **利用不可** |

本アプリはローカル確認時に `file://` で開かれることがあるため、フォールバックを必須とする。

### 3.3 ID生成関数 [必須B]

```
createId():
  1. crypto が存在し、typeof crypto.randomUUID === 'function' なら
       crypto.randomUUID() を返す
  2. そうでなければ
       Date.now().toString(36) + '-' + Math.random().toString(36).slice(2, 10)
       を返す
```

- フォールバックは **UUID互換フォーマットを自作しない。** 本アプリは ID の形式に依存しない（一意な文字列であればよい）。
- フォールバックが返す文字列も 2.4 のバリデーション（非空文字列）を満たす。
- ステップ1の判定は `typeof crypto.randomUUID === 'function'` で行う。`crypto` オブジェクト自体は `file://` でも存在し得るため、`crypto` の有無だけで判定してはならない。

## 4. localStorage仕様

### 4.1 保存キーと形式 [必須A]

- キー： `part16-flashcards`（固定文字列。1キーのみ使用する）
- 形式：

```js
{
  version: 1,
  cards: [ /* 2.1 のカードオブジェクト */ ]
}
```

### 4.2 保存対象 [必須B]

**保存するのは `cards` のみ。** 以下は保存しない。

| 保存しないもの | 理由 |
|---|---|
| 学習中かどうか（`active`） | セッション管理は MVP外（課題32章）。リロード時は常に「学習未開始」状態から始まる。 |
| 現在出題中のカードID | 同上。 |
| 現在の面（問題／答え） | 同上。 |
| 全体集計値 | `cards` から導出する（2.3）。 |
| 学習履歴 | MVP外（課題18章）。日時付き回答履歴は保存しない。 |

### 4.3 読み込み手順 [必須B]

```
load():
  1. localStorage.getItem('part16-flashcards')
     - 例外が発生した場合 → 破損扱い（15.2）
  2. 値が null（キーが存在しない）→ 初回起動。cards = [] で正常起動。エラー表示なし。
  3. JSON.parse()
     - 例外 → 破損扱い
  4. パース結果がオブジェクトでない、または null、または配列 → 破損扱い
  5. root.version !== 1 → 破損扱い
  6. Array.isArray(root.cards) が false → 破損扱い
  7. cards の各要素を 2.4 で検証
     - 1件でも違反 → 破損扱い（全件不採用）
  8. すべて通過 → cards を採用
```

**採用時の正規化 [必須B]**

- カードオブジェクトは、2.1 に定義したフィールドのみを持つ新しいオブジェクトとして再構築する。未知のフィールドは破棄する（読み込んだデータをそのまま信用してメモリに載せない）。
- 配列順は保存時の順序をそのまま採用し、表示時に 8章 の規則で並べ替える。

### 4.4 保存手順 [必須B]

```
save(cards):
  try:
    localStorage.setItem('part16-flashcards', JSON.stringify({version: 1, cards}))
    return true
  catch:
    return false
```

`setItem` は容量超過（`QuotaExceededError`）、プライベートモード、セキュリティ制限（ストレージアクセス拒否）で例外を投げ得る。**必ず try/catch で捕捉し、真偽値を返す。** 呼び出し側は戻り値を必ず確認する（15章）。

## 5. 状態管理

### 5.1 アプリケーション状態 [必須B]

```js
state = {
  // 永続（localStorageに保存）
  cards: [],

  // 非永続（メモリのみ）
  study: {
    active: false,          // 学習中かどうか
    currentCardId: null,    // 出題中カードのid。activeがfalseならnull
    face: 'question'        // 'question' | 'answer'
  }
}
```

### 5.2 「直前カード」の保持方法 [必須A]

連続重複回避（10.3）で除外する「直前のカード」は、**`study.currentCardId`（＝現在出題中のカードのid）** をそのまま使う。

- **index ではなく id で保持する。** 学習中にカードの登録・削除が可能（19章）であり、index は容易にズレるため。
- 抽選の直前に `cards` から id → index を解決する。解決できない場合（削除済み）は除外なし（`excludedIndex = null`）として扱う。
- 「直前カード」用の独立フィールド（`lastCardId` 等）は持たない。現在出題中カード＝直前カードであり、二重管理は不整合の原因になる。

### 5.3 唯一の書き込み経路 [必須B]

`cards` を変更する操作（登録・削除・採点）は、**必ず以下の単一手順を通す。** これ以外の経路で `state.cards` を書き換えてはならない。

```
commit(nextCards):
  1. nextCards（新しい配列・新しいカードオブジェクト）を組み立てる
     ※ state.cards および既存カードオブジェクトを破壊的に変更しない
  2. save(nextCards) を呼ぶ
  3. 戻り値が true の場合のみ  state.cards = nextCards  とする
  4. 戻り値が false の場合、nextCards を破棄する（state.cards は変更前のまま）
  5. 戻り値を返す
```

この方式（**保存成功後に状態を確定**）を、登録・削除・採点のすべてに適用する。詳細と根拠は 15.3。

## 6. 登録仕様

### 6.1 入力欄 [必須A]

| 項目 | 要素 | 理由 |
|---|---|---|
| 問題 | `<textarea>` | 単語だけでなく、専門用語の説明文や資格試験の設問など複数行の入力があり得るため |
| 答え | `<textarea>` | 同上 |

- 両方に `<label>` を関連付ける（`for` / `id`）。
- 初期表示の行数は3行程度とし、CSS で最小高さを確保する。

### 6.2 バリデーション [必須A]

登録ボタン押下時に、以下の順で検証する。

1. 問題が空文字、または `trim()` 後に空文字 → エラー
2. 答えが空文字、または `trim()` 後に空文字 → エラー

**文字数上限は設けない [必須B]。** 課題文が「MVPでは過剰な制限を設けない案を第一候補」としているため。上限を設けると、上限値の根拠、超過時のメッセージ、既存データが上限を超えていた場合の扱い、という論点が発生する。

### 6.3 エラーメッセージ [必須A]

日本語で表示する。

| 状況 | メッセージ |
|---|---|
| 問題が未入力／空白のみ | 問題を入力してください。 |
| 答えが未入力／空白のみ | 答えを入力してください。 |

- 両方が不正な場合は、**両方のメッセージを該当する入力欄それぞれに表示する。**
- 各メッセージは対応する `<textarea>` の直後に配置し、`aria-describedby` で関連付ける（20.4）。
- エラーが発生した入力欄に `aria-invalid="true"` を付与する。正常化したら除去する。

### 6.4 前後空白と改行の扱い [必須A]

- 保存する値は `question.trim()` / `answer.trim()` とする。
- **内部の改行・内部の空白は保持する。**

例：

| 入力 | 保存値 |
|---|---|
| `"  HTTP\nStatus  "` | `"HTTP\nStatus"` |
| `"A\n\nB"` | `"A\n\nB"` |
| `"   "` | 登録不可（エラー） |

- 表示時は CSS の `white-space: pre-wrap` により改行と連続空白を保持する（一覧・学習カードの両方）。

### 6.5 登録成功時の動作 [必須A]

1. `createId()` で id を生成する（3.3）。
2. 新しいカードオブジェクトを作る（`correctCount: 0`, `incorrectCount: 0`, `createdAt: Date.now()`）。
3. `nextCards = [...state.cards, newCard]` を組み立てる。
4. `commit(nextCards)` を呼ぶ（5.3）。
5. **戻り値が true の場合のみ：**
   - 両方の入力欄をクリアする
   - エラー表示を消す
   - 一覧を再描画する
   - 学習中であれば学習エリアの表示を更新する（19章）
6. **戻り値が false の場合：**
   - 入力値を維持する（クリアしない）
   - 一覧は変化しない
   - 保存失敗メッセージを表示する（15.3）

### 6.6 重複カード [必須A]

同じ問題・同じ答えのカードを複数登録できる。**重複チェックは行わない。**

理由：文脈違いで同じ問題文を持つことがあり得る／重複判定ルール（大文字小文字、空白正規化、片方だけ一致など）が複雑になる／課題要件に重複禁止がない。

重複警告は [MVP外]。

## 7. 一覧管理仕様

### 7.1 表示項目 [必須A]

各カードについて、以下をすべて表示する。

| 項目 | 表示 |
|---|---|
| 問題 | ラベル「問題」＋全文 |
| 答え | ラベル「答え」＋全文 |
| 正解数 | 「正解 N」 |
| 不正解数 | 「不正解 N」 |
| 削除ボタン | 「削除」 |

### 7.2 答えの表示方式 [必須A]

**問題・答えともに全文を表示する。** 折りたたみ・省略表示は行わない。

- `white-space: pre-wrap` で改行を保持し、`overflow-wrap: anywhere` で長い連続文字列を折り返す。
- 採用理由：課題文が「問題・答え・正解数・不正解数が確認できること」を最低条件としており、全文表示が最も素直に満たす。折りたたみ方式は「カードごとの展開状態」という新しい状態が生じ、削除・登録による再描画時にその状態を維持するか破棄するかという仕様が追加で必要になる。

### 7.3 並び順 [必須A]

**登録順の新しいものを上に表示する。**

- 定義：`state.cards` は登録順（新しいものが末尾）に並んだ配列であり、一覧はこの配列を逆順にした順序で描画する。
- 実装： **`state.cards.slice().reverse()` の順序で描画する。** ソート関数は使わない。
- **`createdAt` は表示順のソートに使用しない。** 保存データの配列順と `createdAt` の大小が一致しない場合があり得るため（外部から localStorage を編集された場合など）、表示順の基準は配列順のみとする。`createdAt` フィールド自体はカードデータ構造（2.1）に保持し続けるが、並び替えには用いない。
- 理由：直前に登録したカードをすぐ確認できるため。
- 更新順（`updatedAt` 降順）は採用しない。`updatedAt` を持たない（2.2）。
- 昇順（古い順）は採用しない。登録直後のカードを確認するのに毎回末尾までスクロールが必要になる。
- **並び替えUIは [MVP外]。**

### 7.4 0件時の表示 [必須A]

カードが0件のとき、一覧領域に「カードはまだありません。」と表示する。

### 7.5 安全な描画 [必須A]

問題・答え・数値を含むすべてのテキストは `textContent` で設定する。`innerHTML` は使用しない（22章）。

## 8. 削除仕様

### 8.1 確認方法 [必須A]

**`confirm()` による確認を行う。**

| 候補 | 判定 |
|---|---|
| A. `confirm()` | **採用。** 標準機能で追加状態を持たず、ブラウザ標準のフォーカス管理・キーボード操作・読み上げがそのまま働く |
| B. 独自確認UI | 不採用。モーダルの開閉状態、フォーカストラップ、Escキー、背景スクロール抑止など仕様が増える |
| C. 確認なし | 不採用。8.2 参照 |

確認メッセージ： `このカードを削除しますか？（正解・不正解の記録も削除されます）`

### 8.2 Part 15（全消去：確認なし）との性質の違い [必須A]

課題文の指示により、両者の違いを明記する。

| 観点 | Part 15 の全消去 | Part 16 のカード削除 |
|---|---|---|
| 操作頻度 | ワークフロー上、繰り返し使う日常操作。毎回確認が出ると作業のリズムを阻害する | 誤登録の訂正など、日常的に頻発しない操作 |
| 失われるもの | その場の入力内容のみ。作り直しのコストが低い | カード内容に加えて、**それまで蓄積した正解数・不正解数**が失われる |
| 復元可能性 | 同じ内容を再入力すれば実質的に元に戻る | Undo が [MVP外] であり、学習記録リセットも [MVP外] のため、**学習記録は再現不可能** |

頻度が低く、かつ再現不可能な情報が失われるため、Part 16 では確認を設ける。

**Undo は [MVP外]。**

### 8.3 削除処理 [必須A][必須B]

```
deleteCard(id):
  1. confirm() を表示。キャンセルなら何もしない（終了）
  2. nextCards = state.cards.filter(c => c.id !== id)
  3. ok = commit(nextCards)
  4. ok が false の場合：
       - 一覧は変化しない（カードは残ったまま）
       - 保存失敗メッセージを表示（15.3）
       - 学習状態は変更しない
       - 終了
  5. ok が true の場合：
       - 一覧を再描画
       - 全体集計を再計算して再描画
       - 学習状態の追従処理（8.4）を行う
```

**削除されたカードの学習記録も同時に消える。** カードオブジェクト内に記録を持つ設計（2.3）により、これは自動的に成立する。全体集計は `cards` からの導出値なので、削除後の集計から当該カードの分は除かれる。

### 8.4 現在出題中カードを削除した場合の状態遷移 [必須A]

削除の保存が成功した後、`study.active === true` の場合に以下を判定する。

| 条件 | 遷移 |
|---|---|
| 削除したカードが現在出題中カードでない | 学習状態を変更しない（出題中のカード・面をそのまま維持） |
| 削除したカードが現在出題中カード、かつ削除後の `cards.length === 0` | 学習終了状態へ（8.5） |
| 削除したカードが現在出題中カード、かつ削除後の `cards.length >= 1` | 次のカードを選び直す（8.6） |

### 8.5 学習終了状態への遷移（0件になった場合） [必須A]

```
study.active = false
study.currentCardId = null
study.face = 'question'
```

画面表示：

- 学習エリアに「カードを登録してください。」と表示する（0件時の案内と同一：16.2）
- 「答えを見る／問題に戻す」ボタン、「正解」「不正解」ボタンを **`disabled`** にする
- 「学習を始める」ボタンを `disabled` にする（カード0件のため：9.2）
- **aria-live 領域には何も通知しない**（20.5）

### 8.6 次のカードを選び直す [必須A]

```
study.currentCardId = cards[pickNextIndex(Math.random(), cards.length, null)].id
study.face = 'question'
```

- **除外index は `null`（除外なし）とする。** 直前カードは削除済みで候補に存在せず、除外対象がないため。
- 選び直した問題を aria-live 領域に通知する（20.5）。

### 8.7 削除ボタンのラベル [必須B]

視覚上は「削除」とするが、一覧に複数のカードがあるため、`aria-label` に問題文の先頭30文字を含める。

例： `aria-label="「HTTPステータス404の意味は？」を削除"`

- 問題文が30文字を超える場合は先頭30文字＋`…` とする。
- `aria-label` は `textContent` と同様に文字列としてそのまま設定する（属性値なので HTML として解釈されない）。

## 9. 学習モード

### 9.1 画面構成方式 [必須A]

**1ページ内で「登録」「学習」「一覧」をすべて完結させる。** 画面遷移（別ページ・表示切替による排他セクション）は行わない。

| 候補 | 判定 |
|---|---|
| 1ページ内の別セクション | **採用。** 学習中でも一覧・登録を操作でき（19章）、「どの画面にいるか」という状態を持たずに済む |
| 画面遷移 | 不採用。画面状態という追加の状態が必要になり、学習中のカード追加・削除の扱いが複雑になる |

### 9.2 出題開始条件 [必須A]

| カード枚数 | 「学習を始める」ボタン | 学習エリアの表示 |
|---|---|---|
| 0件 | `disabled` | 「カードを登録してください。」 |
| 1件 | 有効 | 未開始時：「学習を始めるボタンを押してください。」 |
| 2件以上 | 有効 | 同上 |

- 0件から1件になった時点で、ボタンの `disabled` を解除する。
- 1件以上から0件になった時点で、ボタンを `disabled` にする。

### 9.3 出題のタイミング [必須A]

**「学習を始める」ボタンの押下時にのみ出題を開始する。**

| 候補 | 判定 |
|---|---|
| A. 「学習を始める」ボタン | **採用。** 一覧確認や登録を先に済ませられる。ユーザーが学習開始を明示的に選べる |
| B. ページ読み込み時に自動出題 | 不採用。一覧を確認したいだけの起動でも出題状態になる |
| C. カード登録後に自動出題 | 不採用。連続してカードを登録したい場面（初回のまとめ登録）で毎回学習エリアが切り替わり、邪魔になる |

### 9.4 学習開始処理 [必須A]

```
startStudy():
  1. cards.length === 0 なら何もしない（ボタンはdisabledだが二重防御）
  2. study.active = true
  3. study.currentCardId = cards[pickNextIndex(Math.random(), cards.length, null)].id
  4. study.face = 'question'
  5. 学習エリアを再描画
  6. aria-live 領域に「問題：<問題文>」を通知（20.5）
```

- 開始時は除外index を `null` とする（直前カードが存在しないため）。
- **`cards` の並び順に依存しない。** `pickNextIndex` には `cards` 配列（登録順）をそのまま渡す。一覧の表示順（降順）とは無関係。

### 9.5 学習中の「学習を始める」ボタン [必須B]

`study.active === true` の間、「学習を始める」ボタンを `disabled` にする。

**理由：学習開始済みの状態に対して「再開始」という操作を定義していないため。** ボタンが押せる状態のまま押された場合の挙動（現在カードを維持するのか／選び直すのか／面をリセットするのか）を仕様として定める必要が生じるが、その操作は課題要件に存在しない。操作を無効化することで、定義されていない遷移そのものを発生させない。

学習が終了状態に戻る（8.5）のは、**現在出題中カードの削除によりカードが0件になった場合のみ**である。この場合、カード0件により「学習を始める」ボタンは引き続き `disabled` となる。

**学習を明示的に終了するボタンは設けない [必須B]。** セッションの開始・終了・リセットを増やさない（課題32章）。

## 10. ランダム出題仕様

### 10.1 純粋関数の分離 [必須A]

`Math.random()` を UI 処理に直接埋め込まない。乱数値から index を決める処理を、副作用のない純粋関数として分離する。

```js
function pickNextIndex(randomValue, length, excludedIndex) {
  if (length <= 1 || excludedIndex === null || excludedIndex === undefined) {
    return Math.floor(randomValue * length);
  }
  const i = Math.floor(randomValue * (length - 1));
  return i >= excludedIndex ? i + 1 : i;
}
```

- `randomValue` は `0 <= randomValue < 1` の数値。
- `length` は 1 以上の整数。
- `excludedIndex` は `null`、または `0 <= excludedIndex < length` の整数。
- **`Math.round()` を使用してはならない。** `Math.round(r * length)` は両端の確率が中間の半分になり、かつ `r` が 1 に近いとき `length` を返して範囲外になる。
- 呼び出し側は `pickNextIndex(Math.random(), cards.length, excludedIndex)` の形でのみ使う。関数内部で `Math.random()` を呼んではならない（決定的テスト不能になるため）。

### 10.2 index の範囲について [必須B]

`randomValue` が `Math.random()` の最大値 `0.9999999999999999`（1未満の最大の倍精度値）のとき、`Math.floor(randomValue * length)` が `length` を返すことはない（浮動小数点の丸め上、積は必ず `length` 未満の値に丸まる）。したがって範囲外を防ぐためのクランプ処理は不要であり、**追加してはならない**（余分な分岐はテスト対象を増やすだけである）。この性質は 24.6 の境界値テストで確認する。

### 10.3 同じカードの連続出題の回避 [必須A]

**カードが2件以上のとき、直前に出題したカードと同じカードを連続して出題しない。**

採用方式： **除外候補から選ぶ方式**（`pickNextIndex` の第3引数）

| 候補 | 判定 |
|---|---|
| 棄却法（直前と同じなら再抽選をループ） | 不採用。乱数の消費回数が不定であり、決定的テストには乱数列をスタブする必要があって検証が煩雑。分布は歪まないが、テスト容易性で劣る |
| **除外候補から選ぶ（`length - 1` 個から1回で選ぶ）** | **採用。** 乱数を1回だけ消費して確定する。境界値テストが素直に書ける |
| 1回だけ振り直す | **禁止。** 直前カードの出現確率だけが `1/length²` に下がり、他カードとの分布が歪む |

**分布が歪まないことの根拠：** `length - 1` 個の候補に対して `Math.floor(r * (length - 1))` で選ぶため、各候補が等しい幅の乱数区間に対応する。その後 `i >= excludedIndex ? i + 1 : i` で index を写像するが、これは単射であり確率を変えない。結果として、除外index 以外の `length - 1` 個の候補が等確率になる。

### 10.4 カード1件時 [必須A]

`length <= 1` のとき、`pickNextIndex` は無条件に `Math.floor(randomValue * length)`（＝常に `0`）を返す。

**カードが1件のときは連続重複回避を適用しない。** 出題できるカードが1枚しかないため、同じカードが連続するのは正しい挙動である。

### 10.5 除外index の解決 [必須A]

採点後の次問選択（12.4）で除外index を決める手順：

```
resolveExcludedIndex():
  1. study.currentCardId が null なら null を返す
  2. cards.findIndex(c => c.id === study.currentCardId) を求める
  3. 結果が -1（該当なし＝削除済み）なら null を返す
  4. cards.length <= 1 なら null を返す
  5. そのindexを返す
```

id から index を解決するのは**抽選の直前**とする。学習中にカードの登録・削除が起こり得るため（19章）、index をキャッシュしてはならない。

### 10.6 カード追加後の出題候補 [必須A]

学習中に登録したカードを、**即時に次回以降の出題候補に含める。**

理由：次のカードは常に最新の `state.cards` から選ぶ。学習セッション専用のカード配列を別に持たないため、追加されたカードは自動的に候補に入る。別配列を持つと、いつ同期するか・削除をどう反映するかという仕様が増える。

## 11. 表面／裏面切替仕様

### 11.1 初期表示 [必須A]

出題時、カードは必ず **「問題」面** から表示する（`study.face = 'question'`）。

### 11.2 切替ボタン [必須A]

**1つのボタンでトグルする。**

| 現在の面 | ボタンのラベル | 押下後の面 |
|---|---|---|
| 問題 | 答えを見る | 答え |

### 11.4 未開始時の表示 [必須B]

`study.active === false` のとき、学習カード領域には面ラベルと本文を表示せず、案内文のみを表示する（16.2）。切替ボタン・正解／不正解ボタンはすべて `disabled`。

## 12. 正解／不正解記録仕様

### 12.1 ボタンの有効化タイミング [必須A]

**「正解」「不正解」ボタンは、答えを表示している間（`study.face === 'answer'`）のみ有効とする。** 問題面を表示している間は `disabled`。

| 候補 | 判定 |
|---|---|
| **A. 答えを表示した後だけ有効** | **採用** |
| B. 常時有効（答えを見ずに自己採点できる） | 不採用 |

**採用理由（両案の比較）：**

B の利点は「答えを見なくても分かったので正解を押せる」という操作の短縮である。しかし、答えを表示してから正解を押しても、記録される値（`correctCount` の +1）は A と B で完全に同一であり、失われるのはボタン1回分の手数のみである。

一方 A を採らない場合、問題を表示した直後の画面に採点ボタンが有効な状態で並ぶため、誤クリックによって意図しない正解／不正解が記録される。学習記録リセットは [MVP外]（課題33章）、編集も [MVP外] であるため、**この誤記録は取り消す手段がない。**

失われる価値（手数1回）と発生するリスク（不可逆な記録汚染）が非対称であるため、A を採用する。

### 12.2 記録の更新 [必須A]

| ボタン | 更新内容 |
|---|---|
| 正解 | 現在カードの `correctCount` を +1 |
| 不正解 | 現在カードの `incorrectCount` を +1 |

更新は破壊的変更ではなく、新しいカードオブジェクト・新しい配列を作って行う（5.3）。

```
nextCards = state.cards.map(c =>
  c.id === study.currentCardId
    ? { ...c, correctCount: c.correctCount + 1 }   // または incorrectCount
    : c
)
```

### 12.3 採点処理の全体手順 [必須A]

```
grade(isCorrect):
  1. study.active が false、または study.face !== 'answer' なら何もしない
     （ボタンはdisabledだが二重防御）
  2. nextCards を組み立てる（12.2）
  3. ok = commit(nextCards)   ← 保存を試みる
  4. ok が false の場合：
       - state.cards は変更されない（記録は増えない）
       - 現在カードに留まる（currentCardId を変更しない）
       - 面も 'answer' のまま変更しない
       - 保存失敗メッセージを表示（15.4）
       - aria-live 領域は更新しない
       - 終了（次の問題へ進まない）
  5. ok が true の場合：
       - 一覧を再描画（当該カードの正解数／不正解数が更新される）
       - 全体集計を再描画
       - 次のカードを選ぶ（12.4）
```

### 12.4 採点後の動作 [必須A]

**採点（保存成功）後は、自動で次のカードへ進む。**

| 候補 | 判定 |
|---|---|
| **採点したら自動で次へ** | **採用** |
| 採点後も同じカードに留まる | 不採用 |

採用理由：留まる方式では、次へ進むために別途「次の問題」ボタンの押下が必要になる。1枚あたり「答えを見る」→「正解／不正解」→「次の問題」の3操作となり、繰り返し学習のテンポを損なう。また留まる方式では、同じカードに対して連続で採点ボタンを押せてしまい、同一カードの記録が意図せず何度も増える経路ができる（自動で次へ進めばこの経路が存在しない）。

処理：

```
1. excludedIndex = resolveExcludedIndex()   ← 10.5
2. nextIndex = pickNextIndex(Math.random(), cards.length, excludedIndex)
3. study.currentCardId = cards[nextIndex].id
4. study.face = 'question'          ← 必ず問題面に戻す
5. 学習エリアを再描画（切替ボタンのラベルを「答えを見る」に戻す）
6. 正解／不正解ボタンを disabled にする（面が 'question' になったため）
7. aria-live 領域に「問題：<次の問題文>」を1回だけ通知（20.5）
```

**遷移は即時とする [必須B]。** 遅延やアニメーションによる待ち時間は設けない。タイマーは [MVP外]。

## 13. 学習状況仕様

### 13.1 カード単位の学習状況 [必須A]

各カードの `correctCount` / `incorrectCount` を一覧に表示する（7.1）。

### 13.2 全体集計 [必須A]

全体集計を学習エリア内に表示する。課題文が「簡単な学習状況を記録」を求めており、カード単位の累計だけでは全体の学習量が把握できないため MVP に含める。

| 項目 | 計算式 |
|---|---|
| 総回答数 | `Σ(correctCount) + Σ(incorrectCount)` |
| 正解数 | `Σ(correctCount)` |
| 不正解数 | `Σ(incorrectCount)` |
| 正解率 | `correct / (correct + incorrect) * 100` |

- **保存しない。** 表示のたびに `state.cards` から導出する（2.3）。
- 学習未開始時も表示する（過去の累計が確認できるため）。

### 13.3 正解率の表示規則 [必須A]

- **小数1桁固定。** `toFixed(1)` を用いる。
- 単位は `%`。表示例： `66.7%`
- **総回答数が0のとき（未回答時）は `0.0%` と表示する。** ゼロ除算を発生させない。

```
formatAccuracy(correct, incorrect):
  total = correct + incorrect
  if total === 0: return '0.0%'
  return (correct / total * 100).toFixed(1) + '%'
```

検証例：

| correct | incorrect | 表示 |
|---|---|---|
| 0 | 0 | `0.0%` |
| 0 | 3 | `0.0%` |
| 1 | 0 | `100.0%` |
| 2 | 1 | `66.7%` |
| 1 | 2 | `33.3%` |
| 1 | 3 | `25.0%` |

### 13.4 保存しない集計 [MVP外]

- 今回のセッションの正解数・回答数（課題32章）
- 1回ごとの回答履歴・日時（課題18章）
- 学習記録のリセット機能（課題33章）

リセットを含めない理由：課題文にない。含めると、リセット確認の要否、カード単位／全体のどちらをリセットするか、リセット後に一覧表示をどう更新するか、といった論点が増える。

## 14. 学習中の一覧・登録操作

### 14.1 操作の可否 [必須A]

**学習中でも、登録フォーム・カード一覧を通常どおり操作できる。**

理由：1ページ内で完結する構成（9.1）であり、学習中に操作を禁止すると「学習を明示的に終了する」操作が必要になる。セッションの開始・終了を増やさない方針（課題32章）に反する。

### 14.2 学習中の登録 [必須A]

- 登録処理は 6.5 と同一。
- 登録成功後、**学習エリアの表示は変更しない**（現在出題中のカード・面をそのまま維持する）。
- 追加されたカードは次回の抽選から候補に含まれる（10.6）。
- aria-live 領域には通知しない（20.5：学習カードの内容が変わっていないため）。

### 14.3 学習中の削除 [必須A]

8.3〜8.6 に従う。現在出題中カードの削除時の処理は必須である。

## 15. 破損データ／保存失敗時の整合性

### 15.1 方針 [必須B]

**「画面に反映されているが保存されていない」状態を一切作らない。** すべての `cards` 変更は 5.3 の `commit()` を通し、保存成功後にのみメモリ上の状態を確定する。

### 15.2 破損データ読み込み時の状態 [必須A]

4.3 のいずれかのステップで破損と判定した場合：

| 項目 | 挙動 |
|---|---|
| メモリ上の状態 | `state.cards = []`（空の初期状態で起動） |
| localStorage | **削除しない。上書きもしない。読み込まないだけ。** |
| アプリの動作 | クラッシュせず、通常どおり起動する。登録・一覧・学習エリアすべて操作可能 |
| 画面表示 | 通知エリアにエラーメッセージを表示する |
| 一覧 | 「カードはまだありません。」 |
| 学習 | 0件時の状態（9.2）：「学習を始める」ボタン `disabled` |

**エラーメッセージ：**

```
保存データを読み込めませんでした。空の状態で開始します。
新しくカードを登録すると、保存データは上書きされます。
```

**自動削除しない理由（他案との比較）：**

| 候補 | 判定 |
|---|---|
| **A. 読み込まず無視し、削除もしない** | **採用** |
| B. 破損データを別キーへ退避してから本キーを削除 | 不採用 |
| C. 自動削除 | 不採用 |

- C は復旧不能になる。ユーザーが開発者ツール等でデータを取り出す余地を残すべきである。
- 「壊れたままだと再読み込みのたびにエラーが出続ける」という A の欠点は事実だが、それが続くのは**破損検知後、まだ1枚もカードを登録していない間だけ**である。カードを1枚登録すれば同じキーに正常なデータが上書きされ、以降エラーは出なくなる（メッセージ2行目でその旨を案内する）。
- B はキーが増えるうえ、退避のための `setItem` 自体が失敗し得る。特に容量超過が破損の原因である場合、退避は必ず失敗する。処理が複雑になる割に確実でない。

**通知エリアの扱い [必須B]：** このメッセージは、ユーザーが閉じるまで表示し続ける（自動消去しない）。閉じるボタン（「閉じる」）を設ける。

### 15.3 保存失敗時の状態確定手順 [必須A]

`localStorage.setItem()` は容量超過・プライベートモード・セキュリティ制限で失敗し得る。

**採用方式： C「保存成功後にだけ状態を確定」**

| 候補 | 判定 |
|---|---|
| A. メモリ上の変更をロールバック | 部分採用。C と結果は等価だが、一度メモリを変更してから戻す手順は、戻し漏れのバグを生みやすい |
| B. 画面には反映し、保存失敗を警告 | **不採用。** 画面と保存内容が食い違う。リロードで消えるカードが画面に見えている状態は、課題文が明示的に避けよと指示した不整合である |
| **C. 保存成功後に状態を確定** | **採用。** そもそもメモリを先に変更しないため、戻す処理自体が存在しない |

**手順（5.3 の `commit()` 再掲）：**

```
1. 変更後の新しい配列 nextCards を組み立てる
   ※ state.cards および既存のカードオブジェクトを一切変更しない
     （スプレッド / map / filter で新しいオブジェクト・配列を作る）
2. save(nextCards) を呼び、try/catch の結果を真偽値で受け取る
3. true  → state.cards = nextCards としてから再描画する
   false → nextCards を破棄する。state.cards は元のまま。再描画しない
4. false のとき、通知エリアにエラーメッセージを表示する
```

これにより、**正常に読み込めた後、およびアプリ内の登録・削除・採点操作において、画面状態と正常な保存状態の不整合を作らない。**

補足：破損データを検出して空状態で起動した場合（15.2）、localStorage には読み込まれなかった破損データが残っているため、画面状態と localStorage のバイト列は一致しない。これは意図した挙動であり、上記の不整合には当たらない。破損データはアプリにとって「正常な保存状態」ではなく、その状態からカードを1枚登録した時点で `commit()` により正常な保存状態が書き込まれ、以降は上記の性質が成り立つ。

**操作別のエラーメッセージ：**

| 操作 | メッセージ |
|---|---|
| 登録（6.5） | カードを保存できませんでした。ブラウザの保存容量やプライベートモードの設定を確認してください。入力内容は残しています。 |
| 削除（8.3） | カードを削除できませんでした。ブラウザの保存容量やプライベートモードの設定を確認してください。 |
| 採点（12.3） | 学習記録を保存できませんでした。ブラウザの保存容量やプライベートモードの設定を確認してください。次の問題には進んでいません。 |

### 15.4 採点の保存失敗 [必須A]

**保存に成功してから次の問題へ進む。** 失敗した場合は現在のカードに留まる。

失敗時の状態（12.3 ステップ4 再掲）：

| 項目 | 状態 |
|---|---|
| `state.cards` | 変更されない（`correctCount` / `incorrectCount` は増えない） |
| `study.currentCardId` | 変更されない（同じカードのまま） |
| `study.face` | `'answer'` のまま（問題面に戻さない） |
| 正解／不正解ボタン | 有効のまま（面が `'answer'` のため。再試行できる） |
| 一覧 | 再描画しない（値が変わっていないため） |
| 全体集計 | 再描画しない |
| aria-live 領域 | **更新しない** |
| 通知エリア | 採点用エラーメッセージを表示 |

保存に成功していないのに次の問題へ進むと、学習記録が失われたことにユーザーが気付けない。

### 15.5 削除の保存失敗 [必須A]

登録・採点と同一の整合性方針（15.3）を適用する。

「画面では消えたが再読み込みで復活する」状態を作らない。`commit()` が `false` を返した場合、**一覧からカードを消してはならない。** 学習状態（現在出題中カード）も変更しない。

### 16.1 画面構成と並び順 [必須A]

上から順に：

```
1. タイトル（h1）「フラッシュカード学習」
2. 通知エリア（エラー・警告。通常は非表示）
3. カード登録フォーム
     - 問題（label + textarea）
     - 答え（label + textarea）
     - エラーメッセージ（各textareaの直下）
     - 「登録」ボタン

     - 「答えを見る」/「問題に戻す」ボタン
     - 「正解」ボタン / 「不正解」ボタン
```

**採用理由（並び順の比較）：**

| 候補 | 判定 |
|---|---|
| **A. 登録フォーム → 学習エリア → カード一覧** | **採用** |
| B. 学習エリア → 登録フォーム → カード一覧 | 不採用 |

課題文が「初めて使う人が0件状態で迷わない構成を優先」と指定している。0件状態で最初に取るべき行動は登録であり、A なら案内文を読む前に入力欄が視界に入る。B は0件時に「カードを登録してください」を読んだ後、下へスクロールして登録フォームを探す必要がある。

トレードオフとして、カードが揃った後の日常利用では毎回登録フォームを通り過ぎることになるが、初回体験の分かりやすさを優先する。

### 16.2 状態別の学習エリア表示 [必須A]

| カード0件 | 「カードを登録してください。」 | `disabled` | `disabled` | `disabled` |

| 学習中・問題面 | 面ラベル「問題」＋問題文 | `disabled`（9.5） | 有効（ラベル「答えを見る」） | `disabled` |
| 学習中・答え面 | 面ラベル「答え」＋答え文 | `disabled`（9.5） | 有効（ラベル「問題に戻す」） | 有効 |

### 16.3 カード一覧の見出し [必須B]

「カード一覧（N件）」の N は `state.cards.length`。0件時は「カード一覧（0件）」とし、本文に「カードはまだありません。」を表示する。

### 16.4 視覚デザイン [必須B]

- 学習カードは枠線または背景色で領域を明示し、一覧のカードより大きく表示する。

## 18. アクセシビリティ

### 18.1 フォーム [必須A]

- 問題・答えの `textarea` に `<label for>` を関連付ける。
- エラー時、該当 `textarea` に `aria-invalid="true"` を付け、エラーメッセージ要素の `id` を `aria-describedby` に設定する。
- エラー発生時、**最初の不正な `textarea` にフォーカスを移す。** これによりスクリーンリーダーがラベルとエラーメッセージを読み上げる。

### 18.2 ボタン [必須A]

- 「登録」「学習を始める」「答えを見る／問題に戻す」「正解」「不正解」「削除」はすべて標準の `<button>` 要素で実装する。`div` + クリックハンドラは使わない。
- `type="button"` を明示する。
- 無効化は `disabled` 属性で行う（CSS で見た目だけ無効にしない）。
- フォーカスリングを消さない（`outline: none` を単独で使わない）。装飾する場合は `:focus-visible` で視認可能な代替スタイルを与える。

### 18.3 色に依存しない表現 [必須A]

- 表面／裏面の状態は、面ラベルの**テキスト**（「問題」「答え」）で判別できる。色だけで区別しない。
- 「正解」「不正解」はボタンの**テキスト**で判別できる。色だけで区別しない。
- 一覧の正解数・不正解数も「正解 N」「不正解 N」のテキストラベル付きで表示する。

### 18.4 通知エリア [必須B]

保存失敗・破損データのエラーを表示する通知エリアは、**`aria-live` を付けない。** live region は 18.5 の1つのみとする。

代わりに、以下で伝達する。

- 通知エリアの要素に `tabindex="-1"` を設定する。
- エラー表示時に `focus()` を呼ぶ。フォーカス移動によりスクリーンリーダーがその内容を読み上げる。
- 通知エリアには「閉じる」ボタンを設ける。閉じた場合は要素を非表示にする。
- 通知エリア非表示時は DOM から内容を空にする（`textContent = ''`）か `hidden` 属性を付ける。

### 18.5 aria-live 領域 [必須A]

**視覚非表示（visually-hidden）の `aria-live="polite"` 領域を1つだけ設ける。** 学習カードの内容（問題文・答え文）そのものを通知する。

**要件：**

| # | 要件 |
|---|---|
| L1 | live region はアプリ全体で**1つだけ**。他の要素に `aria-live` / `role="status"` / `role="alert"` を付けない |
| L2 | 視覚的には非表示（visually-hidden CSS。`display: none` は不可。読み上げられなくなるため） |
| L3 | 属性は `aria-live="polite"` および `aria-atomic="true"` |
| L4 | **視覚的な学習カード要素そのものには `aria-live` を付けない** |
| L5 | 通知内容には**問題文・答え文の本文そのものを含める** |
| L6 | 「次の問題を表示しました」のような、本文を含まない通知だけにしてはならない |
| L7 | 集計値（総回答数・正解数・不正解数・正解率）を live 領域に含めてはならない |
| L8 | 1回の採点で通知は**1回だけ** |

**通知フォーマット：**

| 面 | 文字列 |
|---|---|
| 問題 | `問題：<question の全文>` |
| 答え | `答え：<answer の全文>` |

例：

- `問題：HTTPステータス404の意味は？`
- `答え：リソースが見つからないことを示します。`

**通知タイミング（発火する操作）：**

| # | 操作 | 通知 |
|---|---|---|
| T1 | 「学習を始める」押下（9.4） | `問題：〜`（1回） |
| T2 | 「答えを見る」押下（11.2） | `答え：〜`（1回） |
| T3 | 「問題に戻す」押下（11.2） | `問題：〜`（1回） |
| T4 | 「正解」または「不正解」押下し、**保存に成功**した場合（12.4） | **次のカードの** `問題：〜`（1回のみ） |
| T5 | 現在出題中カードの削除により次のカードを選び直した場合（8.6） | `問題：〜`（1回） |

**通知しない操作：**

| 操作 | 理由 |
|---|---|
| 採点の保存に失敗した場合（15.4） | 学習カードの内容が変化していないため。エラーは通知エリア（18.4）で伝える |
| カード登録（14.2） | 学習カードの内容が変化しないため |
| 現在出題中でないカードの削除 | 同上 |
| 削除により0件になり学習終了した場合（8.5） | 出題する問題が存在しないため。状態はフォーカス移動と静的テキストで伝える |
| 全体集計の更新 | L7 に反するため |
| 通知エリアのエラー表示 | live region を1つに限るため（18.4 の方式で伝達） |

**T4 で「1回だけ」を保証する実装指針 [必須B]：**

採点処理では、記録更新の描画と次問の描画が連続する。この過程で live 領域の `textContent` を複数回書き換えると、読み上げが重複または途中で打ち切られる。**live 領域への書き込みは、採点処理の最後に1回だけ行う。** 一覧再描画・集計再描画の処理内から live 領域に触れてはならない。live 領域を更新する関数は1つに集約し、T1〜T5 の5箇所からのみ呼び出す。

**visually-hidden の CSS [必須B]：**

```css
.visually-hidden {
  position: absolute;
  width: 1px;
  height: 1px;
  margin: -1px;
  padding: 0;
  overflow: hidden;
  clip: rect(0 0 0 0);
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}
```

**長文の読み上げに関する比較 [必須B]：**

本文全体を読み上げる方式は、長い問題文で読み上げが冗長になるという欠点がある。しかし代替案（「次の問題を表示しました」のような本文なし通知）では、画面を見ない利用者が問題文の内容を取得できず、学習アプリとして機能しない。カード本文こそが情報の本体であるため、本文を含める方式を採用する。冗長さの緩和のため、**集計値は live 領域に含めない**ことで通知の長さを本文分のみに抑える（L7）。

### 18.6 見出し構造 [必須B]

- `h1`：アプリタイトル
- `h2`：「カードを登録」「学習」「カード一覧」
- 見出しレベルを飛ばさない。

## 20. セキュリティ

### 20.1 必須条件 [必須A]

| # | 条件 |
|---|---|
| S1 | **`innerHTML` を使用しない**（`outerHTML` / `insertAdjacentHTML` / `document.write` も同様に使用しない） |
| S2 | `eval` / `new Function` / `setTimeout(文字列)` を使用しない |
| S3 | 外部リソース（CDN・Webフォント・外部画像・外部API）を一切参照しない |
| S4 | ユーザー入力の表示は `textContent` で行う |
| S5 | フォームの値の設定・取得は `value` プロパティで行う |
| S6 | localStorage の内容を信用せず、読み込み時に必ず検証する（2.4・4.3） |
| S7 | `JSON.parse()` の例外を必ず捕捉する |
| S8 | 外部通信を行わない（`fetch` / `XMLHttpRequest` / `WebSocket` を使わない） |

### 20.2 DOM構築方法 [必須B]

一覧などの動的な DOM は `document.createElement()` と `textContent` / `appendChild` で構築する。テンプレート文字列から HTML を組み立てて挿入してはならない。

### 20.3 属性値の扱い [必須B]

`aria-label`（8.7）などの属性にユーザー入力を含める場合は `setAttribute()` を用いる。属性値は HTML として解釈されないため安全であるが、文字列連結で HTML を組み立てる用途に流用してはならない。

### 20.4 期待挙動 [必須A]

以下の文字列を問題または答えに登録した場合、**スクリプトが実行されず、入力した文字がそのまま画面に表示される**こと。

- `<script>alert(1)</script>`
- `<img src=x onerror=alert(1)>`
- `"><script>alert(1)</script>`

## 25. 実装時の注意点まとめ

1. `state.cards` を直接書き換えない。必ず新しい配列・新しいオブジェクトを作り、`commit()` を通す。
2. `commit()` は保存成功時のみ `state.cards` を差し替える。失敗時は何も変えない。
3. index をキャッシュしない。カードの同定は常に id で行う。
4. `pickNextIndex` の中で `Math.random()` を呼ばない。引数で受け取る。
5. `Math.round()` を使わない。
6. live 領域への書き込みは、1操作につき1回だけ。集計・一覧の描画処理から触らない。
7. `innerHTML` を使わない。DOM は `createElement` と `textContent` で組み立てる。
8. `localStorage` の読み書きは必ず try/catch で囲む。
9. 採点の保存に失敗したら、次の問題へ進まない。
10. カードを削除したら、それが現在出題中かどうかを必ず判定する。
